서버 업데이트 장해 대처법

이 안내는 Librarian System 1.0.0에서 다음 버전으로 업데이트하거나,
업데이트 전후에 서버 포트를 별도로 변경할 때 적용됩니다.

1. 서버 업데이트만 하는 경우

1.0.0에서 PROGRAM만 교체하는 업데이트를 하면 기존 DATA와 서버 주소·포트가
유지됩니다. 이미 설치한 RisuAI 플러그인에서 같은 주소로 기억을 계속 사용할 수
있습니다. 저장 모드를 다시 적용하거나 새 포트를 지정할 필요는 없습니다.
업데이트가 확정되면 UPDATER 폴더의 업데이터와 이 안내문도 자동 갱신됩니다.
갱신 도중 전원이 꺼진 경우 다음 서버 실행 때 다시 시도합니다. 갱신 오류는
UPDATER/logs/updater-refresh.log에서 확인할 수 있습니다.

업데이트가 중단되었다면 같은 설치 폴더의 업데이트 도구를 다시 실행하세요.
업데이터가 미완료 작업을 확인하고 복구합니다. 복구 중에는 DATA나
UPDATER/update-state.json을 삭제하거나 다른 폴더로 옮기지 마세요.
같은 오류가 반복되면 UPDATER/logs/latest.log에서 오류를 확인하세요.

2. 포트 변경 전에 확인할 사항

서버 단독 모드를 사용 중이고 포트를 바꿀 예정이라면, 최신 플러그인에서
기존 주소로 서버에 접속해 저장된 기억을 한 번 정상적으로 읽으세요.
서버 DATA 식별값이 자동으로 저장됩니다. 서버 단독으로 쓰는 플러그인이
여러 개라면 각 플러그인에서 확인하세요. 기존 포트 번호도 적어 두세요.

3. 포트 변경은 완료됐지만 플러그인이 새 주소를 거부하는 경우

기존 DATA 식별값을 저장하기 전에 포트를 바꾸면 서버가 새 포트에서 정상
실행 중이어도 플러그인이 주소 변경을 보류할 수 있습니다. 이 경우 데이터는
서버에 그대로 있고, 플러그인이 기존 DATA와 같은지 확인할 정보가 부족한 상태입니다.

  1) 서버를 종료합니다. PROGRAM 폴더의 서버 포트 변경 도구
     (서버_포트_변경.bat 또는 서버_포트_변경.sh)로 이전 포트를 복원합니다.
  2) 서버를 실행합니다. 최신 플러그인에서 이전 주소로 기존 기억을 한 번
     정상적으로 읽습니다. 저장 모드를 다시 적용할 필요는 없습니다.
  3) 서버를 종료하고 도구로 원하는 새 포트를 설정합니다. 서버를 다시
     실행한 뒤 각 플러그인의 서버 연결 설정에 새 주소를 적용합니다.

새 주소에서 실제로 다른 DATA가 열려 있다면 원래 DATA를 사용하는 서버와
주소를 먼저 확인하세요. 이 경우에도 DATA를 초기화하거나 삭제할 필요는 없습니다.

4. 포트 변경 도구가 도중에 닫힌 경우

DATA/config/server-config.json을 열어 port 값을 확인하세요.

  - 이전 포트가 적혀 있으면 서버는 다음 실행 때 이전 포트를 사용합니다.
    기존 주소에서 기억을 읽어 확인한 뒤 포트 변경을 다시 시도하세요.
  - 새 포트가 적혀 있으면 포트 설정이 저장된 상태입니다. 서버를 실행하고
    새 주소를 적용하세요. 기존 DATA 식별값이 없어 거부되면 3번을 따르세요.

자세한 서버 접속 안내는 PROGRAM/서버_사용과_접속_관련_상세_안내.txt를 참고하세요.
