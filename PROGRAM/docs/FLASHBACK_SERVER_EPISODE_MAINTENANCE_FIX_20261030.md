# Flashback 서버 에피소드 인덱스 유지보수 패치 — 2026-10-30

## 원인

첨부 `flashback-memory-debug-2026-10-30T05-17-32-367Z.json`에서 서버 스냅샷 검사는 완료됐고 현재/저장 턴은 모두 12개였다. 누락·변경·미완료 임베딩은 0개이며, 원문 매니페스트·샤드 누락·개수 불일치도 없었다. 실제 차단 코드는 `episode_index_stale`이다.

`lastEpisodeIndex`는 `batched_incremental_wait`, `pendingTurns: 2`였다. 정상 백그라운드 정책은 새 턴이 3개 모일 때까지 기존 에피소드를 유지할 수 있다. 그러나 서버 점검 결과에는 누락 턴 동기화나 임베딩 큐 실행만 연결돼 있어, 원문·벡터는 정상이고 파생 인덱스만 오래된 경우 실행할 수 있는 경로가 없었다. 또한 명시적 유지보수의 인덱스 갱신도 같은 묶음 대기를 따르고 있었다.

이는 앞선 스냅샷 허용 목록 문제를 통과한 뒤 드러난 별도의 실행 연결 누락이다. 데이터 손상이나 제공자 연결 실패로 판정한 증거는 아니다.

## 수정

- 원문·벡터와 저장 구조가 검증되고 미완료 임베딩이 없는 서버 범위에 한해 `server_episode_rebuild` 전략을 제공한다.
- 실제 실행 전 새 점검 결과로 자격을 다시 계산하고, 승인한 범위·원문·설정·서버 스냅샷과 일치하는지 확인한다. 호출자가 전략 이름을 바꾸거나 오래된 plan을 제출해도 다른 손상 복구 권한을 얻지 못한다.
- 기존 `maybeRebuildEpisodeIndex()`와 범위 쓰기 잠금·서버 writer fence를 사용한다. 기존 벡터를 평균·묶음 처리하는 파생 계산이며 임베딩 API나 자격 증명 확인 호출을 하지 않는다.
- 명시적인 유지보수에서는 `force: true`로 인덱스를 갱신한다. 일반 백그라운드의 3턴 묶음 정책은 유지한다. 누락 턴 동기화/임베딩 큐가 완료된 뒤에도 같은 대기 상태를 남기지 않는다.
- 저장 후 새 서버 스냅샷으로 재점검한다. 제공자 준비 상태는 여전히 미검증으로 남으며, 서버 원문·저장 점검 통과와 구분한다.
- 진단 창에 **에피소드 인덱스 갱신** 버튼과 **제공자 호출 0회 · 추가 임베딩 없음**을 표시한다. 원문·벡터 이상과 파생 인덱스 갱신 필요를 구분한다.
- 진행 창에 에피소드 갱신 단계를 표시하고 해당 작업의 실제 요청 수는 0건으로 표시한다. 서버 저장 점검을 통과한 복구를 완료 상태로 전달한다.

## 별도 기존 시험 실패

추가로 실행한 `flashback_maintenance_outcome_gui_runtime_test.cjs`는 3개 중 2개가 실패했다. 이 파일의 소형 DOM은 현재 진입점 `maintenanceInspectBtn` 없이 예전 `maintenanceAutoBtn`만 구성하고 예전 확인 창 2개를 기대한다. 현재 버튼은 새 진단 진입점으로 전달되므로 이 fixture에서 실행되지 않는다. `FLASHBACK_TEST_PLUGIN`으로 `git show HEAD:PROGRAM/plugins/Flashback_Memory.js`를 별도 로드해도 같은 두 실패가 재현된다. 이번 변경으로 발생한 회귀로 세지 않았으며 시험을 완화하지 않았다. 새 시험은 현재 실제 진입점·실제 진단 액션·완료 창을 실행한다.

이전 작업에서 기록한 SDK pin 불일치 및 배포물 전용 루트 검사 미통과는 이 패치의 완료 주장에 포함하지 않는다.

## 적용

이번 제품 변경은 `PROGRAM/plugins/Flashback_Memory.js`의 점검·파생 인덱스 유지보수·표시에 한정된다. 이전 패치와 사용자의 기존 DATA 변경은 보존했다. 사용자 DB 복구나 현재 대화 재구축을 실행하지 않았고, 버전 상승·배포·커밋도 하지 않았다.
