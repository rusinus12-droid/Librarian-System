# HAYAKU 설치 후 손대지 않아도 되게 (2026-10-16)

목표: 설치만 하면 HAYAKU가 동작하고, 사용자가 꼭 해야 할 일이 생겼을 때만 알려 준다.

## 점검 결과 (변경 전)

이미 기준에 맞는 부분:

- 설정은 모두 비워 둬도 기본값으로 동작한다.
- 새 채팅은 `플러그인 단독` 저장이 기본이다. 서버, 토큰, 선택창이 필요 없다.
- 패킷 숨김, 프롬프트 방식, 기억 언어는 자동으로 정해진다.
- 대화 중에 스스로 뜨는 창이 없다.

부족했던 부분:

1. 기존 채팅에 설치하면 지난 턴의 기억이 없었다. Cold Start는 뷰어 안의 버튼으로만 시작할 수 있었고, 이를 알려 주는 곳도 없었다.
2. 보조 모델(Other Ax)이 실제로 연결돼 있는지 확인하지 않았다. 연결 테스트는 수동 버튼뿐이었다.
3. 복구가 실패해 기억이 빈 턴이 생겨도 뷰어를 열어 보기 전에는 알 수 없었다.
4. 프리셋의 출력 태그를 확실히 감지하지 못하면 패킷을 응답 끝에 두는데, 그 경고는 뷰어 안의 코드 문자열로만 보였다.

## 변경: 채팅 알림 버튼 하나

- **위치:** 채팅 입력창 옆 버튼(`location: 'chat'`)이다. GRADIA의 ✨ 버튼과 같은 자리다.
- **구분:** 이름을 숨기는 호스트에서도 주황색 `H` 아이콘이 보인다. LIBRA는 파란색 `L`을 쓴다. 작은 `!`·시계·`i` 배지가 알림 종류를 나타내며, 버튼 설명과 접근성 이름에도 플러그인 이름을 유지한다. 두 버튼의 등록·삭제 ID는 각각 독립적이다.
- **표시 조건:** 사용자가 할 일이 있을 때만 생기고, 원인이 사라지면 지운다. 평소에는 화면에 아무것도 늘지 않는다.
- **우선순위:** 한 번에 하나만 보이며, 아래 순서로 정한다.

| 순위 | 표시 | 조건 | 누르면 |
| --- | --- | --- | --- |
| 1 | ⚠️ HAYAKU · 보조 모델 연결 필요 | 보조 모델 확인 실패, 또는 보조 모델 API가 없는데 복구할 일이 있음 | 복구 화면을 열고 연결 확인 요청을 1회 보내 결과를 보여 준다 |
| 2 | 🕘 HAYAKU · 지난 N턴 기억 만들기 | 완료 턴은 있는데 HAYAKU 기록이 하나도 없음(설치 전 대화) | Cold Start 확인창(대상 턴, 예상 호출 수)을 바로 띄운다 |
| 3 | ⚠️ HAYAKU · 기억 없는 턴 N개 | 패킷이 없는 완료 턴이 있음(복구 실패, 건너뜀, 설치 후 첫 턴 이전) | 누락 복구 화면을 연다. 턴을 고르고 비용을 확인한 뒤 복구하거나 제외한다 |
| 4 | ℹ️ HAYAKU · 패킷 위치 확인 | 직전 요청에서 패킷 위치 경고가 있었음 | 설정 화면을 열고 경고 내용과 바꾸는 방법을 보여 준다. 채팅·경고 조합마다 한 번만 보인다 |

햄버거 메뉴 대신 이 자리를 고른 이유는 두 가지다. 햄버거 메뉴는 메뉴 안에 숨어 있어 상태를 알리는 데 쓸 수 없다. 채팅 본문에 문구를 넣는 방식은 대화 내용을 바꾸므로 쓰지 않았다.

## 보조 모델 자동 확인

- 채팅 응답을 한 번 이상 본 뒤, 다른 작업이 없을 때 30초 후 확인 요청을 1회 보낸다. 내용은 짧은 "HAYAKU OK" 응답이다.
- 결과는 호스트 장치 저장소(`getLocalPluginStorage` / `safeLocalStorage`, `hayaku.auxProbe.v1`)에 남긴다. 전역 `localStorage`가 없어도 재시작 후 읽는다. 성공하면 7일 동안 다시 확인하지 않는다.
- 실제 보조 모델 호출(afterRequest 복구, Cold Start)이 성공하면 그것을 성공으로 간주하고 확인 요청을 생략한다.
- 실패하면 1순위 버튼이 뜬다. 다음 세션에서 한 번 더 확인한다.
- 확인 요청이 진행 중일 때 afterRequest 복구가 겹치면, 그 턴은 기존처럼 건너뛰고 3순위 버튼으로 알린다.

## 갱신 시점과 부담

- **갱신 시점:** 응답 출력 2.5초 뒤, 복구·Cold Start 작업 종료 뒤, 채팅 전환 뒤.
- **채팅 전환 감지:** 10초마다 현재 캐릭터·채팅 번호 두 개만 읽는다. 대화 원문은 읽지 않는다.
- **상태 계산:** 먼저 순수 읽기(`loadStorageLedgerSummary`)로 판단한다. 할 일이 있어 보일 때만 복구 화면과 같은 정밀 검사를 한다. 정밀 검사는 대화·원장 상태가 바뀔 때만 다시 한다. 복사한 채팅이나 Journal 항목 같은 경우도 이 검사에서 판단한다.
- **실행 제외:** 캡처, 저장, 복구, Cold Start가 진행 중이면 계산을 미룬다.
- **비용:** 알림 계산 자체는 보조 모델을 호출하지 않는다. 호출은 위의 자동 확인 1회뿐이다.

## 패킷 위치

- 감지가 모호하면 기존 코드대로 패킷을 응답 끝에 둔다. 패킷 저장은 계속된다.
- 뷰어의 "위치 경고"는 코드 대신 설명 문장으로 보인다. 예: "프리셋에 출력 감싸기 태그가 여러 개라 패킷을 응답 끝에 둡니다."

## 확인 범위

- `tests/hayaku_zero_touch_attention_runtime_test.cjs`:
  - 우선순위 판단.
  - 위치 경고를 한 번만 보이는지.
  - 기존 채팅 설치 시 채팅 버튼이 "지난 2턴 기억 만들기"로 등록되고 보조 모델 호출이 없는지.
  - 같은 상태에서 다시 등록하지 않는지.
  - 보조 모델 실패가 Cold Start보다 앞서는지, 성공하면 해제되는지.
  - 종료 시 버튼을 지우는지.
- HAYAKU 관련 테스트 164개를 실행했다. 새 실패는 없고, 실패 8개는 변경 전과 같다.
- 실제 RisuAI에서 채팅 버튼이 어떻게 보이는지는 확인하지 않았다. 아이콘 크기, 이름 표시 방식, 재등록 깜빡임이 그 대상이다.

## 재현 결함 후속 패치

HAYAKU 3.0.142는 비활성화 저장 시 자동 확인 타이머를 취소한다. 이미 실행된 콜백과 모델 큐에서 대기 중인 요청도 실제 제출 직전에 활성 상태·런타임 소유권을 재확인하며, 취소를 연결 실패로 기록하지 않는다. 실제 제출된 호출을 되돌리는 동작은 아니다. [다섯 결함의 재현·검증 기록](ATTENTION_SETUP_REVIEW_FIXES_20261016.md)을 참조한다.
