# HAYAKU 3.0.101 — 승인 기록 오류와 패킷 누락 분리

첨부 3.0.100 로그의 T9는 활성 저장 패킷과 활성 결속 노드가 있으며, 원문 지문·메시지 ID·패킷 해시가 일치했다. 그러나 원문 수정 저널 오류로 SDK blocks()가 true, canWrite()가 false를 반환했다. HAYAKU가 이미 superseded(응답 버전 전환)로 정리한 작업에도 이 쓰기 제한을 패킷 읽기 거부로 적용하여, 점검용 결속에서는 패킷을 제외했다. 저장 원장을 직접 표시하는 목록과 점검 결과를 표시하는 관제가 모순됐다.

## 변경

- 완료·대체 완료된 원문 수정 작업에는 전역 저널 오류에 따른 추가 패킷 거부를 적용하지 않는다. 완료된 교체의 옛 패킷 제외 검사는 먼저 수행한다.
- 전송 패킷을 저널 오류 하나만으로 모두 제거하던 분기를 제거한다. 완료된 교체의 옛 해시 제외는 유지한다.
- 실제 미승인 변경의 새 패킷 차단과 SDK 쓰기 허가 제한을 유지한다.
- 정확한 턴 대조와 복구 상태에 sourceEditError를 별도로 전달하고, 관제에 승인 기록 오류를 설명한다.

## 검증과 한계

hayaku_journal_error_coverage_test.cjs는 가상 호스트에서 저장된 패킷에 응답 버전 전환 작업을 만들고 저널 기록을 실패시킨다. 기존 패킷 필터·결속·누락 대조·관제 모델·전송 경로 보존, 미승인 새 패킷 차단, 모델 호출 0회를 확인한다. 호스트 래퍼가 false를 성공처럼 반환하는 경우에도 실제 저장 재조회 실패가 감지된다.

이 패치는 저장 장치가 저널 쓰기를 거부한 근본 원인을 해결한 것은 아니다. 승인 오류를 숨기거나 승인된 것으로 간주하지 않으며, 사용자 저장 데이터의 삭제·재생성을 수행하지 않는다. 실제 RisuAI 화면 및 사용자 기기 저장소 검증은 수행하지 않았다.
