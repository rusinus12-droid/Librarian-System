# LIBRA 2.3.48 — 구형 실패 작업의 콜드스타트 복구

구형 Ariadne/통합 v1 작업 기록이 현행 Librarian 실행을 막는 문제를 수정했습니다. 수동 콜드스타트, 선택 구간 분석, 실패 배치 복구에서 같은 scope·원문·턴 범위의 구형 실패 또는 중단 작업을 보관하고 새 Librarian 작업으로 전환합니다.

## 적용 방법

1. RisuAI의 기존 LIBRA 플러그인을 이 버전의 `LIBRA.js`로 교체하고 다시 로드합니다.
2. 해당 채팅에서 ‘실패 배치 복구’를 실행하거나, 콜드스타트에서 가장 이른 실패 구간부터 순서대로 선택합니다.
3. 1~5턴의 정본과 State를 저장한 뒤 6~10턴을 처리합니다. 기존 정본과 원문을 먼저 삭제할 필요가 없습니다.

## 저장 경계

- 기존 work와 run은 scope 내 `retired-work` 이력에 보관하고 물리 저장 경로에서 재조회합니다. 이전 run은 수정하지 않습니다.
- 활성 work를 새 기록으로 교체하므로 이전 stageIndex, 초안, Ariadne 예산을 재사용하지 않습니다. 새 run에 이전 run/operation 및 보관본의 연결을 남깁니다.
- 보관본과 새 run을 확인하기 전에는 활성 work를 교체하지 않습니다. 교체 저장 또는 재조회 실패 시 원래 work를 복원하고 다시 확인합니다. 복원도 확인할 수 없으면 오류를 반환하며 Provider를 호출하지 않습니다. 보관본은 유지합니다.
- 이미 정본에 연결된 작업, 다른 scope/원문/턴 기록, 실행 중인 작업, 알 수 없는 엔진은 전환하지 않습니다. 구형 building 기록은 대응 run이 실패/중단으로 확인될 때만 전환합니다.
- 자동/중단 재개는 구형 작업을 자동 전환하지 않습니다. 일반 스캔의 현행 실패 작업 재호출 억제도 유지합니다.
