# Flashback 문맥 중심 검색 (1.0.49)

최근 대화와 현재 입력을 함께 임베딩해 기억을 찾는다. 단어별 특별 규칙을 추가하지 않고, 현재 설정된 실제 임베딩 모델이 산출한 유사도를 후보 생성부터 최종 선택까지 사용한다.

## 요청과 후보

- 현재 사용자의 입력과 설정된 수의 최근 user/assistant 대화를 시간순으로 묶는다. 대화는 현재 입력과 단어가 겹치지 않아도 보존한다. 호스트의 실제 대화 기록을 우선하며 시스템 프롬프트, 플러그인 주입, 숨은 분석은 기존 정제 경로로 제외한다.
- 최근 대화는 최대 6,000자, 메시지 수는 기존 설정(기본 5, 최대 20)을 따른다. 최근 메시지를 먼저 확보하고 오래된 메시지를 통째로 제외한다. 가장 최근 메시지 하나가 한도를 넘으면 생략 표시와 끝부분을 전달한다. 현재 입력은 별도 6,000자 상한이다.
- `최근 대화 + 현재 입력`을 하나의 질의로 임베딩한다. 문맥이 없으면 현재 입력만 임베딩한다. 별도 생성 호출이나 별도 현재 입력 임베딩은 없다.
- 75:25 고정 혼합을 삭제했다. 전체 질의 벡터와 저장 벡터의 유사도를 그대로 사용한다.
- 의미 후보에 60%를 우선 배정하던 고정 배분 규칙을 삭제했다. 설정된 후보 수/샤드 수 한도 안에서 의미 유사도로 정렬한다. 단어별 우선권, 문형별 질문 분할 및 시간·감정 의도 추정은 의미 검색 순위를 제어하지 않는다.

## 최종 선택과 저장

- 실제 임베딩이 호환되는 후보는 키워드·최신성 보정을 계산한 후 덮어쓰는 대신 처음부터 의미 유사도로만 평가하고 최소 점수 미만이면 제외한다. 특정 단어의 직접 일치, 추정한 검색 대상, 중요도·최신성 보정이 의미 순위를 덮어쓰지 않는다.
- 단어로 추정한 현재/과거 의도 때문에 의미 후보를 사전에 거절하지 않는다. 세계선·접근 범위·공개 여부·원본 유효성 보호는 유지한다. 원문은 과거 기록의 시점과 함께 전달되며 과거 사실을 현재 사실로 다시 저장하지 않는다.
- 의미 비교에 사용한 완전한 기억 조각을 전달한다. 선택 후 키워드가 들어간 한 문장으로 다시 바꾸지 않는다. 물리 출력 예산 안에 들어오지 않는 조각은 제외한다. 큰 조각의 일부를 별도로 의미 평가하는 기능은 이번 범위 밖이다.
- 저장된 원문, 벡터, 벡터 프로필 및 기존 아카이브는 변경하지 않는다. 재임베딩이나 데이터 마이그레이션이 필요 없다.
- 결과 진단의 `contextualRecall.mode`는 `semantic_embedding`, `lexical_fallback`, `legacy`를 구분한다. 호환 벡터 후보 수와 단어 검색 대체 후보 수도 따로 기록한다. 둘이 섞인 경우 의미 검색 후보를 먼저 선택한다. Hash와 원격 임베딩 실패 후 대체 검색을 의미 이해 성공으로 표시하지 않는다.

## 설정과 범위

설정의 **문맥 중심 의미 검색**은 기본 켜짐이다. 현재 선택한 임베딩 모델을 사용한다. Hash는 단어 기반 대체 검색이므로 자연어 의미 이해를 제공하지 않는다. 기존 적응형 문맥 창 설정은 문맥 중심 검색을 끈 호환 경로에서만 적용된다. `리콜 문맥 채팅 수 = 0`이면 최근 대화를 사용하지 않고 현재 입력만 의미 검색한다.

이번 배포는 Flashback만 변경한다. HAYAKU는 작업 전 3.0.67 소스와 동일하며 별도 임베딩/AI 호출을 추가하지 않았다. HAYAKU의 AI 호출 방식에 관한 작업은 사용자 지시에 따라 보류했다.

## 확인의 한계

오프라인 테스트는 실제 저장·임베딩 전송 형식·캐시·후보 선택·beforeRequest 주입과 저장 불변을 확인한다. 제어된 벡터를 사용한 시험은 모델의 한국어 이해 능력을 입증하지 않는다. 실제 RisuAI GUI, 외부 임베딩 모델의 자연어 평가, 대규모 자료의 검색 적중률 및 사용자 기기 성능은 별도 확인이 필요하다. 후보 한도 안에 들어오지 않은 기억까지 찾는다는 보장은 없다.

## 1.0.48 점검 범위

문맥 검색의 고정 혼합·후보 비율과 단어별 의미 결정 경로를 제거했다. 사용자 설정의 Top K, 최소 관련도, 선택적 MMR 다양성 설정, 입력 길이/시간 제한, 세계선·공개 범위·저장 무결성 검사는 유지한다. 이들은 특정 예문에 대한 정답 규칙이 아니다. 문맥 검색을 끈 호환 모드와 임베딩 불가 시의 기존 단어 검색 코드는 남아 있다. 따라서 플러그인 전체의 정규식이나 상수를 전부 삭제한 패치는 아니다.

## 1.0.49 엔진 호환성 보완

- 호환 모델 벡터를 가진 기억은 의미 순위로 검색한다. Hash·미갱신·벡터 비호환 기억에는 기존 sparse/exact/hashRecovery 대체 경로를 적용하며, 그 점수를 의미 후보에 가산하지 않는다. 모델 유사도가 최소 점수에 못 미치는 후보가 대체 후보의 자리를 소모하지 않는다. 기존 후보·출력 상한 안에서 처리한다.
- 샤드의 centroid는 제공자·모델·차원·연결 프로필의 호환성을 확인한다. 모든 샤드가 비교 가능할 때 의미 순위를 사용하고, 일부 또는 전부가 비교 불가하면 기존 호환 라우터로 탐색한다. 비교 불가를 관련도 0으로 확정하지 않는다. 기존 호환 라우터의 읽기 한도·저신뢰 확장·전수 읽기 조건은 유지한다. 부분 읽기를 전체 범위 확인으로 표시하지 않는다.
- 기존 선택기가 명시적 비교 요청에 대해 만든 동반 근거 요구를 일반 의미 순위보다 먼저 처리한다. 같은 목적의 후보 사이에서는 문맥 유사도와 MMR을 사용하며, topK와 물리 예산은 넘지 않는다. 일반 문맥 요청에 비교 쌍을 새로 강제하지 않는다.
- Hash 우선 커밋과 비동기 모델 임베딩 갱신, 아카이브·원문·벡터 저장 형식은 유지한다. 추가 모델 생성 호출이나 자동 재임베딩은 없다.
