# HAYAKU 직접 원문 재분석의 실행 전 확인

기준은 main `7843201`, HAYAKU 3.0.152이며 수정 버전은 3.0.153이다.

## 수정 내용

직접 원문 재분석 GUI가 선택 목록을 `runHayakuSelectedReanalysis`에 바로 전달하여 비용 안내나 교체 확인 없이 모델을 호출했다. 기존 `previewSourceEdits` → 사용자 확인 → `applySourceEdits` 경로로 연결했다.

첫 버튼은 **재분석 내용 확인**이다. 프리뷰는 모델을 호출하지 않으며, 확인창에 선택한 턴, 대상 수, 기본 Other Ax 호출 수, 설정에 따른 추가 호출 허용 상한, Provider 비용 발생 가능성을 표시한다. 검증과 저장 확인에 성공하면 기존 기억을 새 기억으로 자동 교체함을 안내하고 **재분석 후 기억 교체** 버튼으로 실행한다.

프리뷰 API의 경고에도 호출 수·상한과 자동 교체를 포함한다. GUI는 목록을 표시했을 때의 스코프·토폴로지·메시지 identity를 프리뷰에 전달한다. 목록 이후 다른 메시지나 채팅으로 바뀌면 새 대상으로 조용히 재지정하지 않고 목록 새로고침을 요구한다. 기존 API의 턴 키 배열 입력도 유지한다.

확인창 취소, Escape, 배경 클릭, 다른 복구 하위 탭이나 상위 메뉴로 이동, GUI 닫기, 플러그인 종료는 확인창을 닫고 티켓을 무효화한다. 일회용 티켓과 확인창의 완료 처리가 중복 승인을 막는다. 확인창에는 키보드 포커스를 가두고 취소 버튼에 초기 포커스를 두며, 취소 후 실행 버튼으로 포커스를 돌려준다.

프리뷰 당시 추가 호출 허용량을 실행의 단일 턴·여러 턴 경로에 전달한다. 확인창을 연 뒤 설정을 바꿔도 해당 작업의 호출 허용 상한이 증가하지 않는다. 표시한 상한은 허용 예산이며 실제 호출을 보장하는 수치가 아니다. 기존 모델 응답·종료 상태·구조 복구 자격 검사와 호출 계약을 유지한다.

## 저장 동작

확인창은 생성 결과나 이전·이후 원문의 차이를 미리 생성하는 기능이 아니다. 실제 분석은 승인 시점의 현재 원문을 사용한다. 안정적인 메시지 ID가 있는 채팅의 본문 편집은 실행 시점에 읽으며, ID가 없는 예전 채팅은 편집 후 목록을 새로고침해야 한다.

실행 도중의 원문·메시지·세계선 변경 검사, 원문 증거 재조회, 근거 검증, 저장 후 재조회는 유지한다. 여러 턴은 검증을 모두 마친 후 한 번에 교체한다. 선택하지 않은 턴은 자동 재작성하지 않는다. 채팅 원문 자체도 수정하지 않는다.

## 검증과 한계

`hayaku_source_reanalysis_confirmation_gui_test.cjs`의 14개 검사는 제품 플러그인과 GUI DOM에서 다음을 실행한다.

- 확인창의 선택 범위·호출 수·상한·비용·교체 안내와 초기 포커스를 확인한다.
- 취소 버튼, Escape, 배경 클릭은 모델 호출과 정본 원장 쓰기를 수행하지 않는다.
- 승인 후 현재 본문으로 1회 분석하고, 검증된 저장 이후 GUI에 성공을 표시한다. 중복 승인은 호출을 추가하지 않는다.
- 두 턴 승인에서 두 번째 분석이 대기 중일 때 기존 원장을 유지하고, 모두 검증한 뒤 두 기억을 함께 교체한다.
- 프리뷰 전후의 메시지 identity 변경은 모델 호출 전에 차단한다.
- 화면 전환·닫기·종료 후 남은 버튼으로 실행할 수 없으며, 돌아온 화면에서는 새 프리뷰를 열 수 있다.
- 프리뷰 후 추가 호출 설정을 높여도 단일 턴과 여러 턴 모두 실제 호출 계획의 허용량이 증가하지 않는다. 허용 상한이 2회여도 정상 응답은 1회만 호출한다.

새 GUI 검사를 포함한 관련 회귀 18개 파일과 배포 메타데이터·파일 목록·버전·출처 검사 5개 파일이 통과했다. 기존 명시적 재분석·발행 경계·세 저장 모드·재시작·다른 GUI 확인 경로를 포함한다. 문법·체크섬·출처 생성 결과의 일치도 확인했다. 전체 프로젝트 회귀 스위트를 실행한 결과는 아니다.

기존 호출 계약 테스트 한 곳은 이미 퇴역한 실패 상세 화면의 마크업을 요구하여 기준 커밋에서도 실패했다. 근거·호출 예산 검사는 유지하고, 해당 UI 항목을 현재 로그의 명시적 상세 조회·선택적 내보내기에 맞췄다.

검증은 통제된 모델 응답과 호스트·서버·DOM 환경을 사용하며, 이번 변경에서 외부 실모델이나 실제 사용자 RisuAI 앱을 실행한 결과는 아니다.
