# 원문 실측 실패 원인과 후속 보강

> 후속 필드 감사: [LIBRA_STATE_FIELD_AUDIT_20261106.md](LIBRA_STATE_FIELD_AUDIT_20261106.md). 실제 원문과 최종 State를 대조해 외모·현재 목표·습관 후보·방문 과제 종결 등의 누락을 확인했다. 아래의 '근거 부족/판정 유보' 설명만으로 원문의 빈 필드를 설명할 수 없다. 합성 자료 성공은 실제 원문 전체의 추출 완전성을 입증하지 않는다.

## 범위

사용자가 전송 승인한 기존 원문 T1~10과 선택 로어 3건을 로그인된 로컬 Ollama의 native adapter를 통해 `deepseek-v4.1-flash:1017-cloud`로 분석했다. 실제 모델 응답 이름은 `deepseek-v4.1-flash:1017`이다. API 키 추가 없이 요청에 성공했다.

배포 LIBRA 전체 코드를 격리된 VM/저장소에서 실행하고, Micro 5턴 → 정본 5턴을 두 차례 수행한다. 실제 데이터베이스는 읽기 전용이며 실제 RisuAI 설치 UI나 실사용 저장소를 변경한 실측은 아니다. 모델 응답을 모방한 테스트와 구분한다.

원문, 모델 응답, 격리 저장소는 비공개 `.development/libra-completeness-20261106/` 아래에 보관한다. 이 문서에는 원문을 복사하지 않는다.

## 첫 실측에서 구분된 원인

| 구분 | 관측된 원인 | 보강 |
|---|---|---|
| 코드 | Ollama native adapter가 수동 context_window를 무시하고 기본 32K를 적용해 정본 요청 전 예산 오류 발생 | native 옵션, 수동 설정, 일치하는 catalog 순서로 사용하고 전체 출력 토큰을 예약 |
| 프롬프트/형식 검증 | 서사 압력이 인용 사건 ID 없는 문자열로 반환되어 폐기됨 | 유효한 JSON 예시와 object/null 계약 명시, 잘못된 형태의 진단 기록 |
| 모델 출력/복구 경로 | 첫 thread fact가 text/temporalRole/certainty/evidenceSpans 없이 출력됨 | 기존 1회 근거 복구 요청에서 누락된 필수 의미 필드도 복구하고 다시 원문 검증 |
| 연결 규약 | 최초 구간에서 존재하지 않는 이전 이야기 alias를 전제로 reaffirm이 반환됨 | 이전 기록이 없음을 완전히 확인한 최초 구간에 한해서 새 이야기로 정규화; 불완전 조회에는 적용하지 않음 |
| 코드 | 자동 Micro 검토가 canonical_overlap_conflict를 재적용하여 정본의 최신 위치·상태를 과거 값으로 덮음 | 자동 검토에서 충돌 보류를 유지; 사용자의 명시적인 교정과 구분 |
| 코드 | parentRef 제안이라는 이유만으로 일반 사물의 주체를 장소로 생성 | 확인된 장소 주체만 직접 포함 관계 반영; 미확인 주체는 정본 검토용 Micro 후보로 유지 |
| 자료/의미 판단 | 선호·습관 등의 빈 칸을 근거 유무와 구분하지 않고 모두 실패로 세면 과잉 추론 발생 | 일회 반응·현재 강요·일회 행동을 지속적인 취향·습관·능력으로 승격하지 않도록 명시 |

첫 실측의 선호 관련 검색 결과에는 동의·거절·현재 장면 반응이 섞여 있다. 이것만으로 지속적인 취향을 확정할 수 없다. 반대로 현재 행위에 대한 명시적 거절은 범위가 한정된 경계의 근거가 될 수 있다. 따라서 '빈 필드 = 결함' 또는 '빈 필드 = 원문에 없음'으로 일괄 판정하지 않는다. 마무리된 이야기 역시 실제로 해결된 과제와 진행 중인 장면을 구분해야 한다.

Micro는 모든 영역의 임시 기억을 남기고, 정본은 그 검증된 데이터와 원문을 함께 종합한다. 직접 State 반영 권한과 정본 입력 범위는 별개다. 서사 후보도 보존하며 정본 입력에 포함한다.

## 정적 검증

후속 관련 테스트 30개 스크립트가 모두 통과했다. 공급 복구의 정확한 인용 검사, 기존 불확실성 보존, 조작된 인용 거부, 정본 우선순위, 잘못된 사물 포함 관계, native 컨텍스트 설정을 추가 검증했다. 플러그인 단독·미러·서버 모드의 합성 모델 검증을 포함한다. 전체 회귀 수백 개나 실제 설치 UI 검증을 대신하는 결과는 아니다.

첫 시도와 재개 실행에서 모델 생성 18회를 사용했다. 별도 연결 확인 1회가 있었다. 후속 실측은 앞선 18회를 포함하는 최대 40회 제한을 유지하고, 같은 원문으로 새로운 격리 저장소에서 실행한다.

## 후속 실측 결과

## 후속 조사 전의 잔여 항목

1. **장소 연결 1건 보류 — 이름 바인딩/입력 연결 문제.** 두 번째 정본의 `e5` 이름 '좁은 방'이 해당 구간 원문 이름으로 인정되지 않아 `UNIFIED_ENTITY_NAME_UNBOUND`, 그 장소를 가리키는 `f24` 위치가 `UNIFIED_VALUE_REFERENCE_INVALID`로 격리됐다. 앞 구간에는 같은 장소 이름이 있다. 데이터가 전혀 없다고 볼 사례가 아니다. 이전 정본의 장소와 현재 구간의 지시어를 근거 있게 연결하는 경로를 추가 검토해야 한다. 잘못된 현재 위치를 임의 확정하지는 않았다.
2. **Micro 장소 종류 — 코드의 종류 추정 공백.** 그릇을 장소로 만드는 parentRef 문제는 차단했지만, description 제안으로 생성된 '방'은 `kind:object`로 남았다. 최종 조회의 세계 7건 중 한 건이다. description 필드만으로 장소/사물을 판별할 수 없으며 Micro entity kind의 명시적 후보 계약과 Registry 결합이 추가로 필요하다. 이번 차단만으로 세계 종류 문제 전체가 해결됐다고 주장하지 않는다.
3. **선호·습관·목표의 빈 칸 — 원문 의미 검토가 필요한 영역.** 현재 자료에서 검색된 좋아/싫어 반응을 지속 취향으로 단정할 수 없고, 습관이나 안정적인 목표가 충분히 주어진 통제 양성 자료도 아니다. 실제 자료만으로 필드 수집의 재현율을 산출할 수 없다. 지속 취향·습관·목표가 명시된 양성 자료 및 일회 반응 음성 자료를 추가 실측해야 한다. 합성 회귀에서는 해당 필드의 저장 경로가 검증됐다.
4. **마무리된 이야기 0 — 판정 유보.** 현재 장면의 진행과 장기 갈등 종결은 다르다. 기존 원문에 대해 종결되어야 할 과제 목록을 사람이 확정한 정답표 없이 0을 결함 또는 데이터 부재로 단정하지 않는다. 명시적 약속 이행/과제 완료 자료의 양성 실측이 필요하다. 최초 이야기의 필수 필드와 잘못된 reaffirm 문제는 후속 첫 구간에서 재현되지 않았다.

위 목록은 원문 재실측 직후의 판정이다. 이어서 수행한 조사·수정 결과는 아래와 같다.

## 이어서 수행한 수정과 판정 정정

### 위치 보류는 근거 부족을 올바르게 차단한 사례

원문 재실측의 `e5`는 문이 닫히고 잠금장치가 채워졌다는 문장으로 장소 이름을 증명하려 했다. `f24`는 밧줄이 여전히 묶였다는 문장으로 인물의 현재 장소를 증명하려 했다. 두 인용 모두 해당 장소 이름이나 현재 위치를 확정하지 않는다. 따라서 기존 장소가 이전 정본에 있다는 사실만으로 이 두 인용을 통과시키는 것은 부정확하다. 앞선 '이름 연결 문제' 판정을 **모델의 근거 없는 위치 재단정과 정상적인 격리**로 정정한다.

프롬프트에는 State가 이전 위치를 유지하므로 문 닫힘·기상·구속 상태만으로 위치를 새로 추론하지 말라고 명시했다. 검증기는 완화하지 않았다. 추가 회귀에서는 첫 정본의 장소가 이후 배치에 이름 없이 이어질 때 잘못된 장소 제안을 거부하고 기존 locationRef는 유지하면서 현재 condition만 갱신하는 것을 확인했다.

### Micro 종류 계약과 기본값 수정

`stateIntent.target`이 이름만 허용하고, 신규 세계 주체는 사물을 기본값으로 사용하던 것이 '방' 오분류의 원인이었다.

- 세계 target에 선택적인 `entityKind`(location/object/organization/rule/environment/condition/other)를 허용하고 enum을 검증한다.
- 생성 프롬프트에서 원문에 근거해 종류를 전달하도록 요구한다. 방·장소의 description을 사물로 해석하지 않는다.
- 종류가 없으면 신규 주체를 `other`로 두며 사물로 단정하지 않는다. 기존 Micro 기록의 이름만 있는 계약도 계속 읽는다.
- 이미 확인된 Registry 종류와 충돌하는 제안은 보류하고 자동 검토로 우회하지 않는다.
- 종류가 location으로 제안된 신규 장소는 포함 관계를 만들 수 있다. 종류 없는 그릇에 parentRef를 썼다는 이유만으로 장소를 만들지는 않는다.

확장된 3모드 행렬 검사에서 32개 긍정 사례와 12개 보류 사례가 통과했다. 신규 방/컵/종류 불명/기존 장소와 종류 충돌/신규 장소 포함 관계를 검증한다.

## 의미 양성·음성 자료의 실제 모델 검증

개인정보가 없는 별도 5턴 합성 자료로 같은 모델에 Micro 1회, 정본 1회, 서사 구성 1회, 선호·경계 확인 1회를 요청했다. 원문 실측과 구분하며 실사용 자료의 재현율로 환산하지 않는다.

실행: `.development/libra-completeness-20261106/run-field-positive-1/`. 생성 4회, 약 19.1초, 입력 11,996 / 출력 4,230 토큰. 누적 실측 38회이며 연결 확인 1회는 별도다. 모든 응답 HTTP 200.

| 검사 | Micro | 정본 |
|---|---|---|
| 명시적 쓴 커피 선호 | 저장 | 저장 |
| 매일 아침 일기 습관 | 저장 | 저장 |
| 등대에 지도 전달 목표 | 저장 | 저장 |
| 작은 방 / 청동 컵 종류 | 장소 / 사물 | 장소 / 사물 |
| 일회성 동의 반응 | 지속 취향으로 저장하지 않음 | 지속 취향으로 저장하지 않음 |
| 명시적 약속 이행 | 정본 검토 후보 | closedThreads 1건, fulfilled |

정본 보류 0, 재생성 성공 및 전후 동일. 원문 5턴과 T5 Micro claim 10개를 함께 종합했다(T1~4는 Micro가 없는 것으로 출처에 명시). 검증 결과는 `assertions.json`에 기록했다. 이것으로 이 필드들이 영구적으로 채워지지 않는 경로라는 가설은 반증된다. 원래 민감한 원문에서의 선호·습관 0이나 종결 0이 모두 정확하다는 주장까지 하지는 않는다.

최종 프롬프트는 예산 회귀 검사를 맞추기 위해 위치 연속성 안내를 같은 의미의 짧은 문장으로 줄였다(정본 system 17,193자). 위 실측은 축약 직전 문구로 수행했고, 축약 후에는 정적/회귀 검증했다. 추가 모델 요청은 하지 않았다.

## 최종 검증 범위와 잔여 한계

관련 기존 30개 스크립트 중 29개가 통과했다(프롬프트 예산 실패는 안내 축약 후 통과). `libra_q04_reopen_budget_test`는 병렬 및 단독 실행 모두 'large reopen delivered'에서 실패했고, 변경 전 HEAD `2a9614d`에서도 같은 지점에서 재현됐다. 추가로 확인한 thread lifecycle e2e는 통과했고, boundary matrix의 Recall closure 기대 실패도 같은 HEAD에서 재현됐다. 이 두 Recall 전달 문제를 이번 패치의 해결 사항에 포함하지 않는다. 전체 회귀가 통과했다고 보고하지 않는다.

구문 검사와 diff 공백 검사는 통과했다. 실제 설치 RisuAI UI·실사용 DB에 패치를 적용하거나 기존 저장 기억을 자동 교정하지 않았다. 기존에 잘못 분류된 기억은 향후 설치/재분석 또는 명시적 교정이 필요하다. 커밋·푸시는 수행하지 않았다.
