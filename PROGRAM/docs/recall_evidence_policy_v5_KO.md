# 리콜 근거 정책 v5

HAYAKU 3.0.67 / Flashback 1.0.46. 이전 `recall_query_plan_v4`의 대상 배열에 검색 단서·인물 확인·전달 판정을 모두 맡기던 동작을 교체한다.

## 요청과 검색

호스트의 기존 현재 사용자 판정을 유지한다. 선택된 입력은 `requestSpec` 객체가 원문과 출처를 보유하고, 문자열 검색 입력은 별도로 제한한다. 전역 문자열→원문 복구 Map은 제거했다. 문자열만 전달하는 구형 호출은 그 문자열을 새 입력 범위로 취급한다.

요청/배경 구간, 분석 대상 인용의 원문 좌표, 명시적인 문장·연결 경계로 나눈 goalId, 시간·비교·충돌·문맥 의도를 동결한다. 인용 내용은 검색할 수 있지만 제어 의도에는 사용하지 않는다. 복합 시간 의도가 전체 요청에서 혼재하면 전역 시점은 미지정으로 처리한다. 이는 각 질문의 정답 시점을 자동 판정했다는 뜻이 아니다.

등록 인물의 이름·별칭은 표현별 소유자 집합으로 해소한다. 같은 인물 연결은 먼저 중복 제거하며, 서로 다른 명시적 owner/scope는 병합하지 않는다. 공유 별칭은 확정 별칭 확장에 포함하지 않는다. 불완전한 사전에서 관측된 유일성을 전역 유일성으로 인증하지 않는다.

Flashback은 현재 manifest와 검증된 아카이브 manifest 체인의 공개 파생 사전을 사용한다. 기존 아카이브 깊이 상한을 유지하며, 이 단계에서 원문 shard나 벡터를 새로 전수 읽지 않는다. 아카이브 라우터와 제한시간 대체 검색에도 원래 계획을 전달한다. 계획의 커밋이 달라진 대체 검색은 이전 계획을 재사용하지 않는다.

일반 검색에는 온전한 단어, 형태 후보, n-gram, 벡터가 남는다. 추정 주어 어간은 보호 대상에서 제외한다. sparse 점수에서 같은 원문 단어에 속하는 파생 토큰의 총 가중치를 분배하고, 온전한 단어 일치를 일반 관련성에 반영한다. 문서 특징은 요청 해석과 별도의 API에서 만든다.

## 기록별 근거와 선택

공통 근거 생성기는 recordId, source digest/revision, 원문 UTF-16 좌표, goalId, 사전 바인딩을 담는다. 요청 계획과 기록을 키로 한 약한 참조 캐시를 사용하고, 원문/연결/메타데이터가 바뀌면 다시 계산한다.

| 종류 | 필요한 근거 | 의미 |
|---|---|---|
| text_match | 사용자가 지정한 표현의 원문 일치 | 문자열이 포함됨. 인물 정체성이나 질문의 정답을 증명하지 않음 |
| entity_mention | 완전한 사전의 고유한 정식 이름, 같은 스코프의 공개 인물 연결, 실제 원문 좌표 | 해당 인물의 이름이 포함됨. 문서 속 모든 행동 주체를 확정하지 않음 |
| fact_support | 기존 인물 연결, 허용된 사실, 원문과 정확히 맞는 기존 지원 구간 | 저장 사실의 지원 원문을 포함함. 모델 답변의 진실성을 보증하지 않음 |

문서 전체의 characters 배열만으로 별칭·대명사의 행동 주체를 인증하지 않는다. 기존 사실의 entity/지원 구간이 유효하면 별칭만 등장하는 구간도 해당 사실의 지원 근거로 취급할 수 있다. 별칭만 일치하는 구형 기억은 일반 검색을 계속 사용할 수 있다.

후보 보호에는 기록별 근거와 질문의 다른 단어에 대한 관련성을 사용한다. 기존 적격성·공개 범위·세계선·상한은 유지한다. 선택기가 별칭 문자열을 재검색해 인물 확인으로 승격하지 않는다.

발췌는 선택에 쓰인 원문 구간과 같은 위치를 포함해야 지원 표시를 받을 수 있다. 같은 이름이 다른 문장에 반복돼도 앞 문장의 근거로 바꿔 붙이지 않는다. 근거를 담기 어려운 후보는 우선권을 내려 일반 순위로 재평가한다. 예산에 맞지 않는 원문을 만들어 대체하거나, 선택을 위해 기억 저장을 거부하지 않는다.

`targetCoverage`는 `literalIncluded`, `entityMentionIncluded`, `factSupportIncluded`, `scopeComplete`, `reason`, `evidence`를 구분한다. 호환 `delivered`는 렌더링한 근거의 포함 여부일 뿐 정답/전체 질문 완료 표시가 아니다. `selectionOnly` 결과에서는 전달을 주장하지 않는다.

## 보존과 한계

원문·벡터 저장 형식은 유지한다. 파생 버전은 sparse 6, shard 8, lane v5, HAYAKU 요청 캐시 v5로 갱신한다. 구형 색인의 기존 읽기 대체 경로를 유지하고, 정상 저장 때 새 파생 요약을 만든다. 자동 재분석·재임베딩·추가 생성 모델 호출은 도입하지 않는다.

명시적인 경계 밖의 자연어 문법, 대명사의 실제 지시 대상, 모든 복합 질문의 시간별 정답은 자동으로 보장하지 않는다. 불확실한 경우 일반 검색과 부분 범위 표시를 사용한다. 잘못된 연결 필드가 일반 기억의 저장 거부 조건이 되지는 않는다.

기능 검증은 실제 저장/검색/beforeRequest를 사용하는 격리된 모의 호스트, 로컬 hash 임베딩, 별도의 디스크 readback 및 HTTP/SQLite 회귀로 수행한다. 실제 RisuAI 설치·외부 모델·사용자 기기 성능 검증은 별도이다.
