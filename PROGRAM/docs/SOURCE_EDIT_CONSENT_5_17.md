# 원문 수정 감지 · 동의 후 재분석

Librarian System 0.3.20 / LIBRA 2.3.27 · Book UX 5.17 / HAYAKU 3.0.44 / Flashback 1.0.27

## 사용자 흐름

저장/관측된 원문과 현재 RisuAI의 U+A가 달라지면 각 owner가 다음 확인창을 표시한다.

> 원문이 수정된 것을 감지했습니다. 재분석을 진행하시겠습니까?

확인창에는 해당 플러그인, 처리할 턴/구간, 기존 분석/임베딩 사용에 관한 안내가 붙는다. **재분석 진행**만 승인이다. **나중에**, Escape, 창 닫힘, 권한 부족, 응답 미확정은 승인으로 해석하지 않는다. 한 플러그인에서 누른 승인으로 다른 플러그인의 작업을 실행하지 않는다. 세 플러그인의 창은 root DOM을 사용해 직렬 표시되며 서로 겹쳐 승인을 함께 받지 않는다.

감지는 LLM을 호출하지 않는다. 취소하면 해당 revision은 보류되고 같은 revision에 대한 자동 팝업을 반복하지 않는다. 수정 전 기록은 현재 요청의 회상에서 제외하지만 이전 버전/원본 세션/공유 아카이브를 삭제하지 않는다. 기존 자동 스캔, State 추적, 패킷 복구, Flashback 원문 재수집 경로도 동의 검사를 통과해야 한다.

## 각 플러그인의 처리 단위

| Owner | 승인 후 작업 |
|---|---|
| LIBRA | 완성된 5턴 정본 구간을 Ariadne/활성 ito로 다시 작성. 현재 근거에 묶인 정본 revision과 기존 State/색인 경로를 사용한다. 수동 교정 정본이나 미결 후보는 자동 덮어쓰기하지 않는다. |
| HAYAKU | 현재 U+A만을 결과 근거로 기존 Other Ax 특정 턴 복구를 수행한다. 오래된 hidden carrier를 새 원문의 패킷으로 재import하지 않는다. 원문 메시지나 기존 carrier를 직접 다시 쓰지 않는다. |
| Flashback | 해당 U+A 원문과 검색용 자료를 갱신한다. 요약 LLM을 추가하지 않는다. 원문 저장 후 필요한 원격 임베딩은 별도 대기 상태로 처리한다. |

LIBRA/HAYAKU의 뒤쪽 기록은 앞선 기억·패킷을 입력으로 삼을 수 있으므로 영향이 없다고 증명되지 않은 후속 범위를 보수적으로 포함한다. 실제 대상은 승인 전에 표시한다. Flashback의 변경되지 않은 후속 원문은 재분석하지 않으며, 수정된 원문을 포함하는 기존 episode 요약도 오래된 근거로 회상하지 않는다.

완료 표시는 단계별로 구분한다. 정본 생성이 완료되어도 optional ito/State가 경고·부분 실패이면 영수증의 상태를 유지한다. Flashback의 원문 반영과 원격 임베딩 준비 완료는 다르다. 외부 모델 실패를 빈 정본이나 skeleton으로 대신하지 않는다.

## 동의와 원문 revision

동의는 owner/scope/처리단위/본문 digest/메시지 identity/입력 의존성에 묶인다. 확인창을 띄운 뒤 원문을 다시 수정하거나 채팅을 바꾸면 이전 동의로 새 내용을 처리하지 않는다. 실행 전, 물리 분석 호출 전, 결과 채택/저장 전 및 readback 뒤의 기존 원문 검증을 유지한다. LIBRA State Registry/Head 쓰기 직전에도 수정 동의를 확인한다.

이미 시작된 외부 모델 호출을 모든 provider에서 물리적으로 취소할 수 있다는 보장은 없다. 이 경우 오래된 결과를 채택하지 않으며, 새 revision은 새 동의가 필요하다. 재시작 시 중단된 승인/실행 상태는 자동 네트워크 재시도가 아니라 **다시 확인 필요**가 된다. 한 owner의 실패 때문에 다른 owner의 완료 기록을 롤백하지 않는다.

## 감지 시점과 권한

LIBRA/Flashback은 활성 채팅의 기존 원문 조회/캐시를 활용한 저빈도 관찰(약 12초 간격)과 요청 전 검사를 사용한다. HAYAKU는 기존 세계선 관찰기를 재사용한다. 생성·저장·복원 등 다른 작업 중, 비활성 탭, 불확실한 snapshot은 보류한다. 전용 편집 저장 이벤트를 모든 RisuAI 호스트가 제공한다고 가정하지 않는다.

확인창은 제공된 Plugin API v3의 SafeElement/root document를 사용한다. main DOM 권한이나 해당 API를 사용할 수 없으면 자동 승인으로 우회하지 않고 보류한다. 편집 도중의 임시 원문이 관측되어도 클릭 이후 실제 원문을 다시 검증하며, 확인창에는 재분석 대상 범위를 표시한다. 실 RisuAI 전체/부분 편집 및 모바일 편집 종료 타이밍의 장시간 시험은 별도 필요하다.

설치 전의 모든 과거 메시지를 임의로 수정으로 분류하지 않는다. owner가 보유한 기존 원문 binding이 없는 범위는 정상 수동 복구/콜드스타트 정책을 따른다. LIBRA의 미완성 5턴을 1턴짜리 정본으로 만들지 않는다.

## GUI에서 다시 검토

- LIBRA: 설정실 → 일반 · 진단 → 원문 수정 동기화
- HAYAKU: 개요 → 원문 수정 동기화
- Flashback: 개요 → 원문 수정 동기화

각 카드에서 보류·동의 대기·처리 중·완료·실패와 대상 턴을 보고 다시 동의를 요청할 수 있다. GUI 버튼/API는 승인 자체가 아니라 **확인창 열기**만 수행한다. public approve API나 localStorage에 저장한 일반 boolean으로 분석을 허가하지 않는다.

## 저장과 기존 기능의 경계

작업 journal은 owner별 기존 저장 모드에 맞는 작은 source-edit-consent 기록이다. 전체 원문을 별도의 기억 DB에 복제하지 않는다. 원문/기억/패킷/벡터의 기존 저장 스키마와 배포 DATA는 유지한다. 승인 중 프로세스가 중단될 수 있으므로 journal readback 실패는 분석 허가 실패로 처리한다.

LIA와 RE:TRACE는 변경하지 않는다. 서버 인증, 정상 HAYAKU 메인 모델 패킷 작성, 수동 콜드스타트, 모델 변경에 대한 명시적 임베딩 재생성, 세션 승계 원본 보존을 유지한다.

## 검증 경계

새 시험은 실제 배포 함수/플러그인을 실행하고 호스트 저장·SafeElement·모델 경계에 결정적 입력과 실패를 주입한다. SafeElement fixture는 x-* 속성과 문서 단위 이벤트·좌표/포커스 승인을 검증한다. 실제 사용자 RisuAI 설치, 실제 provider 응답 품질/과금, iOS/Android 실기기의 즉시 감지 또는 장시간 무오류를 증명하는 시험은 아니다.
