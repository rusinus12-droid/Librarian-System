# 리콜 키워드 설계 검토 후속 수정

HAYAKU 3.0.65 / Flashback 1.0.44. 검색 특징 v3.

- `next appointment`를 지시어 후속 질문으로 오인하지 않는다. 실제 지시어가 함께 있더라도 별도로 명시한 대상의 최종 선택 우선순위는 유지한다. 단순 이어쓰기와 검색 휴리스틱 비활성화 설정은 유지한다.
- 긴 이름에 포함된 짧은 이름을 다른 인물의 독립 언급으로 취급하지 않는다. 문장에 따로 언급된 두 인물과 모호한 공통 별칭은 그대로 구분한다.
- 배경 문단과 질문을 구분하여 마지막 요청의 온전한 단어를 먼저 보존한다. 인용 블록과 코드 블록은 일반 검색 대상으로 남지만 요청 예산을 차지하지 않는다. 기존 토큰 상한을 유지한다.
- Flashback은 기존 적격성 조건을 적용한 뒤, 직접 대상 후보를 후보 절단에서도 보존한다. 기존 후보 수 상한 안에서 동작하며 원문을 수정하지 않는다.
- 현재 주 검색 경로에서 사용하지 않는 인물 후보 helper도 검색용 이름 정규화로 맞춰 이름을 반복해서 자르는 동작을 제거한다.
- 파생 특징 버전과 요청 캐시, Flashback sparse/shard/memory-lane 버전을 갱신한다. 기존 기억과 벡터는 보존하며 구형 요약은 호환 읽기 경로로 처리한다. 새 분석 모델 요청과 자동 재임베딩을 추가하지 않는다.

새 회귀 테스트는 격리 런타임의 실제 함수·공개 ingest/recall/hook 경로를 사용한다. 호스트와 임베딩은 모의/로컬 환경이며 실제 RisuAI 또는 외부 제공자 운영 검증을 의미하지 않는다.
