# LIBRA / HAYAKU 스코프 데이터 관리

스코프 데이터 관리와 서버 관리는 서로 다른 화면이다.

- LIBRA: 설정 → 기억과 검색 → 스코프 데이터 관리.
- HAYAKU: 기억 → 스코프 데이터 관리. 모바일에서는 더보기에서도 접근한다.
- 서버 주소, 저장 모드 전환, 서버 복사·복구는 기존 서버 연결 화면에 둔다. 스코프 데이터 화면에서 서버 정본은 삭제하지 않는다.

## 조회와 분류

전체 소유자 인벤토리를 읽어 현재·비활성 채팅, 저장 자료만 남은 스코프, 목록 잔재와 식별 미확인 자료를 표시한다. 검색과 첫 50개 이후의 페이지 표시는 전체 인벤토리를 대상으로 한다. 캐릭터/채팅 이름, 스코프 키, 저장 키 개수와 위치, 저장 모드, 진단 정보를 제공한다. 진단 JSON에는 기억 본문과 API 키를 넣지 않는다.

원본 캐릭터·채팅 ID를 확인했고 호스트 전체 목록에 해당 쌍이 없을 때만 고아로 분류한다. ID 미확인, 호스트 조회 실패, 읽기 실패를 고아 또는 빈 저장소로 간주하지 않는다. 고아라는 이유로 자동 삭제하지 않는다. 빈 목록 정리는 소유 데이터 키가 없고 검증된 목록 항목만 남은 경우에 한정한다. 기억 저장소의 빈 내용과 저장 키가 없는 상태는 구분한다.

## 작업

- 선택 데이터 백업: 선택 스코프의 로컬 물리 키와 값, 필요한 공유 자료를 JSON으로 내려받는다. 형식은 `memory-suite.scope-data-backup.v1`이다. 기존 Portable Memory 가져오기 형식과는 별도인 원본 보존용 백업이다.
- 선택 빈 목록 정리: 선택한 LIBRA 네이티브 레지스트리 항목만 제거한다. 다른 캐릭터·채팅의 항목은 보존한다.
- 선택 데이터 삭제: 선택 스코프 소유의 로컬 키와 확인된 물리 분할 청크를 지운다. LIBRA 네이티브 목록의 대응 항목도 정리한다. 공유 아카이브와 다른 스코프의 자료는 보존한다.

현재 채팅은 삭제 대상에서 제외한다. 대상과 활성 채팅 모두 플러그인 단독 권한이어야 한다. 전체 인벤토리와 참조 검사가 완료되지 않았거나 외부 자료에서 삭제 대상 키를 참조하면 삭제하지 않는다. 서버 모드 자료는 해당 사실과 제한 사유를 표시하고 서버 관리로 구분한다.

확인창은 선택 대상과 개수를 표시한다. 삭제는 백업·영구 삭제 동의 체크를 해야 실행 버튼이 활성화된다. 취소와 Escape는 저장 자료를 바꾸지 않는다. 실행 직전 새 인벤토리와 선택 지문을 대조하고, 소유자 쓰기를 배출·차단한 상태에서 현재 채팅, 호스트 목록, 모드, 원본 값을 재확인한다. 실패하면 이 작업이 바꾼 값을 원래 값으로 복구하고 외부 변경값은 덮어쓰지 않는다. 복구 실패 키는 오류의 rollback 정보에 남긴다. 프로세스 강제 종료에 대한 새 삭제 저널은 추가하지 않았다.

목록 확인·백업·삭제는 LLM을 호출하지 않는다. WebCrypto가 없으면 조회만 가능하다. 식별 불가능한 물리 키는 진단에 남기며 이름 추정이나 접두사만으로 삭제하지 않는다.

## 검증

`owner_scope_management_runtime_test.cjs`는 선택 범위, 현재 채팅 보호, 서버 사본 보존, 외부 참조 차단, 빈 네이티브 목록 정리, 물리 분할 청크와 실패 복구, 338개 조회와 검색, 부분 조회 실패를 검사한다.

`browser/owner_scope_management_browser_test.py`는 전체 LIBRA/HAYAKU 플러그인을 Chromium에서 실행하여 1440/900/640/390/320px 화면, 고아 분류, 백업 다운로드, 삭제 동의·취소, 선택 고아 삭제와 다른 스코프 보존, LLM·외부 네트워크 호출 부재를 확인한다. 테스트 데이터만 사용한다.

`storage_global_owner_public_gui_test.cjs`는 서버 연결 화면에 데이터 관리 패널이 섞이지 않는지와 기존 실제 핸들러/SQLite 전체 이전·재시작·역방향 복원을 확인한다.
