# LIBRA 기억 유형별 검색·전달 배분

## 확정된 방향

정본·Micro·State의 생성 및 저장 체계는 유지한다. 렌즈를 이들로 대체하거나
이들을 렌즈로 다시 생성하지 않는다. 검색·최종 전달에서 렌즈의 몫을 확보한다.

State와 원본 기록의 중복을 점검한 뒤 확정한 기본값:

| 유형 | 비중 |
|---|---:|
| 렌즈 | 40% |
| State·정본·Micro 공통 근거 | 60% — 질문별 선택 |

로어는 LIBRA가 직접 검색해 응답 기억으로 전달하지 않는다.
로어를 분석에 참고하는 기존 기능과 호스트의 로어북 처리는 이 변경의 대상이 아니다.

## 선택 규칙

`memoryAllocationMode: query_adaptive`, `recallLensSharePercent: 40`을 적용한다.
렌즈와 공통 근거의 문자·항목 몫을 먼저 확보한다. 그다음 남는 예산으로
축별 부족분과 관련 후보를 선택한다. 예전 `memoryFamilyWeights` 설정에서는
렌즈 비중만 새 설정으로 이행하며 정본·Micro·State의 고정 몫은 사용하지 않는다.

현재 상태 질문은 State, 과거 경위·원인은 정본, 정확한 발언·세부 질문은 Micro를
우선한다. 혼합·불명확한 질문은 관련도 중심으로 선택한다. 분류는 한국어·영어의
명시적인 질의 표현을 사용하는 규칙 기반이며 의미 분류 완성을 주장하지 않는다.
후보 읽기 상한도 질문 목적에 맞추되 사용자 설정의 상한을 넘지 않는다.

이는 관련도 점수에 유형별 비중을 단순 곱하는 규칙이 아니다. 점수 배율만으로는
서로 다른 유형의 점수 분포와 문장 길이 때문에 실제 전달 몫을 확보할 수 없다.
반대로 비중을 반드시 채우려고 문장을 자르거나 없는 정보를 만들지도 않는다.
자료 부족·중복 제거·문장 길이·전체 예산 때문에 최종 문자 비율은 목표와 달라질 수 있다.
부족한 유형의 미사용 몫은 다른 유형이 사용할 수 있다.

렌즈 후보는 기존 인물·시점·근거·해석 구분과 검색 규칙을 유지한다.
렌즈는 공통 packet에 포함되므로 Classic 및 두 GRADIA 읽기 경로에서 다시 덧붙이지 않는다.
비중 증가는 사실 권한의 변경을 뜻하지 않는다. 렌즈의 해석은 해석으로 전달한다.
선택된 렌즈는 최종 전달 시 저장 기록·렌즈 지침·원문 스냅샷 변경도 검사한다.

렌즈 후보 수집의 예전 기본 상한 4,000자는 전체 12,000자 예산의 40%도
수집하지 못하므로 기본 상한을 12,000자로 올렸다. 실제 전달은 공통 예산으로 제한된다.
과거 기본값(22%/2,600자, 30%/4,000자)은 새 기본값으로 이행하고,
다르게 저장된 사용자 상한은 유지한다.

`bundle.budget.familyAllocation`과 `diagnostics.familyAllocation`에 렌즈/공통 근거의
목표 비중, 예약 문자·항목, 실제 선택 항목·문자 사용량을 기록한다.
`allocationPlan`에 질문 분류와 우선순위, 후보 상한을 명시한다.
로어 후보는 수집하지 않으며 `includeLore: true`로도 재활성화되지 않는다.

## State의 실제 내용과 검증

State는 원본 사건 전체의 복사본이 아니다. 현재 검색은 기존
`loadContinuityStateForResponse`를 사용해 저장된 정본 Head에 승인된 Micro 변경과
리뷰 결정을 투영한다. 투영 결과와 근거는 최종 전달 때 다시 검증하며,
검색이 투영 Head를 저장하지 않는다. 과거 시점 요청에 현재 State를 섞지 않는다.

각 필드는 자기 근거 턴을 표시한다. State 권한이 불완전하면 `last_known`으로 표시하고
진단도 `partial`로 공시한다. 현재 상태 질문에 한해 동일한 원본 assertion/claim이
이미 State로 선택됐다면 원본의 중복 선택을 억제한다. 과거·발언 질문은 원문을 우선하며,
유사한 문장이라는 이유만으로 서로 다른 근거를 합치지 않는다.

## 검증

엔진·직접 런타임·State 투영 회귀·GRADIA 소유자·모드 이행·렌즈 인물 검색의
51개 테스트와 플러그인 문법·소스 동기화·diff 검사를 통과했다.
추가 회귀 실험은 T5 State의 보유자 민아가 승인된 T6 Micro로 준호가 되는지,
실제 Classic 전달과 과거 경위·정확한 약속 발언의 별도 회상, 과거 cutoff,
Micro 승인 삭제 시 전달 거부, 저장된 Head 불변을 확인한다.

최종 테스트 로그는 `.development/state-coverage-audit/final-tests.log`에 보관한다.
기존 17턴 합성 실험에서 State 검증을 연결한 뒤 345요청·약 170ms가 측정됐다.
로컬 지연이 작은 시험으로, 실제 원격 지연을 보장하지 않는다. 원격 지연 측정과
검증을 유지하는 묶음 읽기 최적화는 남은 과제다.

별도로 의미 검색 테스트 파일 6개 중 5개 실패를 확인했다. 이번 작업 직전
LIBRA 소스에서도 같은 5개 실패가 재현되며, 현재 의미 벡터 저장·재검색 경로는
별도 진단이 필요하다. 이 변경으로 의미 검색 정상화를 주장하지 않는다.
로그는 `.development/lens-weighted-recall/`에 보관한다.
실제 RisuAI UI 및 원격 서버 검증은 수행하지 않았다.
