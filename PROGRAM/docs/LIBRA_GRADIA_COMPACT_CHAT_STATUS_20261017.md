# LIBRA·GRADIA 채팅 상태 표시줄 · 2026-10-17

LIBRA 2.3.161 / GRADIA 0.25.88. 기준 커밋은 `974828a11c40494083c378980e2f6029d09f7f26`이다.

두 플러그인은 RisuAI의 같은 `chatPanelStore` 표시 영역을 사용한다. 서로 다른 ID로 등록되므로 독립적으로 지워지지만, 이전에는 호스트 카드 안에 다시 테두리와 여백을 둔 카드가 들어갔다. LIBRA 완료 결과는 기본으로 펼쳐져 있어 두 패널이 함께 나타나면 채팅 공간을 많이 차지했다.

## 변경

- 두 패널을 같은 디자인의 상태 표시줄로 바꿨다. 브랜드, 상태 글자·점, 현재 작업, 상세 펼치기, 닫기 버튼을 한 줄에 표시한다. 접힌 높이는 데스크톱 40px, 모바일 42px이다. 기존 호스트 간격 8px은 유지한다.
- 긴 작업 설명은 줄임표로 표시한다. 제목 툴팁과 기본적으로 접힌 네이티브 `details`에서 전체 설명·결과를 확인할 수 있다. 상세 본문은 최대 160px에서 스크롤하며, 완료 결과를 자동으로 펼치지 않는다.
- 각 패널에 독립적인 닫기 버튼을 추가했다. 닫아도 작업·응답 생성·저장·결과 상태는 계속된다. 같은 작업의 단계·완료 알림이 패널을 다시 열지 않으며, 다음 작업의 `begin`에서 표시를 복원한다. LIBRA 새 기억 작업, GRADIA 새 파이프라인 및 명시적 Input Writer 시작이 복원 경계다.
- GRADIA의 기존 `전송 취소`는 별도 버튼·기존 처리 경로로 유지한다. 닫기를 눌러도 `cancelRequested`가 바뀌지 않는다. 닫을 때 취소 버튼의 DOM 바인딩도 해제한다.
- 마우스·터치 클릭과 키보드 버튼 활성화를 지원한다. 과거 SafeElement의 문서 위임 클릭은 버튼 좌표로 필터링하고, 키보드의 좌표 없는 클릭은 해당 닫기 버튼의 포커스를 확인한다.
- 공유 렌더러는 두 플러그인에 빌드 시 내장한다. 표시 쓰기를 직렬화해 늦게 도착한 표시가 닫기·새 단계·언로드 뒤에 남지 않도록 하고, 리스너를 교체·해제한다. 빌드와 SDK 동기화 검사가 내장본 일치를 확인한다.

CSS는 각 `data-plugin-chat-panel`의 정확한 소유 ID에만 적용한다. 해당 호스트 카드의 중복 여백·테두리·배경을 없애고 내부 상태 표시줄이 이를 담당한다. 공통 컨테이너, 입력창, 다른 플러그인의 패널 위치와 스타일은 바꾸지 않는다. 두 플러그인의 작업 상태를 합치거나 공통 전역 UI 소유자를 만들지 않는다.

## 검증

- `chat_status_runtime_test.cjs`: 8건 통과. 수동 닫기 유지·새 작업 복원, 키보드 포커스 검증, 소유자별 독립 제거, 느린 호스트 쓰기 중 닫기·언로드, 문자열 이스케이프·접힌 상세·취소 버튼 보존, 반복 렌더 리스너 회수, DOM 미지원·권한 거절을 검사했다.
- `browser/chat_status_panels_browser_test.py`: 실제 LIBRA·GRADIA 전체 소스를 실행해 데스크톱 1440px·모바일 390px과 요소 이벤트·문서 위임 이벤트 조합 4건 통과. 40/42px 높이, 8px 간격, 클릭·Enter 닫기, 닫기 이후 단계·완료 처리, 새 작업 복원, 상세 펼치기, 닫기와 취소의 분리를 확인했다. 외부 네트워크·모델 호출은 0회다. 이 호스트 픽스처 자체는 HTML sanitizer를 재현하지 않는다.
- 별도로 공개 RisuAI `e773240bfab72f3704f3efa52722ec7d105cdcf3`의 `setChatPanel`, `SafeElement`/`SafeDocument`, `DefaultChatScreen.svelte` 패널 블록을 분리해 Svelte 5·Tailwind 4·DOMPurify 3.3.2로 실행했다. 두 화면 크기·두 등록 순서·두 완료 상태·고정 입력창 유무의 16건에서 포개짐·입력창 침범 없이 표시됐다. 실제 SafeElement를 통한 클릭·Enter 닫기도 통과했다. 과거에 기록한 호스트 `f9728b14c733d073168d8d0c6a8f34f8febf0304`와 현재 호스트의 패널 템플릿은 동일했다.
- 기존 LIBRA 작업 상태, 실제 기억 작업 UI, scope 이동·빠른 설정 검사가 통과했다. Micro 검색의 정확 코사인 top-8 검사 및 실제 플러그인의 30개 벡터 뒤쪽 정답 전달 검사도 통과했다.
- GRADIA의 `producer-owner-migration` 4건, `memory-retirement` 3건, `draft-only` 7건, `turn-eligibility` 21건이 통과했다.
- 두 플러그인의 Full 산출물이 생성·구문 검사됐고 읽기 가능한 소스와 바이트 단위로 일치했다. 공유 상태 표시줄·기존 SDK의 동기화 검사도 통과했다. 빌더가 출력하는 과거 크기 기준 초과는 보고용이며 이번 검증을 크기 최적화 성과로 사용하지 않는다.

집계·소스 해시는 [검증 기록](LIBRA_GRADIA_COMPACT_CHAT_STATUS_VALIDATION_20261017.json)에 보관한다.

기존 `gradia_suite_test.cjs --list` 총괄 런처는 `suite-inventory.json`에서 `model-context-budget`·`producer-owner-migration` 두 파일이 빠진 불일치로 실패한다. 런처·인벤토리는 이번 변경 전과 동일하며 이 작업에서 수정하지 않았다. 위 관련 개별 파일은 직접 실행했다.

## 범위와 한계

사용자의 설치된 RisuAI 앱에 직접 연결해 검사한 결과는 아니다. 실제 소스의 분리 실행과 전체 플러그인 브라우저 픽스처 결과다. 다른 호스트 테마·별도 채팅 화면·커스텀 CSS는 추가 확인이 필요하다. 닫기 버튼의 이벤트 연결에는 RisuAI `mainDom` 권한과 `getRootDocument` 지원이 필요하며, 권한이 없으면 상태 본문은 표시되지만 수동 닫기는 연결되지 않는다. 기존 자동 닫힘 정책은 유지한다.

이번 변경은 UI에 한정한다. 실제 모델 비교를 다시 수행하지 않았으며, 이전 Voyage/Ollama 비교의 성과·수치가 새로 측정됐다고 주장하지 않는다. 근거 검색·추출·원본 검증·자원 예산 정책을 변경하지 않았다. 화면·원시 재현 산출물은 저장소 밖 `/tmp`에 보관한다.
