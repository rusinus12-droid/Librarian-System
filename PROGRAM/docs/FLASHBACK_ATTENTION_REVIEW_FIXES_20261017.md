# Flashback 채팅 알림 리뷰 후속 패치 — 2026-10-17

`codex/libra-memory-network-20261013`의 `8712b68`을 기준으로 리뷰에서 확인한 결함을 수정했다. 후속 리뷰 패치를 포함한 Flashback 버전은 **1.0.106**이다.

## 동작 변경

| 리뷰 결함 | 변경한 동작 | 회귀 근거 |
| --- | --- | --- |
| 아카이브 기억을 누락으로 오판 | owner의 논리 읽기로 로컬과 검증된 아카이브 원문을 함께 비교한다. 알림 읽기는 `readOnly`·`rawTextOnly`로 요청하며 외부 자료 퇴역 작업을 예약하지 않는다. | 공개 백업→다른 채팅에 아카이브 복원 시 정상 원문은 누락 0건이다. 그 뒤 추가된 실제 새 턴은 누락 1건으로 표시한다. |
| 다른 채팅의 벡터 실패가 표시됨 | 실패·결과 불명은 현재 저장된 응답 작업 상태로 판단한다. query 오류도 들어가는 `lastEmbedError`와 과거 큐 진단만으로 실패를 만들지 않는다. 큐의 대기 사유는 현재 scope와 generation이 일치할 때만 참고한다. | A의 실패 기록과 query 오류가 빈 B에 경고를 만들지 않는다. 합성 401 응답으로 실제 생성한 durable 실패는 계속 표시되고 재시작 후에도 유지된다. |
| 원문 복구 후 실패 알림 유지 | 캡처 실패를 해당 scope·턴·원문 revision의 미동기화 상태와 연결한다. 정확한 원문이 저장됐으면 과거 진단을 지우지 않고도 경고를 해소한다. terminal monitor 진단에도 턴 번호를 남긴다. | 실패→공개 콜드스타트 복구→실제 저장소 읽기 후 경고가 해제된다. 다른 턴이나 과거 revision의 실패가 새 누락을 덮어쓰지 않는다. |
| 수정된 원문 알림 누락 | diff의 `missing`과 `changed`를 모두 반영한다. 수정된 원문은 `원문 동기화 N턴` 알림으로 제공하며, 현재 scope에서 실제 처리 중인 턴은 잠시 제외한다. | 로컬·아카이브에 보관된 옛 원문 모두 현재 수정된 원문과 비교한다. 다른 채팅의 pending 상태는 이를 숨기지 않는다. |
| 임베딩 알림이 이전 서버 탭을 엶 | provider 알림이 임베딩 하위 탭 `emb`까지 지정한다. | 실제 DOM에서 이전 `srv`·`mig` 패널을 열었다 닫아도 알림 버튼은 `emb` 패널을 연다. |

설정과 manifest의 검증된 저장 완료도 알림 갱신을 예약한다. 따라서 공개 API나 관리 화면에서 저장을 끝낸 후에도 버튼이 갱신된다. 알림 계산 자체는 활성 runtime scope를 전환하지 않으며, 비동기 읽기 중 채팅이 바뀌면 그 결과를 게시하지 않고 다시 계산한다.

후속 리뷰에서는 임베딩 시도 레지스트리의 구조나 digest가 손상된 경우에도 알림 계산을 중단하지 않고 `저장소 오류 확인`으로 표시하도록 보강했다. 채팅 폴링은 캐릭터·채팅 인덱스뿐 아니라 현재 원문의 경량 revision도 비교하므로, 같은 채팅에서 이미 저장된 응답을 수정해도 자동으로 `원문 동기화` 알림을 갱신한다.

중단된 running 작업이나 미해결 시도 기록은 현재 런타임의 실제 활성 시도와 대조해 `상태 확인 필요`로 남긴다. 단순히 과거 오류를 무시하면서 확인이 필요한 물리 호출 결과까지 감추지 않도록 했다.

## 검증

1.0.104 기준 관련 검사 **82/82**, Full/Min 공개 GUI 검사 각각 **4/4**를 통과했다. 1.0.105 후속 패치에서는 손상된 레지스트리의 안전한 경고 변환과 동일 채팅 원문 revision 폴링 회귀 2건을 추가해 통과시켰다. 1.0.106에서는 알림 폴링을 정규화 캐시와 분리한 경량 revision 추적으로 교체해 4,096개 초과 채팅의 캐시 스래싱을 제거했다.

- `tests/flashback_attention_review_fixes_runtime_test.cjs`: 전체 플러그인·실제 owner 저장소를 사용하는 경계 시나리오 **13건**. 공개 아카이브 복원, 실제 저장 실패 상태, 재시작, 캡처 복구, 원문 수정, pending scope, 중단된 시도, 손상된 임베딩 레지스트리, 대형 채팅 폴링을 확인한다.
- `tests/flashback_attention_gui_review_fixes_runtime_test.cjs`: 공개 API·등록된 실제 버튼 콜백·DOM 이벤트를 사용하는 **4건**. Full/Min 각각에서 서버·이관 탭 이동, 복구 후 자동 버튼 해제, 아카이브 복원 후 정상 상태를 검사한다.
- 기존 `flashback_chat_attention_runtime_test.cjs`는 정상 원문 상태와 무관한 과거 진단이 오류를 만들지 않는 계약으로 갱신했다.
- 함께 확인하는 기존 검사: L/H 버튼 공존, raw-pending 계약, 캡처 profile, archive reporting, 읽기 전용 아카이브 유지보수, 원문 편집의 최종 주입 3개 저장 모드, raw page reference.
- Full/Min 빌드 생성과 구문 검사를 통과했으며 Full 산출물이 소스와 바이트 단위로 일치함을 확인했다. 빌드 도구의 과거 크기 기준 경고는 생성 실패가 아니다.

모델 오류는 합성 HTTP 응답으로 생성했다. 실제 외부 제공자에 대한 과금 호출과 실제 RisuAI 앱에서의 수동 검증은 실행하지 않았다. GUI 복원 검사는 빈 대상에 공개 복원을 끝낸 뒤 보존된 대화 원문을 비교하도록 구성해, 독립적인 native-copy 관찰자가 대상 저장소를 먼저 채우는 경로와 구분한다.
