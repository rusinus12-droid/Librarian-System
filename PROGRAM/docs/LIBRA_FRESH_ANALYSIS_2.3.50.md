# LIBRA 2.3.50 — 이전 작업 폐기 후 새 분석

## 변경

수동 콜드스타트, 선택 구간 분석, 실패 재시도, 중단 분석의 재실행은 이전 미완료 분석을 복구하지 않는다. 선택 구간의 work, 실패/중단 run, 2.3.48/49가 남긴 retired-work 보관본을 삭제하고 실제 부재를 확인한 뒤 새 run/operation으로 시작한다. 이전 초안·stageIndex·단계 결과·예산·부모 작업 연결을 재사용하지 않는다.

삭제 중 오류가 나면 이전 기록을 복원하지 않는다. 분석을 시작하지 않고 중단하며, 다음 수동 시도에서 남은 기록을 삭제한다. 새 work/run의 저장 여부도 모델 호출 전에 재조회한다.

삭제는 선택 구간의 미완료 실행 기록에 한정한다. 저장된 정본, 원문, State, 완료 실행 기록 및 다른 범위의 데이터는 삭제하지 않는다. 저장된 정본을 변경하는 승인/후보 채택 절차도 유지한다. 자동 실시간 스캔은 이 폐기 작업을 수행하지 않는다.

## 타임아웃

정본 생성의 otherAx 요청은 제출 후 LIBRA의 270초 배치 제한으로 응답을 버리지 않고 호스트 완료 또는 사용자 취소까지 기다린다. 전송 전 예산 검사, 직접 HTTP 호출 및 다른 소비자 작업의 시간 정책은 유지한다.

사용자 취소 후에도 실제 RisuAI 요청이 남아 있다면 새 OtherAx 분석은 `CANONICAL_HOST_REQUEST_PENDING`으로 차단한다. 이전 임시 기록도 이때는 삭제하지 않는다. 실제 요청 종료 후 새 분석을 허용하며, 취소한 요청의 늦은 결과는 채택하지 않는다. 호스트가 응답하지 않는 문제 자체나 제공사의 응답 속도를 보장하는 변경은 아니다.

## 사용

기존 LIBRA를 이 파일로 교체·재로드한 뒤 해당 채팅에서 **실패 구간 새 분석** 또는 구간 선택 후 수동 분석을 실행한다. 현재 RisuAI 보조 요청이 진행 중이면 그 요청의 종료를 먼저 확인한다. 정본·원문을 수동으로 삭제할 필요는 없다.

실제 RisuAI 설치 및 외부 Provider 검증은 별도이며, 이 패치 작업은 실제 소스를 실행한 모의 호스트와 저장소 장애 주입으로 검증한다.
