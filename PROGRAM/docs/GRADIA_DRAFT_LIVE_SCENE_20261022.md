# GRADIA 초안 파이프라인의 직전 상황 연결

날짜: 2026-10-22 · GRADIA `0.26.7`

## 점검 방법

실제 `beforeRequest` 훅과 4단계 파이프라인을 오프라인 호스트에서 돌렸다. RisuAI 새로고침 직후와 같은 조건이다.
- 요청 메시지에는 네이티브 ID가 없다.
- 저장된 채팅에는 ID가 있다.
- 출력 영수증은 없다.

RisuAI 동작은 고정 커밋 `02a8369`의 `sendMain`·`sendChat`·`reroll` 코드로 확인했다.
- 일반 전송: 유저 메시지를 저장한 뒤 요청한다.
- 재생성: 이전 응답을 먼저 지운다.
- 빈 입력 전송과 Continue: 유저 메시지를 추가하지 않는다.
- 그룹 채팅: 두 번째 화자는 새 유저 메시지 없이 요청한다.
- 응답 자리표시자는 요청 뒤에 추가된다.

## 결과

| 상황 | 변경 전 | 변경 후 |
|---|---|---|
| 일반 전송 | 최신 응답이 직전 장면 ✓, 직전 유저 입력 없음, 이전 턴은 가장 오래된 턴 앞부분 + 최신 끝만 | 최신 응답 + 직전 유저 입력, 이전 턴은 최신 턴부터 통째로 |
| 재생성 | 이전 응답이 직전 장면 ✓ | 같음 + 그 턴의 유저 입력 |
| 빈 입력 전송 / Continue / 그룹 다음 화자 | 이미 답한 직전 유저 입력을 현재 입력으로 잡아 그 턴을 다시 써서 주입 | GRADIA가 개입하지 않고 요청을 그대로 전달 (`no_new_user_input_after_reply`) |
| 프리셋 프리필이 붙은 일반 전송 | 초안 작성 ✓ | 같음 |

## 바뀐 점

- **새 유저 입력이 없는 요청 통과.**
  - 조건: 저장된 채팅이 정상 응답(스트리밍·오류·코멘트·비활성·빈 응답이 아님)으로 끝나고, 요청의 현재 입력이 그 응답 앞의 유저 입력과 같다.
  - 이때 초안 단계를 실행하지 않는다.
  - 채팅을 읽지 못하면 예전처럼 진행한다.
- **직전 유저 입력.** 최대 600자를 "이미 일어난 일" 블록으로 넣는다. 들어가는 곳은 다음과 같다.
  - SHADOW 초안·분석
  - AIDE 패치·분석
  - 사용자 정의 템플릿의 `{{previous_turn_user}}`. 종전에는 늘 빈 값이었다.
- **이전 턴 축약.** 가운데를 자르던 방식(가장 오래된 턴 앞부분이 남음)을 바꿨다. 이제 최신 턴부터 통째로 채우고 오래된 턴을 먼저 뺀다.
  - SHADOW 이전 턴: 2,200자
  - AIDE 전체 초안: 4,200자
  - 템플릿 `recent_chat`: 5,000자

## 남은 점

- 그룹 채팅에서 같은 라운드의 두 번째 이후 화자는 GRADIA 초안 없이 생성된다. 종전에는 앞 화자의 응답을 무시한 채 같은 턴을 다시 썼다.
- 현재 입력이 저장되기 전에 요청이 오는 흐름에서는 최신 응답이 빠질 수 있다. 확인한 RisuAI 코드에서는 이런 흐름이 없다.
