# HAYAKU 3.0.87 — 정상 항목의 부분 저장·회상

## 변경

기존에는 `HAYAKU_NATIVE_RECORD_PARTIAL`의 정상 항목도 실패 진단에만 남았다. 이제 누락 턴 복구, 단일 콜드스타트, 배치 콜드스타트에서 항목 수용 검사를 통과한 개별 기록을 `hayaku.v2.partial_memory.<scope>`에 별도로 영속 저장한다. 실패 진단 저장과 같은 직렬화 경로를 사용하고, 저장 후 실제 내용 재조회가 일치해야 저장 성공으로 인정한다.

실패 항목, 진단 이유, 혼합된 종합 요약, scalar State는 이 저장소에 넣지 않는다. 정상 항목은 기존 로컬 어휘 검색으로 선택하고, 실제 `beforeRequest`의 공통 증거 예산 안에서 `[PARTIAL HISTORICAL MEMORY]` 구간으로 전달한다. 원문 인용으로 오인하지 않도록 분석된 과거 기억임을 명시한다. 추가 LLM 호출은 없다.

부분 기억을 완전한 정규 패킷으로 승격하지 않는다. 현재 State나 턴 완료 판정도 변경하지 않으므로 누락 상태는 남는다. 나중에 명시적으로 재생성할 수 있지만 폐기한 실패 응답 재분석·사용자 확인 대기 기능을 되살리지 않는다. 패킷 상태 문구도 ‘기억 미저장’ 대신 ‘패킷 불완전’으로 바꿨다.

## 경계와 보존

- 저장 시 현재 스코프와 원문을 검증하고 원문 단위 해시·앞선 원문 해시를 결속한다. 회상 시 다시 검사하므로 원문이나 세계선의 근거가 바뀐 항목은 회상하지 않는다.
- SDK 스코프 라우팅, 스코프 소유 키, 백업 분류, 복원 검증에 새 저장소를 등록했다.
- 실패 진단과 별도로 저장하므로 진단 데이터가 없어져도 정상 항목은 남는다.
- 스코프당 최대 256개 원문 단위, 단위당 최대 512개 항목을 보존한다. 초과 시 기존 기억을 삭제하지 않고 저장 실패를 기록한다. 요청당 회상은 최대 8개이며 공통 문자 예산을 적용한다.
- 읽기 실패는 경고로 기록하고 기존 정규 기억 검색을 계속한다. 저장 실패를 실제 기억 보존 성공으로 보고하지 않는다.
- 과거 버전의 진단 후보를 일괄 변환하지 않는다. 이번 버전에서 항목 수용 검사를 거쳐 새로 분석되는 결과에 적용한다.

## 검증

`hayaku_record_admission_runtime_test.cjs`에서 누락 복구·단일 콜드스타트·배치 콜드스타트 각각에 대해 정상 항목 검색, 실제 beforeRequest 전달, 거부 항목 제외, State·완료 판정 유지, 새 인스턴스 재조회, 다른 스코프 차단, 원문 변경 차단을 검사했다. 진단 저장소를 제거한 뒤에도 부분 기억이 유지됨을 확인했다. 저장 API가 성공만 반환하고 기록하지 않는 장애에서는 신규 항목을 성공으로 수용하지 않고 기존 기억을 보존함을 확인했다.

선택한 회귀 시험 17개 중 14개 통과. 아래 3개는 변경 전 3.0.86 백업을 주입해도 동일한 지점에서 실패했다. 버전 문자열만 현재 계약에 맞춰 기준 파일을 로드했다.

| 기존 실패 시험 | 원인 |
|---|---|
| hayaku_otherax_evidence_grounding_runtime_test.cjs:162 | 폐기된 awaitingUserReview=true 요구 |
| hayaku_native_otherax_recovery_contract_test.cjs:98 | 폐기된 Failed Recovery 진단 UI 요구 |
| hayaku_gui_ux_contract_test.cjs:14 | 폐기된 failed_recovery 탐색 탭 요구 |

정상 통과 범위에는 응답 수용, 단순 복구, Other Ax 복구, 콜드스타트 근거·배치, afterRequest 원장, 자동 실패 재시도 폐기, 회상 내용·선택·실제 전달, 휴대용 백업 UI 계약이 포함된다. 위 3개 낡은 시험의 갱신은 남아 있다.

검증은 호스트 모의 런타임 기준이다. 실제 RisuAI GUI, 실제 모델 제공자, mirror/server_only 실서버의 동작·성능, 다른 채팅으로의 전체 이관은 이번 시험으로 인증하지 않는다.
