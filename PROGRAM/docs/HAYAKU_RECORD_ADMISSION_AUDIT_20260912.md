# HAYAKU 3.0.84 데이터 수용 패치와 직후 감사

## 결론과 범위

이 패치는 LIBRA의 항목별 수용 원칙을 HAYAKU의 기존 패킷 구조에 적용하는 보수적인 단계다. JSON 포장 처리 이후에도 정상 항목을 보존하고, 잘못된 항목과 명시적 의존 항목을 분리한다. 그러나 LIBRA와 완전히 같은 동작은 아니다. **부분 패킷은 실패 복구 저장소의 검토 후보로 영속 보존되며, 일반 기억 검색이나 현재 상태에 자동 반영되지 않는다.** HAYAKU가 부분 패킷을 완전한 턴 스냅샷으로 소비하는 것을 방지하기 위한 경계다.

따라서 “LIBRA처럼 유효한 사실을 즉시 검색 가능한 정본 기억에 부분 저장”까지 요구한다면 아직 충족되지 않았다. 그 단계에는 기억 저장과 현재 상태·복구 완료 판정을 분리하는 별도 설계가 필요하다. 이번 결과를 전체 수용 방식의 동등성 달성으로 보고하지 않는다.

## 구현

- `prepareNativePacketRecords`를 누락 복구 및 콜드스타트 공통 정규화 경로에 연결했다. 누락 복구는 전체 grounding 검사 전에 원래 항목 경로와 해당 근거를 사용한 개별 검사도 수행한다.
- 기존 스키마 정규화기를 재사용하며 별칭과 구조화된 필드 표현의 변환을 기록한다. 자연어로 누락 필드를 추측하지 않는다.
- 필수 필드가 빠진 항목, 추론 필드를 포함한 항목, 모호한 중복 ID, 사용할 수 없는 명시적 의존성과 순환 의존성을 격리한다. 제외된 인물 식별자를 직접 참조하는 항목도 격리한다.
- `meta.record_admission`에 정상 항목의 원래 경로와 제외 사유를 남긴다. 부분 결과에서는 `HAYAKU_NATIVE_RECORD_PARTIAL` 오류와 별도 미리보기를 생성한다.
- 기존 실패 저장소가 원래 AI 응답과 정규화된 후보, 항목별 진단을 함께 저장하고 물리적으로 재조회한다. 일부 의미 항목이 제외된 후보는 그대로 채택할 수 없고, 복구 부채를 해소하지 않는다.
- 기존의 메타데이터 상한·지원하지 않는 계획 필드에 대한 수동 검토 경로는 유지한다. 무조건적인 부분 결과 차단으로 이 경로까지 막았던 초기 구현은 회귀 검사 후 수정했다.
- AI 호출 예산, 원문 동의, 세계선·원본 재검증, 저장 검증은 변경하지 않았다.

## 직후 감사

새 런타임 테스트는 다음을 확인한다.

1. 누락 복구의 잘못된 관계 항목을 제외하고 정상 인물 항목을 보존한다.
2. 단일 콜드스타트에서도 동일한 구조 오류를 격리한다.
3. 배치 콜드스타트에서는 정상 턴을 검증된 체크포인트로 보존하고, 부분 턴을 검토 대기로 유지한다. 전체 원장 반영은 모든 턴 검증 후 이루어진다.
4. 부분 후보와 제외 사유, 원래 AI 응답을 실패 저장소에서 durable 재조회한다.
5. 그대로 채택 시도로 부분 후보를 완료 처리할 수 없다. 누락 복구 부채가 남는다.
6. 두 분석 종류에서 기존 별칭 정규화가 유지되고, 순환 의존 항목을 격리한다.
7. 순환 의존성으로 나중에 제외된 인물을 참조하는 관계도 격리한다. 전체 경고 목록의 출력 상한에 의존하지 않고 항목별 필수 필드를 검사한다.
8. 저장 API가 실제 기록 없이 성공을 반환하면 메모리상의 임시 보존을 durable 저장으로 보고하지 않는다.

기존 실패 저장·수동 해결 테스트에서 드러난 메타데이터 손실 검토의 호환성 회귀는 수정 후 통과했다. 테스트는 실제 배포 JavaScript를 모의 RisuAI 호스트에서 실행하며 실제 제공자를 호출하지 않는다.

관련 테스트 파일 17개를 실행했다. 새 `hayaku_record_admission_runtime_test.cjs`는 10개 실행 시나리오를 포함한다. 기존 응답 수용, 콜드스타트 배치·계약·근거, 누락 복구·후보·세계선 경쟁, 대상 재생성, 실패 보존·수동 해결·자동 재시도, UI 계약 및 검토 강화 검사를 포함한다. 전체 프로젝트 회귀 테스트 전부를 실행한 것은 아니다.

## 남은 차이와 제한

- LIBRA는 사실 저장과 State 적용이 분리되어 있다. HAYAKU의 부분 후보는 현재 일반 검색 대상이 아니다.
- 누락 복구의 원문 grounding 규칙은 유지한다. LIBRA와 동일한 자연어 사실 의미 검증을 구현했다는 뜻이 아니다.
- 콜드스타트는 기존 패킷 구조 검사와 검증을 유지한다. 누락 복구와 동일한 항목별 grounding 봉투를 모델에 요구하는 프로토콜로 변경하지 않았다.
- 실제 모델의 출력 품질, 원래 T5/T10 실패의 해결 여부, 실제 RisuAI GUI는 검증하지 않았다.
