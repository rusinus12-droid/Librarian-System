# LIBRA 로컬 main 통합

## 브랜치 조사와 통합 범위

통합 기준은 로컬 main `8d8978171641f4311339fe4db2e33867cc68b0ad`이다. 로컬 브랜치 9개와 등록된 작업 디렉터리 1개를 조사했다. 현재 작업 브랜치 `codex/libra-identity-link-review`와 `codex/libra-quote-evidence-guard`의 커밋 끝은 기준 main과 같았으며, 아래 구현은 아직 커밋되지 않은 변경이었다.

플래시백 외에는 main에 없는 별도 브랜치 커밋이 없다. 플래시백의 `0c0c797`, `82c8edc`는 사용자가 의도적으로 제외한 커밋으로 명시했으므로 포함하지 않는다. LIA 설정 저장·랜덤 페르소나, 플러그인 열기 실패 처리, 기존 메모리 점검·재분석 관련 브랜치 커밋은 이미 main의 이력에 포함돼 있다.

사용자가 LIBRA 변경의 로컬 main 커밋을 지시한 범위에 따라 다음을 함께 통합한다.

1. 잘못된 근사 인용을 원문으로 보정해 사실로 인정하던 경로 제거.
2. 자동 인물 연결 유지, 선택적 연결 검토, 원래 ID와 사실별 역할 출처 저장, 자동 배정과 재분리.
3. 인물 병합·분리 공통 창과 평면 인물·관계 관리 탐색.
4. 한 페이지에서 7개 영역으로 읽는 정본과 표시 전용 턴 참조 정리.
5. 하단 기억 카드 기준의 단일 기억 관리 도구·수정 진입점.
6. 관련 회귀·생산 렌더러 검사 및 사서의 여백 점검 문서. 사서의 여백의 Classic 전달 누락은 진단 결과이며 구현 완료 항목에 포함하지 않는다.

`DATA/data-layout.json`의 기존 수정은 포함하지 않는다. Flashback 소스·설정·버전은 변경하지 않으며, 원격 fetch·merge·push는 실행하지 않는다.

## 실행 증거와 한계

- 인용 보호 4건, 자동 연결 검토 6건, 원래 ID별 출처와 자동 배정 9건: 19건 통과.
- 실제 임시 HTTP/SQLite의 server_only·mirror 연결 확정·분리·재생: 2건 통과. 정본 바이트 보존과 추가 모델 호출 없음 확인.
- 기존 인물 분리 13개 내부 사례, 병합 후 프로필 교정, 원문 부분 prefix 후속 재분석 통과.
- 생산 렌더러의 자동 연결 검토, 통합 인물 병합·분리 창 브라우저 검사 통과.
- 같은 최종 LIBRA 소스로 기억 관리의 수정·후보 저장·비교·기존 유지, 빈 화면, 좁은 화면 및 7개 영역 열람을 확인했다. 정본·현재 상태의 저장 바이트는 같다.
- 관리·읽기·사서의 여백 집중 회귀 12건 통과. 관련 프로그램 manifest와 루트 SHA256 목록을 갱신하고 모든 항목을 실제 파일에서 다시 읽어 대조한다.

전체 회귀가 모두 성공했다는 뜻은 아니다. 기존 `libra_canonical_job_runtime_test.cjs`의 폐기된 재분석 API 호출과 `libra_canonical_variant_job_gui_contract_test.cjs`의 구형 drawer 문자열 검사는 기준 HEAD에서도 동일하게 실패했다. `libra_canonical_reader_evidence_binding_test.cjs`의 구형 정규식 문자열 검사도 기준 main과 불일치한다. 이 검사를 약화하거나 통합 성공 근거에 포함하지 않았다.

실제 RisuAI 앱·외부 모델·과금·사용자 서버 검증 및 릴리스 패키징은 수행하지 않았다. 로컬 main 커밋 뒤 Git 커밋 내용·파일 모드·manifest·체크섬과 기존 DATA 수정 보존 여부를 다시 확인한다.
