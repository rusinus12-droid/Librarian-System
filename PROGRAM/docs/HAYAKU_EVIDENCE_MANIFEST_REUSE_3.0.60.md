# HAYAKU 3.0.60 — 업데이트 후 수동 누락 복구의 manifest 충돌 수정

같은 원문을 구버전에서 보관한 뒤 새 버전으로 수동 복구하면, `coverage_scan`에서 `recovery_evidence_manifest_write_failed:key_collision`로 중단되던 결함을 수정했습니다.

저장 키는 같은데 manifest 해시에는 작성 플러그인 버전이 들어가므로, 동일한 증거도 업데이트 후 다른 자료로 판정됐습니다. 기존 해시 형식은 그대로 유지하고, 기존 manifest 자체의 무결성을 확인한 뒤 작성 버전을 제외한 증거 필드가 같으면 기존 manifest와 참조를 재사용합니다. 이후 저장소에서 manifest와 모든 원문 조각을 다시 읽어 본문·해시·길이·소유 범위를 검증합니다.

원문, 출처 해시, 턴, 채팅 범위 또는 기록 ID가 다른 경우와 손상된 자료는 계속 거절합니다. 기존 증거를 일괄 삭제하거나 덮어쓰는 마이그레이션은 없습니다.

검증에는 실제 3.0.57 플러그인으로 생성한 고정 증거 fixture를 사용했습니다. 기존 3.0.59에서는 같은 실패가 재현됐고, 3.0.60에서는 수동 복구 모델 호출 1회, 복구 패킷 저장, 런타임 재시작 후 패킷 유지가 확인됐습니다. 기존 증거의 저장 값도 보존됐습니다. 이는 격리 호스트와 모의 모델 응답을 사용한 시험이며 실제 사용자 RisuAI/Provider 접속 시험은 포함하지 않습니다.

적용 파일은 `plugins/HAYAKU_Locator_Continuity.js`이며 플러그인 버전은 3.0.60입니다. 이번 수정에서는 통합 패키지와 서버 버전 0.3.44를 유지합니다. RisuAI에서 기존 HAYAKU를 이 파일로 업데이트하고 다시 로드한 뒤 수동 누락 복구를 실행하면 됩니다. 기존 pluginStorage를 삭제할 필요가 없습니다.

회귀 시험: `tests/hayaku_evidence_manifest_upgrade_runtime_test.cjs`.
