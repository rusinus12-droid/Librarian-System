# HAYAKU 3.0.88 변경·검증

## 디버그 내보내기

파일 저장·표시·복사 경로가 실패 artifact를 새로 읽는다. `analysisDiagnostics`에 최근 작업의 실패 ID를 우선하여 최대 10개의 실제 응답, 응답 메타데이터, 파싱 후보, 정상화 후보, 항목별 수용·거부·파생 판정, 저장소에서 확인한 부분 기억을 포함한다. 전체 대상 수와 생략 수, 읽기 실패도 표시한다. 기존 credential 필드 제거를 적용하며 모델 호출은 없다. 내보낸 파일에는 이야기 내용과 모델 응답이 포함된다.

srcdoc 환경의 복사도 캐시만 내보내던 경로를 우회하여 상세 데이터를 읽는다. 비동기 조회 때문에 클립보드 활성 시간이 끝나면 기존의 직접 선택·복사할 수 있는 텍스트 표시로 대체한다.

부분 저장의 성공·실패·미실행 이유를 작업 로그와 최종 복구 결과에 전달한다. 물리 저장 재조회가 성공한 경우 `partial_memory_saved`로 구분한다. UI는 완전 패킷 수와 부분 기억 저장 턴 수를 별도로 표시한다. 중복 진단 재사용 경로에서도 부분 저장을 확인한다. 삭제한 실패 복구 화면으로 검토하라는 안내를 제거하고 명시적 재생성에 불필요한 대기 시간을 추가하지 않았다.

## 요약 수용과 상태 경계

정확한 인용 근거를 가진 개별 `summary`, `description`, `text`는 원문과 문장이 달라도 source-bound derived history로 보존한다. 인용문은 여전히 실제 대상 원문에 있어야 한다. 이름·상태·관계·직접 대사 등은 이 완화 대상이 아니다.

파생 문장의 의미를 기계적으로 검증했다고 주장하지 않는다. 파생 기억에는 원문 인용을 동봉하고, 충돌 시 인용을 우선하도록 표시한다. 현재 State와 완전한 턴 패킷으로 승격하지 않는다. 직접 인용 오류·필수 필드 오류·의존성 오류는 계속 항목별로 제외한다. 따라서 요약이 존재한다는 이유만으로 모든 턴이 완전 복구되는 변경은 아니다.

기존의 ‘invented’ 문자열만 넣어 의미 오류라고 판정하던 합성 시험은 실제로 원문에 없는 grounding 인용을 넣어 거부하는 시험으로 갱신했다. 어휘 문자열의 차이만으로 참·거짓을 증명한다는 계약을 유지하지 않는다.

## 지연과 GUI

프롬프트에서 동일 사실을 여러 필드에 반복해 채우지 않도록 하고, 파생 요약과 정확 인용의 지시를 정리했다. 실패 결과에 요청·응답 문자 수와 제공된 응답 메타데이터를 전달한다. 유료 재시도나 호출 동시성을 추가하지 않았다. 실사용 제공자 지연 개선 수치는 아직 측정하지 않았다.

진단 상세와 보존된 분석 진단의 글자색을 `#173c43`, 배경을 `#e4edef`로 고정해 이전 다크 테마의 연한 글자 규칙이 덮어쓰지 못하게 했다. 계산 대비는 10.01:1이며 글자는 12px이다. 실제 RisuAI 화면의 스크린샷 검증은 미실시다.

## 검증 결과

- 새 `hayaku_derived_memory_debug_runtime_test.cjs` 통과: 요약 수용, 허위 인용·잘못된 이름 거부, State 승격 없는 영속 저장·검색, 실제 응답 및 진단 내보내기, 저장소 부재 판정, 추가 모델 호출 없음.
- 기존 선택 회귀 시험 17개 중 14개 통과. 신규 시험 포함 18개 중 15개 통과.
- 이전 버전부터 남은 3개 실패: `hayaku_otherax_evidence_grounding_runtime_test.cjs:162`의 awaitingUserReview=true 요구, `hayaku_native_otherax_recovery_contract_test.cjs:98`의 폐기된 Failed Recovery UI 요구, `hayaku_gui_ux_contract_test.cjs:14`의 폐기된 탐색 탭 요구.
- 문법·SDK 동기화 통과. 패키지 manifest 및 checksum은 최종 파일로 갱신한다.

실제 사용자의 T5·T10 응답은 이전 첨부에 없으므로 새 버전으로 디버그를 내보내야 구체적인 항목 수용 결과를 확인할 수 있다. 이 과정에 재분석 호출은 필요하지 않다.
