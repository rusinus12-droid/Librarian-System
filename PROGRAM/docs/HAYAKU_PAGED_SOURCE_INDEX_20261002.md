# HAYAKU bounded source postings

The source-first recall path now reuses a derived inverted posting index to avoid repeated raw routing and temporary posting construction on warm requests. The previous baseline already reused unchanged source term sets. Canonical/raw packets and their existing record projections remain the evidence authority. This change does not add a model, embedding, semantic parser, or global ranking policy.

## Producer, storage, consumer and currentness

| Boundary | Implementation and proof |
| --- | --- |
| Accepted source inventory | `localRecallPostingInventory` reads each accepted descriptor, checks exact raw equality against its existing descriptor revision, hashes new raw revisions, and records source identity/position/locator, raw digest and character count. Declared hashes and string length alone never prove currentness. |
| Routing producer | The first request builds bounded temporary source terms. `localRecallSchedulePostingBuild` runs outside the awaited request, reuses unchanged source terms, yields every 32 sources, and derives raw-free postings and pages. |
| Stored representation | `hayaku.v2.recall_index.<scope>::<binding>::page::<pageDigest>` holds `hayaku.recall_posting_page.v1`: source IDs/digests/lengths and term-to-source postings. Immutable `manifest::<sourceSetDigest>` references all pages with digests and UTF-8 byte counts. No raw packet body is serialized. |
| Storage owner | HAYAKU's own key prefix and scope resolver route pages through the existing plugin/mirror/server-only storage proxy. No common SDK implementation changes are required. |
| Restart reader | Manifest, scope/binding/version, page digest/bytes, posting indices, source coverage and current raw proof must all match. Restored pages rebuild the in-memory postings map without rebuilding source tokens in the background loader. |
| Updating/invalidation | Add/edit builds only missing/changed source term sets. Current inventory removes deleted sources and filters old postings immediately. Source identity, scope, URL/mode binding and raw changes produce a different derived generation. |
| Product consumer | `handleBeforeRequest` already calls `localRecallPrepareSources`; its router now looks up requested posting lists, scores matching sources with the existing lexical formula, then uses the existing bounded record parser, multilingual record retrieval, alias certification, visibility and final request binding checks. |
| Publication | Runtime ownership/generation and actual host pluginStorage provider-reference checks surround asynchronous I/O and RAM/durable adoption. Provider replacement invalidates previous ready state even when scope/mode/URL match. Raw is revalidated before RAM publication and manifest publication. New pages receive exact write readback; reused pages are re-read, and missing/mismatching bytes are rewritten before manifest readback. An old generation cannot overwrite a newer source-set manifest key. |
| Failure | Binding/validation/size failures use bounded legacy routing. Corrupt/read-rejected pages fall back to raw source recall. Storage write/quota failure keeps validated RAM postings usable but reports `current=false`, `durable=false`, `status=unavailable`; retries are limited to once per five seconds for the same failed source set. Chat does not await the background persistence job. |

## Cost and size contract

`lastDebug().localRecallSourceIndex.routing` exposes `readChars` and `built` for request-time raw tokenization; `routingPostingBuildTerms` for temporary posting construction; `postingLookups` and `scoredSources` for query work. A query matching every source still scores every matching source. Those counters do not include record-level ranking/parsing or mean constant total request cost.

`validationRawReads`, `validationSources`, and `validationChars` record the full accepted inventory/character coverage checked; JavaScript string equality can avoid walking characters when identical string references are retained. `validationHashChars` counts characters actually passed through the raw digest function, and `sourceProofChars` counts the serialized inventory digest input. The real host commonly supplies new descriptors each request, so its warm raw hash count can still equal the full corpus. Without an authoritative host revision certificate, an old same-length edit must be found by this safe scan. No O(1) or O(delta) total-cost guarantee is made.

Background metrics separately report changed `builtSources`, all-source `postingBuildTerms`, exact raw validation coverage, page/manifest read and write counts/bytes, write-readback counts/bytes, and reused pages. Add/edit does not promise delta-only total work: page serialization and the RAM posting map are rebuilt for the bounded source set; deletion can shift 32-source page groups. On restart, the first request may still use temporary raw routing while the asynchronous page loader settles.

The derived path accepts at most 2,048 sources/8,000,000 raw characters, 250,000 source-term memberships, 128 pages per generation, 65,536 UTF-8 bytes per page and 4,194,304 page bytes per generation; excess inputs keep the previous bounded raw fallback. At most four scope states are retained in RAM. The persisted per scope/binding inventory stops allocating at 256 page keys or 32 immutable manifest keys. There is no automatic destructive eviction: deleting a shared page while an older physical storage operation is in flight can break a newer manifest. Quota saturation reports unavailable durable status and keeps current raw/RAM recall useful. Existing orphan pages are counted. A previously accepted physical write may finish late, leaving an unreferenced immutable page, but it cannot publish an obsolete manifest after cancellation. Host writes are not cancellable; this is an allocation admission limit rather than an atomic multi-process disk quota. A future cleanup design must preserve in-flight generation ownership.

`durable=true` records successful exact readback of the accepted generation on the currently bound actual provider, not a promise that an external process can never subsequently delete storage. Provider identity is a runtime reference fence and is not serialized into persistent keys, so a fresh VM can restore the same persisted pages with new exact readback. Replacing the actual host pluginStorage object resets previous ready/durable proofs, cancels old generation adoption, and requires current-provider page/manifest verification or rebuilding; unavailable replacement storage keeps raw recall with durable/current false. Uncancellable old physical writes can finish in the old provider, but their acknowledgements cannot certify the replacement. Unchanged warm-provider requests do not reread every page. Later reuse/restart rechecks storage. Existing server URL, token/reset-epoch and scope ownership fences continue to apply. Bootstrap currently supplies no authoritative DATA instance UUID/revision certificate; this change does not claim to close that separate protocol gap. A same-object backend change without a host revision signal remains that separate unsupported identity boundary.

## Bounded H02 comparison

`tests/fixtures/hayaku_same_language_ab.cjs` contains six hand-authored English/Korean/Japanese role and negation pairs. `hayaku_same_language_ab_runtime_test.cjs` compares the actual product record lexical rank with an evaluation-only normalized whole-sentence equality control. This dataset yields product top-1 5/6 and control 6/6; all six opposing records remain lexical hits. The English role-reversal tie is preserved as an explicit lexical limitation. The equality control is not activated in production and establishes no paraphrase, cross-language or general semantic accuracy guarantee.

## Verification

`hayaku_paged_source_index_runtime_test.cjs` drives the actual product preparation and registered `beforeRequest` routes. It covers cold/warm/add/edit/delete/restart, old same-length edits with unchanged declared hashes, source-owner identity changes, rejected writes, corrupt/rejected page reads, removed reusable page repair, late old writes, backend URL changes, retained-generation quota, and all three storage modes against a local mock server. No model calls occur. Existing source-routing scale/visible-hash/identity/stale-writer/alias-restart/current search-binding, native branch and background recovery tests remain required companions. Runtime metrics and exact commands are recorded in the phase2 recovery evidence directory.

`hayaku_paged_provider_fence_runtime_test.cjs` adds positive durable→actual provider replacement controls for both product preparation and the registered beforeRequest hook, rejected replacement I/O, provider changes during held page write/restart manifest read/manifest write, old acknowledgement/adoption rejection, old-page preservation, and fresh-VM restoration from the replacement's verified pages. It uses zero model/fetch calls.
