## 이번 변경

- HAYAKU 3.0.128: 복구 원문 근거의 읽기·쓰기를 fulfilled/rejected/indeterminate로 구분합니다. 1.5초의 초기 호스트 응답 제한 뒤 원래 작업을 최대 10초 더 관찰하고, 정확한 되읽기가 끝난 경우에만 다음 단계로 진행합니다. 동일 키의 재시도는 진행 중인 원래 쓰기에 합류하며 미확정 상태에서 근거를 지우지 않습니다. 늦게 끝나는 저장을 성공으로 가정하지 않습니다.
- Flashback 1.0.90: 한 항목/모든 항목의 잘못된 임베딩도 유지보수의 보류 결과로 돌려줍니다. 실제 자동복구 결과에 보류 항목을 전달합니다. 한 U+A의 일부 chunk가 실패하면 해당 U+A 전체를 보류하고, 문맥형 임베딩의 원래 그룹을 재시도 단위로 보존합니다. 인증 실패·취소·세대 변경은 개별 데이터 실패로 숨기지 않습니다. 전체 재구성/원문 교체는 계속 원자적으로 검증합니다.
- Flashback: 누락 턴 복구 준비가 자신의 worldline 세대 토큰을 무효화하던 순서를 수정했습니다. 실행 준비 단계에서 정합성을 먼저 확인하고 작업 세대를 잡되, 이후 실제 원문·스코프·설정 변경은 계속 차단합니다.
- LIBRA 2.3.120 / HAYAKU / Flashback: 실제 owner의 원문 확인 adapter가 manual/origin을 공통 비교창에 전달합니다. 수동 클릭은 곧바로 비교창을 열며, 비교창 열기 자체는 재분석 승인이 아닙니다.
- Storage SDK 1.8.20: 결과 요약에 요청 모드와 실제 적용 모드를 함께 표시합니다. 기존 상세 진단과 fail-closed 저장 모드 전환은 유지합니다. 내장 SDK 갱신으로 LIA 0.26.76, RE:TRACE 1.9.78도 배포합니다.

## 범위와 제한

- RE:TRACE의 브라우저 파일 선택/전체 ZIP 업로드·다운로드 UI는 아직 구현되지 않았습니다. 서버 로컬 archivePath 기반 import/export/restore와 구별해야 합니다.
- 서버의 사용자 DATA, 실제 RisuAI 설치, 실제 외부 모델, 실제 PocketRisu Docker/Windows/macOS/Android를 이 패치 환경에서 실행한 것으로 주장하지 않습니다. 실제 Linux HTTP/SQLite와 합성 host/provider 경계의 런타임·Chromium 시험을 수행합니다.
- 서버 동기화 failures=7/1의 실제 사용자별 key/error가 제공되지 않았으므로 그 특정 데이터의 원인이 해결됐다고 단정하지 않습니다. 상세 진단을 통해 원인을 확보해야 합니다.
- 기존 자료가 서버에 남아 등록을 막던 정확한 원인은 실제 장애 DATA 없이 확정할 수 없습니다. current-scope 삭제 기능과 근본 원인 진단은 서로 다른 범위입니다.
- ZIP 엔진은 동기 메모리 기반이며 항목 512MiB/총 해제량 2GiB 제한이 있습니다. 큰 DATA에 대한 스트리밍 전송·ZIP64는 별도 작업입니다.

상세 최종 시험 수와 감사 결과는 이 배포본과 별도로 제공하는 감사 보고서·로그를 기준으로 합니다.
