# LIBRA Book UX 5.16 · HAYAKU 패킷 작성 설정

배포 0.3.19 / LIBRA 2.3.26 / HAYAKU 3.0.43

## LIBRA

기억이 없는 서가에서 `기존 대화로 기억 만들기`를 눌러 기존 수동 콜드스타트를 실행한다. 자동 콜드스타트가 아니다. `정본 관리`는 기억의 유무와 무관하게 열린다.

선택한 장의 `교정`은 해당 scope/기억 ID/revision/worldline을 다시 확인한 뒤 관리 대상을 지정한다. 이력에서 장으로 이동할 때에도 같은 Reader 로더를 사용한다. 늦게 도착한 이전 채팅·닫힌 화면·이전 선택의 결과는 채택하지 않는다. 읽기에 실패하면 오류를 표시하고 `다시 읽기`를 제공한다. 렌더가 무제한 재시도를 시작하지 않는다.

빠른 설정의 저장 버튼은 값 변경과 함께 갱신된다. 입력이나 스크롤을 유지하기 위해 버튼 갱신만으로 전체 Drawer를 다시 그리지 않는다. 버전 기록은 페이지당 10개, 세계 색인은 페이지당 18개이며 검색·이동을 제공한다. 인물·세계 관련 바로가기는 실제 ID 또는 유일한 정확 이름 일치가 있을 때만 연결한다. 상태의 출처와 최신/마지막 확인값/부분 상태는 별도 표시한다.

## HAYAKU 설정 편집·패킷 원장

설정 조회·저장 중 새로 입력한 초안은 유지한다. 35개 기존 설정에 출력 위치 관련 2개 설정을 추가했으며 같은 argument 저장·재읽기·rollback 계약을 사용한다.

원장은 페이지당 40개를 렌더링하며 검색은 180ms 지연 처리한다. 선택된 패킷 deep link는 해당 페이지로 이동한다. 이는 DOM 수를 제한하는 개선이며 저장소 원장 자체를 서버 페이지화한 것은 아니다.

`출처 메타데이터` 탭은 패킷의 source/anchor 정보를 보여준다. 실제 U+A 원문을 조회하는 기능은 아니다. 개별 쓰기 영수증이 없는 과거 레코드를 저장 검증 완료라고 표시하지 않는다. Other Ax 테스트 성공과 메인 응답 패킷 생성 성공도 구분한다.

## 패킷 출력 위치

기본값은 `자동`이다. 한국어·영어의 명시적인 출력 형식과 확인 가능한 닫는 태그를 사용한다. 단지 과거 발화에 인용된 태그, unresolved 조건 분기, 임의의 태그는 위치로 채택하지 않는다. 서로 다른 필수 wrapper가 여러 개라 결정할 수 없으면 경고를 남긴다.

고급 출력 위치는 자동 / 본문 뒤 / 지정 닫는 태그 앞 / 필수 footer 앞이다. 닫는 태그는 `</Story>`와 같은 단일 태그만 입력한다. 실제 활성 출력 지시에서 확인되지 않으면 override를 채택하지 않는다. `본문 뒤`는 필수 wrapper나 footer를 무효화할 수 없다. 응답 전체가 순수 JSON/XML이어야 하는 충돌 형식은 기존 안전 우회를 유지한다.

자동 판정은 제한된 규칙 기반이며 모든 자연어 프리셋을 이해한다고 보장하지 않는다. 위치 경고가 있으면 `이번 패킷 작성`에서 HAYAKU가 관측한 위치를 확인한다. 이 정보는 HAYAKU beforeRequest 시점이며 다른 플러그인과 Provider 변환이 끝난 최종 payload를 관측했다는 뜻이 아니다.

## 본문 + 숨은 기록 계약

정상 경로에서는 메인 응답 모델이 본문과 current_snapshot 한 개를 함께 작성한다. 새로운 패킷 작성 LLM 호출을 추가하지 않았다. 기존 6개 최상위 객체와 세부 collection/item schema, 의미·원문·lineage 검증은 유지한다.

런타임 안내는 정확히 복사할 meta 상수와 실제 최종 본문에서 작성할 의미 필드를 분리한다. 전체 빈 패킷을 완성 예제로 주지 않는다. 근거 없는 축을 채우기 위해 사실을 만들면 안 된다. 내부 종료 점검은 별도 audit 선언/추론/두 번째 패킷을 출력하라는 요구가 아니다.

LIBRA/GRADIA의 `본문만 출력` 및 서사 끝점 제한은 보이는 소설/RP 본문에 적용된다. 별도로 요구된 숨은 런타임 기록은 지정 슬롯에서 작성할 수 있지만 서사를 연장하거나 미실현 초안/계획을 사실로 승격할 수 없다.

## 이번 패킷 작성 진단

작성 계약 적용/우회, 선택 위치·경고, 본 계약/형식/알림 길이, 메인 출력의 marker/JSON/의미/lineage 검사, 기존 Other Ax 복구 결과, 패킷 저장 상태를 구분한다. 복구 후보가 반환됐다고 저장 완료로 표시하지 않으며, 원문 recovery vault 보관도 정본 패킷 성공이 아니다. 요청 nonce 또는 일치하는 capture sequence와 scope가 확인된 결과만 연결한다.

입력 지시를 넣을 공간과 본문+패킷을 생성할 출력 공간은 다르다. 현재 경로가 Provider의 finish reason을 관측하지 못하면 출력 한도 도달을 확정하지 않는다. 설정된 maxResponse를 몰래 늘리거나 본문을 자동 축약하지 않는다.

실제 모델의 누락률 개선은 실서비스 A/B 시험이 별도로 필요하다. 함수/형식/회귀 시험은 실제 생성 성공률의 증명이 아니다.
