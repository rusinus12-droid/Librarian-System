# 원문 수정 추적 모드

LIBRA 2.3.107 · HAYAKU 3.0.112 · Flashback 1.0.73

## 사용 방법

원문 수정 확인창과 GUI의 ‘원문 수정 추적 모드’에서 같은 설정을 변경한다. 변경은 즉시 저장·재조회하며 일반 설정 저장 버튼을 별도로 누를 필요가 없다. 각 플러그인의 설정은 독립적이다.

| 모드 | 동작 |
|---|---|
| 추적 및 알림 | 메인 beforeRequest에서 수정 대상을 등록하고 afterRequest 이후 확인 알림을 준비한다. 사용자가 원문을 보고 승인해야 재처리한다. |
| 조용히 기록 | beforeRequest에서 GUI 기록만 갱신한다. 같은 구간은 최신 수정 상태 한 건으로 관리한다. GUI의 구간별 ‘원문 비교 및 처리’를 눌러 승인 후 처리한다. |
| 완전히 끄기 | 수정 감지 기록과 자동 알림·재처리를 중지한다. 다시 켤 때 현재 원문으로 별도 추적 기준을 저장하므로 OFF 기간의 차이는 소급 등록하지 않는다. |

설정 위치:

- LIBRA: 설정실 → 일반·진단(모바일 선택 메뉴의 진단 항목) → 원문 수정 동기화.
- HAYAKU: 구간 점검 → 원문 수정 동기화, 설정 → 복구·안전.
- Flashback: 고급 설정, 기억 유지보수 → 원문 수정 동기화.

기존 설정이 없는 사용자는 ‘추적 및 알림’으로 시작한다. 조용히 기록한 항목과 OFF 전에 남아 있던 대기 기록은 보존되며, 모드를 바꿨다는 이유로 자동 실행하거나 일괄 알림을 띄우지 않는다. 기존 기록은 수동 검토로 접근한다.

## T6에서 끄고 T50에서 켜는 경우

T50에서 켜는 순간 현재 채팅의 비교 가능한 원문 지문·메시지 식별·의존 근거를 저장한다. T6~T50 사이에 생긴 차이는 알리지 않는다. 이후 T10을 다시 수정하면 다음 메인 요청에서 그 변경과 필요한 후속 영향 구간을 등록한다.

설정은 플러그인 전체에 적용되지만 기준점은 채팅/세계선별로 격리한다. 다시 켜는 순간 열려 있지 않은 다른 스코프는 이후 처음 관찰할 때 별도 기준점을 만든다. 다른 스코프의 OFF 기간을 소급 분석하지 않는다. 스코프나 원문을 확실히 읽을 수 없으면 재활성화 성공으로 표시하지 않는다.

기억 생성 당시의 원문 증거는 기준점과 별도로 보존한다. 재활성화는 과거 기억을 최신 원문으로 생성한 것처럼 바꾸는 동작이 아니다. OFF 동안 수정된 내용은 기존 기억에 반영되지 않는다.

## 요청 및 저장 보호

편집만 하고 요청을 보내지 않으면 새 수정 기록도 생기지 않는다. afterRequest를 최종 저장 완료의 증거로 간주하지 않는다. 확인창을 만들 때와 승인 후 실행·저장 직전에 현재 저장 원문과 스코프를 다시 검증한다. 승인 이후 원문이 달라지면 이전 승인으로 덮어쓰지 않는다.

일반 새 대화 수집·검색 경로는 유지한다. 기존 데이터 덮어쓰기를 막는 무결성 검사는 OFF에서도 유지하며, 이러한 검사에서 사용하는 일시적 쓰기 보호 정보는 수정 추적 저널로 누적하지 않는다. 과거 수정 구간에 의존하는 쓰기는 필요하면 해당 구간만 보류한다.

모드 변경 중 이미 실행 중인 한 건은 기존 허가로 저장 확인까지 마무리하고, 다음 건을 시작하지 않는다. 전송된 모델 요청의 비용이나 이미 완료된 저장을 되돌리지 않는다. 설정 저장·재조회 실패는 오류로 표시하고 새 수정 재처리를 차단한다.

요청이 취소·실패하여 afterRequest가 오지 않으면 자동 검토를 시작하지 않는다. 대기 기록을 보존하고 다음 정상 요청 경계에서 다시 진행한다. 영구 승인은 저장하지 않으므로 재시작 뒤 미완료 작업도 재승인해야 한다.

## 검증 범위

공통 상태 검사: OFF/재활성화·재시작, 조용한 기록 누적, 후속 의존 변경, 승인 중 모드 변경, 실행 중 OFF, 저장 실패·재조회 불일치, 요청 완료 전 차단, OFF 기간의 후속 작업 재등장 방지.

세 플러그인 실제 JS를 실행한 격리 호스트 검사: before/after 경계, 승인 전 기존 기억 보존, 승인 후 소유 저장 경로, OFF 후 재활성화와 이후 수정의 기록.

Chromium 모바일 모의 환경: 실제 GUI와 실제 원문 확인창의 모드 선택, 값 동기화, 모델 호출 없이 설정 변경. 실제 RisuAI 기기·실서버·외부 모델에 대한 실사용 검증과는 구분한다.
