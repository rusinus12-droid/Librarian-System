# LIA 채팅 랜덤 페르소나 팝업

채팅 버튼 `리아로 랜덤 페르소나 생성하기`를 추가했다. 별도 팝업에서 기존 LIA 랜덤 후보 생성 엔진으로 세 가지 후보를 제안한다. 세계관 Blueprint가 없으면 기존 엔진이 먼저 분석하며, 저장을 선택할 때 해당 후보를 완성된 Persona로 상세 생성한다. Provider 호출은 사용자의 기존 설정을 따른다.

- 후보마다 **저장만**, **저장 및 채택**을 제공한다.
- 상단 **선택지 모두 저장**은 세 후보를 순차 생성·저장한다. 성공한 후보는 재저장하지 않으며, 중간 실패 후에도 저장된 결과는 보존한다.
- 저장은 기존 Persona DB mutation lock과 물리적 readback을 사용한다. 채택은 기존 scope Persona 변경 트랜잭션을 사용해 현재 채팅에 Live 바인딩까지 적용한다. 기본 Persona 선택과 다른 채팅은 변경하지 않는다.
- 채택·바인딩 readback 성공 후에만 상단에 **10초 자동 닫기** 문구·progress와 **자동 닫기 취소** 버튼을 표시한다. 다른 후보 작업을 시작하면 이전 타이머를 취소한다.
- 창 닫기와 Escape를 지원한다. 닫힌 팝업의 늦은 후보 결과는 저장하거나 다시 표시하지 않는다. 이미 시작된 DB 쓰기는 저장 프로토콜에 따라 끝날 수 있으며, 닫은 뒤 새 채택은 시작하지 않는다.
- 팝업 실행 전 LIA 편집 초안과 후보 선택 상태를 보관하고 종료 시 복원한다. 기존 설정 UI와 팝업이 동시에 생성 상태를 편집하지 않게 한다. 플러그인 종료 시 타이머와 채팅 버튼도 정리한다.

## 검증

`lia_random_chat_popup_test.cjs`는 실제 제품 팝업·채팅 등록·Persona 저장·Live 바인딩을 실행한다. 모델 생성 단계는 합성 후보/완성 응답으로 대체했다. 세 후보 전체 저장, 재저장 방지, 저장만의 연결 보존, 두 후보의 순차 채택, 10초 표시·취소·만료, 생성 중 닫기와 늦은 결과를 검증했다.

관련 `lia_scope_persona_management_runtime_test.cjs` 11건, Persona DB mutation guard, binding transaction safety도 통과했다. 이는 실제 Provider 호출·과금·실제 RisuAI 호스트에서의 버튼 표시를 검증한 결과는 아니다.

제품 DOM을 Chromium 1100px/390px에서 렌더링해 세 카드와 버튼, 스크롤 영역을 확인했다. 출력은 Codex visualization 폴더의 `lia-random-popup*.png`이며 합성 후보를 사용한 UI 검증이다. 전체 릴리즈 회귀와 실제 RisuAI 재로드는 미실행이다.

적용 파일: `PROGRAM/plugins/LIA_Persona_Linker.js`. 플러그인 재등록·재로드 후 채팅 버튼에서 실행한다.
