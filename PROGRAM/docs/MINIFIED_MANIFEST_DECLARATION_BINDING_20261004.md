# Release manifest declarations after minification

The official release build at source HEAD `5fc7ff69da4a879966a30684ef8a44fd14a6e7f7`
produced and captured all five minified plugins, then failed before creating its release ZIP:
`manifest_constant_missing:libra-fingerprint`. The readable LIBRA declaration and source
manifest contain `7a096a212eb71e1a87639347659ca9216fe32149068153491315734133217840`,
while the old generator's renamed-identifier fallback contained an older fingerprint.
Generic Storage/Compute SDK source files do not declare these plugin-specific pilot pairs.

Readable named declarations remain authoritative. For renamed release declarations,
the official builder now captures the SHA-256 of its five readable plugin inputs before
the smoke gate, staging, and minification. Before refreshing staged metadata it rechecks
all five captures and explicitly supplies its own readable `PROGRAM` root and bindings;
inherited declaration-root or binding environment values cannot select another source.

The generator requires a complete operation/fingerprint pair from the same captured
canonical plugin, matching canonical/staged `//@version` values, and exact string
literals in the staged plugin. Renamed-input literal validation lazily uses the existing
builder's offline Acorn tokenizer, so substrings, comments, nested quotes in documentation
strings, and regex-only values after `return` or `throw` cannot substitute for string tokens.
Readable primary declarations retain their existing static-scanner boundary on trusted,
captured canonical source; this is not arbitrary-source parser hardening. Missing,
duplicate, partial, malformed, changed,
or mismatched inputs fail before replacing the manifest. Fingerprints are not inferred
from a fixed historical table.

Model-only Flashback continues to omit its retired hash-vector pilot. The retired operation
name is used only to reject a stale renamed legacy artifact paired with a model-only
canonical source. Complete readable legacy pairs remain supported. This marker never
supplies a fingerprint or advertises a pilot for the current model-only source.

Tokenizer resolution is read-only and uses the build tool's existing local resolver;
this change does not install packages or request network access. Renamed inputs fail
before writes when Acorn is unavailable. Ordinary readable/model-only generation stays
lazy and is tested with a resolver that throws if called. The unavailable-tokenizer
negative uses a deliberately stubbed resolver in its own temporary fixture, not a
replacement dependency for the official build.
The cheap literal precheck requires the declared value's spelling to occur in the source;
escape-only spellings are conservatively rejected even if their decoded token value would
match. The captured current five artifacts satisfy this boundary without transformation.

The focused suite has 24 normal fixture cases. Supplying `MANIFEST_RELEASE_ARTIFACT_DIR`
adds one actual-artifact case; the owner ran all 25 against the five unchanged artifacts
captured from the failing official release. Negative cases compare the complete staged
and canonical file snapshots, including the old manifest, to prove failure before writes.
The original release failure and the RED run remain separate evidence.

No plugin/SDK source or captured artifact bytes, size ceilings, gold values, fingerprint
validators, existing smoke expectations, or the mandatory 80-file smoke list are changed.
Only the source metadata producer, builder invocation, focused test, and this note change.
Final source manifest/checksums are regenerated by the normal generators after composition.

Matching versions and literals alone do not prove arbitrary artifact derivation. This
validation is scoped to the official producer chain and its captured source/output pins.
Focused metadata success does not establish a complete release build, strict ZIP readback,
native installation, GUI acceptance, or model/embedding execution. Those remain separate
gates; the final official build and ZIP checks are performed on the newly composed source.
