# GRADIA 초안 파이프라인 점검 (SHADOW ACT + AIDE 3종)

날짜: 2026-10-22 · GRADIA `0.26.3`

## 구성 확인

- 순서: `shadow_act` → `aideStageOrder`(기본 인물 → 세계관 → 플롯). AIDE 순서는 정규화되어 중복·누락 없이 3개로 고정된다.
- SHADOW만 전체 초안을 쓰고, AIDE는 직전 초안을 블록 단위 패치(`replace`/`insert`/`delete`, `expected_hash` 확인)로만 고친다. 패치가 실패하거나 적용할 편집이 없으면 직전 초안을 그대로 넘긴다.
- 경량: 단계당 1회(표준 4회, 간소 2회). 중량: 분석 JSON 후 초안/패치(표준 8회, 간소 4회). 간소(`lite`)는 SHADOW + 플롯 AIDE만 실행한다.
- 소설/RP 계약은 네 단계 모두에 들어간다. SHADOW는 `shadowDraftModeContract`, AIDE는 `shadowDraftModeAideInheritanceContract`(단계별 역할 문구 포함), RP에서는 유저 행동 원장과 handoff 계약이 추가된다. RP에서 소설 초안 방식(classic / input_inclusive)은 무시되고, 소설 모드로 돌아오면 복원된다.
- 마지막에는 현재 입력의 확정 사항을 결정적으로 다시 검사하고, 위반이 있을 때만 복구한다.

## 이번 수정 — 외부 근거(LIBRA·HAYAKU·Flashback) 연동 시 충돌

1. **AIDE 하나의 실패가 턴 전체를 폐기하던 문제.** 근거 세션이 열린 요청에서 AIDE 응답이 잘리거나 JSON이 깨지면 `LIB_READ_MODEL_INCOMPLETE`·`LIB_READ_RETRY_DISABLED`로 세션이 무효화되어 이미 완성된 SHADOW 초안까지 버려졌다. 근거를 쓰지 않는 경로에서는 같은 상황에서 직전 초안을 유지한다.
   - 이제 AIDE의 불완전 응답은 재전송 없이 버리고 직전 초안을 유지한다.
   - 근거 세션에서는 repair 호출(JSON 복구, 계보·확정사항 재작성)을 보내지 않는다. SHADOW는 기존대로 실패 처리(fail-closed)되고, AIDE는 직전 초안을 유지한다.
   - 재시도 금지, 근거 비보존, 현재성 검사, 시간 초과 처리는 그대로 유지된다.
2. **근거 사용 지침.** 근거 블록에는 "신뢰하지 않는 과거 데이터"라는 머리말만 있어서 단계별 쓰임이 정해져 있지 않았다. 근거가 연결된 호출에만 시스템 프롬프트에 짧은 지침을 붙인다. 현재 입력과 최신 장면이 우선하고, 과거 장면 재연이나 출처 언급은 금지되며, 렌즈 메모는 비정본으로 다룬다. RP 모드에서 기억은 유저 행동의 근거가 되지 못한다. 단계별 분담은 다음과 같다.
   - SHADOW: 관계사·약속·미해결 줄기
   - 인물 AIDE: 지식·기억·감정·약속
   - 세계관 AIDE: 장소·물건·부상·시간
   - 플롯 AIDE: 복선과 미해결 줄기, 다만 진전시키지 않음

## AIDE를 유지하는 이유

외부 기억 플러그인은 **사실을 공급**하고, AIDE는 그 사실과 초안의 **불일치를 찾아 국소 수정**한다. 역할이 겹치지 않는다. 기억이 많이 주어질수록 한 번에 쓴 초안이 일부 사실을 놓치거나 오래된 상태를 현재처럼 쓸 위험이 커지므로, 연동 시에도 AIDE는 의미가 있다. 플러그인이 없는 사용자에게 AIDE는 로어북·채팅 기준의 유일한 검증 단계다. 비용을 줄이려면 간소 모드(SHADOW + 플롯)나 단계별 끄기를 쓰면 된다.

## 후속 수정 — 근거 전달 비용 (GRADIA 0.26.4)

앞 판의 "남은 관찰" 세 가지를 다시 확인하고 처리했다.

1. **"근거가 첫 단계 크기로 줄어든다"는 관찰은 잘못이었다.** 각 호출은 이전 호출의 블록이 아니라 같은 capture의 전체 묶음에서 자기 모델 문맥에 맞춰 다시 선별한다. 실측에서 SHADOW(2만 토큰 모델)는 5개, 뒤의 AIDE 세 호출은 각각 31개를 받았다. 코드 변경은 없고, 회귀 테스트만 추가했다.
2. **캐시.** 근거 연결 시 꺼져 있던 것은 근거가 아니라 공유 로어·캐릭터 참조 prefix의 cache였다. 이제 근거 연결 중에도 이 prefix를 cache한다(1st-party OpenAI·Anthropic endpoint만). 근거 블록은 사용자 메시지 끝, 모든 breakpoint 뒤에 그대로 남는다. 경량 모드에서 단계당 호출이 한 번이라 OpenAI/Claude는 캐시 계획에서 빠지던 문제도 고쳤다. 단계 사이에 같은 prefix가 반복되면 이제 cache 대상이 된다.
   - **근거 자체의 cache는 하지 않았다.** 근거를 cache되는 prefix로 옮기려면 단계별 system 지시보다 앞, 즉 system 영역에 두어야 한다. 이는 "신뢰하지 않는 근거는 user 메시지 끝에만 둔다"는 보안 계약(테스트로 고정됨)과 설계 문서의 no-cache 규칙에 반한다. 근거 블록은 단계마다 계속 전량 전송된다.
3. **최근 대화 중복.** 호출마다 실제 요청 본문에 이미 그대로 들어 있는 근거 항목(예: 최근 턴의 Flashback 기록)을 그 호출에서 뺀다. 텍스트가 조금이라도 다르거나 짧은 항목은 남기는 보수적 비교다. HAYAKU 기록은 원문이 아니라 구조화된 요약 패킷이므로 대개 그대로 남는다.
