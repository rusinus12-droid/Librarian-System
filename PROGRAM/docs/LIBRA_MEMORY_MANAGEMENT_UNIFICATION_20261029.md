# 기억 관리 화면 일원화

## 적용한 기준

사용자 캡처 하단의 기억 카드(재분석 / 수정 / 버전 기록 / 실행 기록)를 관리 화면의 기준으로 유지한다. 상단 관리 배너와 하단 수동 작업 도구에 반복되던 버튼은 `buildCanonicalActionPanel` 한 곳으로 모았다.

- 공통 도구: 기억 생성 구간 선택, 재분석, 수동 콜드스타트, 상태 점검 및 자동 복구, 버전·실행 기록, 복구·재구축.
- 개별 기억: 구간별 원문 표시와 기존 네 작업 버튼을 유지한다.
- 기억이 없는 상태에서도 공통 도구는 한 번만 표시한다. 중복 콜드스타트 진입점은 제거했다.
- 관리 모드에서는 `buildLibraMemoriesPanel`만 마운트한다. 같은 페이지에 독서용 기억 본문과 별도 편집 진입점을 다시 붙이지 않는다.
- 읽기 모드에서는 기존 7개 영역 독서 화면을 유지한다. 숨겨진 관리 카드와 독서 화면의 별도 교정·버전 버튼도 만들지 않는다.
- Micro·렌즈 열람 및 원문 근거 관리 경로는 유지한다. `memory-root`는 현재 표시되는 화면 하나만 소유한다.

저장 엔진, 정본 원문, 근거, 인물 식별 정보는 변경하지 않았다. 수정은 기존 복사본/수동 권위 후보 생성 경로를 사용한다. 수정본 저장은 활성 정본 덮어쓰기가 아니며, 비교와 상태 결정·명시적 채택 절차는 그대로 적용된다.

## 실행한 검증

`tests/browser/libra_memory_management_unified_browser_test.cjs`는 실제 제품 렌더러·이벤트·공개 저장 API를 합성 호스트에서 실행한다.

1. 관리 도구와 기억 관리 화면이 각각 하나이며 독서 화면이 중복 마운트되지 않는다.
2. 카드 수정으로 편집창 하나가 열리고, 취소할 수 있다.
3. 다시 수정해 별도 교정 후보를 저장하고 실제 비교 창에서 기존 정본을 유지할 수 있다.
4. 이 과정 전후 활성 정본과 현재 상태 Head의 저장 바이트가 같다.
5. 읽기 모드의 7개 영역과 Micro·렌즈 전환이 유지된다.
6. 기억이 없는 상태에서도 도구가 한 번만 나타난다.
7. 390px 화면에서 도구 가로 넘침이 없고, 모델·네트워크 호출 및 페이지 오류가 없다.

기존 독서 영역 브라우저 검사도 통과했다. 관리·읽기·사서의 여백 관련 집중 회귀 12건이 통과했다. `libra_main_memory_gui_wiring_test.cjs`에는 자동 연결 기록이 없는 기존 Head 테스트 환경의 누락 의존성만 보완했다. 기존 사실 표시·빈 상태·교정 저장 조건은 약화하지 않았다.

별도로 실행한 아래 두 검사는 현재 작업 이전 HEAD에서도 동일하게 실패했다. 전체 테스트가 모두 성공했다고 주장하지 않는다.

- `libra_canonical_job_runtime_test.cjs`: 이미 폐기된 `startManualCanonicalScan` 재분석 경로 호출.
- `libra_canonical_variant_job_gui_contract_test.cjs`: 현재 렌더러에 없는 `existingDrawer` 문자열을 요구하는 정적 계약. 렌더러 함수는 이번 변경 전후 동일하다.

증거는 로컬 `memory-management-unified` 시각화 폴더의 전체 화면 PNG, `focused-regression.txt`, 이전 HEAD 대조 로그에 보관했다. 실제 RisuAI 호스트·서버 저장 모드·유료 제공자 실행 검증은 포함하지 않는다. 사용자 요청에 따라 관련 LIBRA 변경을 로컬 main에 함께 커밋한다. 원격 푸시는 실행하지 않는다.
