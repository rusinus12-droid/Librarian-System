# LIBRA 2.3.49 — OtherAx 콜드스타트 대기 수정

2.3.48에서 구형 작업 복구를 통과한 뒤 RisuAI 보조 모델(otherAx)에 제출된 요청을 LIBRA 내부 배치 기한 270초에 포기하는 문제가 확인됐다. 제공사 응답이 끝난 것이 아니므로 `OUTCOME_UNKNOWN_TIMEOUT`이 발생하고 다음 배치도 선행 State 부재로 차단됐다.

정본 생성의 OtherAx 응답은 제출 후 호스트가 완료하거나 사용자가 취소할 때까지 기다리도록 수정했다. 제출 전 기한/호출 예산 검사는 유지한다. 직접 HTTP 호출과 소비자 작업, 연결 시험의 기존 시간 정책은 변경하지 않았다. 사용자 취소는 논리적 취소이며, API가 물리 요청 취소를 지원하지 않으므로 호스트가 끝날 때까지 물리 큐를 유지하고 취소한 요청의 늦은 결과는 채택하지 않는다.

## 적용

현재 실행 중인 보조 모델 요청이 있으면 RisuAI에서 처리 종료를 먼저 확인한다. LIBRA를 2.3.49 파일로 교체·재로드한 뒤 같은 채팅에서 ‘실패 배치 복구’를 실행한다. 정본과 원문을 삭제할 필요는 없다.

호스트가 실제로 응답하지 않는 경우에는 기다리는 상태가 유지된다. 사용자는 LIBRA 작업을 취소할 수 있으며, 실제 요청의 종료 상태는 RisuAI에서 확인해야 한다. 이 패치는 실제 모델의 응답 시간이나 성공을 보증하는 변경이 아니다.

## 검증 경계

지연된 호스트 응답과 짧은 배치 기한으로 기존 오류를 재현했다. 수정 뒤 실제 플러그인 소스를 실행하는 모의 호스트에서 기한을 넘긴 정본 및 State 저장, 제출 전 만료 차단, 연결 시험 기한 유지, 취소·늦은 결과·물리 큐 보존을 확인했다. 실제 RisuAI와 외부 Provider 재실행은 수행하지 않았다.
