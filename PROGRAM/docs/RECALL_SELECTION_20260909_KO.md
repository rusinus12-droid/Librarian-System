# HAYAKU 3.0.63 / Flashback 1.0.42 리콜 선택 통합

기억 후보를 선택한 뒤 다른 단계에서 다시 끼워 넣거나 교체하던 경로를, owner별 하나의 선택 계획으로 통합했습니다. 저장된 기억의 형식, 원문 수정 승인, 분석·임베딩 작업의 저장 계약은 유지합니다.

## 변경

- Flashback RRF는 명시적 가중치 0을 비활성 arm으로 처리합니다. 같은 arm에서 같은 ID·원본 revision은 한 번만 가산하고, 서로 다른 arm의 기여는 합산합니다. 잘못된 가중치는 기존 기본값을 사용합니다.
- HAYAKU는 검색·보충 후보, 의미 평가, 비교에 필요한 전후 근거, 축별 상한과 실제 출력 예산을 하나의 계획으로 처리합니다. 기존 두 종류의 행 키와 병합 항목의 출처를 명시적으로 연결합니다.
- Flashback은 일반 리콜, API 미리보기, 긴급 sparse 리콜에 같은 선택기를 사용합니다. 기존 topK, lane/MMR, 출처·턴 제한, 상태/사건 예산과 긴급 경로의 2개·1,500자 상한을 유지합니다.
- 렌더러는 선택된 근거만 직렬화합니다. 제목·라벨·구분선을 포함한 문자열 길이로 예산을 계산하며, 같은 준비 결과로 기존 의미 예산 단계 안에서 재계획합니다.
- 전후 근거를 모두 전달하지 못한 경우 미충족·부분 상태를 남깁니다. ID가 함께 선택됐다는 이유만으로 의미상 완전성을 인증하지 않습니다. 일부 잘못된 선택 필드나 상태 항목은 다른 정상 기억의 전달을 막지 않습니다.
- Flashback 발췌에는 원본 revision 식별값, 텍스트 공간, 확인 가능한 문장 구간과 출력 구간을 남깁니다. 원문 offset을 확인할 수 없으면 임의로 추정하지 않습니다.
- 안정성 이력은 실제 요청 훅으로 반환한 근거만 사용합니다. API 미리보기는 이력을 갱신하지 않습니다. 설정 변경·원문 저장·요청 교체·unload 경계와 일반→긴급 branch 전환에서 오래된 결과의 발행을 차단합니다.
- 각 제품의 기존 리콜 화면에 선택·실제 전달·예산 제외·근거 일부 부족을 구분합니다. 새 설정 항목이나 영구 전달 장부는 추가하지 않습니다.

## 확인 범위

### 설계 대조 후 보완

- HAYAKU의 기존 채팅 범위 조회가 다른 채팅을 확인하면 RAM 요청 epoch를 변경하고 진행 중인 리콜을 만료시킵니다. 돌아온 이전 채팅도 취소된 요청을 되살리지 않습니다.
- 안정성 이력은 요청의 범위 epoch와 세계선에 연결합니다. 최근 대화가 같아도 명시 질문이 달라지면 이전 가산을 적용하지 않습니다. 같은 질문과 문맥, 참조형 후속 입력의 기존 가산은 유지하며 명시 장면 전환은 제외합니다.
- Flashback의 비교 완전성은 기존 구조화 사실에 연결된 실제 원문 근거와 전달 발췌를 확인합니다. 단어 포함만으로 완전 충족을 표시하지 않으며, 연결이 없거나 손상되면 `support_unknown`으로 두고 원문을 전달합니다. 새 모델 판정은 없습니다.
- 필수 비교 쌍의 구성원이 exact·현재 상태·인물·주제 등 기존 독립 목적도 갖는 경우 단독 후보를 함께 등록합니다. `topK=1`이면 해당 독립 자료 하나를 전달하고 비교는 `partial`입니다. 독립 목적 없는 쌍은 임의 분할하지 않습니다.
- 양쪽 선택기는 이미 선택된 구성원을 제외한 점수로 겹치는 묶음을 다시 정렬합니다. 동점에서는 추가 요구 충족, 중복, 실제 추가 직렬화 비용, stable ID를 사용합니다. Flashback은 기존 final comparator의 출처·현재 장면 우선순위와 MMR 신호를 유지하며, 기존의 이야기 시점·ID 동점 순서를 새 비용 기준으로 대체합니다. 전체 조합 최적화가 아닌 유한 greedy 방식입니다.
- Flashback은 앞선 우선순위와 점수에서 순서가 정해지면 동점용 직렬화 비용을 계산하지 않습니다. 어휘 토큰과 후보 간 중복도는 요청 안에서 재사용하고, 실제로 선택할 후보의 비용은 반드시 확인합니다.

새 `recall_selection_conformance_runtime_test.cjs`는 위 다섯 경계 조건, 정상 근거의 완전 충족, 잘못된 근거의 부분 수용, 휴리스틱 및 안정성 OFF, 겹치는 묶음과 입력 순서 독립성을 실행합니다. 범위 전환 검사는 모의 호스트의 실제 범위 조회·요청 fence·발행 함수를 사용합니다. 실제 RisuAI에서 화면을 전환하는 실험과 구분합니다.

신규 runtime 회귀는 실제 제품 JS를 모의 RisuAI 호스트에서 실행합니다. 가중치 0/오류/중복, 비교 묶음의 순서와 상한, 실제 출력 구간, 일부 잘못된 항목, 휴리스틱 OFF, 설정 저장 시 만료, 원문 보존, API 미리보기, 일반 경로의 지연 완료와 긴급 결과의 소유권, 두 제품의 요청 훅 반환을 확인합니다.

실제 RisuAI 설치·화면 조작, 외부 provider 호출, 모델 응답 품질과 사용자 장치의 지연 개선은 별도 실측 전까지 미확인입니다. `returned_to_hook`은 이 플러그인이 반환했다는 뜻이며, 후속 플러그인이나 provider의 수신을 인증하지 않습니다.

패키지 버전과 서버·다른 플러그인은 이번 변경 대상이 아닙니다. 롤백은 이전 플러그인 파일을 복원하고 다시 로드하면 됩니다. DATA를 되감거나 기존 기억을 삭제할 필요가 없습니다.
