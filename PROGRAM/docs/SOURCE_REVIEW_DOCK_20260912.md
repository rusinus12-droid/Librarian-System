# 원문 수정 알림 및 최소화

버전: LIBRA 2.3.88, HAYAKU 3.0.100, Flashback 1.0.65.

- 첫 표시에는 전체 화면 컨테이너를 열지 않는다. 호스트 SafeElement를 사용해 오른쪽 아래에 작은 버튼을 표시한다.
- 왼쪽 위에는 해당 플러그인 이름, 본문에는 ‘원문 수정을 대기 중입니다 · 확인하기’를 표시한다. 테마 색상도 소유 플러그인별로 구분한다.
- 각 플러그인은 독립된 위치와 승인 상태를 가진다. 알림을 누를 때만 해당 플러그인의 상세 비교 창을 연다.
- 상세창 우측 상단은 ‘최소화 / 닫기’ 순서다. 최소화와 Escape, 배경 클릭은 선택 상태를 그대로 유지하며 작은 알림으로 돌아간다. 닫기는 기존처럼 미승인 종료다.
- 다른 상세창이 열린 동안 알림들은 일시 숨김 처리하여 승인 버튼을 가리지 않는다. 이는 표시 조정이며 승인 전파가 아니다.
- 스코프 변경·플러그인 종료·승인·닫기 시 알림과 이벤트 처리기를 정리한다. 호스트 알림 API를 사용할 수 없으면 강제로 전체 화면을 열지 않고 대기 처리한다.

## 검증

실제 공통 SDK를 Chromium의 서로 다른 iframe 3개에서 실행하고, 호스트 SafeElement의 document-wide 이벤트 전달을 모사했다. 초기 showContainer 호출 0회, 포커스 유지, 세 알림 비중첩, owner별 확대, 최소화 후 체크 상태 유지, 승인/닫기 정리를 검증했다. 1280px 및 390px 화면의 알림, 데스크톱 상세창 스크린샷을 확인했다.

- tests/source_review_dock_browser_test.cjs: 통과.
- tests/source_review_consent_v12_test.cjs: 15개 통과.
- 관련 원문 수정·복구 회귀 파일 13개: 통과.
- 공통 SDK 동기화: 통과.

실제 RisuAI 앱에서 설치 후 호스트 권한 및 컨테이너 표시까지 검증한 결과는 아니다. 기존 Python 브라우저 시험 중 ‘mainDom 호출 0회’를 전제로 한 시험은 새 호스트 알림 설계의 검증 대상과 다르며 이번 실행에 포함하지 않았다.
