# LIBRA 인물·세계·서사 기록 공백 수정 결과

작성일: 2026-11-06 · 대상: LIBRA 2.6.36 작업 트리(미커밋, 버전 미변경) · 이관서: `LIBRA_CONTENT_COMPLETENESS_HANDOFF_20261106.md`

## 1. 실측 방법

- 실제 LIBRA.js를 테스트 VM에 올리고, `DATA/stores/libra/libra.sqlite`(읽기 전용)의 scope `bf8f10a0_11:4` source receipt에서 T1~T10 원문과 당시 선택된 캐릭터 로어 3건을 넣었다.
- `runLLMModel`은 deepseek-v4.1-flash로 보냈다. 앞 회차는 로컬 Ollama를 거친 `:cloud`, 마지막 회차는 Ollama Cloud의 `deepseek-v4.1-flash:1017-cloud`(사용자 실사용 프리셋)다. 사고(think)는 꺼 두었다. 켜면 출력 한도 전체를 사고에 써서 빈 응답이 나온다.
- 구간 분석 → 정본 저장 → State → 화면 모델(인물 카드·세계 도감·서사 연감)을 같은 저장소에서 읽었다. 화면을 읽을 때는 모델 호출과 저장소 변경이 없었다. 재생(rebuild) 전후 State를 비교했다.
- 실사용 DB와 실제 RisuAI UI는 건드리지 않았다. 원문은 공개 fixture에 넣지 않았다.
- 증거: `.development/libra-completeness-20261106/run-*` (회차별 모델 요청·응답, 저장소, `summary.txt`, `gui.txt`).

## 2. 원인과 수정

| 문제 | 원인 | 수정 |
|---|---|---|
| 현재 위치가 내부 ID로 표시 | 정본과 겹치는 Micro 경로가 승인 패치의 새 항목 이름을 넘기지 않음 | 패치 기준 Registry 보기(`microRegistryViewWithPatch`)를 겹침 경로에도 사용. 그래도 이름이 없으면 ID 대신 "이름 확인 필요한 장소/대상" 표시 |
| 소속·사물의 "기록 없음"과 연결 공존, 위치 혼입, 역방향 라벨 | 빈 안내는 affiliations만 검사, 연결은 장소 쪽 라벨 재사용 | 인물 쪽에서 소유·소지·관리·접근·소속을 다시 계산. 위치는 제외. 실제 표시 항목 기준으로 빈 안내 판단 |
| 배경이 State에 안 들어감 | 배경은 대개 `historical`로 오는데 State는 `current_sequence`만 받음 | `character_background`만 historical/flashback도 허용 (`unifiedFactStateEligible`) |
| 소개·선호·경계 추출 부족 | 한 번의 대형 호출이 프로필을 거의 내지 않음 | 프롬프트에 인물별 점검 추가. 선호·경계는 단서 문장 주변만 보내는 작은 확인 호출(`[LIBRA PREFERENCE AND BOUNDARY CHECK]`) 추가. 말한 사람을 주어로 보여 주는 두 번째 인용을 런타임이 검사하고, 범주와 문구가 맞지 않으면 버림. `character_info`의 boundary/dislike/fear 범주를 그대로 존중 |
| 장소 설명 없음 | 지속 설명을 담는 계약·저장·표시 경로 없음 | `world_description`(world, `description[]`, 누적형) 추가. 세계 도감 카드 본문(lead)에 표시 |
| 흐름·전환·반복 소재 없음 | 통합 정본에 해당 writer 없음 | `story_arc`/`turning_point`/`motif`(narrative, 제목 엔티티 기준) 추가. 해당 배치의 검증된 사건 ID만 인용해 구성하는 작은 호출(`[LIBRA STORY STRUCTURE]`) 추가. 반복 소재는 서로 다른 두 턴 이상의 근거 필수. 같은 제목으로 다음 배치에서 이어짐 |
| 구조 행이 저장돼도 화면에서 사라짐 | Head 로더(`normalizeCurrentNarrativeState`)가 turningPoints/motifs를 버림 | 근거가 있는 구조 행, 종결 이야기, 해결된 흐름을 상한을 두고 유지 |
| 마무리된 이야기 공백 | 해결된 thread를 Head에서 삭제. 마무리 탭은 수동 이력 로드에서만 읽음 | `closedThreads`에 보관하고 해결 사유(이행·완료·깨짐 등)를 표시. 이력과 중복 표시 방지 |
| 이야기 중복 | 참여자를 생략한 재확인, 문구가 겹치지 않는 재확인, alias 없는 associate가 보류되어 새 행 생성 | 사실 자신의 문장이 후보 참여자를 모두 지칭할 때만 참여자 상속. reaffirm은 원문 문구 겹침 요구 제외(변경이 없으므로). alias 없는 associate는 새 thread로 처리. 남은 보류는 "연결 확인 필요"로 구분하고 열린 갈래 수에서 제외 |
| 같은 이름의 사물과 서사 제목 충돌 | Registry 이름 매칭이 kind를 보지 않음 | thread 종류 엔티티는 thread 종류끼리만 매칭 |
| 단순 형식 실수로 사실 대량 탈락 | event를 character 도메인에, 경계 scope 축 누락 | 의미가 하나뿐인 경우만 정규화(event→event, 누락 축→빈 값) |

새 읽기 전용 기록(종결 이야기, 해결된 흐름, 전환점, 반복 소재)은 기억 그래프의 현재 State 회상에서 제외했다(`tools/libra_memory_graph_readers.cjs` 수정 후 동기화). 이 내용은 정본 기억에 이미 있으므로, 답변 프롬프트에 현재 상태처럼 들어가지 않게 했다. 이미 끝난 이야기가 다시 종결로 들어와도 기존 행과 근거를 바꾸지 않는다.

서버 권한 코덱(`server/authority/libra-typed-codec.cjs`)에 새 claim 종류를 반영했고, 원래 빠져 있던 `character_emotion`도 함께 넣었다. thread 제목 엔티티 규칙과 reaffirm 규칙도 플러그인과 맞췄다.
