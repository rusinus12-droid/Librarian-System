# 여는·닫는 표식 직접 지정

LIBRA 2.3.117 / HAYAKU 3.0.124 / Flashback 1.0.85, 공통 Source Edit Consent 1.6.1.

원문 수정 확인의 세 카드에서 **여는 표식**과 **닫는 표식**을 실제 본문에 나타나는 전체 형태로 입력하고 **추가 → 규칙 저장**을 누릅니다. 대표 이름으로 종료 형태를 추측하지 않습니다.

| 여는 표식 | 닫는 표식 | 용도 예시 |
| --- | --- | --- |
| `<GigaTrans>` | `</GigaTrans>` | 원문 영역 선택 |
| `[LBDATA START]` | `[LBDATA END]` | 영역 제외 |
| `[ORIGINAL BEGIN]` | `[ORIGINAL FINISH]` | 원문 영역 선택 |
| `<wrapper>` | `</wrapper>` | 표식만 제거 |
| `<display-only/>` | 빈 칸 | 단일 표식 제외 |

어느 모듈의 이름인지 판별하지 않으며 정규식이나 사용자 코드는 실행하지 않습니다. 일반 표식은 대소문자와 공백까지 입력한 문자열 그대로 찾습니다. 내부 공백, 괄호 종류, START/END 이름은 자유롭게 지정할 수 있습니다. 표식은 각각 최대 256자, 카드별 최대 128개입니다.

표준 `<태그>` / `</태그>` 쌍은 기존 태그 규칙으로 정규화합니다. 이 경우 대소문자를 구분하지 않으며 여는 태그에 속성이 붙어도 인식합니다. 특정 속성까지 포함한 여는 표식을 직접 입력하면 일반 문자열 규칙으로 처리합니다.

- **원문 영역 선택**은 닫는 표식이 반드시 필요합니다. 표식이 없으면 전체 본문으로 비교합니다. 비어 있는 영역, 중복 영역, 불완전한 표식은 원문 선택을 적용하지 않습니다.
- **영역 제외 / 표식만 제거**는 닫는 칸을 비우면 단일 표식으로 처리합니다.
- 정상적으로 중첩된 시작/종료 표식을 지원합니다. 짝이 맞지 않는 작업은 본문을 보존합니다.
- 같은 표식을 여러 규칙에 중복 지정하거나 여는·닫는 표식을 동일하게 지정하면 저장을 거부합니다.
- 기존 태그명 설정과 기본 제어문 묶음은 호환 경로로 유지합니다. 화면에서는 가능한 경우 실제 시작·종료 형태를 보여 줍니다. Suite 자체 운용 표식은 내부에서 처리하며 사용자 목록에 노출하지 않습니다.
- 기존 기본 항목을 지운 후에는 여는·닫는 표식으로 원하는 규칙을 직접 추가할 수 있습니다. 새 UI에 `@lbdata` 같은 내부 예약 이름을 입력할 필요가 없습니다.
- 모든 외부 규칙을 비우면 전체 본문을 비교합니다. Suite 자체 운용 표식은 별도 내부 처리 대상입니다. 저장된 채팅·기억을 설정 변경만으로 덮어쓰지 않습니다.

공개 API는 기존 태그명 배열과 함께 `{open, close}` 항목을 받습니다.

```js
await api.setSourceEditRules({
  ignoredTags: [{open: '[LBDATA START]', close: '[LBDATA END]'}],
  unwrapTags: [{open: '[WRAP BEGIN]', close: '[WRAP END]'}],
  sourceTags: [{open: '[ORIGINAL BEGIN]', close: '[ORIGINAL FINISH]'}]
});
```

검증: 공통 파서의 일반·중첩·불완전·빈 영역·단일 표식·충돌·새 VM 재시작, 세 제품의 실제 런타임 fixture에서 정본/원장/본문 저장 이후 비대칭 표식 전환과 실제 변경 감지, 세 제품 GUI에서 두 입력란 추가·삭제·저장. 실제 RisuAI/외부 번역 모델 동시 실행은 별도 검증 범위입니다.

## 외부 규칙과 내부 운용 표식

사용자 목록은 외부 모듈·모델이 본문에 추가하는 표식을 위한 것입니다. `hayaku_packet_contract`와 Suite 기억·패킷 운반 블록은 내부에서 처리하며 목록에 노출하지 않습니다. 출처가 확인되지 않은 `dag_runtime_contract`는 기본 목록과 기존 LIBRA 자동 제거에서 제외했습니다. 일반 HTML 주석 전체를 내부 표식으로 간주하지는 않습니다.

이전 설정의 해당 기본 항목은 불러올 때 분리하고, 나머지 사용자 정의 규칙은 유지합니다. 설정을 읽기만 할 때 저장소를 재작성하지 않으며, 다음 설정 저장 시 읽기 검증을 거쳐 반영합니다. 과거 원문 근거나 기억을 소급하여 덮어쓰지 않습니다.
