# GRADIA 소설·RP 모드 분리 점검

날짜: 2026-10-22 · GRADIA `0.26.8`

## 점검 방법

오프라인 호스트에서 실제 `beforeRequest` 훅과 인풋 작성기를 돌렸다. 모델로 가는 모든 요청과 본 모델로 넘어가는 최종 주입문을 모았고, 각각에 들어간 모드 계약 표식을 셌다.
- RP 표식: `PLAYER-CONTROLLED`, `USER AGENCY`, `USER-AGENCY FRONTIER`, `AGENCY LEDGER`
- 소설 표식: `NOVEL MODE`, `NOVEL / CLASSIC`, `NOVEL CLASSIC MODE`, `INPUT-INCLUSIVE`, `FULL-CAST`

## 결과

| 대상 | 소설(클래식) | 소설(인풋 포함) | RP |
|---|---|---|---|
| SHADOW·AIDE 3종, 경량 4회 / 중량 8회 | 클래식 계약만 | 인풋 포함 계약만 | RP 계약만 |
| 최종 주입문 | 소설 계약만 | 소설 계약만 | RP 계약만 |
| 인풋 작성기 (기억 연결 유무 모두) | 3관점 선택지 프롬프트, 선택지 3개 | 같음 | 플레이어 행동 조언 프롬프트, 선택지 3개 |
| 모드 전환 | — | RP로 갔다가 돌아오면 인풋 포함 방식 복원 | 전환 중 `author_directed`로 고정 |

## 고친 점

플롯 AIDE에 RP 전용 지침 세 줄이 모드와 관계없이 들어가 있었다. 모두 "RP 계약이 있으면 …" 형태의 조건문이라 소설 모드에서는 쓸모없는 지시였다. 이제 RP 모드에서만 넣는다.
- 패치 지침: 이어받은 결말이 유저를 대신 연기하거나 플레이어 차례를 건너뛰면 보호하지 않는다
- 분석 지침: 문장 단위 행위 주체 감사
- 분석 지침: AGENCY-BYPASS CLOSURE 감사

`tests/gradia/writing-mode-separation.test.cjs`가 경량·중량 × 소설 두 방식·RP에서 계약 분리와 방식별 변형을 확인한다.

## 확인 범위 밖

- 프롬프트에 계약이 들어가는지만 봤다. 실제 모델이 계약을 지키는지는 확인하지 않았다(가짜 모델).
- 복구 경로(JSON 재요청, 계보·확정사항 재작성)는 이 프로브로 직접 실행하지 않았다. 해당 함수들은 같은 모드 판정 함수를 쓴다. 문자열로 찾아본 범위에서는 "RP 계약이 있으면" 형태의 다른 무조건 문구가 없었다.
