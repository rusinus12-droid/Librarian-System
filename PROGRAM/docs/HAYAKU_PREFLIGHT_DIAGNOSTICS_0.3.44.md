# HAYAKU 누락 복구 중단 진단 · 3.0.59 / 합본 0.3.44

선택 복구가 모델 분석 전에 중단되는 경우, 기존 화면은 오류를 표시한 직후 상태 조회로 덮고 작업 로그도 남기지 않았습니다. 이 패치는 그 진단 손실과 사전 검사 중 중복 실행을 수정합니다. 아직 확인되지 않은 라이브 환경의 저장/원문 오류를 우회하지 않습니다.

- 첫 호스트 조회 전에 작업 ID와 잠금을 생성합니다. 범위 조회, 원문/저장 검사, 선택 원문 비교, 턴 확인, 부채 조회, lease, 증거 검증, 모델 호출, 응답 검증 단계를 기록합니다.
- 사전 검사 반환, 예상 밖 예외, 취소, 부분 실패 모두 마지막 결과·단계·코드·시간을 보존하고 잠금을 해제합니다. 중복 실행은 별도 거절 기록으로 남으며 진행 중 작업을 대체하지 않습니다. 사전 검사 중 Cold Start/재생성도 기존 작업을 침범하지 않습니다.
- 실제 `runLLMModel` 호출 직전에 횟수를 증가시켜, 분석 전 중단 0회와 실제 호출 뒤 실패를 구분합니다. 추가 재시도나 임의 호출 제한 시간을 도입하지 않았습니다.
- 복구 결과는 별도 화면 영역에 유지됩니다. 실패 시 ‘최근 복구 중단’ 상태와 ‘분석 시작 전 중단’ 또는 ‘복구 미완료’, 호출 횟수, 단계/코드를 표시합니다. 작업창을 닫거나 상태를 새로 조회해도 결과는 남습니다. 다른 채팅에서는 표시하지 않습니다.
- 디버그 JSON의 `recoveryExecution`에 현재 진단, 마지막 수동 복구 결과, 실행 거절, 작업 요약, 마지막 repair 결과 요약을 추가했습니다. 새 진단 필드에는 원문 대신 digest·식별 해시와 상태만 기록합니다. 실행 기록은 세션 내 상태이며 플러그인을 다시 로드하면 초기화됩니다.

검증: 실제 플러그인 VM에서 원문 불일치/채팅 메시지 미조회/저장 읽기 timeout/실제 fixture 모델 호출, 사전 검사 중 중복 요청/취소/Cold Start 차단, debug JSON 결과 일치를 확인했습니다. 조정 함수의 예상 밖 예외도 작업 실패로 종료됨을 검증했습니다. Chromium의 실제 GUI에서 실패 결과가 새로고침/작업창 닫기/390px 화면에서도 유지되고 다른 채팅에서 숨겨지는 것을 확인했습니다. 외부 모델/서버 호출 및 실제 RisuAI 실행 환경 검증은 수행하지 않았습니다.

업데이트 후 같은 현상을 재현하고, 플러그인을 다시 로드하기 전에 디버그 JSON을 추출하면 이번 로그에서 누락됐던 중단 코드를 확인할 수 있습니다.
