- HAYAKU 3.0.39는 Recovery Journal 누락 확인을 전체 원장 GUI와 분리된 경량 확인창으로 표시합니다. 확인 전에는 정본 원장 화면을 자동으로 열지 않으며, 독립 확인 UI를 표시할 수 없는 환경에서는 자동 복구를 시작하지 않고 저널을 pending으로 유지합니다.
- HAYAKU 3.0.40은 실패 복구 화면에 사람이 읽을 수 있는 실패 원인·복구 단계·다음 조치를 표시하고, 빈 canonical 미리보기의 그대로 채택을 명시적으로 차단합니다. 실패 복구 LLM은 incremental envelope·grounding·coverage를 검증한 뒤 성공 시 즉시 정본으로 반영하며, 직접 수정은 canonical packet 또는 envelope 입력을 허용합니다.
- HAYAKU 3.0.46는 이 `indeterminate` 상태의 작은 reconciliation journal을 영구 저장하여 RisuAI reload 뒤에도 exact/superseding ledger readback으로 결속을 이어갑니다. packet 본문이나 대형 ledger를 중복 저장하지 않고 이 경로에서 LLM을 다시 호출하지 않습니다.

- 현재 스코프의 저장 위치가 연산 위치도 결정합니다. 플러그인 단독은 로컬 연산, 미러와 서버 단독은 검증된 서버 연산을 우선하고 실패하면 같은 로컬 kernel로 복귀합니다.

저장 및 연산 설정
1. 서버를 실행합니다. Compute token signing key는 서버 내부에서 자동 생성되며 사용자가 열거나 입력하지 않습니다.
2. 각 플러그인의 `저장 및 연산` 화면에서 현재 캐릭터·채팅 스코프의 저장 위치를 선택합니다. `플러그인 단독`은 로컬 연산, `미러`와 `서버 단독`은 내부적으로 `prefer_server`를 사용합니다.
3. 미러나 서버 단독에서 `연결 확인`을 누르면 Storage와 Compute를 함께 확인합니다. 서버 중단, 자동 인증 실패, queue 포화, timeout, 현재성·결과 검증 실패 시 계산만 같은 로컬 kernel로 정확히 한 번 복귀합니다.
- 이 패키지에는 독립 Compute 모드, `shadow`, `memory_suite_*_compute_mode`, 사용자 token 또는 secret 입력 argument가 없습니다.
- 플러그인 단독은 Compute 네트워크 호출 0회입니다. remote-only 모드는 없습니다.
- DATA/config/server-config.json의 computeEnabled=false로 서버 Compute Plane을 끌 수 있고, computeWorkers는 0(자동) 또는 1~16입니다.
- 서버 단독에서 서버가 꺼지면 Compute 계산은 로컬로 돌아가지만 데이터 I/O는 기존처럼 fail-closed입니다.
