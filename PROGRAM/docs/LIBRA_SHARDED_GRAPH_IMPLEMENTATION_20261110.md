# LIBRA 다중 묶음 상설 그래프 — 2026-11-10

작업 위치: `.claude/worktrees/libra-memory-engine-audit-728563`. 배포 후보는 LIBRA 2.6.41 / 서버 패키지 0.5.1이다. 커밋·푸시·설치·배포하지 않았다. 이전 엔진·주입 예산·렌즈·GUI 패치를 유지한 위에 구현했다.

## 저장과 구축

- 전체 corpus의 64구간 상한을 제거했다. 묶음은 최대 64구간이며, 묶음 직렬화 예산을 기본 1 MiB로 제한한다. 기존 읽기 횟수·원본 바이트·디코드·상주 메모리 admission을 넘는 경우에도 묶음을 반으로 줄여 새 자원 컨텍스트에서 시도한다. 한 구간 자체가 한도를 넘으면 실패를 숨기지 않는다.
- 기존 v1 corpus를 각 묶음의 검증·페이지 저장 형식으로 재사용한다. 묶음은 외부 mutable root를 따로 게시하지 않는다. 내용 해시로 고정된 묶음 manifest와 위치 색인을 모두 준비한 뒤 상위 root 한 개를 교체한다.
- 상위 root/manifest는 `libra.graph_corpus.v2`, 위치 색인은 `libra.graph_corpus_forest.v1`, 디렉터리 노드는 `libra.graph_corpus_forest_node.v1`이다. 새 root 스키마는 옛 브라우저 탭의 v1 정리기가 새 구조를 빈 corpus로 오인해 삭제하는 것을 막는다. 기존 v1 읽기는 유지한다.
- 기본 한 작업은 네 묶음까지 준비한다. 이후 immutable 체크포인트를 남기고 자동 재개한다. 재시작 뒤에도 이어가며, 도중 원본이 바뀌면 묶음별 원본 헤드를 다시 비교해 검증 가능한 준비본을 재사용한다. 바뀐 묶음 내부는 다시 구축한다. 전체 게시 전 취소·실패는 기존 root를 바꾸지 않는다.
- State/로어는 첫 묶음이 소유한다. 역사 묶음에는 Canonical/Micro를 두고, 한 자료 종류가 먼저 끝나면 마지막 자료를 이후 묶음에 반복해서 넣지 않는다. 과거 자료의 인물 레지스트리·분기·원본 결속 검증은 유지한다.
- 바이트 한도로 축소된 묶음 크기는 다음 묶음·체크포인트에도 적용해, 큰 묶음의 실패를 매번 반복하지 않는다.

## 검색

- 해시 radix 디렉터리에 단어·인물·관계 종류·노드 위치·간선의 시작점/끝점별 묶음 위치를 저장한다. 단어 디렉터리와 단어별 묶음 디렉터리를 분리하여, 모든 묶음에 반복되는 단어도 긴 단일 해시 가지를 만들지 않는다. 디렉터리와 catalog 자체도 내용 해시로 페이지화한다. 요약문으로 자료를 제외하지 않는다.
- 검색어에 맞는 묶음을 고르고 연결된 노드·간선을 따라 다른 묶음을 추가로 연다. 묶음별 상위 결과를 잘라 합치지 않는다. 선택한 그래프를 기존 단일 검색 커널·점수·근거 컴파일러·최종 원본 검증에 전달한다.
- 현재 State가 과거 묶음의 근거를 가리키면 정확한 Canonical 정체성 또는 Micro 턴으로 그 묶음을 선택한다. 이미 선택한 근거의 원본 페이지를 기존 reader로 재투영하고, 양 끝 노드와 근거의 binding이 일치하는 `derived_from` 간선만 연결한다. State가 바뀔 때 역사 묶음을 모두 다시 구축하거나 과거 State를 현재 것으로 사용하지 않는다. 이 과정에서 기존 State 정규화가 Micro 전용 근거를 일반 Canonical 포인터로 축소하던 문제도 고쳤다. claim digest 불일치는 연결하지 않는다.
- 선택 그래프의 기본 예산은 4 MiB / 32묶음이다. 예산을 넘으면 `selectionComplete:false` 및 source coverage 이유를 남겨 부분 탐색으로 표시한다. GUI는 전체 묶음 수와 실제 읽은 묶음 수를 구분한다.
- 선택한 그래프의 공통 접근 색인은 요청 안에서 한 번 구성한다. 전체 corpus를 요청마다 컴파일하지 않는다. 이 선택 부분의 컴파일도 `indexBuildsDuringQuery`에 포함해 진단 수치를 숨기지 않는다.
- 의미 검색은 기존 저장 벡터와 질의 임베딩 캐시를 사용한다. 문서 임베딩은 새로 만들지 않는다. 의미 전용 근거를 단어 색인으로 잘못 제외하지 않도록 의미 검색 활성화 시 Canonical/Micro 묶음은 보수적으로 탐색 대상에 넣는다. **묶음 간 ANN/벡터 상한 색인으로 의미 검색을 좁히는 최적화는 이번 범위에 없다.** 따라서 넓은 의미 검색은 더 많은 묶음을 읽거나 부분 탐색이 될 수 있다.
- 게시본이 없거나 낡은 긴 채팅의 임시 읽기는 검증한 제한 구간과 남은 cursor를 부분 결과로 제공하면서 자동 구축을 예약한다. 첫 제한 구간을 전체 이력 검색으로 표시하지 않는다.

## 원본 검증과 메모리

호스트에 외부 쓰기까지 증명하는 신뢰 가능한 source epoch가 없으므로, 전역 최신성은 원본 문서 전체 대신 작은 manifest 참조·turn pair·Micro 헤드/작업 헤드·레지스트리·State·로어의 rolling digest로 확인한다. 이 관찰은 일정 크기로 나누고 서버 모드에서는 배치 읽기를 사용한다. 의미에 영향을 주는 임베딩 설정과 ref의 임베딩 상태도 포함한다. 단순 실행 상태 변경과 같은 manifest 전체 바이트를 전역 내용 정체성으로 사용하지는 않는다.

**작은 원본 헤드의 전역 관찰 비용은 아직 이력 길이에 비례한다.** 실제 전달 근거와 선택한 묶음은 기존 물리적 원본 검증을 통과해야 한다. 저장 그래프와 위치 색인은 권한이나 정본 사실이 아니다. 자원 계수는 전체 VM heap을 측정·보증하지 않는다.

## 정리와 동시성

- 서버는 게시 뒤 유휴 시간에 정리를 예약한다. 한 번에 고아 페이지 최대 32개를 정리하고 남으면 다시 예약한다. 현재 scope·활성 검색·구축 상태를 확인한다.
- 새 검색은 GC 잠금 충돌 시 서버에 양보를 요청하고 SDK 내부에서 50ms 간격, 최대 5초 동안 lease 획득을 재시도한다. GC는 진행 중인 한 페이지 작업 뒤 잠금을 놓으며 나중에 재개한다. 요청은 lease 없이 근거를 읽지 않는다.
- 서버 GC의 도달 가능성 집합은 배타적 GC lease 동안만 재사용한다. 고아 페이지마다 전체 corpus를 다시 순회하는 비용을 제거했다. 실제 삭제는 현재 revision/digest와 lease를 재검증한다.
- 서버와 IndexedDB의 게시·정리 검증은 같은 forest 참조 규칙을 따른다. 현재 root, 활성 읽기 pin, 의미 벡터, 최근 체크포인트의 하위 묶음/색인을 보존한다. 서버는 `libra-graph-forest.v1` capability를 요구하여 새 그래프를 모르는 구버전 정리기와 조합하지 않는다.
- IndexedDB 정리는 모든 페이지 본문을 Map에 모으는 대신 native cursor와 참조 mark를 사용한다. 한 transaction의 삭제는 최대 256개이며 남으면 유휴 작업으로 이어간다. v2 게시의 누적 32 MiB 읽기 제한도 개별 값/참조 admission으로 분리했다. 참조 안전 한도는 여전히 존재하며 무제한 저장을 보증하지 않는다.

## 검증 기록

최종 결과와 기준선 비교는 `.development/libra-forest-implementation/`에 보존한다. 합성 129/257구간, 크기가 큰 구간의 분할, 부분 탐색, 구간 간 후속 사건의 단일 frontier 전달, 원본 변경, 체크포인트/재시작, 서버 자동 정리와 검색 우선 양보를 검증한다. 실제 RisuAI 설치·실제 제공자·OOM 재발 및 대규모 실사용 지연 검증과는 구분한다.

- 신규 forest 단위 7/7 및 실제 플러그인 API 런타임 8/8 통과 (`final-forest.log`). 129개 묶음에서도 희소 검색은 첫 묶음과 적중 묶음 두 개만 읽는다. 실제로 발행한 65개 Micro를 가진 70턴 채팅은 70구간 구축을 완료하고 T70 근거를 전달한다. State 변경 후 역사 묶음 재사용과 올바른 Micro 연결, claim digest 불일치의 연결 거부도 포함한다.
- IndexedDB 저장소 14/14, 상설 그래프 GUI 모델 8/8 통과 (`local-gui-final.log`). 32 MiB 이상의 고아 페이지가 있는 저장소를 1 MiB retained ledger로 정리하는 시험 및 삭제 실패 시 transaction 롤백을 포함한다.
- 실제 Chromium의 두 탭·프로세스 재시작·원자적 롤백·읽기 pin 보존/해제 후 정리가 통과했다 (`final-suite/libra_memory_graph_local_store_browser_test.cjs.log`).
- Micro State 관련 추가 7개 파일의 9개 시험이 통과했다 (`micro-state-final.log`). 플러그인·mirror·서버 모드의 원본 근거와 공급, reader GUI를 포함한다.
- 플러그인 바이트 출처·릴리스 메타데이터·기존 graph GC 계약 3개 파일 통과 (`metadata-gc-final.log`). LIBRA 내장 SDK와 graph 모듈의 원본 일치 및 JavaScript 문법 검증 통과.
- Runtime/Source 배포 선택과 런타임 의존성 폐쇄 검사 2개 파일 통과 (`runtime-package-final.log`). 서버가 사용하는 forest 참조 검증 모듈을 Runtime 도구 포함 목록에 등록했다.
- 전역 `check_sdk_sync.cjs`의 Flashback SDK/source-review 불일치는 이전 HEAD에서도 재현된다 (`sdk-check-baseline.log`). 이번 LIBRA 내장 SDK는 정확히 일치한다. `libra_graph_lifecycle_sqlite_test.cjs`도 이전 HEAD와 수정본 모두 임시 SQLite 폴더 삭제 단계에서 EPERM으로 종료하며 전체 통과로 집계하지 않았다 (`lifecycle-baseline.log`).

전체 실행은 314개 고유 파일에서 종료했다. 기존 305개 외 추가 9개 파일은 최종 재검증을 반영해 모두 통과했다. 추가 묶음의 원 실행에서는 마지막 진단 코드 수정에 따른 바이트 출처 값 갱신 전 검사가 한 번 실패했으며, 갱신 후 통과 기록을 `reruns.json`에 남겼다. 마지막 긴 채팅 런타임 묶음도 8/8 통과로 종료했다. 최종 무결성 대조는 manifest 2,845개 항목과 체크섬 2,880개 모두 불일치 0건이다 (`final-integrity.json`).
