# LIA 상태 응답의 형식 검증과 GUI 표시 복구

기준은 main `32d8f43`, LIA 0.26.87이며 수정 버전은 **0.26.88**이다.

## 문제와 수정

Ollama Cloud의 `deepseek-v4.1-flash:cloud` 실측에서 모델은 목표·부상·소지품·약속을 추출했지만 `liveState`를 배열 대신 분류별 객체로 반환했다. Ollama 경로는 strict schema를 사용하지 않아 요청에는 `response_format: json_object`가 전달됐고, 분석 프롬프트에는 필수 출력 모양이 없었다.

기존 `normalizeLiveDelta`는 JSON 객체라는 점만 확인한 뒤 `asArray(parsed.liveState)`를 호출했다. 그 결과 상태를 빈 배열로 바꾸고 수동 갱신이 성공해, 처리 범위는 5쌍에서 10쌍으로 전진하면서 상태 0개와 빈 요약이 저장됐다. GUI도 성공을 알린 뒤 상태 없음으로 표시했다.

수정본은 다음 경계에서 이를 막는다.

- 수동 분석 프롬프트에 전체 출력 스키마와 배열·항목 계약을 명시한다. strict schema를 지원하지 않는 공급자도 같은 모양을 전달받는다.
- 새 모델 응답의 필수 상위 필드, 배열 여부·상한, 항목의 키·분류·값·지속성·정수 신뢰도·근거 형식을 정규화 전에 검사한다. 유효한 항목과 잘못된 항목이 섞여 있어도 전체 응답을 거부한다.
- 형식 오류는 `LIA_LIVE_DELTA_INVALID`로 알린다. Persona 쓰기와 원장 갱신에 들어가기 전에 중단하므로 기존 상태·본문·완료 범위를 보존하고 같은 5쌍을 다시 실행할 수 있다. 형식 오류에 자동 재분석 호출을 추가하지 않는다.
- 정상적인 `liveState: []`는 상태가 해소된 결과로 계속 허용한다. 잘못된 형식을 빈 결과로 취급하는 것과 구분한다.

기존 저장 레코드를 읽는 호환 정규화는 그대로 사용한다. 2,200 토큰의 상태 분석 출력 예산과 추론 설정은 변경하지 않았다. 정상 coreCandidates는 기존 보수적 정책에 따라 제안 이력에 남으며 자동 승격되지 않는다.

## 실제 응답과 실모델 검증

수정 전 받아 둔 실제 응답 두 개를 제품 HTTP 경계에서 그대로 재생했다. 수정 전에는 상태를 비운 채 완료됐지만, 수정 후에는 오류를 표시하고 물리 pluginStorage 소유 데이터·Persona DB·현재 채팅·완료 범위를 모두 보존했다. 실행 버튼도 같은 범위로 다시 사용할 수 있었다. 이 재생 검사에는 새 외부 모델 호출이 없었다.

별도로 수정본의 제품 GUI를 Chromium에서 열고 실제 Ollama HTTPS 경로로 수동 분석을 실행했다. 모델 공급자 함수는 대체하지 않았다.

| 항목 | 관측 결과 |
|---|---|
| 모델 | `deepseek-v4.1-flash:cloud` |
| 실제 모델 호출 | 1회, HTTP 200, `finish_reason=stop` |
| 상태 | 6개: Brin 구조 목표, 왼손목 골절, 황동 열쇠, Mira에 대한 약속, 검 사용 제한, Aria와의 협력 |
| 검증 | 물리 저장 재조회·Live Persona 본문·편집 요약의 현재 상태 값 일치 |
| 처리 범위 | 5 → 10쌍, 원장 1개 |
| GUI 갱신 | 별도 새로고침 없이 6개 상태 표시, 브라우저 예외 0개 |
| 단일 작업 측정 | 약 6.845초; 이 중 실제 HTTP 응답 완료 약 6.341초 |
| 사용량 | 입력 1,075 + 출력 1,520 = 2,595 토큰 |

이 시간은 해당 VM의 한 번 실행에서 모델·네트워크·브라우저·검사 시간을 포함한 값이다. 수정 전과 동일 저장 스냅샷을 사용한 통제 성능 비교나 일반적인 지연 보장은 아니다. 실제 사용자 RisuAI RPC/IPC는 연결하지 않았고, 캐릭터·로어·대화·호스트 저장소는 합성 어댑터를 사용했다. 번역·이미지 생성·다른 공급자의 실모델 품질 검증은 이번 범위에 포함하지 않는다.

## 회귀와 배포 검사

- `lia_live_delta_contract_runtime_test.cjs`: 원본·축약 실행 각각 48개 사례. 객체형 응답·누락 필드·잘못된 항목·혼합 배열·개수 초과를 거부하고 기존 데이터를 보존한다. GUI 오류 후 같은 범위의 명시적 재시도, 정상 상태 표시, core 제안 보존, 유효한 빈 상태로 해소하는 경우를 검사한다. 실제 비엄격 Ollama 전송 경로를 사용하며 호스트 HTTP 응답만 가로챈다.
- 기존 수동 분석 36개 사례, 공급자 시간 초과·취소, 대기 상태, 영구 저장 실패 48개 사례, Persona 목록 읽기 실패와 8개 제품 GUI 경로가 통과했다. Chromium의 취소·중복 클릭·처리 중 원문 변경 보호도 통과했다.
- 실제 Full/Min 배포 파일을 빌드하고, 비공개 함수를 노출하지 않은 공개 등록 GUI에서 형식 오류 보존·명시적 재시도·상태 표시를 확인했다.
- 배포 파일 검사는 퇴역한 `dpg-live-*` 선택자 때문에 기준 커밋에서도 실패했다. 현재 제품의 `upd-go`·`upd2-range` 조작으로 옮겼으며, 실제 파일 바이트·중복 클릭·소스 Persona 보호·불충분 범위 차단 검사를 유지하고 오류 보존 검사를 추가했다.

SDK 삽입본, 버전 출처, 설치 안내·manifest·체크섬을 확인한다. 제품 배포 버전은 LIA만 올린다. 전체 프로젝트 회귀 배치나 사용자 앱 설치 검증을 의미하지 않는다.

키와 원본 모델 응답·HTML·저장 레코드·캡처는 저장소 밖 비공개 경로에 보관했다. 키나 원본 저장 스냅샷은 Git·이 문서에 포함하지 않는다. 이번 패치 검증의 새 외부 모델 호출은 위 1회이며, 이전 결함 조사에서 사용한 호출은 별도 조사 기록에 속한다.
