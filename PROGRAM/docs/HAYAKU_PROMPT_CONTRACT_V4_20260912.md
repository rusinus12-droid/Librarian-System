# HAYAKU 3.0.104 — 정규 패킷 작성 계약 수정

2026-09-12. 대상: `plugins/HAYAKU_Locator_Continuity.js`. 3.0.103 프롬프트 감사 결과에 따른 수정이다. 정규 응답과 함께 패킷 하나를 작성하는 흐름을 유지한다.

## 수정 내용

1. **선택 인용이 다른 기억을 제외하는 결함 수정.** 정규 패킷의 `meta.record_grounding`은 항목별 선택 근거다. 빈 배열이나 요약에만 붙인 인용 때문에 인물·사건 등이 제외되지 않는다. 제출된 인용은 실제 현재 응답과 대조하고, 잘못된 인용은 해당 항목에만 적용한다. 인용하지 않은 항목은 기존 정규 수용 규칙을 따른다. 복구·콜드스타트의 필수 항목 근거 검사는 유지한다. 부분적인 선택 인용을 전체 근거 검증이나 새로운 State 권한으로 취급하지 않는다. 수용 결과의 `groundingCoverage`는 검사·미제출·대응하지 않는 경로를 구별한다.

2. **배열 정리 후 인용 연결 오류 수정.** 첫 항목을 제외하고 두 번째 항목이 앞당겨질 때, 첫 항목의 잘못된 인용이 두 번째 항목을 다시 제외시키는 문제를 재현했다. 제외한 항목의 인용을 제거하고 남은 인용 경로를 이동시킨다. 반복 수용·원장 재조회에서도 같은 항목과 패킷 해시를 유지한다.

3. **Full·Compact·Critical 공통 규격.** 컬렉션 이름, 배열/객체 구분, 필수 항목 필드를 실행 스키마에서 생성한다. 압축 모드도 필수 규격을 생략하지 않는다. 작성 지시는 한 함수로 공유하고, 요청 상수와 출력 위치는 runtime, 끝맺음 확인은 마지막 지시에서 맡는다. 정적 캐시 프로필은 `p4-*`이며 요청 nonce·세계선·출력 한도가 정적 해시를 바꾸지 않는다.

4. **언어·인용·완성 지시 정리.** 요약과 설명에는 설정 언어를 사용하고, 이름·식별자·정확한 인용은 원문을 유지한다. JSON 구분자와 문자열 안의 인용부호를 구별하고, 백슬래시·줄바꿈 이스케이프를 명시한다. 근거 있는 요약만으로도 완전한 패킷을 작성할 수 있다는 규칙을 한 번 설명한다. 변화가 없는 턴에는 확인된 기존 사실을 남길 수 있지만, 기억할 사실이 전혀 없는 빈 패킷을 정상 기억으로 만들어 성공 처리하지 않는다. Full에는 실제 스키마 검사를 통과하는 작은 완성 예시를 넣고, 예시가 실제 이야기의 근거가 아님을 명시했다.

5. **패킷 전용 중립적 추출.** 민감한 사건도 비노골적으로 사실·경계·피해·결과를 요약하고, 불확실한 동의나 정체성을 추정하지 않도록 한다. 이는 숨은 패킷의 추출 규칙이며, 정규 응답에 복구용 “장면을 계속하지 말라”는 지시를 주입하지 않는다.

6. **확인된 출력 한도 전달.** RisuAI에서 읽은 `maxResponse`가 유효하면 runtime 지시에 전달한다. 본문과 패킷이 함께 출력 한도를 사용하며, 필수 필드나 닫는 마커보다 중복 사실·선택 별칭을 먼저 줄이도록 한다. 모델 이름을 추측하거나 temperature·thinking·provider 설정을 강제로 변경하지 않는다. 추가 모델 호출도 만들지 않는다.

## 크기 비교

동일한 합성 요청, 회상 데이터 없음. 모델 토큰 수나 실행 시간 측정이 아닌 문자 수다.

공통 규격을 빠짐없이 제공하면서 동적 중복 지시를 줄였다. Full 조립 결과는 약 23.7% 감소했다. 실제 `beforeRequest` 모의 실행에서는 새 출력 한도 안내를 포함해 7,608자였다. 각 모델의 지연·비용 개선률을 뜻하지 않는다.

## 검증

- 관련 회귀 스크립트 **32/32 통과**. 전체 저장소의 모든 테스트를 실행한 것은 아니다.
- 새 `hayaku_prompt_contract_v4_runtime_test.cjs`: 빈 선택 인용, 요약만 인용, 잘못된 개별 인용, 인용 경로 이동, State 권한 유지, 정규 원장 저장·재조회·중복 방지, 복구·콜드스타트 필수 근거, 스키마 동일성, 다국어·이스케이프, 완성 예시, 캐시 안정성, 예산 하한, wrapper/footer/순수 JSON 보호, 리롤, 실제 `beforeRequest` 함수 실행을 검증한다.
- 기존 정규/복구 공통 수용, 콜드스타트 배치, 후보 계약, 원문 수정 승인·재시작·의존성, 저장 검증, 검색 및 관련 LIBRA/Flashback 회귀도 통과했다.
- 과거 버전 고정 검사는 헤더/실행 버전 일치 검사로 갱신했다. GUI 설정 검사도 과거 개수 39 고정 대신 실제 선언과 컨트롤의 양방향 일치를 확인한다. 정적 계약으로 옮긴 규칙은 새 위치에서 검사한다. 이미 폐기된 실패 복구 창을 요구하는 검사는 해당 창이 다시 나타나지 않는지 확인하도록 갱신했다. 근거 검사는 현재 공통 수용 호출과 필수 근거 조건을 확인한다.
- JS 문법 및 내장 SDK 동기화 통과. 배포 manifest 752개·체크섬 754개 항목의 실제 파일 재해시 검증도 통과했다.

증거 파일은 워크스페이스의 `_diagnostics/hayaku-prompt-audit-20260912/`와 `_diagnostics/hayaku-prompt-patch-20260912/`에 있다. 후자에는 수정 전 JS, 변경 diff, 주입 프롬프트, `results.json`, `verification.json`이 있다. 합성 데이터와 호스트/저장소 모의 실행이며 실제 사용자 채팅이나 원장 데이터를 수정하지 않았다.

## 남은 검증 범위

이번 작업에서 실제 외부 모델 API는 호출하지 않았다. 사용자가 열거한 GPT·Gemini·Claude·GLM·Kimi·DeepSeek 각 버전의 성공률·속도·비용을 검증했다는 의미는 아니다. 공통 프롬프트의 불일치를 수정한 것이며, 실제 RisuAI의 제공사별 직렬화, thinking 블록 보존, 응답 종료 사유와 출력 한도 적용은 실제 호스트 요청으로 별도 확인해야 한다. 모델별로 임의의 전송 우회나 재시도를 넣지 않았다.

설계 참고: [OpenAI prompting](https://developers.openai.com/api/docs/guides/prompt-engineering), [Gemini prompting](https://ai.google.dev/gemini-api/docs/prompting-strategies), [Claude prompting](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices). 모델별 최신 정보의 확인 근거와 한계는 앞선 감사 보고서에 기록했다.
