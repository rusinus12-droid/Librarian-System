# LIBRA Micro 상태 표시 수정 — 2026-10-19

기준 커밋: `9ac4f8b`. 수정 플러그인: LIBRA **2.3.173**. 패키지 버전은 0.4.1을 유지한다. 기존 감사 문서를 근거로 삼지 않고, 리뷰에서 재현한 두 사례와 현재 실행 코드로 확인했다.

## 수정 내용

- Micro 상세의 상태 판정은 개별 claim의 admission 합계 대신 **응답에 사용되는 최종 상태 투영**의 `pendingClaims`와 `transitions`를 사용한다.
- 같은 턴의 동일 필드에 상충하는 값이 있으면 승인으로 집계하지 않고 충돌 보류 사유를 표시한다.
- 이후 정본에 흡수된 Micro는 `absorbed`, 이후 정본·교정으로 대체된 Micro는 `corrected`로 구분한다. 이전 턴에 현재 Head 기준의 admission 결정이 없다는 이유만으로 보류하지 않는다.
- 현재 상태에 적용된 승인, 정본·교정에 반영된 기록, 이후 변경으로 대체된 기록, 보류를 GUI에서 구분한다.
- 정본/상태 세대와 admission 갱신이 바뀌면 열려 있는 Micro 목록과 상세를 다시 조회한다.
- 전체 진단의 64개 제한과 별도로 선택한 턴의 최종 판정을 받는다. 진단 목록에서 빠진 항목을 승인으로 추정하지 않는다.
- 조회는 읽기 전용이다. 결과 반환 전에 Micro·결정의 실제 저장 본문, scope·분석 revision, 정본/Registry/분기 경계를 다시 검증하고 임시 소비 근거 참조를 해제한다. 검증에 실패하면 판정을 확정하지 않는다.

실제 상태 투영의 승인·충돌·흡수 규칙, 저장된 State Head, 기억 생성 프롬프트, 모델 호출 정책, 벡터 선별과 예산은 변경하지 않았다.

## 범위
