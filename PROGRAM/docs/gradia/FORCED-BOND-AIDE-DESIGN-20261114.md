# 억결 AIDE 재설계: 관계 긴장 강제 장치

2026-11-14 작성. 대상: GRADIA `aide_forced_romance`(현재 브랜치 `fix/capture-reconcile-and-gui-oom`).

억결 AIDE를 "지정 여성 인물 1명과의 연애 강제"에서 **페르소나 중심 관계망의 복합적 긴장을 강제하는 장치**로 바꾼다. 강제성은 살리되, GRADIA의 기존 설계(작성 모드 계약, AIDE 순서, 관계 정사 잠금, 자체 기억 은퇴, LIB 독립 연동)를 지킨다.

## 1. 확정된 결정 (2026-11-14, 사용자)

| 항목 | 결정 |
|---|---|
| 관계의 결 | 호감만이 아니라 증오, 애증, 미련, 집착, 질투, 경쟁, 죄책감 등 복합 |
| 관계 대상 | 페르소나 중심으로 시작하고, NPC 사이의 연결선도 만든다 |
| 관계 카드 생성 | 유저가 만들고, AI가 이야기에서 발견한 관계를 제안할 수 있다 |
| 한 턴의 범위 | 주 관계 1개 + 그 여파로 움직이는 보조 관계 0–1개 |
| 관계 변화 | 장면 결과에 따라 자동 반영한다 |
| 근거 | LIB 기억을 최대한 쓰고, LIB가 없으면 최근 n턴의 장면 신호로 만든다 |
| 페르소나 성향 | 바람둥이 같은 성향은 페르소나 설정을 입력으로 받는다 |

## 2. 지켜야 하는 기존 설계

| 기존 설계 | 위치 | 억결에 주는 제약 |
|---|---|---|
| 자체 기억 영구 은퇴 | `arcDirectorBriefForPrompt` | 억결이 관계 진행 상태를 자체 저장소에 쌓으면 안 된다. 상태는 매 턴 근거에서 다시 읽는다. |
| 관계 정사 잠금 | `buildRelationshipCanonLock` | 로어에 적힌 관계(부부, 형제, 소꿉친구 등)와 호칭은 읽기 전용이다. 억결은 그 위에 **감정의 결**을 얹을 뿐, 관계 종류를 바꾸지 않는다. |

| 인물 일관성 | 인물 AIDE OOC 규칙 | 근거 없는 감정은 만들지 않는다. **유저가 선언한 관계 카드는 근거(정사)로 본다.** |

## 3. 개념 모델

### 3.1 결 (bond tone)

관계 하나는 결 여러 개의 조합이다.

- 기본 결: 호감, 증오, 미련, 집착, 질투, 경쟁, 죄책감, 동경, 경멸, 빚(은혜), 빚(원한)
- 조합 예: 애증 = 호감 + 증오, 미련 = 호감(과거) + 거리(현재), 라이벌 = 경쟁 + 인정

결마다 억지로 만드는 계기의 종류가 다르다.

| 결 | 억지로 만드는 계기 |
|---|---|
| 호감 | 밀착, 둘만의 시간, 사적인 대화 |
| 증오·경멸 | 대면, 함께 해야 하는 일, 피할 수 없는 거래 |
| 애증 | 서로가 필요한데 원망이 걸리는 상황 |
| 미련 | 추억이 묻은 물건이나 장소, 끝내 못 한 말 |
| 질투·경쟁 | 제3자가 끼는 장면, 비교당하는 순간 |
| 죄책감·빚 | 갚을 기회, 들킬 위기 |

### 3.2 관계 카드 (유저 설정)

```
{
  id,                       // 카드 식별자
  from, to,                 // 인물 이름. 한쪽은 보통 페르소나. NPC↔NPC 가능
  direction: one_way | mutual,
  tones: [tone, ...],       // 결 1–4개, 앞에 둔 결이 주된 결
  stage,                    // 출발 단계(낯섦 → 의식 → 긴장 → 표출 → 결착)
  visibility: hidden | known,
  pressure: subtle | situational | explicit,  // 관계 진행을 밀어붙이는 속도
  limits: [string],         // 금지선(예: 육체적 진전 없음)
  origin: user | accepted_proposal
}
```

- 카드는 **설정**이지 기억이 아니다. 유저가 쓴 출발점이고, 채팅별로 저장한다.
- 성별을 가정하지 않는다. "지정 여성 인물" 표현은 모두 "지정 인물"로 바꾼다.
- 현재 단일 대상 설정(`forced_romance_target_character`, `_intensity`, `_force_appearance`, `_scope_overrides`)은 카드 1장으로 옮긴다(§9).

### 3.3 관계 판독 (매 턴 재구성, 저장하지 않음)

매 턴 다음 근거로 각 카드의 **현재 판독**(지금 결, 지금 단계, 최근 계기)을 다시 만든다.

1. 관계 정사 잠금 사실(최우선, 읽기 전용)
2. LIB 기억 근거(LIBRA·HAYAKU·Flashback이 고른 기억 중 카드 인물이 함께 나오는 것)
3. 최근 n턴의 장면 신호(LIB가 없거나 근거가 부족할 때)
4. 관계 카드(출발점)

"자동 반영"은 저장을 고쳐 쓰는 것이 아니라, 장면에서 일어난 일이 다음 턴 판독에 그대로 드러나는 것이다. 증오가 애증으로 바뀐 장면이 LIB 기억이나 최근 대화에 남아 있으면, 다음 턴 판독은 애증이 된다. 카드가 말하는 결과 근거가 다르면 **근거를 따르고**, 카드는 출발점으로만 남긴다.

마지막 판독은 GUI 표시를 위해 실행 중 메모리(`Runtime`)에만 둔다. 로어 연속성(`Runtime.loreContinuity`)과 같은 방식이다.

### 3.4 관계 제안

AI는 이야기에서 카드에 없는 관계를 발견하면 **제안**을 낸다(예: "B가 페르소나와 A의 사이를 질투하기 시작함"). 제안은 GUI에 후보로 쌓이고, 유저가 받으면 카드가 된다. 받기 전에는 프롬프트에 강제 요소로 들어가지 않는다.

## 4. 근거 패킷 (모델 호출 없음)

억결은 모델을 더 부르지 않고, 결정적 코드로 **관계 근거 패킷**을 만든다.

- 인물 인식: `buildContinuityEntityIndex`, `continuityEntitiesInText`
- LIB 근거: LIB 증거 블록에서 카드 인물 둘 이상이 함께 나오는 줄을 고른다.
- 최근 n턴 신호: 같은 방식으로 최근 n턴에서 고른다. 결 단서 어휘(감정 표현, 접촉, 충돌, 회피)가 있으면 우선한다. n은 단계 슬롯의 `turnWindow`를 따른다.
- 정사 잠금: `recent.relationshipCanonLock.facts` 중 카드 인물이 걸린 사실을 함께 싣는다.
- 상한: 패킷 문자 수 상한을 둔다(정사 잠금의 `RELATIONSHIP_CANON_LOCK_MAX_CHARS`와 같은 방식).

LIB 근거가 하나도 없으면 패킷에 "LIB 근거 없음, 최근 장면 신호만"을 표시해, 모델이 기억을 지어내지 않게 한다.

## 5. 한 턴의 흐름

```
관계 근거 패킷(결정적)
  → SHADOW: 스포트라이트(주 관계 1 + 보조 0–1)와 계기를 계획, 초안에 반영
  → 인물 AIDE: 각 인물의 결이 성격·이력에 맞게 표현됐는지
  → 세계관 AIDE: 계기가 지금 장소·시간에서 그럴듯한지
  → 억결 AIDE(선택): 긴장이 약하면 보강, 관계 판독과 제안을 JSON으로
  → 플롯 AIDE: 긴장이 결말로 닫히지 않고 다음 턴 씨앗으로 남는지
```

- 억결 AIDE는 일반 AIDE로 실행 루프에 들어가고, 사용자가 정한 핵심 AIDE 순서에서 **플롯 AIDE가 어디에 있든 바로 앞**에 놓인다(`withForcedBondStage`). 사용자는 핵심 AIDE 셋의 순서만 바꾼다. 플롯 AIDE가 언제나 억결 뒤에서 점검한다.
- 억결 AIDE를 끄더라도 근거 패킷과 단계별 지침은 동작할 수 있게 한다(설정: 억결 사용 켬/끔, 보강 단계 켬/끔).
- 스포트라이트 선택 기준: 지금 장면에 있는 인물, 오래 다루지 않은 관계, 쿨다운이 끝난 관계, 유저 입력이 건드린 관계.

### 5.1 단계별 지침

`LIB_EVIDENCE_STAGE_USE`처럼 단계마다 다른 한 줄 지침을 준다.

| 단계 | 억결 지침 |
|---|---|
| SHADOW | 스포트라이트 관계와 계기를 고르고, 계기를 장면 초중반에 자리 잡게 한다. 등장 브리지는 이때 계획한다. |
| 인물 AIDE | 각 인물이 자기 결대로 반응하게 한다. 증오하는 인물이 갑자기 다정해지지 않게 하되, 카드에 선언된 결은 근거로 인정한다. |
| 세계관 AIDE | 계기와 등장 브리지가 현재 장소·시간·사회적 맥락에서 성립하는지 본다. |
| 억결 AIDE | 주 관계의 긴장이 약하면 보강하고, 판독과 제안을 남긴다. |
| 플롯 AIDE | 관계 긴장이 해소·결착으로 닫히지 않고 씨앗이 되는지, 등장이 결말용이 아닌지 본다. |

### 5.2 단계별 관계 검증 체인 (정확도)

자체 기억이 없으므로 판독의 정확도는 **여러 AIDE가 각자 자기 영역의 근거로 판독을 검증**해서 높인다. 판독을 처음 세우는 단계와 확정하는 단계는 하나씩만 두고, 나머지는 검증 메모만 남긴다. 여러 단계가 판독을 번갈아 고쳐 쓰면 오히려 흔들리기 때문이다.

| 단계 | 역할 | 검증하는 것 |
|---|---|---|
| 근거 패킷(코드) | **초기 판독** | 카드·정사·LIB·최근 장면을 결정적으로 모은다 |
| SHADOW | 계획 | 패킷으로 스포트라이트와 계기를 고른다. 중량 모드 분석에서는 `bond_check`도 낸다 |
| 인물 AIDE | 검증 | 인물이 **알 수 있는 것만으로** 반응하는가(B가 보지 못한 일로 질투하지 않음), 결이 성격·이력과 맞는가, 말투와 호칭이 정사 잠금과 맞는가 |
| 세계관 AIDE | 검증 | 누가 그 자리에 있었고 무엇을 목격할 수 있었는가, 시간 경과가 결 변화를 뒷받침하는가(미련에는 시간이 필요함), 사회적 제약 |
| 플롯 AIDE | 검증 | 결 변화에 장면 안의 **원인**이 있는가, 변화가 너무 이른가, 긴장이 씨앗으로 남는가 |
| 억결 AIDE | **확정** | 검증 메모를 모아 이번 턴 판독과 제안을 확정한다 |

억결 AIDE를 끈 경우에는 플롯 AIDE의 검증 메모를 반영한 SHADOW 판독을 최종으로 본다.

**검증 메모 형식** (각 AIDE의 출력 JSON `domain.bond_check`):

```
"bond_check": [{
  "card": "<id>",
  "verdict": "confirm | adjust | uncertain",
  "claim": "검증 대상 판독 문장",
  "reason": "자기 영역의 근거",
  "evidence": "canon | LIB | recent | draft"
}]
```

**정확도 규칙:**

- 모든 판독 항목은 근거 출처를 단다(canon / LIB / recent / card). 출처 없는 판독은 쓰지 않는다.
- 결의 **변화**는 장면 안의 구체적 원인이 근거에 있을 때만 인정한다. 원인이 애매하면 직전 판독(없으면 카드)을 유지한다.
- 근거끼리 부딪히면 섞지 않는다. 정사 잠금 > 최근 장면의 명시적 사건 > LIB > 카드 순으로 따르고, 판단이 안 되면 `uncertain`으로 남기고 단정하지 않는다(정사 잠금의 충돌 규칙과 같음).
- 모르는 것은 복구하지 않는다. LIB에도 최근 n턴에도 없는 과거는 어느 AIDE도 되살릴 수 없으므로, "근거 없음"으로 두고 지어내지 않는다. 검증 체인은 **틀린 단정을 막는 장치**이지 빠진 기억을 채우는 장치가 아니다.
- 직전 판독은 실행 중 메모리(`Runtime`)에만 두고, 판독이 턴마다 뒤집히지 않게 하는 참고로만 쓴다. 다시 시작하면 사라져도 된다.

**전달 경로 (현재 코드에서 필요한 변경):**

- 처음 문서에는 "경량 모드에서는 AIDE 분석이 원장에 기록되지 않는다"고 적었으나 틀렸다. 경량 결과도 `twoCallAnalysis`로 기록된다. 실제 빈틈은 두 가지였다: 패치 schema의 `domain`이 빈 닫힌 객체라 관계 출력을 받을 수 없었고, 원장 프롬프트는 앞 AIDE의 분석 내용을 의도적으로 빼고 단계 이름만 보여 준다. 그래서 `bond_check`·`bond_readings`·`bond_proposals`를 억결이 켜졌을 때만 schema 최상위 필드로 추가하고, 검증 메모는 실행 원장의 별도 칸(`ledger.forcedBondChecks`)으로 넘긴다.
- 원장 프롬프트는 `CORE_AIDE_STAGE_IDS`만 걸러 보여 준다. 그래서 지금 억결 단계의 기록은 뒤 단계에 보이지 않는다. 억결 단계와 `bond_check`가 보이게 고친다.
- 모델 호출은 늘리지 않는다. 검증 메모는 각 AIDE의 기존 호출 출력에 붙는다. 늘어나는 것은 출력 토큰 약간이다.

## 6. 작성 모드별 동작

| 모드 | 억지 등장 | 결 신호(생각·감정·말·몸) | 강제의 형태 |
|---|---|---|---|
| 소설 | 허용 | NPC와 페르소나 모두 | 작가 권한 안에서 최대. 작가가 명시적으로 남겨 둔 선택은 존중 |
| RP 페르소나 전용 | 허용 | **NPC만** | NPC가 페르소나에게 계기를 건네고, 그것이 다음 턴 씨앗이 된다 |
| RP 장면 연출 | 끔 | 입력에 적힌 행동의 연출 색깔만 | 입력에 카드 인물의 행동이 있을 때만 몸짓·어조를 결에 맞게 연출 |
| RP 문장화 | 끔 | 없음 | 억결 단계 건너뜀(호출 0회). GUI에 이유 표시 |

- RP에서 페르소나의 바람기, 작업 멘트, 속마음은 AI가 쓰지 않는다. 대신 NPC가 페르소나 설정에 있는 평판을 알고 반응하고, 유저 입력의 행동이 다른 관계로 파급된다(예: A에게 던진 추파를 B가 봄 → B의 질투가 보조 관계).
- 소설 모드에서 페르소나 쪽 결 신호를 쓰는 범위는 기존 소설 모드 계약("작가 지시에 맞으면 페르소나 행동 작성 가능")을 따른다.

## 7. 억지 등장 규칙

- 지정 인물이 이미 장면에 있으면 브리지를 만들지 않는다.
- 브리지는 SHADOW 계획 단계에서 장면 초중반에 둔다. 결말을 만드는 도착은 금지(`NEXT_TURN_SEED_RULES`).
- 관계별 쿨다운: 최근 턴 안에 이미 등장 브리지로 들어온 인물이면 간접 계기로 바꾸라고 지시한다. 판단은 모델이 최근 장면을 보고 하며, 저장하지 않는다(코드로 세는 쿨다운은 남은 판단).
- 세계관 AIDE가 성립하지 않는다고 판단하면, 등장 대신 연락·소문·물건 같은 간접 계기로 낮춘다.

## 8. 억결 AIDE 출력 (분석 JSON의 domain)

```
"domain": {
  "spotlight": { "primary": "<card id>", "secondary": "<card id or empty>" },
  "bond_readings": [{ "card": "<id>", "tones": [...], "stage": "...", "evidence": "LIB | recent | card" }],
  "occasion": "이번 턴의 계기",
  "appearance_bridge": "필요할 때만",
  "channel_cues": { "thought": "", "heart": "", "words": "", "body": "" },  // RP에서는 NPC 쪽만
  "ripple": "보조 관계로 번진 여파",
  "proposals": [{ "from": "", "to": "", "tones": [...], "why": "" }],
  "agency_check": "모드별 권한 확인"
}
```

`bond_readings`와 `proposals`는 GUI 표시와 제안 목록에만 쓰고, 저장된 기억이 되지 않는다.

## 10. 구현 단계

1. **안전 차단:** 캐스트 잠금 모드 분기, AIDE 순서 편입(플롯 앞), 단계 전용 모드 제거.
2. **관계 카드:** 설정 구조, 채팅별 저장, 기존 설정 이전, GUI 카드 목록(기존 컴포넌트 사용).
3. **근거 패킷:** 정사 잠금·LIB·최근 n턴에서 결정적으로 구성, 상한 적용.
4. **단계별 지침과 억결 AIDE 프롬프트:** 스포트라이트, 결별 계기, 모드별 권한, 출력 schema.
4-1. **관계 검증 체인:** 각 AIDE의 `bond_check` 출력, 경량·중량 모드 공통 전달 경로, 원장의 억결 표시, 정확도 규칙.
5. **판독·제안 표시:** 마지막 판독을 `Runtime`에 두고 GUI에 표시, 제안 받기/버리기.
6. **억지 등장 규칙:** 쿨다운과 간접 계기로의 강등.

각 단계는 회귀 테스트와 함께 들어간다. GUI는 기존 디자인 컴포넌트로 만들고 브라우저에서 확인한다.

## 11. 테스트 기준

- 문장화 모드에서 억결 호출이 0회이고, 장면 연출 모드에서 억지 등장 지시가 프롬프트에 없다.
- 순서 프리셋을 바꿔도 억결이 그 순서에 따라 실행되고, 기본값은 플롯 앞이다.
- RP에서 억결 프롬프트가 페르소나의 생각·감정 신호를 요구하지 않는다.
- LIB 근거가 없을 때 패킷이 "최근 장면 신호만"을 표시하고, LIB 근거가 있으면 그것이 먼저 실린다.
- 정사 잠금이 "형제"인 두 인물에게 연애 결 카드가 있어도, 관계 종류와 호칭은 바뀌지 않는다.
- 판독이 저장소에 쓰이지 않는다(pluginStorage 쓰기 0회).
- 제안은 받기 전에는 프롬프트의 강제 요소에 들어가지 않는다.
- 경량 모드에서도 인물 AIDE의 `bond_check`가 다음 AIDE 프롬프트에 실린다.
- 목격하지 않은 사건에 근거한 결(예: 보지 못한 장면 때문의 질투)을 인물 AIDE가 `adjust`로 잡는다.
- 원인 없는 결 변화는 확정되지 않고 직전 판독이 유지된다.
- 근거가 충돌하면 판독이 `uncertain`으로 남고 프롬프트가 단정하지 않는다.
- 기존 단일 대상 설정이 카드 1장으로 옮겨진다.

## 14. 확장 AIDE 틀 (2026-11-14)

억결은 첫 번째 **확장 AIDE**다. 인물·세계관·플롯은 핵심 AIDE로 남고, 그 밖의 선택형 AIDE는 모두 `EXTENSION_AIDE_DEFS` 한 곳에 선언한다. 상태 AIDE와 세계 동역학도 이 틀에 올린다.

| 선언 항목 | 뜻 | 억결의 값 |
|---|---|---|
| `placement` | 실행 위치. `before_plot`은 사용자 순서에서 플롯 AIDE 바로 앞 | `before_plot` |
| `isActive(settings)` | 켜짐 여부와 작성 모드 제한 | 켜짐 + 모드가 off가 아님 + RP 문장화가 아님 |
| `stageBlock(stage, recent, settings, ledger, phase)` | 모든 초안 단계에 붙는 지침 | 관계 블록(규칙·근거 패킷·검증 메모) |
| `jsonProperties(stage, settings)` | 켜졌을 때만 schema에 더하는 최상위 필드 | `bond_check`, `bond_readings`, `bond_proposals` |
| `recordOutput(ledger, stage, parsed, settings)` | 출력 수집. 저장소에는 쓰지 않음 | 원장의 검증 메모, 메모리의 판독·제안 |

공통 도우미: `withExtensionAideStages`(실행 순서), `activeExtensionAideStages`(사전 점검·로어·예산 목록), `extensionAideStageBlocks`(프롬프트), `withExtensionAideJsonProperties`(schema), `recordExtensionAideOutputs`(수집), `DRAFT_PIPELINE_STAGE_IDS`(초안 단계 목록). GUI 사다리도 같은 배치 규칙(`placeExtensionAideStages`)으로 그린다.

확장 AIDE는 아무것도 저장하지 않는다. 오래 남는 상태는 LIBRA 렌즈와 State가 기록하고, 확장 AIDE는 매 턴 그것을 읽어 계산한다. RP 모드에서 페르소나의 몸 상태(임신, 질병, 주기 결과)는 판정하거나 확정하지 않는다. NPC만 판정한다.

## 15. 남은 판단

- 관계 단계 이름과 수(낯섦 → 의식 → 긴장 → 표출 → 결착)는 초안이다.
- 쿨다운 기본값(3턴)과 최근 n턴 기본값은 실제 대화로 조정한다.
- NPC↔NPC 연결선을 처음부터 카드로 만들게 할지, 제안으로만 생기게 할지는 2단계 GUI 작업 때 정한다.
