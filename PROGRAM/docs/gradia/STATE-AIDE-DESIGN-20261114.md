# 상태 AIDE 설계

2026-11-14 작성. 대상: GRADIA 확장 AIDE `aide_body_state`(화면 이름 '상태 AIDE'). 상태: 설계, 구현 전.

인물의 몸 상태(건강 신호, 생체 주기, 부상, 질병, 임신·피임)를 추적하고 계산해, 인물이 지금 몸 상태에 맞게 반응하도록 한다. 목적은 인물의 생동감이다.

## 1. 확정된 결정 (2026-11-14, 사용자)

| 항목 | 결정 |
|---|---|
| 상태의 기록 주체 | LIBRA 렌즈(와 State). GRADIA는 매 턴 읽어서 계산만 하고 저장하지 않는다 |
| RP 모드의 페르소나 | 몸 상태를 판정하거나 확정하지 않는다. NPC만 판정한다 |
| 구현 틀 | 확장 AIDE 틀(`EXTENSION_AIDE_DEFS`) 위에 올린다 |
| 생식 판정(임신·피임) | 별도 토글, 기본 꺼짐. NSFW 설정과 연동하지 않는다 |
| LIBRA 렌즈 | "생체 주기·생식" 기본 렌즈를 이 작업에 포함한다 |
| 계산 표 | 코드 상수로 고정한다 |
| 이야기 시계 | GRADIA에는 두지 않는다. **LIBRA가 소유한다(B안)** |

## 2. 기존 설계에서 받는 제약

| 기존 설계 | 상태 AIDE에 주는 제약 |
|---|---|
| 자체 기억 은퇴 | 발병일, 주기 시작일, 판정 결과를 GRADIA가 저장하지 않는다 |
| LIBRA 렌즈 "몸 상태 · 건강 기록" | 인물별(`trackSubject`) 증상·부상·질병·치료·회복을 시점(`trackTime`)과 함께 기록한다. 시점은 이야기가 쓴 표현 그대로("사흘 전", "4월 2일")이고 원문 턴에 묶인다 |
| 렌즈는 비정본 참고 메모 | 정본 기억·최근 장면과 다르면 렌즈가 밀린다 |
| LIBRA State `sceneTime` | 장면 시간은 이야기가 쓴 표현(날짜·시각·"그날 밤")이다. 정규화된 달력이 아니다 |
| RP 계약 | 페르소나 쪽은 입력 그대로. 장면 연출 모드는 새 행동·새 전개 없음, 문장화 모드는 입력 렌더링만 |
| 다음 턴 씨앗 | 상태 변화로 장면을 닫지 않는다(예: 갑자기 쓰러져 장면 종료) |

## 3. 핵심 아이디어: 저장 없이 계산이 재현되게

상태 AIDE의 모든 판정은 **같은 근거면 언제 다시 계산해도 같은 답**이 나오게 만든다. 그래서 저장할 필요가 없다.

- **입력은 LIBRA 기록:** 사건(발병, 부상, 복약, 관계, 피임)은 LIBRA 렌즈 메모로 남아 있다. 메모는 고유 ID와 원문 인용 해시를 가진다.
- **계산은 결정적 코드:** 경과일, 주기 위상, 예상 회복일은 표와 산술로 계산한다. 모델이 숫자를 정하지 않는다.
- **확률 판정은 고정 시드:** 임신 같은 확률 사건은 `시드 = hash(채팅 키, 인물, 사건 메모 ID)`로 굴린다. 같은 사건이면 다시 생성해도, 다음 턴에 다시 계산해도 결과가 같다.
- **결과가 장면에 드러나면 LIBRA가 기록한다:** "세라가 열이 내렸다"가 응답에 나오면 LIBRA가 평소대로 회복을 기록하고, 다음 턴 계산은 그 기록을 따른다.

## 4. 시간: 이야기 달력

경과일 계산에는 "지금"과 "그때"가 같은 달력 위에 있어야 한다. 이야기가 날짜를 말해 주지 않으면 계산할 수 없다. 그래서 시간 근거를 신뢰도와 함께 다룬다.

| 신뢰도 | 근거 | 할 수 있는 것 |
|---|---|---|
| 확정 | 이야기가 쓴 절대 날짜(장면 시간, 렌즈 시점), 또는 채팅별 **이야기 달력** 설정 | 경과일, 위상, 예상일 계산 |
| 추정 | 최근 n턴 안의 상대 표현("다음 날", "사흘 뒤")을 이어 붙인 값 | 범위로만 계산("3~4일째") |
| 모름 | 시점 근거 없음 | 시간에 의존하는 판정을 하지 않는다. "며칠째인지 모름"으로 둔다 |

**이야기 달력을 GRADIA에 두지 않는 이유 (2026-11-14 검토):**

- 유저가 적은 날짜를 고정값으로만 두면 설정이지만 쓸모가 거의 없다. 날짜가 바뀔 때마다 유저가 고쳐야 한다.
- GRADIA가 "다음 날"을 보고 날짜를 스스로 넘기면, 그 순간 GRADIA가 이야기 상태를 쌓는 것이다. 은퇴한 자체 기억을 되살리는 구현이다.
- 지금 LIBRA에는 현재 장면 시간 라벨(`sceneTime`)만 있고, 누적 일수를 세는 곳은 어디에도 없다.

**대안:**

| 안 | 내용 | 장점 | 한계 |
|---|---|---|---|
| A. 시계 없음 | 이야기가 절대 날짜를 말할 때만 계산 | 변경 없음 | 날짜를 말하지 않는 이야기에서는 경과일 계산이 대부분 "모름" |
| B. LIBRA가 이야기 시계를 소유 | LIBRA가 턴을 기록할 때 이미 감지하는 시간 변화로 "이야기 n일째 · 시간대"를 누적하고, 렌즈 메모에 그 턴의 일차를 붙인다. 유저는 LIBRA에서 기준 날짜를 정할 수 있다 | 기억은 기억 플러그인에. GRADIA는 "사건 12일째, 지금 17일째"를 읽어 계산만 | LIBRA State·렌즈 변경. State 엔진은 tools/sdk 원본에서 생성되므로 원본 수정과 재동기화 필요 |
| C. 매 턴 전체 채팅 재계산 | GRADIA가 저장 없이 매 턴 채팅 처음부터 시간 변화 표현을 세어 일차를 복원 | 저장 없음 | 대사 속 "다음 날"도 세어 부정확, 긴 채팅에서 매 턴 비용 |

권장: **B**. 기억은 LIBRA가 갖고, GRADIA는 계산만 한다는 원칙에 맞는 유일한 자동 시계다.

## 5. 추적 대상과 계산

| 영역 | 근거(LIBRA) | 계산 | 출력 예 |
|---|---|---|---|
| 건강 신호 | 몸 상태 렌즈의 증상·컨디션 | 증상 묶음 → 활동 제약(피로, 통증 부위, 열) | "세라: 미열 2일째, 오래 서 있기 힘듦" |
| 부상 | 부상 기록과 정도(약함/중간/심함) | 정도별 회복 표 → 경과일 대비 단계(급성/회복/잔흔) | "준호: 왼팔 찰과상 5일째, 거의 아묾" |
| 질병 | 발병 기록, 진단, 복약 | 질병 유형별 기간 표 → 진행 단계, 예상 종료, 악화 신호 | "독감 4일째(보통 5~7일), 기침 남음" |
| 생체 주기 | 주기 렌즈(§8) 또는 상태 카드의 마지막 시작일·주기 길이 | 날짜 → 주기 일차·위상(월경/난포기/배란기/황체기) → 위상별 신호 | "세라: 26일째, 황체기 후반, 예민·복부 불편" |
| 임신 | 관계 사건 메모 + 주기 위상 + 피임 메모 | 위상별 수정 확률 × 피임 효과 → 고정 시드 판정 → 경과 주수별 신호 | NPC: "임신(판정 고정), 5주째: 아직 본인도 모름" |
| 피임 | 피임 수단 메모(종류, 사용 여부) | 수단별 실패율(전형적 사용 기준) | 임신 확률 계산에만 쓰임 |
| 복합 상태 | 위 결과 전체 | 겹치는 신호 정리(예: 미열 + 황체기 → 짜증↑, 활동↓) | 인물별 "지금 몸 상태 요약" 한 줄 |

**표는 현실 근사치이고 허구용이다.** 의학적 정확성을 주장하지 않는다. 표는 코드 상수로 두고, 범위로 계산한다(예: 감기 7~10일).

**임신 판정의 시점 규칙:**
- 판정은 사건이 있던 순간에 확정되지만, 인물이 아는 시점은 따로 계산한다(예: 생리 지연 → 의심 → 검사). 경과 주수에 맞지 않는 조기 자각을 막는다.
- 판정 결과는 **알 수 있는 인물에게만** 정보로 준다. 인물 AIDE의 "알 수 있는 것만 반응" 규칙과 같다.

## 6. 작성 모드별 동작

| 모드 | 페르소나 | NPC | 비고 |
|---|---|---|---|
| 소설 | 판정·서술 가능(작가 권한 안에서, 유보된 선택은 존중) | 판정·서술 | |
| RP 페르소나 전용 | **판정·확정 금지.** 입력에 적힌 상태만 사실로 다루고, 세계와 NPC가 그 상태에 반응 | 판정·서술 | 페르소나 관련 확률 사건은 계산 자체를 하지 않는다 |
| RP 장면 연출 | 판정 금지 | 새 판정 없음. 이미 기록된 상태로 **연출 색깔만**(아픈 인물의 몸짓·호흡) | 새 전개를 만들지 않는 모드라서 |
| RP 문장화 | 단계 건너뜀(호출 0회) | 단계 건너뜀 | |

RP에서 NPC의 임신처럼 페르소나와 함께한 사건에서 생기는 판정은, NPC의 상태로서 판정한다. 페르소나에게 무엇을 느끼거나 결정하라고 쓰지는 않는다.

## 7. 파이프라인 배치와 역할

확장 AIDE 틀의 선언:

| 항목 | 값 |
|---|---|
| `placement` | `before_plot`. 같은 위치의 확장이 여럿이면 **상태 → 억결 → 플롯** 순서(몸 상태가 관계 긴장보다 먼저 정해져야 하므로). 틀에 확장 간 순서 값(`rank`)을 추가한다 |
| `isActive` | 켜짐 + 모드가 off가 아님 + RP 문장화가 아님 |
| `stageBlock` | 모든 초안 단계에 **상태 패킷**(§7.1)과 단계별 지침 |
| `jsonProperties` | 검증 단계: `state_check`. 상태 AIDE: `state_readings`, `state_events` |
| `recordOutput` | 검증 메모는 실행 원장(`ledger.bodyStateChecks`), 판독은 GUI용 메모리. 저장 없음 |

### 7.1 상태 패킷 (모델 호출 없음)

코드가 매 턴 만든다. 인물마다:
- 근거 줄(정본·LIB 렌즈·최근 장면), 각 줄의 시점과 시간 신뢰도
- 계산 결과(경과일·위상·예상일·판정), 각 결과의 신뢰도
- RP 페르소나는 "입력에 적힌 상태만, 판정 없음" 표시

### 7.2 단계별 지침과 검증

| 단계 | 상태 관련 역할 |
|---|---|
| SHADOW | 패킷의 상태를 장면 계획에 반영(아픈 인물의 동선·대사량) |
| 인물 AIDE | 반응이 몸 상태와 맞는가, 인물이 **알 수 있는** 상태만 의식하는가 |
| 세계관 AIDE | 몸 상태가 허락하는 행동인가(부상으로 못 뛰는데 뛰지 않는가), 시간 경과가 회복·진행과 맞는가 |
| 상태 AIDE | 검증 메모를 모아 판독 확정, 새 사건(발병·복약·관계·피임)을 `state_events`로 표시, 몸 상태 묘사가 약하거나 틀린 곳만 패치 |
| 플롯 AIDE | 상태 변화로 장면을 닫지 않는가, 질병·부상이 한 턴에 해결되지 않는가 |

### 7.2.1 정확도 규칙

- 모든 상태 주장에 근거 출처와 시간 신뢰도를 단다. 시간이 "모름"이면 경과일에 의존하는 서술을 하지 않는다.
- 숫자(경과일, 확률, 주수)는 패킷의 계산값만 쓴다. 모델이 새 숫자를 만들지 않는다.
- 기록에 없는 병명·원인을 만들지 않는다(LIBRA 렌즈의 제외 규칙과 같다).
- 회복·완치는 근거가 있거나 계산상 기간이 지났을 때만. 계산상 지났어도 이야기에 회복 근거가 없으면 "회복 중일 가능성"으로 둔다.

## 9. 설정과 GUI

확장 AIDE 패널 구조(실행 설정 / 이 채팅의 데이터 / AI 제안)를 따른다.

- **실행 설정:** 사용, AI 프리셋, 참고 상한, 대기 시간, 영역별 켜기(건강·부상·질병 / 생체 주기 / 생식 판정)
- **이 채팅의 데이터:**
  - 이야기 달력(현재 날짜, 선택)
  - 상태 카드(인물별, 선택): 주기 길이, 마지막 시작일, 체질(예: 감기에 약함), 피임 기본값. 이야기가 말하지 않는 기본값을 유저가 정해 두는 용도
  - 이번 턴 판독(메모리에만, 읽기 전용): 인물별 몸 상태 요약과 신뢰도
- **AI 제안:** 이야기에서 발견한 기본값(예: "세라 주기 30일로 보임")을 카드로 받기

## 10. 이야기 시계 (LIBRA, 2026-11-14 확정)

**현재 LIBRA에 있는 것:** `world.sceneTime`은 이야기 시계가 아니라 **장소 엔티티의 "장면 시각" 필드**다(위치 필드처럼 다뤄진다). `detectLibraSceneBoundary`의 `time_change`는 현재 입력 한 줄에 대한 감지일 뿐 누적하지 않는다. 즉 시계는 새로 만든다.

**설계:**

| 부분 | 내용 |
|---|---|
| 시간 진행 추출 | LIBRA가 턴 쌍을 읽는 기존 추출 호출에 `time_advance` 항목을 더한다: none / 같은 날 이후(시간대) / +N일 / 절대 날짜. 모델 호출 수는 늘지 않는다 |
| 누적 | 결정적 코드가 쌍 순서대로 더해 **쌍별 일차**(이야기 n일째 · 시간대, 절대 날짜를 알면 날짜)를 만든다. 스코프 단위 시계 기록으로 저장한다 |
| 기준 날짜 | 유저가 LIBRA에서 채팅별 기준 날짜를 정할 수 있다(선택). 없으면 "1일째"부터 센다 |
| 렌즈 메모 일차 | 렌즈 메모는 원문 턴(`t{n}-u/a`)에 묶여 있으므로, 그 턴의 쌍 일차를 붙여 읽기 결과에 함께 싣는다 |
| GRADIA 전달 | LIB 읽기 결과에 "현재 n일째"와 메모별 일차가 실린다. GRADIA는 읽어서 경과일만 계산한다 |
| 저장 모드 | LIBRA는 플러그인 모드와 서버 모드가 모두 살아 있다. 시계 기록은 두 모드에서 같은 경로로 저장·읽기돼야 한다 |
| 기존 채팅 | 시계가 없던 쌍은 "일차 모름"으로 둔다. 재분석으로 채울 수 있게 한다(선택) |
| 정정 | 유저가 LIBRA GUI에서 특정 쌍의 일차·날짜를 고칠 수 있다. 이후 쌍은 다시 누적된다 |

## 11. 구현 순서

| 단계 | 플러그인 | 내용 | 선행 |
|---|---|---|---|
| 1 | LIBRA | 이야기 시계: `time_advance` 추출, 누적, 스코프 시계 기록(두 저장 모드), GUI 표시·기준 날짜·정정 | — |
| 2 | LIBRA | 렌즈 메모 일차 부착, LIB 읽기 결과에 일차 포함 | 1 |
| 3 | LIBRA | "생체 주기·생식" 기본 렌즈 | — |
| 4 | GRADIA | 확장 틀에 `rank` 추가, 상태 AIDE 등록·모드 분기·별도 생식 토글 | — |
| 5 | GRADIA | 계산 표(코드 상수), 시간 신뢰도, 상태 패킷, 단계별 지침과 `state_check` 체인 | 4 (시간 계산은 2) |
| 6 | GRADIA | 고정 시드 판정(임신), 자각 시점, GUI(상태 카드·판독·제안) | 5 |
| 7 | 공통 | 릴리스 처리(버전·provenance·manifest·checksum) | 전부 |

1~3(LIBRA)과 4~5(GRADIA)는 서로 다른 파일이라 나란히 진행할 수 있다. GRADIA의 시간 계산만 2단계 이후에 연결한다.

## 12. 구현 단계(초안)

1. 확장 틀에 확장 간 순서(`rank`) 추가, 상태 AIDE 등록(모드 분기 포함)
2. 상태 카드와 이야기 달력 설정(채팅별), GUI
3. 시간 해석: 절대 날짜·상대 표현 → 신뢰도 있는 경과일
4. 계산 표: 부상·질병 기간, 주기 위상, 수정 확률, 피임 실패율
5. 상태 패킷과 단계별 지침, `state_check` 체인
6. 고정 시드 판정(임신)과 자각 시점 계산
7. (LIBRA) 생체 주기·생식 렌즈

## 13. 테스트 기준

- RP 페르소나 전용에서 페르소나에 대한 판정·확률 계산이 없다. NPC 판정은 있다.
- 장면 연출 모드에서 새 판정이 없고, 문장화 모드에서 호출이 0회다.
- 같은 사건 메모로 두 번 계산하면 같은 판정이 나온다. 메모가 바뀌면 다시 계산된다.
- 시간 근거가 없으면 경과일 서술 지시가 없다.
- 상태 → 억결 → 플롯 순서로 실행된다.
- pluginStorage에 상태 관련 키가 생기지 않는다.

## 14. 남은 판단

- 관계 단계와 마찬가지로, 계산 표의 구체적 값(질병별 기간, 위상별 수정 확률, 피임 수단별 실패율)은 구현 때 표로 제시하고 확인받는다.
- 이야기 시계의 `time_advance` 추출이 실제 대화에서 얼마나 정확한지는 LIBRA 구현 후 실제 채팅으로 측정한다.
