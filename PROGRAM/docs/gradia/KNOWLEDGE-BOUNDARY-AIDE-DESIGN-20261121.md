# 지식 경계 AIDE 설계 (초안)

2026-11-21 작성. 대상: GRADIA 확장 AIDE `aide_knowledge_boundary`(화면 이름 '지식 경계'). 상태: 설계 초안, §8의 결정 대기.

**인물이 알 수 없는 것을 아는 듯 말하지 않게 하는 장치다**(사용자, 2026-11-21). 비밀을 맡고 누설을 막는다. 인물 AIDE의 하위 AIDE로 둔다(사용자 지시). 관계 시뮬레이터·정사·상태 AIDE와 같은 자리다.

## 1. 계기 (실측)

채팅 ffeb99ef_19:0, T33 응답.

| 대사·서술 | 소연이 알 수 있었나 | 근거 |
|---|---|---|
| "하연과도 무슨 일이 있었다는 걸 알고" | 알 수 있다 | T33 유저 입력: "어제 푸딩이 하연과 함께 있는 걸 보았기 때문에" |
| "언니지." (카톡 진동 뒤) | 추측으로 가능 | 화면에 보이는 단서(푸딩의 얼굴). 추측으로 말하는 것은 경계 안 |
| "복도에서 언니한테 진심이라고 했어" 이후의 반응 | 알 수 있다 | 같은 장면에서 푸딩이 직접 말함 |
| "어젯밤에도 그랬어. 계단에서 기다리면서 발 시린 것도 모르고 있었지" | **알 수 없다** | T30: 하연은 불 꺼진 복도 계단참에 앉아 기다렸고, 소연은 문이 닫힌 방 안에 있었다. 그 뒤 누가 소연에게 말한 장면도 없다 |

현재 인물 AIDE의 일반 지침("knowledge they cannot possess", "knowledge paths")은 있다. 하지만 인물별로 무엇을 보고 들었는지 대조할 근거가 없어서 이런 누설을 잡지 못했다.

## 2. 하는 일

1. **초안 전 (코드):** 장면에 있는 인물마다 "이 인물이 아는 것 / 모르는 것"을 짧은 지침으로 SHADOW와 이후 단계에 넘긴다. 근거는 §3. 모르는 것은 "말하지 않는다, 추측이면 추측으로만, 묻는 것은 된다"로 넘긴다.
2. **초안 후 (인물 AIDE 호출 안):** 초안의 대사·속마음·그 인물 시점 서술이 사실을 쓸 때마다 그 인물의 **지식 경로**를 확인한다.
   - 경로: 직접 봄·들음(그 장면에 있었음) / 화면 안에서 들음(누가 말해 줌) / 공개된 사실 / 화면에 보이는 단서로 한 추측
   - 경로가 없으면 누설이다. 고치는 방법은 셋 중 하나: 지운다, 추측·질문으로 바꾼다, 그 인물이 모르는 상태를 행동으로 보인다.
3. **보고:** 무엇을 누설로 보고 어떻게 고쳤는지 인물 AIDE 출력에 남기고, 코드가 고친 문장이 실제 초안에 있는지 확인한다. GUI '이번 턴 판독'에 보인다.

## 3. 근거 (읽기 우선순위)

1. 관계 정사 잠금 사실, 현재 입력(그 턴에만). 유저 입력이 "소연은 ~를 알고 있었다"고 정하면 그대로 따른다.
2. LIBRA 비밀 렌즈(누가 무엇을 아는가), LIBRA State 인물 `knowledge`.
3. 최근 대화 원문: 장면마다 누가 있었는지(문이 닫혔는지, 자리를 떴는지, 잠들었는지). 인물 AIDE가 이미 받는 최근 턴 창 안에서 읽는다.
4. 관계 시뮬레이터의 공개 범위·`knownBy`(켜져 있을 때).

근거가 없으면 "모른다"로 둔다. 지식은 지어내지 않는다.

## 4. 작성 모드별 동작

| 모드 | 동작 |
|---|---|
| 소설 | 모든 인물에 적용 |
| RP 페르소나 전용 | NPC에만 적용. 페르소나의 지식·말은 유저의 것이므로 고치지 않는다. NPC가 페르소나만 아는 것을 아는 듯 말하는 것은 누설로 본다 |
| RP 장면 연출 | 유저가 정한 장면은 그대로 두고, AI가 쓴 NPC 대사만 본다 |
| RP 문장화 | 실행하지 않는다 |

## 5. 실행 위치

- 확장 AIDE `aide_knowledge_boundary`, 인물 AIDE 호스트. 순서는 상태(10)와 정사(15) 사이 `rank` 12를 제안한다. 누설을 먼저 고쳐 두면 뒤의 하위 AIDE가 고친 대사를 기준으로 본다.
- 별도 모델 호출은 없다. 인물 AIDE 호출 안의 의무(duty)와 출력 스키마로 들어간다(관계 시뮬레이터와 같은 방식).
- 설정·프리셋·프롬프트 교체/추가, 단계 표, 파이프라인 노드와 칩, 실행 결과 탭은 기존 확장 AIDE와 같은 틀을 쓴다.

## 6. 출력 (인물 AIDE 안)

```
"knowledge_boundary": {
  "leaks": [{ "character", "draft_quote", "fact", "why_unknown", "evidence_quote", "repair": "remove|guess|ask|show_unknowing", "replacement" }],
  "kept_inferences": [{ "character", "draft_quote", "visible_cue" }]
}
```

- `draft_quote`는 초안에 그대로 있어야 하고, `evidence_quote`는 최근 원문·LIBRA 블록에 그대로 있어야 한다. 코드가 둘 다 확인하고, 없으면 그 항목은 버린다(지어낸 누설 판정을 막는다).
- 고친 문장은 인물 AIDE의 기존 초안 수정 경로로 들어간다.

## 7. 테스트 기준

- §1 장면 재현: 계단 장면에 없던 인물이 그 장면의 사실을 말하면 누설로 잡히고 고쳐진다.
- 같은 장면에서 화면 안에서 들은 사실, 공개 사실, 보이는 단서로 한 추측은 고치지 않는다.
- 유저 입력이 "X는 알고 있었다"고 정한 사실은 누설로 보지 않는다.
- RP 페르소나 전용에서 페르소나의 대사는 고치지 않는다.
- 초안에 없는 `draft_quote`, 근거에 없는 `evidence_quote`는 버려진다.
- AIDE가 꺼져 있으면 프롬프트·출력·GUI에 흔적이 없다.

## 8. 결정이 필요한 것

| 항목 | 선택지 | 제안 |
|---|---|---|
| 기본값 | 켜짐 / 꺼짐 | 꺼짐(다른 확장 AIDE와 같음). 켜면 인물 AIDE 프롬프트가 늘어난다 |
| 저장 | 저장 안 함(LIBRA와 최근 원문만 읽음) / GRADIA가 "누가 언제 무엇을 알게 됐는지" 원장을 가짐 | 저장 안 함. 최근 턴 창을 넘는 오래된 지식은 LIBRA 비밀 렌즈가 맡는다 |
| 고치는 강도 | 초안을 직접 고침 / 플롯 AIDE에 지적만 넘김 | 직접 고침(지우기·추측·질문·모르는 행동) |
| 추측 허용 | 화면에 보이는 단서로 한 추측은 허용 / 추측도 막음 | 허용하되 추측으로만(단정 금지) |
