# HAYAKU 3.0.102 — 원문 수정과 누락 복구의 보류 처리

- 정확한 턴 대조에서 누락 사실은 유지하며 recoveryExecutable과 recoveryBlockedReason을 별도로 제공한다. 승인 저널 오류가 있으면 복구 가능 수·실행 대상은 0이며, 선택 UI는 보류 사유를 표시한다.
- 승인 검사에서 저널 오류를 먼저 확인하여 저장 실패를 채팅 범위 조회 실패로 오인하지 않는다. 원래 저널 오류 코드를 유지한다.
- 선택 복구는 대상 검사 전에 승인 상태를 확인한다. 승인·원문 변경 중단은 suspended로 집계하고 실패 수에서 제외한다. 작업창은 복구 보류 상태로 종료된다.
- 실행 중 승인 문제가 발생하면 복구 실행권을 suspended로 해제하여 실패 횟수와 재시도 지연을 추가하지 않는다. 직접 재생성 API의 기존 예외 계약과 쓰기 승인 제한은 유지한다.

검증: hayaku_recovery_consent_block_test.cjs는 정상 T1·누락 T2를 가진 가상 호스트에서 저널 저장 실패를 주입한다. 누락 유지와 실행 차단, 반복 검사 오류 일관성, 선택 복구 보류·실패 0·모델 호출 0, 실행권 해제 후 repairAttempts 0·nextRepairAt 0을 확인했다. 기존 관련 테스트 13개와 hayaku_journal_error_coverage_test.cjs도 통과했다.

실제 RisuAI GUI 검증과 사용자 저장 장치의 저널 실패 원인 해결은 포함하지 않는다. 과거 실패 횟수나 사용자 저장 데이터를 일괄 초기화하지 않는다.
