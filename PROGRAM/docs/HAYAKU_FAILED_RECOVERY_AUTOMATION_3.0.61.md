# HAYAKU 3.0.61 — 실패 복구 자동 처리

실패 복구 화면에서 사용자가 매번 재분석·채택 버튼을 누르던 작업을 자동 처리합니다. 기본값은 **자동 검증 + 같은 실패 건당 AI 재분석 최대 1회**입니다. 추가 AI 호출에는 RisuAI에 설정한 Provider 비용이 발생할 수 있습니다.

## 사용 방법

기존 HAYAKU를 3.0.61 파일로 업데이트하고 다시 로드합니다. `설정 → 복구·안전 → 실패 복구 자동 처리`에서 다음 중 하나를 선택할 수 있습니다.

- 자동 검증 + AI 재분석 1회: 기본값. 기존 결과를 먼저 검증하고 필요한 경우에만 AI를 호출합니다.
- 자동 검증만: 추가 AI 호출 없이 저장된 결과 검증과 저장 복구를 시도합니다.
- 끄기: 기존 수동 검토·수정·채택 기능을 사용합니다.

이 설정은 afterRequest 자동 복구, 백그라운드 누락 복구 확인 설정과 별개입니다. 실패 기록이 이미 있는 건은 이 설정에 따라 처리하며 건별 확인창을 반복해서 띄우지 않습니다. 아직 실패 기록이 없는 누락 턴의 기존 확인 흐름은 유지됩니다.

## 자동 처리 순서

1. 현재 채팅의 미해결 실패 이력을 같은 문제 단위로 묶습니다. 새 실패 생성 또는 플러그인 시작 후 처리를 예약하고, 대기 항목은 약 30초 간격으로 확인합니다. 한 번에 최대 2건을 처리합니다.
2. 보존된 결과와 현재 원문·채팅·턴의 일치 여부를 확인합니다. 불완전하게 저장된 실패 자료는 남아 있는 자료로 저장을 복구할 수 있는지 확인합니다.
3. 기존 모델 응답의 실제 envelope를 다시 읽고 형식·인용 근거·내용 누락을 검증합니다. 통과하면 추가 AI 호출 없이 저장합니다. 인용 근거나 사용자 승인을 만들어 넣지 않습니다.
4. 재분석이 필요하고 허용된 경우, 호출 한도를 먼저 저장하고 물리 재조회로 확인한 뒤 AI를 최대 1회 호출합니다. 이 자동 호출에는 별도의 형식 교정 추가 호출 설정을 더하지 않습니다.
5. 결과가 검증을 통과하면 저장하고 처리 완료로 표시합니다. 실패 응답, 원문, 이전 후보와 처리 이력은 보존합니다.

완료한 항목은 더 이상 미해결 개수에 포함하지 않습니다. 실패 상세 화면에서 자동 처리 상태와 재분석 한도 사용 여부를 확인할 수 있습니다. 보고된 한도 사용은 호출 전에 영속 예약한 횟수입니다. 호출 중 종료되어 실제 완료 여부를 확인할 수 없는 경우에도 같은 건을 다시 자동 호출하지 않습니다. 물리 호출 정보는 작업·디버그 기록에서 확인합니다.

## 제한과 보존

- 재시작하거나 수정 이력이 생겨도 같은 실패 건의 AI 한도는 초기화되지 않습니다. 자동 처리 원장의 해시와 카운터도 검증합니다.
- 로컬 확인·저장 시도도 한 건당 최대 3회로 제한합니다. 해결할 수 없는 항목은 수동 검토 대상으로 남습니다.
- 원문 변경·다른 채팅·근거 불일치·모델 거절·저장 확인 실패를 승인으로 간주하지 않습니다.
- 수동 복구·콜드스타트와 자동 처리를 중복 실행하지 않습니다. 자동 모드를 끄거나 채팅이 바뀐 뒤 도착한 결과에도 현재 상태와 저장 전 검증을 적용합니다.
- 콜드스타트는 실패한 구간을 복구합니다. 모든 구간이 이미 준비된 경우에는 추가 호출 없이 전체 반영을 진행할 수 있습니다. 아직 분석하지 않은 구간까지 새 AI 호출로 이어가지는 않으며, 이 경우 **구간 저장 완료 · 전체 반영 대기**로 구분합니다.
- 기존 pluginStorage나 실패 자료를 삭제할 필요가 없습니다. 실패 기록을 수동 삭제해도 별도 자동 처리 한도 기록을 지워 비용 한도를 초기화하지 않습니다.

## 검증 범위

격리 호스트·모의 Provider로 자동 재분석 저장, 기존 후보의 무호출 저장, 재시작 후 한도 유지, 원문·채팅 변경, 저장 확인 실패, 손상된 한도 기록, 중복 실행, 실제 타이머 실행, 콜드스타트 처리를 시험했습니다. 브라우저에서는 실제 설정 컨트롤을 저장하고 버튼 클릭 없이 복구가 완료되어 화면에 반영되는 것을 데스크톱·모바일 크기로 확인했습니다. 실제 사용자 RisuAI/Provider 연결 시험은 포함하지 않습니다.
