# LIBRA 빠른 연결과 번거로움 점검 (2026-10-16)

## 점검 결과

이미 기준을 만족하는 부분:

- 새 채팅은 서버 없이 바로 저장된다.
- 5턴마다 자동으로 기억을 만들고, 실패하면 자동으로 재시도한다.
- 생성 AI는 기본값이 RisuAI 보조 모델이라 별도 설정 없이 동작한다.
- 대화 중에 스스로 뜨는 창이 없다.

사용자를 번거롭게 하는 부분:

| 우선순위 | 항목 | 이번 처리 |
| --- | --- | --- |
| 1 | 임베딩 기본값이 키 없는 Voyage AI다. 벡터 검색이 꺼진 상태인데 화면에는 "voyage-4-lite · Voyage AI"로 정상처럼 보인다. 키 입력칸은 접힌 상세 설정 안에 있다. | **해결** |
| 2 | 생성 AI를 직접 연결하려면 제공자·모델·키를 따로 입력하고 연결 테스트를 따로 눌러야 한다. | **해결** |
| 3 | 기존 채팅에 설치하면 지난 대화는 기억되지 않는다. 안내는 첫 기억이 생기면 사라진다. 수동 콜드스타트는 비용 확인 없이 실행된다. | **해결** (알림 + 확인 후 실행) |
| 4 | 자동 재시도 5회를 넘긴 실패 구간은 설정 창 안에서만 보인다. | **해결** (채팅 알림 버튼) |
| 5 | 업그레이드 사용자의 "이전 기억 지침 확인" 대기가 기억 생성 전체를 멈추는데, 화면에는 "기억 생성 실패"만 보인다. | **해결** |
| 6 | 효과 없는 설정이 남아 있다: `story_arc_preset`, `*_ito_preset` 3개. | **정리** |

키는 플러그인마다 따로 유지한다(사용자 결정). 리브라와 플래시백은 각자 키를 저장한다.

## 빠른 연결

빠른 연결은 처음 설정할 때 팝업으로 뜬다.

- LIBRA 창을 처음 열 때, 임베딩을 쓸 수 없는 상태면 "LIBRA 시작하기" 팝업이 한 번 뜬다.
- "나중에 하기"를 누르거나 연결을 마치면 다시 뜨지 않는다. 기록은 호스트의 장치 저장소(`getLocalPluginStorage` / `safeLocalStorage`) `libra.firstSetupSeen.v1`에 남는다. 전역 `localStorage`가 없어도 재시작 후 유지된다.
- 임베딩이 이미 정상이면 팝업 없이 지나간다.
- 알림 버튼이 다른 화면을 여는 중에는 뜨지 않는다.
- "AI 연결"과 "임베딩 연결" 화면 맨 위에는 현재 상태 두 줄과 "빠른 연결 열기…" 버튼만 있는 작은 카드가 남는다. 같은 팝업을 다시 열 수 있다.

팝업에서 하는 일:

1. **API 키 한 칸.** 키 앞부분으로 제공자를 알아낸다.

   | 키 앞부분 | 제공자 | 생성 AI | 임베딩 |
   | --- | --- | --- | --- |
   | `sk-ant-` | Claude | ○ | |
   | `sk-or-` | OpenRouter | ○ | |
   | `AIza` | Gemini | ○ | ○ |
   | `sk-proj-` 등 `sk-` | OpenAI | ○ | ○ |
   | `sk-` + 32자리 16진수 | DeepSeek | ○ | |
   | `pa-` | Voyage | | ○ |
   | `jina_` | Jina | | ○ |
   | `csk-` | Cerebras | ○ | |
   | `fw_` | Fireworks | ○ | |

   자동 감지가 틀리거나 형식을 모르는 키면 "제공자"에서 직접 고른다.
2. **추천 모델 자동 선택.** 제공자의 모델 목록을 받아 기억 분석에 맞는 빠르고 저렴한 계열의 최신 버전을 고른다. 목록 조회는 토큰 비용이 없고, 그 자체로 키 확인도 된다.
   - OpenAI는 `gpt-*-mini`, Claude는 haiku, Gemini는 flash, DeepSeek는 `deepseek-chat`을 고른다.
   - 미리보기, 오디오, 이미지 계열은 제외한다.
   - 고를 수 없으면 짐작하지 않고 모델 이름을 입력해 달라고 한다. 모델 칸에 직접 입력해도 된다.
   - 임베딩은 제공자 기본 모델을 쓴다. OpenAI는 `text-embedding-3-small`, Gemini는 `gemini-embedding-001`, Voyage는 `voyage-4-lite`.
3. **시험 후 저장.** 생성 AI는 짧은 시험 호출 1회, 임베딩은 연결 시험(다국어 확인 포함)을 한다. 요청한 항목이 모두 성공해야 저장한다. 시험 하나라도 실패하면 설정을 바꾸지 않고 이유를 보여 준다. 저장은 생성 프리셋·Librarian 연결·임베딩·키를 하나의 설정 트랜잭션으로 처리하며, 저장/읽기 검증 실패 시 기존 값을 복원한다. 복원도 실패한 경우에는 이를 오류로 알린다.
   - 생성 AI는 새 프리셋 "OpenAI 빠른 연결" 같은 이름으로 만들고 전역 기본 연결과 실제 Librarian 전용 연결로 함께 지정한다. 기존 Librarian 지정이 남아 이전 모델을 호출하지 않도록 한다.
   - "기억 분석 AI로 사용"을 끄면 기존 기억 분석 연결을 유지한다.
4. **키 처리.** 저장 후 입력칸을 비우고 키를 다시 표시하지 않는다. 키는 기존 키 저장 경로를 그대로 쓰므로 백업에 포함되지 않는다.

## 상태 표시

- 빠른 연결 카드는 "기억 분석 AI"와 "임베딩"의 실제 상태를 보여 준다.
- 임베딩이 쓸 수 없는 상태면 "설정 안 됨 · 키워드 검색만 사용 (API Key)"와 "키워드 검색만" 배지를 보여 준다.
- 기억 화면의 모델 요약도 "임베딩 미설정 · 키워드 검색만 사용 중 · 빠른 연결로 키 하나만 넣으면 됩니다"로 바꿨다. 이때 버튼 이름은 "빠른 연결"이다.

## 확인 범위

- `tests/libra_quick_connect_test.cjs`: 키 감지, 직접 선택, 추천 모델(날짜 붙은 스냅샷보다 별칭 우선, 미리보기 제외), 화면 연결과 첫 설정 팝업 연결, 시험 후 저장 순서.
- `tests/libra_quick_connect_flow_test.cjs`(jsdom, 제공자 모의):
  - 양식과 정직한 상태 표시, 설정 화면의 작은 카드.
  - OpenAI 키 하나로 생성 AI와 임베딩 동시 설정.
  - 임베딩 시험 실패 시 아무것도 저장하지 않음.
  - Voyage 키는 임베딩만 설정.
  - 모델을 못 고르면 입력 요청, 알 수 없는 키 처리.
  - 첫 설정 팝업이 한 번만 뜨는지, 설정돼 있으면 안 뜨는지, 알림 버튼이 화면을 여는 중에는 안 뜨는지.
- 실제 RisuAI와 실제 제공자 키로는 확인하지 않았다.

## 채팅 알림 버튼 (3·4·5번)

하야쿠와 같은 방식이다. 채팅 입력창 옆(`location: 'chat'`)에 버튼 하나를 둔다. 사용자가 할 일이 있을 때만 생기고, 원인이 사라지면 지운다. 버튼 자체는 모델을 호출하지 않는다.

아이콘만 표시하는 호스트에서도 LIBRA는 파란색 `L`, HAYAKU는 주황색 `H`로 구분한다. 작은 `!`·시계·`i` 배지가 상태를 표시한다. 전체 플러그인 이름과 구체적인 알림 사유는 버튼 설명에 유지한다. 등록·삭제 ID가 달라 한 플러그인의 상태 변경이나 종료가 다른 버튼을 지우지 않는다.

| 순위 | 표시 | 조건 | 누르면 |
| --- | --- | --- | --- |
| 1 | ⚠️ LIBRA · 기억 지침 확인 필요 | 업그레이드 후 이전 사용자 기억 지침 검토 대기로 자동 기억 생성이 멈춤 | LIBRA 창 위에 검토 패널(가져오기 / 원본만 보존)을 팝업으로 연다 |
| 2 | ⚠️ LIBRA · 기억 실패 N구간 | 실패 상태인 5턴 구간이 있음 | 구간 선택 창을 "실패 구간 새 분석"으로 열고 실패 구간을 모두 선택해 둔다. 선택 수와 예상 호출 수를 보고 실행한다 |
| 3 | 🕘 LIBRA · 지난 대화 N구간 기억 만들기 | 기억이 없는 완성 구간이 있음. 최신 구간도 포함한다. 같은 채팅·현재 예약 번호의 자동 분석이 실제 대기/실행 중인 대상 구간만 잠시 제외한다 | 구간 선택 창을 "누락 구간 생성"으로 열고 해당 구간을 모두 선택해 둔다. 확인한 뒤에만 실행한다 |

- 작업이 진행 중이면 버튼을 띄우지 않는다. 기억 기능이 꺼져 있어도 띄우지 않는다.
- 갱신 시점: 턴 출력 3초 뒤, 채팅 전환, 기억 작업 상태 변화. 채팅 전환과 작업 상태는 10초마다 채팅·캐릭터 번호 두 개와 메모리 안의 작업 상태만 읽어 확인한다.
- 수동 콜드스타트에도 비용 확인을 넣었다. "수동 콜드스타트"와 빈 기억 화면의 "지난 대화 기억 만들기…" 버튼은 먼저 대상 구간 수와 예상 호출 수(구간당 정상 생성 1회)를 보여 주고 확인을 받는다. 만들 구간이 없으면 아무것도 실행하지 않는다.
- 업그레이드 검토 오류는 이제 "기억 생성 실패" 대신 "이전 기억 지침 확인 필요"로 보인다. 설명에 해결 위치도 함께 나온다.

## 효과 없는 설정 정리 (6번)

- `story_arc_preset`, `character_ito_preset`, `world_ito_preset`, `plot_ito_preset`의 설명을 "Retired and ignored; kept only so an old saved value is not lost"로 바꿨다. RisuAI 설정 목록에서 무시해도 된다는 것이 바로 보인다.
- AI 연결 화면의 "고아 AI 연결" 경고가 퇴역한 단계(Ariadne, 인물·세계·플롯 ito)에 남은 연결 이름까지 세던 것을 고쳤다.
- `ariadne_preset`은 업그레이드 사용자의 Librarian 연결 이전에 쓰이므로 그대로 둔다.

## 확인 범위 (3~6번)

- `tests/libra_zero_touch_attention_test.cjs`:
  - 우선순위와 최근 구간 제외.
  - 작업 중이거나 기억 기능이 꺼져 있으면 버튼을 띄우지 않음.
  - chat 위치 등록, 같은 상태에서 다시 등록하지 않음.
  - 누르면 구간 선택 창만 열리고 아무것도 실행되지 않음.
  - 실패 구간, 해결 시 버튼 제거, 업그레이드 검토 팝업, 종료 시 정리.
  - 콜드스타트 확인: 취소하면 실행하지 않음, 개수와 호출 수 표시, 만들 구간이 없으면 실행하지 않음.
  - 분류 문구와 설정 정리.
