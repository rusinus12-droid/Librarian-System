# LIBRA 빠른 연결과 번거로움 점검 (2026-10-16)

## 점검 결과

이미 기준을 만족하는 부분:

- 새 채팅은 서버 없이 바로 저장된다.
- 5턴마다 자동으로 기억을 만들고, 실패하면 자동으로 재시도한다.
- 생성 AI는 기본값이 RisuAI 보조 모델이라 별도 설정 없이 동작한다.
- 대화 중에 스스로 뜨는 창이 없다.

사용자를 번거롭게 하는 부분:

| 우선순위 | 항목 | 이번 처리 |
| --- | --- | --- |
| 1 | 임베딩 기본값이 키 없는 Voyage AI다. 벡터 검색이 꺼진 상태인데 화면에는 "voyage-4-lite · Voyage AI"로 정상처럼 보인다. 키 입력칸은 접힌 상세 설정 안에 있다. | **해결** |
| 2 | 생성 AI를 직접 연결하려면 제공자·모델·키를 따로 입력하고 연결 테스트를 따로 눌러야 한다. | **해결** |
| 3 | 기존 채팅에 설치하면 지난 대화는 기억되지 않는다. 안내는 첫 기억이 생기면 사라진다. 수동 콜드스타트는 비용 확인 없이 실행된다. | 다음 단계(알림 + 확인 후 실행) |
| 4 | 자동 재시도 5회를 넘긴 실패 구간은 설정 창 안에서만 보인다. | 다음 단계(채팅 알림 버튼) |
| 5 | 업그레이드 사용자의 "이전 기억 지침 확인" 대기가 기억 생성 전체를 멈추는데, 화면에는 "기억 생성 실패"만 보인다. | 다음 단계 |
| 6 | 효과 없는 설정이 남아 있다: `story_arc_preset`, `*_ito_preset` 3개, `ariadne_preset`. | 다음 단계 |

키는 플러그인마다 따로 유지한다(사용자 결정). 리브라와 플래시백은 각자 키를 저장한다.

## 빠른 연결

"AI 연결"과 "임베딩 연결" 화면 맨 위에 같은 "빠른 연결" 카드가 있다.

1. **API 키 한 칸.** 키 앞부분으로 제공자를 알아낸다.

   | 키 앞부분 | 제공자 | 생성 AI | 임베딩 |
   | --- | --- | --- | --- |
   | `sk-ant-` | Claude | ○ | |
   | `sk-or-` | OpenRouter | ○ | |
   | `AIza` | Gemini | ○ | ○ |
   | `sk-proj-` 등 `sk-` | OpenAI | ○ | ○ |
   | `sk-` + 32자리 16진수 | DeepSeek | ○ | |
   | `pa-` | Voyage | | ○ |
   | `jina_` | Jina | | ○ |
   | `csk-` | Cerebras | ○ | |
   | `fw_` | Fireworks | ○ | |

   자동 감지가 틀리거나 형식을 모르는 키면 "제공자"에서 직접 고른다.
2. **추천 모델 자동 선택.** 제공자의 모델 목록을 받아 기억 분석에 맞는 빠르고 저렴한 계열의 최신 버전을 고른다. 목록 조회는 토큰 비용이 없고, 그 자체로 키 확인도 된다.
   - OpenAI는 `gpt-*-mini`, Claude는 haiku, Gemini는 flash, DeepSeek는 `deepseek-chat`을 고른다.
   - 미리보기, 오디오, 이미지 계열은 제외한다.
   - 고를 수 없으면 짐작하지 않고 모델 이름을 입력해 달라고 한다. 모델 칸에 직접 입력해도 된다.
   - 임베딩은 제공자 기본 모델을 쓴다. OpenAI는 `text-embedding-3-small`, Gemini는 `gemini-embedding-001`, Voyage는 `voyage-4-lite`.
3. **시험 후 저장.** 생성 AI는 짧은 시험 호출 1회, 임베딩은 연결 시험(다국어 확인 포함)을 한다. 요청한 항목이 모두 성공해야 저장한다. 하나라도 실패하면 아무것도 바꾸지 않고 이유를 보여 준다.
   - 생성 AI는 새 프리셋 "OpenAI 빠른 연결" 같은 이름으로 만들고 전역 기본 연결로 지정한다.
   - "기억 분석 AI로 사용"을 끄면 RisuAI 보조 모델을 그대로 쓴다.
4. **이 PC의 Ollama로 무료 임베딩.** `127.0.0.1:11434`에서 설치된 임베딩 모델을 찾는다. 다국어 모델(bge-m3 등)이 있으면 그것을 고른다. 모델이 없으면 `ollama pull bge-m3` 실행을 안내한다.
5. **키 처리.** 저장 후 입력칸을 비우고 키를 다시 표시하지 않는다. 키는 기존 키 저장 경로를 그대로 쓰므로 백업에 포함되지 않는다.

## 상태 표시

- 빠른 연결 카드는 "기억 분석 AI"와 "임베딩"의 실제 상태를 보여 준다.
- 임베딩이 쓸 수 없는 상태면 "설정 안 됨 · 키워드 검색만 사용 (API Key)"와 "키워드 검색만" 배지를 보여 준다.
- 기억 화면의 모델 요약도 "임베딩 미설정 · 키워드 검색만 사용 중 · 빠른 연결로 키 하나만 넣으면 됩니다"로 바꿨다. 이때 버튼 이름은 "빠른 연결"이다.

## 확인 범위

- `tests/libra_quick_connect_test.cjs`: 키 감지, 직접 선택, 추천 모델(날짜 붙은 스냅샷보다 별칭 우선, 미리보기 제외), Ollama 모델 선택, 화면 연결, 시험 후 저장 순서.
- `tests/libra_quick_connect_flow_test.cjs`(jsdom, 제공자 모의):
  - 카드 렌더링과 정직한 상태 표시.
  - OpenAI 키 하나로 생성 AI와 임베딩 동시 설정.
  - 임베딩 시험 실패 시 아무것도 저장하지 않음.
  - Voyage 키는 임베딩만 설정.
  - 모델을 못 고르면 입력 요청.
  - 알 수 없는 키 처리.
  - Ollama 연결.
- 실제 RisuAI와 실제 제공자 키로는 확인하지 않았다. 특히 RisuAI 웹에서 `127.0.0.1` Ollama 접근은 브라우저 정책 때문에 막힐 수 있다. 그때는 연결 실패 이유를 보여 준다.
