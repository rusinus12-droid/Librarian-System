# GRADIA 단계별 수동 스킬 선택

GRADIA 0.26.9에서 자동 스킬 라우터를 퇴역시켰다. 장면과 스킬 설명의 단어 유사도, 단계 친화도·가산점, 상대 점수 하한, Top-K 경쟁, 참고 문서 자동 선별을 사용하지 않는다. 선택용 LLM 호출도 없다.

## 화면과 실행

`자료 · Skill → Skill`에서 9개 장르 스타일을 카드로 고른다. 0.26.10부터 카드에는 짧은 연출 소개와 한국어 스킬 이름만 표시한다. 우측 하단 **자세히 보기**는 실제 라이브러리의 단계별 스킬 설명과 선택된 장르 연출을 읽기 전용 팝업으로 연다. 상세 확인만으로 선택·저장·모델 호출이 발생하지 않는다.

**직접 스킬 고르기**를 펼치면 단계별 체크·순서·추가 연출·사용량을 조정할 수 있다. 기본 품질 규칙은 카드 아래 작은 버튼에서 확인한다. 원문 보기와 사용자 스킬 추가·편집·삭제를 유지한다. 이 화면에서는 공통 서버 연결 패널과 기술적인 계산 설명을 표시하지 않으며, 기존 모델 예산·검증 정책은 유지한다. 데스크톱은 2열, 태블릿·모바일은 1열 카드로 표시한다.

- 기본 품질 규칙은 별도 고정 계층이다. 지식 경계, 현재 상태 연속성, 인물 고유성, 의미 반복 절제, 장면 표현, 출력 형식을 항상 적용한다. RP 모드에는 유저 행동 경계를 더하고 소설 모드에서는 제외한다. 이전 스킬 우선도나 라우터 켜기/끄기는 이 계층에 영향을 주지 않는다. 완성 응답의 품질 보존 계약도 선택과 독립적이다.
- 추가 스킬은 SHADOW·인물·세계관·플롯별 명시적 선택 목록만 사용한다. 선택하지 않으면 추가 스킬을 주입하지 않는다. 기본 규칙은 전문 스킬로 중복 주입하지 않는다. 옛 Top-K 3개 경쟁이나 관련도 필터로 선택을 탈락시키지 않는다. 새 한도는 아래의 실제 글자 수 예산으로 결정한다.
- 참고 문서도 단계·스킬별 체크 목록만 사용한다. 선택하지 않은 문서는 추가하지 않는다.
- 선택한 원문은 기존 스킬 컴파일러로 분석·작성·국소 패치에 맞게 투영한다. AIDE의 편집 범위, 소설/RP 권한, 현재 입력과 최신 장면의 우선순위는 유지한다.
- 없는 스킬·사용 중지된 사용자 스킬·없는 참고 문서는 실행할 전체 단계 계획을 검사할 때 사유와 함께 거부한다. 그 검사는 첫 모델 호출 전에 한다. 꺼진 단계의 선택은 실행하지 않는다.
- 모델이 문맥 초과를 반환한 경우, 수동 스킬이 있는 프롬프트 전체를 자동 축약하여 재시도하지 않는다. 스킬 선택을 줄이거나 문맥이 더 큰 모델을 선택하라는 오류를 표시하고 기존 단계 실패 정책을 따른다. 수동 스킬이 있는 요청에서는 참조 패킷 재포장도 하지 않는다. 기존 대화·로어·연속성 자료를 스킬 때문에 축소하지 않는다.
- 실제 사용 자료에는 기본 품질 규칙과 수동 스킬·참고 문서를 별도로 기록한다. 선택 변경이나 사용자 원문 변경은 근거가 연결된 진행 중 실행의 현재성을 무효화한다.

## 장르별 추천 세트

일상·문학, 로맨스, 판타지, SF, 미스터리·추리, 스릴러, 호러, 코미디, 액션·모험의 9개 세트를 제공한다. 카드의 **이 스타일 적용**은 전체 단계에 적용한다. 상세 팝업에서는 **현재 단계에만 적용**도 선택할 수 있다. 대상 단계의 기존 선택·참고 문서를 교체하는 미저장 초안이며, 저장·변경 취소는 일반 설정과 같다. 적용 이후 각 스킬을 수동으로 바꿀 수 있다. 저장되는 것은 구체적인 선택 목록이며, 프리셋이 나중에 자동으로 다시 적용되지 않는다.

SHADOW에는 보통 장르 렌즈와 전문 스킬 1개, 해당 장르 참고 문서 1개를 권장한다. 각 AIDE에는 담당 영역에 맞는 스킬 1개를 배치한다. 액션은 장르 렌즈 없이 전투 전문 스킬을 사용한다. 어떤 장르든 기본 품질 규칙은 유지된다. 작은 모델에서 세트가 한도를 넘으면 일부를 몰래 적용하지 않고 안내한다.

## 글자 수 한도와 핵심 자료 보존

한도는 **단계별·호출별**이다. 기본 품질 규칙을 제외한 추가 스킬의 분석·작성·패치·복구 전문 중 가장 긴 것을 청구하며, 선택한 참고 문서·컴파일러 지침·구분자도 포함한다. CBS 문맥이 있으면 확장된 스킬 문구로 다시 계산한다. 글자 수 단위는 기존 GRADIA 문맥 예산과 같은 JavaScript 문자열 길이(UTF-16 코드 단위)다.

1. 안전 입력 글자 수 추정 = `max(0, floor((모델 문맥 토큰 × 0.90 − 출력 예약 토큰) × 2.4) − 4096)`. 출력 예약과 10% 여유 및 요청 프레이밍을 먼저 확보한다. 선택 단계의 실제 AI 프리셋을 사용한다.
2. 추가 스킬 상한 = **24,000자**와 **안전 입력 글자 수의 10%** 중 작은 값. 기본 자료 공간의 대부분을 추가 스킬이 점유하지 못한다.
3. 최대 개수는 선택 조합의 실제 글자 수로 결정한다. 현재 선택과 남은 공간에 들어갈 수 있는 가장 짧은 스킬들을 기준으로 화면에 개수 상한을 표시한다. 이는 임의의 긴 스킬 N개를 선택할 수 있다는 뜻이 아니다. 길이가 다른 사용자 스킬도 같은 글자 수 기준을 따른다.
4. 체크·참고 문서 선택·장르 세트 적용 시 한도를 넘으면 그 변경을 반영하지 않고 사유를 표시한다. 저장한 스킬 원문도 수정 시 같은 검사를 거친다. 가져온 과대 선택은 자동 삭제하지 않고 실행 전 거부한다.
5. 전체 활성 단계의 선택을 첫 모델 호출 전에 검사한다. 모델 문맥 크기가 미확인인 상태의 24,000자는 편집용 임시 상한이며, 스킬을 실행하려면 AI 프리셋에 문맥 크기를 설정하거나 카탈로그를 갱신해야 한다.
6. 실제 요청 직전에는 **시스템·사용자 입력, 공유 로어/연속성 접두부, LIB 근거를 모두 포함한 전체 글자 수**도 검사한다. 따라서 직전 턴·최근 N턴·SA/AIDE 분석·리브라/하야쿠/플래시백 연속성·로어북 등 이미 구성된 초안 자료를 스킬에 자리를 내주기 위해 잘라내지 않는다. 초과하면 호출을 거부하고 스킬 축소 또는 큰 문맥 모델을 안내한다. 중량 모드의 분석과 작성, AIDE의 국소 패치도 각각 검사한다.

2.4자/토큰은 기존 문맥 복구에 쓰는 추정치다. 실제 제공자 토큰 계량을 대체하지 않으며, 제공자가 문맥 초과를 반환해도 수동 스킬 요청은 자료 축약·재포장으로 재시도하지 않는다. 기존 자료 자체의 수집 범위·참고 자료 예산은 그대로이며, 이 변경이 모든 원본 대화와 로어를 무제한 주입하는 것은 아니다.

## 저장과 이전

- `skill_stage_selections`: 단계별 스킬 ID 배열. 배열 순서가 적용 순서다.
- `skill_stage_references`: 단계별·스킬별 참고 문서 ID 배열.
- `skill_custom_library`: 기존 사용자 원문과 참고 문서 보존.
- `skill_router_legacy_archive`: 이전 라우터·우선도 설정 보관. 실행에 사용하지 않는다.

기존의 양수 우선도는 명시적 선택이 아니므로 새 선택으로 자동 변환하지 않는다. 수동 선택이 없는 기존 설치는 기본 품질 규칙만 적용한다. 새 사용자 스킬도 기본적으로 추가만 하고 선택하지 않는다. 추가 시 적용할 단계를 사용자가 명시할 수 있다. 삭제 시에는 해당 스킬의 선택·참고 문서 연결만 모든 단계에서 제거한다. 저장·변경 취소·재열기와 설정 내보내기·가져오기에 새 필드를 포함한다.

- `tests/gradia_manual_skills_gui_runtime_test.cjs`: 단계별 저장·재열기·변경 취소, 사용자 스킬 추가 기본값·삭제, 기존 설정 보관, 장르 세트의 저장·변경 취소, 과대 선택 거부, 미저장 선택을 포함한 프롬프트 미리보기.

테스트 모델 응답은 합성했다. 수동 스킬이 실제 모델의 글 품질을 얼마나 바꾸는지는 이 시험의 판정 범위가 아니다.
