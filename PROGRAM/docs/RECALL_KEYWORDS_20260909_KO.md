# 리콜 검색어 수정 — HAYAKU 3.0.64 / Flashback 1.0.43

일반 단어를 인물 일치로 취급하면서 “민수의 약속 장소는?”에 최신 아리아 기록만 전달하던 문제를 수정했습니다. 기억 저장·분석 모델·벡터 형식은 변경하지 않았습니다.

## 변경

- 일반 lexical 단어, 직접 표면 표현, 공개 인물 선언과 별칭, 이전 문맥을 구분합니다. Flashback의 원문 기억은 인물 정보가 없어도 검색됩니다.
- 확인된 인물은 선언된 ID로 비교하며, 긴 이름 일치를 먼저 해소하고 같은 별칭의 여러 인물은 모호한 상태로 남깁니다. 일반명사만으로 인물 집중 후보를 만들지 않습니다.
- 명시 요청의 직접 대상 근거를 최신성보다 먼저 선택합니다. 이어쓰기는 기존 현재 장면 우선순위를 유지합니다. 최종 발췌가 대상 표현을 잃으면 그 발췌를 대상 근거로 전달하지 않습니다.
- 검색용 NFKC·U+200B/U+FEFF 정리, 한 글자 등록명, 한국어 복합 조사 대조를 지원합니다. 이름을 반복해서 잘라 동일 인물로 합치지 않습니다.
- 영어 힌트는 단어 경계에서 대조합니다. `city`의 `it`, `storage`의 `rage` 오인을 제거했습니다. 검색 개념으로 부정 사건을 찾는 것은 유지합니다.
- 새 주제에서는 이전 인물 별칭을 질의에 붙이지 않습니다. 명시 요청의 과거 문맥은 직접 관련된 메시지만 사용하며, 접근 범위/POV 상태는 별도로 유지합니다.
- 한정된 토큰 예산에서 직접 대상과 마지막 질문을 먼저 보존합니다. 문서 단어 빈도는 BM25F에 보존합니다.
- 검색 특징 버전과 스코프·별칭 메타데이터를 캐시에 반영합니다. 구형 샤드 인덱스는 호환 전체 읽기로 처리하며, 커밋이 같은 동시 읽기는 공유합니다. 읽기 중 정본 재저장이나 자동 재임베딩을 추가하지 않았습니다.

## 배포와 복구

HAYAKU 요청 캐시 v2 / 투영 캐시 v3, Flashback sparse index v3 / shard index v5 / memory lane v2입니다. 이들은 파생 검색 표현의 버전이며 정본/세계선 ID 버전이 아닙니다. 오래된 인덱스의 최초 호환 읽기는 추가 비용이 들 수 있습니다. 새 인덱스 저장은 기존 정상 쓰기/유지보수 경로가 담당합니다.

단독 JS 플러그인은 외부 공통 런타임 없이 실행됩니다. `tools/recall_keyword_features.cjs`의 helper를 `tools/sync_recall_keyword_features.cjs`로 각 소유자에 내장하며, 테스트에서 같은 구현이 내장되어 있는지 확인합니다.

원문과 기존 벡터는 보존합니다. 이전 버전으로 복귀하려면 배포 전 백업의 제품 파일 및 해당 파생 인덱스/캐시를 복구하거나 재구축합니다. 새 인덱스를 구버전과 호환된다고 가정해서는 안 됩니다.

## 검증 범위

`recall_keyword_features_runtime_test.cjs`와 `recall_keyword_hook_storage_runtime_test.cjs`는 원문만 있는 기억의 실제 요청 훅 전달, 저장 순서/슬롯 수, 인물·별칭·표기 경계, 긴 입력, 발췌 예산, 구형 샤드 읽기, 캐시 무효화, 동시 읽기 및 원문/벡터 보존을 실행합니다. 기존 선택기의 출처 근거와 시간 비교 회귀도 함께 실행합니다.

테스트 호스트와 결정적 벡터의 결과입니다. 실제 RisuAI GUI와 외부 임베딩/응답 모델 품질, 실기기 성능은 별도 확인이 필요합니다. 해당 검증을 수행했다고 주장하지 않습니다.
