# LIBRA 2.3.54 — 기억 저장과 상태 반영 분리

콜드스타트의 응답 수용, 요청 예산 판정, 상태 적용 순서를 수정했다. 기존 정본과 사용자 대화 데이터는 마이그레이션하거나 삭제하지 않는다.

## 동작

- 알려진 태그·코드 블록과 앞뒤 설명을 제거해 명확한 단일 JSON 객체를 로컬에서 읽는다. 다중 객체, 배열·문자열 안의 객체, 잘린 JSON, 중복 키, 잘못된 원문 근거는 거절한다. 자동 모델 수리 호출은 추가하지 않았다.
- 정본 기억 요청에서 UTF-8 바이트 상한을 모델의 실제 입력 토큰 수로 취급하지 않는다. 컨텍스트 압력이 추정되면 선택적 참고 자료와 과거 상태부터 제외하고, 선택한 5 U+A 원문은 보존한다. 제공자의 실제 오류, 설정된 출력 제한, 호출 수 제한은 유지한다.
- 각 실행의 provider/model, 컨텍스트 값과 출처, 입력 추정치, 출력 예산, 제출 여부와 실패 단계를 기록한다. 원본 응답은 해당 실행 진단에 최대 256,000자까지 남기고 초과 여부를 표시한다. 새 분석은 이전 미완료 작업과 진단을 이어받지 않는다.
- 유효한 기억 본문과 선택적인 상태 연결을 분리한다. `factTempId`만 명시된 연결은 claim 계약의 고정 필드로 채운다. 잘못되거나 중복된 연결은 제외하고 사유를 남긴다. 기억의 사실을 임의로 삭제하거나 보충하지 않는다.
- 1–5턴이 실패해도 6–10턴 기억을 분석·저장·검색할 수 있다. 현재 상태는 공백을 건너뛰지 않는다. 앞 구간이 완성되면 저장된 산출물을 순서대로 재생하며 뒤 구간 AI를 재호출하지 않는다.
- 정상적인 연속 추가는 기존 증분 저장 경로를 유지한다. 빈 구간을 채울 때만 재생하고, 이미 재생된 작업은 저장된 완료 영수증으로 확인한다.
- 열람대는 저장된 기억 수, 상태가 반영된 턴, 상태 반영 대기 구간을 구분해 표시한다. 기존 실패 안내 닫기, 모델 설정 표시와 세계선 카드 기능은 유지한다.

## 상태 보류와 호환성

자동 처리에서 현재 사실의 필수 연결이 빠지면 기존 상태를 유지하고 기억만 저장한다. 기존의 의미 충돌 처리에서는 확정할 수 없는 필드를 보류하고 안전한 필드만 반영하는 부분 상태 동작을 유지한다. 부분 상태를 전체 완료로 표시하지 않는다.

기존 월드 매니저의 명시적 상태 재구성·확인·정정 기능은 유지한다. 사용자가 상태를 재구성하면 저장된 기억에서 부분 상태를 검토하고 보류 사실을 명시적으로 정정할 수 있다. 이 과정에서 모델을 호출하거나 저장된 기억 본문을 바꾸지 않는다.

기억 스키마 v4, 정본 revision, 원문·채팅·세계선 확인, 실행 중 변경 감지, 저장 후 읽기 확인, 취소·중복 요청 방지는 유지한다. OtherAx는 RisuAI의 응답 완료를 기다리는 기존 경로를 유지한다. 직접 제공자의 실제 컨텍스트 부족이나 잘린 출력까지 성공으로 바꾸는 패치는 아니다.

## 검증 경계

배포 소스 전체를 실행한 VM 회귀와 실제 로컬 HTTP·SQLite 회귀에서 직접 제공자/OtherAx 경계는 합성 응답으로 통제했다. 실제 RisuAI 앱에서 사용자의 모델을 호출한 실측 성공과는 구분한다. 전체 회귀 결과와 파일 해시 확인은 작업 폴더의 `review_artifacts/libra_memory_first_20260908`에 기록한다.
