# RE:TRACE 서버 사본 정리

RE:TRACE 1.9.71에서는 작업 중 변경 없는 플러그인의 본문 재조회·색인 재생성을 생략합니다. 저장 키의 revision/digest, 무결성, 서버 주소·초기화 세대, 채팅 목록 및 해당 플러그인의 서버 목록·참조 정보가 같을 때만 재사용합니다. 변경·조회 실패·불안정한 채팅 목록에서는 다시 검사하며 수동 새로고침은 전체 검사입니다.

'저장 정보·참조 확인'은 저장 키·레코드 수·채팅 ID·참조 관계를 보여 줍니다. 기억 본문 열람 기능은 아닙니다. 작업 중에만 중단 버튼이, 미완료 항목이 있을 때만 재시도 버튼이 표시됩니다.

서버 0.3.46 / RE:TRACE 1.9.70부터 일반 스코프 정리는 한 번 확인하면 자동으로 진행됩니다. 서버와 플러그인을 함께 업데이트하세요.

1. 서버 관제실에서 대상을 확인하고 개별 '서버 사본 삭제' 또는 '선택한 서버 사본 삭제'를 누릅니다.
2. 대상 목록과 로컬 원본 보존·필요한 플러그인 단독 모드 전환 내용을 확인합니다.
3. 로컬 보존, 백업, 삭제 조건 확인, 실제 삭제가 이어집니다. 검증 후 같은 버튼을 다시 누를 필요가 없습니다.
4. 화면 안에서 결과를 확인합니다. 응답 유실이나 일부 실패는 '이전 작업 결과 확인·실패 항목 재시도'로 확인합니다. 마지막 작업은 로컬에 저장되며 새로 열린 화면에서도 이 버튼으로 불러옵니다.

'진행 중 작업 중단'은 다음 항목 처리를 멈춥니다. 이미 완료된 복원·모드 전환·삭제를 되돌리지 않습니다. 중단 요청 전에 시작한 항목은 완료될 수 있습니다.

같은 작업에서 데이터가 변경되지 않은 같은 플러그인의 DB 백업을 재사용합니다. 다른 쓰기가 확인되면 새 백업을 생성하므로 언제나 정확히 한 번만 백업한다고 보장하지는 않습니다. 공유 목록은 앞 항목 삭제 후의 최신 값으로 다시 구성합니다. 보존 지정, 다른 자료의 참조, 불완전한 데이터 보호는 유지합니다.

응답을 받지 못한 작업은 서버 상태를 먼저 조회합니다. 이미 커밋된 삭제는 반복하지 않습니다. 실행 전이라면 로컬 보존 상태를 다시 확인합니다. 결과를 확정할 수 없는 항목은 보류로 남습니다. 서버 주소가 달라졌거나 서버가 초기화·복원된 경우 기존 삭제 작업으로 계속 진행하지 않습니다.

이 기능은 서버 사본을 정리하며 로컬 기억까지 폐기하지 않습니다. 플러그인 전체 서버 기억 초기화는 별도 메뉴입니다. 자동 재시도로 다른 대상까지 삭제하거나 기존 확인 불가 자료 보호를 우회하지 않습니다.
