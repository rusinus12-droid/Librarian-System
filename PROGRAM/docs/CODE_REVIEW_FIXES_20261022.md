# 최근 변경 검토와 수정 (2026-10-22)

검토 기준: `claude/lens-presets-scope-parity`, HEAD `bd69e0e` 및 현재 작업 트리.

범위는 최근 렌즈·스코프 작업(`bd69e0e`), 그래프 모듈 동기화(`9cec631`), 로컬 업데이터 배포 파일(`aa59a18`), 그리고 후속 설정 퇴역·GRADIA 기억 읽기 변경이다. 관련 구현의 원래 변경인 `31b0a42`와 `1e331fc`도 추적했다. 전체 저장소의 모든 커밋을 감사하거나 미해결 회귀 목록 전체를 해소했다는 의미는 아니다.

## 수정 1: 콜론이 있는 스코프의 그래프 고아 자료가 정리되지 않음

- 위치: `PROGRAM/tools/libra_memory_graph_store.cjs`, 동기화된 `LIBRA.js`.
- 원인: 원자적 namespace fence를 사용하는 GC가 스코프를 `[^:]+`로 판별했다. 실제 `7747bb57_1:0` 같은 키는 정상이어도 후보가 0개였다. 원래 모듈은 `31b0a42`에서 추가됐고 `9cec631`에서 플러그인에 동기화됐다.
- 수정: 소유자가 지정한 정확한 스코프 접두사를 먼저 확인한 후, 나머지 문자열에서 허용된 파생 자료 종류만 판별한다.
- 검증: 단순 키와 콜론 포함 키 두 종류를 대상으로 dry run·선택 정리·전체 후보 정리를 검사한다. 도달 가능한 페이지, root, 정본 기억 및 다른 스코프의 키는 보존한다. 새 회귀 시험은 수정 전 두 종류의 콜론 키에서 실패했다.

## 수정 2: 취소된 읽기의 늦은 정리가 새 요청의 취소를 무력화함

- 위치: `PROGRAM/tools/libra_gradia_unified_read.cjs`, 동기화된 `LIBRA.js`·`GRADIA.js`.
- 원인: `1e331fc`의 세션 정리에서 operation ID만으로 Map 항목을 삭제했다. A 취소 → 같은 ID로 B 시작 → A의 늦은 완료 순서이면 B의 추적 항목이 삭제됐다. B를 취소해도 실행이 반환 후 해제되지 않을 수 있었다.
- 수정: Map에 들어 있는 객체가 정리 대상 객체와 동일할 때만 제거한다. 영수증 Map에도 같은 소유권 조건을 적용한다.
- 검증: 두 대기 중 요청, 취소와 늦은 완료 순서를 제어해 양쪽 실행이 각각 해제되고 남은 권한이 없는지 확인한다. 수정 전 새 회귀 시험은 해제 횟수가 1회여서 실패했고 수정 후 2회가 된다.

## 시험 준비의 상태 갱신 대기

GRADIA 렌즈 IPC 시험은 Micro 발행 직후 후속 상태 갱신이 남을 수 있었다. 통합 재실행에서 서버 최신성 거부 한 건이 나왔고, 같은 코드는 단독 실행에서 통과했다. 시험 준비가 실제 분석·영수증·쓰기·분기 감사 작업과 예약된 스냅샷 갱신의 완료를 확인하도록 보완했다. 제품 소스의 최신성 거부 조건은 완화하지 않았다. 읽기 도중 설정을 변경해 중단시키는 음성 대조 시험은 계속 수행한다.
