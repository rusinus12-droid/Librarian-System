# HAYAKU 수동 재분석 경로 통합

패킷 상세의 **재분석** 버튼은 `구간 점검 → 직접 원문 재분석`을 열고 해당 패킷의 전체 원문 범위를 선택합니다. 화면 이동만으로 모델을 호출하지 않습니다. 직접 연 원문 재분석은 기본적으로 접혀 있고, 구간이 지정된 진입은 선택 범위를 펼칩니다.

- 단일 턴: 바로 재분석 / 확인 후 재분석.
- 여러 턴: 바로 재분석.
- 여러 턴을 담은 기존 패킷: 그 패킷의 전체 범위를 함께 선택·해제합니다. 직접 API도 부분 범위 교체를 거절합니다.
- 검증과 원장 저장이 완료되면 기존 패킷을 교체합니다. 이전 패킷은 replacement tombstone과 버전 선택으로 보존합니다.
- 새 재분석에는 별도의 후보 비교·채택 단계가 없습니다. 기존에 저장된 후보의 모델 호출 없는 최종 결정과 이전 버전 선택은 유지합니다.

## 대상과 보호

대상 목록은 현재 채팅의 일반 활성/미결속 패킷, 구형 여러 턴 패킷, 현재 채팅에서 생성한 콜드스타트 패킷의 실제 원문 범위를 사용합니다. 콜드스타트 레코드의 `targetPairIndex`가 0이어도 패킷의 `source_turn_range`로 선택합니다.

승계받은 과거 기억, 영구 보호 기억, 감사 사본, 원문 범위를 확인할 수 없는 레코드는 교체 대상으로 삼지 않습니다. 콜드스타트 출처만으로 승계받은 기록을 현재 채팅 기록으로 취급하지 않습니다.

선택은 채팅 범위, 메시지 위치·식별 정보, 저장된 교체 대상의 식별자·내용 해시·범위를 함께 고정합니다. 삭제되거나 변경된 패킷, 다른 채팅, 원문이 사라진 범위는 다른 대상으로 대체하지 않습니다. 모델 실행 중 원문·태그 규칙·대상 패킷이 바뀌면 게시를 막습니다. 모든 선택 턴을 분석·검증한 뒤 원장을 한 번에 교체하며, 최종 쓰기 중 변경도 재검증합니다. 실패한 작업은 자기 소유의 확정된 쓰기만 복구하며 다른 작업의 원장을 덮어쓰지 않습니다.

콜드스타트 일부를 교체한 뒤에도 같은 원본 묶음의 나머지 기억이 계속 유효하도록, 검증된 교체 tombstone을 원본 묶음의 완전성 계산에 반영합니다. 교체된 옛 본문은 회상 대상으로 추가하지 않습니다.

## 지원 API

- `HAYAKU.openSourceReanalysis({scopeKey, recordId, recordHash})`: 저장된 패킷에 해당하는 범위를 선택해 화면을 엽니다.
- `HAYAKU.openSourceReanalysis({scopeKey, startTurn, endTurn})`: 지정한 범위와 연결된 패킷의 전체 범위를 선택합니다.
- `listReanalysisRanges`, `previewSourceEdits` / `applySourceEdits`, `reanalyzeSelectedRanges`: 공통 선택·검증·실행 경로입니다. 선택에는 조회 결과의 패킷 리비전 증명이 포함돼야 합니다.

`recovery.regenerateTurns`는 제거했습니다. `repairNow`로 기존 패킷 교체를 요청하는 우회 경로도 거절합니다. 원문 재분석에서 사용하는 네이티브 분석·검증·원장 게시 엔진은 내부 구현으로 공유합니다. 새 분석을 시작하는 다른 공개 재생성 API는 제공하지 않습니다.

## 실패 분석 재시도 제거

꺼진 상태로 남아 있던 자동 재시도 작업자, 스케줄러, 설정/argument, 타이머, 실패 분석 재처리·후보 채택 코드, 숨겨진 실패 복구 화면과 이벤트, 실행 API와 테스트용 노출을 삭제했습니다. `failedAnalysis.resolve`, `inspectAdoption`, `automationStatus`는 존재하지 않습니다.

실패 진단의 생성·보관·조회·내보내기와 명시적 삭제는 유지합니다. 과거 실패 진단을 모델 입력으로 다시 사용하지 않습니다. 누락 턴 생성, 콜드스타트, 정상 응답의 제한된 afterRequest 복구 및 한 작업에 허용된 형식 보정은 각 목적에 따라 계속 작동합니다.

## 검증

- 전체 DOM에서 패킷 상세 → 자동 선택 → 비용 확인 → 실행 → 원장 교체 및 목록 갱신.
- 일반 단일 턴, 여러 턴 레코드의 전체 범위, 현재 채팅 콜드스타트, 보호 기록, 변경된 대상·채팅, 실행 중 별도 리비전 생성.
- 게시 완료까지 다른 모델 실행 진입의 중복 호출 차단.
- plugin_only / mirror / server_only에서 여러 턴·콜드스타트 교체, 재시작, 이전 버전과 나머지 턴의 coverage 유지.
- 기존 원문 게시 경합·롤백·다중 선택 원자성 및 확인 화면 회귀.
- 실제 Chromium의 패킷 버튼, 원문 재분석 연결과 비용 확인, 데스크톱·모바일 원문/태그 검토.

검증은 합성 호스트·모델 대역·로컬 서버를 사용합니다. 사용자 데이터, 외부 모델 품질, 배포 또는 전체 테스트 모음 통과를 의미하지 않습니다.
