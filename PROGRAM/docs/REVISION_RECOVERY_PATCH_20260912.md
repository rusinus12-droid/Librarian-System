# 원문 수정·리롤·벡터 호환 패치

대상: LIBRA 2.3.87 / HAYAKU 3.0.99 / Flashback 1.0.64.

## 구현 범위

플러그인별 승인·실행을 유지한다. 공동 승인창이나 플러그인 간 자동 승인 전파는 구현하지 않았다.

- HAYAKU 전체 패킷 ingest의 미정의 `meta` 참조를 `packetMeta`로 수정했다. 상태 권한 제한은 유지한다.
- HAYAKU는 저장된 응답 버전과 일치하는 패킷, 또는 세계선 관찰에서 응답이 사라졌다가 교체된 근거를 사용한다. 관찰된 새 응답은 원문 수정 승인이 아닌 정상 누락 복구 대상이 될 수 있다. 같은 응답의 후속 직접 편집은 다시 승인 대상이다.
- LIBRA는 실제 저장 기억의 sourceDigest와 sourcePairs가 일치하는 이력을 원문 수정으로 차단하지 않는다. 기존 branch reconciliation이 이력을 재활성화한다. 관찰된 미완성 구간 뒤의 새 응답은 별도 본문 승인 없이 정상 분석 경로를 사용하되 현재 스코프·배치·접두 원문의 해시를 검증한다.
- Flashback은 비활성 응답 이력도 원문과 메시지 식별자가 일치하면 재연결 대상으로 인정한다. 진행 중인 reroll capture에서는 원문 수정 관찰을 보류한다. 세계선에 기록된 응답 공백은 새 응답 전환으로 처리한다. 기존 활성 레코드의 식별자 없는 구형 데이터 비교도 유지한다.
- 관찰된 응답 전환은 소유 플러그인의 기존 동의 저널에 해시 기반 `response_variant` 기록으로 남긴다. 새 본문이나 다른 prefix에 승인을 재사용하지 않는다.
- LIBRA의 승인된 원문 재분석은 구형 기억을 readonly 이력으로 보존하는 전환 기록을 만들 수 있다. 원본 기억은 변경하지 않는다. 전환 기록의 물리 재조회 실패 시 기록을 제거하고 제거 결과도 확인한다. 기존 전환 기록이 잘못된 경우 덮어쓰지 않는다.
- 원문 검증 실패는 scopeKey / unit_missing / digest / sourceDigest / basis / identity 중 어느 필드가 달랐는지 저널에 기록한다. HAYAKU는 모델 시작·완료·후보 저장 단계도 기록한다.

## Voyage 벡터

이전 배포본 `_release_audit/v515_adoption_20260905/prepared/MemorySuite/PROGRAM/plugins/Flashback_Memory.js`의 프로필에는 executionDescriptor가 없었고, 현재 프로필에는 포함된다. 전처리 버전은 양쪽 모두 1이었다. 이 차이는 모델과 차원 변경 없이도 프로필 해시를 바꾼다.

동일한 현재 설정에서 **실제로 배포됐던 구형 프로필을 다시 계산하여 일치하는 Voyage 프로필만** 호환시킨다. 제공자·모델·차원·숫자 벡터 검증은 유지하며, 임의의 프로필 또는 modelRevision 변경을 허용하지 않는다. 모델 호출이나 벡터 재저장을 요구하지 않는다. 레코드 검색과 샤드 중심 벡터 비교에 같은 호환 규칙을 사용한다.

lastRecall의 vectorCompatibility에 원인별 집계, 최대 64개 레코드의 모델·차원·프로필·제외 사유를 포함했다. 좌표 배열과 본문은 이 진단에 넣지 않는다.

첨부 로그는 레코드별 프로필을 포함하지 않으므로 기존 36개 전부가 이 프로필 변경 때문이라는 확정은 하지 않는다. 같은 모델이라는 사실만으로 서로 다른 설정의 벡터를 무조건 허용하지 않는다.

별도로 기존 동의 상태기계·선택·재시작·후속 구간 의존성·통합 전환·임베딩 실행 시험을 실행했다. 공통 SDK 동기화 검사도 통과했다.
