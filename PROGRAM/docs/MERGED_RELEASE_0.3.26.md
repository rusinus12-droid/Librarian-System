## Flashback — 기존 정본 유지와 비교 후 교체

- 원문 변경 감지·보류·취소·실패만으로 이미 확정한 기억을 리콜에서 제외하지 않습니다. 현재 채팅과 대응하는 기존 정본과 뒤쪽의 변경되지 않은 턴을 유지합니다.
- `기억 유지보수 → 변경 전·후 비교하기`에서 사용자/응답 본문을 양쪽에 표시합니다. 삭제·추가 부분을 표시하고, 각 턴 선택·전체 선택·전체 해제가 가능합니다. 여러 변경은 공통 앞뒤를 제외한 한 변경 구간으로 묶어 표시합니다.
- 선택한 정확한 원문 버전만 승인합니다. 선택하지 않은 턴은 보류하며, 즉시 같은 확인창을 다시 띄우지 않습니다. 취소·Escape·채팅 전환·창 종료는 승인하지 않습니다.
- 새 원문을 저장하고 다시 읽어 확인한 뒤 이전 기억을 비활성 이력으로 전환합니다. 저장 도중 실패하면 기존 정본 복원을 시도하고, 복원까지 실패하면 이를 별도 오류로 남깁니다. 관련 없는 채팅이나 플러그인의 데이터는 변경하지 않습니다.
- 최초 캡처가 아직 한 번도 확정되지 않은 상태와 기존 정본의 수정 대기를 구분합니다. 전자는 `최초 출력 확인 대기 · 아직 정본 아님`입니다. 실제 완료 U+A와 양쪽 메시지 ID가 정확하게 같을 때만 자동으로 초기 결속을 확정합니다. 본문이 다른 이전 미확정 캡처는 비교 후 명시적 승인 경로로 처리합니다.
- 수정 검토는 로컬 본문 비교입니다. 별도 생성 모델을 호출하지 않습니다. 새 원문의 임베딩은 기존에 설정한 공급자 경로를 유지합니다.

## HAYAKU — 헤더 작업 대시보드와 문제별 실패 이력

- 우상단 기존 복구 상태 표시를 작업 대시보드로 통합합니다. 펼치면 작업 종류, 현재 단계, 대상 턴, 완료 수, 경과 시간, 실제 제출한 AI 호출 수, 대기/응답 상태를 확인합니다.
- 원문 수정 재분석과 실패 복구도 실제 작업에 연결합니다. 원문 재분석은 최소화 상태로 진행해 GUI 탐색을 막지 않습니다. 경과 시간 갱신만으로 전체 화면을 다시 만들지 않습니다.
- 응답 시간을 미리 알 수 없는 경우 남은 시간이나 가짜 완료율을 생성하지 않습니다. 수 초짜리 타이머가 끝났다는 이유로 성공 처리하지 않습니다.
- 같은 원문·턴·분기의 동일 문제는 목록 카드 하나로 묶습니다. 직접 수정·AI 재시도는 해당 문제의 펼침 이력에서 읽을 수 있습니다. 완전히 동일한 실패 본문은 재사용하고 반복 횟수만 갱신합니다. 실제로 달라진 후보와 원본 실패 내용은 감사 이력으로 남깁니다.
- 성공한 자식 수정본까지 해결 완료로 기록하여, 이미 처리한 문제의 과거 이력이 남았다는 이유로 다시 미해결로 집계하지 않습니다.
- 원본 및 이력 보기의 실제 버튼을 연결했습니다. 문제 카드 삭제는 확인 후 그 문제의 이력을 함께 삭제하며, 정본 패킷이나 Recovery Journal 원문 보관소를 삭제하지 않습니다.

## HAYAKU — 첫 응답 성공을 방해하던 형식 불일치 수정

- 실패 복구의 시스템 지시는 패킷+근거 객체를 요구하면서 사용자 지시의 끝에서는 단일 패킷을 요구하던 충돌을 제거했습니다.
- 정확한 인용 비교에서 NFC 및 공백·줄바꿈만 정규화합니다. 인용의 단어·부정 표현·행동·내용은 변경하지 않습니다.
- 의미가 명확한 `packet.` 접두사와 점 표기 배열 인덱스를 동일한 경로로 읽습니다. 잘못된 경로, prototype 계열 경로는 거부합니다.
- 정해진 스키마 상태/종류 enum과 실제 사실 서술을 구분합니다. 구조상 enum 토큰을 원문에 그대로 등장해야 하는 대사로 요구하지 않습니다. 이름·행동·서술의 근거 요구는 유지합니다.
- 존재하지 않는 인용, 서로 떨어진 구절을 합친 인용, 누락 근거, 다른 턴·분기·변경된 원문은 자동 채택하지 않습니다. 모델 거절이나 빈 응답도 성공으로 바꾸지 않습니다.
- 처리 이력 수에는 직접 수정·검사도 포함되므로 이를 모두 AI 호출 수로 표시하지 않습니다. 실제 호출 수는 새 대시보드에서 별도로 셉니다.
- 한 번의 모델 응답이 계약을 충족하면 재호출 없이 채택합니다. 모델의 모든 응답이 반드시 첫 시도에 성공한다고 보장하는 변경은 아닙니다.

## 세 플러그인 공통 — 삽화 태그

LIBRA/HAYAKU/Flashback은 `<lb-xnai ...>{{inlay::...}}</lb-xnai>` 또는 삽화 전용 자기닫힘 태그를 비교용 사본에서 제외합니다. 삽화 ID·operation·인레이 참조만 달라져도 실제 대화 수정으로 취급하지 않습니다. 실제 RisuAI 원문·이미지 태그는 그대로 보존합니다. 태그 안에 실제 대사나 서술이 들어 있으면 그 내용을 무시하지 않습니다.

## LIBRA 이전 수정 보존

중첩된 화면 요소 배열 때문에 자료가 있는 기억·세계 페이지에서 발생하던 appendChild 오류, 세계 검색 Enter 미반영, 정본 생성 뒤 실패한 상태 추적을 같은 실행에서 이전 구간부터 중복 분석하는 경로를 수정한 2.3.32 내용이 포함되어 있습니다. 정본 저장과 상태 추적 결과를 따로 표시하고 시간 측정 정보도 보존합니다. 이미 저장한 정본을 삭제하거나 다시 생성할 필요는 없습니다.

## 갱신 및 검증 범위

서버를 종료하고 DATA를 백업한 뒤 기존 DATA는 유지하고 PROGRAM만 교체합니다. RisuAI에는 plugins의 최신 JS를 기존 항목에 업데이트합니다. 구·신 플러그인을 중복 활성화하지 마세요. ZIP의 DATA는 신규 설치용 빈 구성입니다.

실제 배포 코드를 사용하는 Node/Chromium 검증이며, 모델·RisuAI API·저장소에는 시험 경계를 사용합니다. 사용자 DB, 외부 공급자, 모바일 실기기 시험은 별개입니다. 최신 검증의 실제 결과와 ZIP 체크섬은 배포에 함께 제공하는 검증 보고서에서 확인하세요. 개인 디버그 원문·API 키·실제 DATA는 배포에 포함하지 않습니다.
