# GRADIA 선택적 기억 연결

2026-10-22 · GRADIA 0.26.14

LIBRA·HAYAKU·Flashback은 어느 것도 GRADIA의 필수 플러그인이 아니다. 연결되지 않은 기본 상태에서는 외부 기억을 조회하지 않고 현재 대화·캐릭터·선택한 로어로 초안과 인풋 후보를 만든다.

## 연결과 사용

- 플러그인 모드는 기존에 허용한 owner 중 현재 응답하는 대상만 새 읽기에 포함한다. 없거나 제거된 owner가 건강한 다른 owner의 새 읽기를 막지 않는다.
- 서버 모드도 LIBRA 등록이나 플러그인 설치를 요구하지 않는다. HAYAKU만, Flashback만, 둘만 있는 조합을 지원한다. LIBRA는 사용 가능할 때만 통합 검색을 제공한다. 오래된 LIBRA 등록이 남았지만 공급자가 응답하지 않으면 나머지 owner를 사용한다.
- 서버 readonly 권한·owner별 native scope·저장 모드·DATA/reset·영수증·현재성 검사를 유지한다. 이전 연결 동의에 없던 owner를 자동으로 추가하지 않는다. 응답하지 않는 LIBRA를 예전 논리 검색으로 대신하지 않는다.
- IPC 읽기 전과 발급된 읽기의 현재성 검사 전에 가벼운 응답 확인을 한다. 기본 확인 시간은 1.5초이며 실제 큰 자료를 읽는 capture의 25초 제한은 유지한다. 확인 직후 공급자가 사라지는 경합이나 응답하는 공급자의 실제 읽기 정지는 capture 제한의 대상이다.

## 인풋 작성기

첫 외부 기억 조회가 공급자 부재·타임아웃으로 실패하면 기존 native 대화가 그대로인지 다시 확인하고, 외부 기억 없이 후보 생성을 진행한다. 추가 후보 모델 재시도나 과거 선택지 재사용은 하지 않는다.

취소, 연결 해제/교체, 설정·스코프·native 원본 변경은 대체 경로로 숨기지 않는다. 이미 수락해 사용한 기억의 현재성이 깨지면 파생 선택지·초안은 전달할 수 없다. 기억 기반 선택지의 재생성 도중 공급자가 사라져도 기존 선택지의 권한을 복구하지 않는다. 새 작성 작업은 외부 기억 없이 시작할 수 있다.

LIBRA 작성기 합계 3,000자와 일반 응답 12,000자 예산, 기존 NSFW 최종 전달 설정은 유지한다.

## 검증 범위

- `gradia_optional_memory_runtime_test.cjs`: 실제 GRADIA·upstream RisuAI 채널 함수, 제어된 owner/HTTP/model 응답으로 단독 실행, 두 작성 모드, 6개 부분 설치 조합, 저장된 연결 실패, 조회 전후 연결 소실, HAYAKU/Flashback만 있는 서버 모드의 초안·작성기 전달을 검사한다.
- 채널·SDK·연결·작성기 회귀는 권한/스코프/reset 검증, 취소, 재생성 및 이미 기억을 사용한 결과의 전달 차단을 함께 검사한다.
- 실제 LIBRA와 SQLite를 사용하는 기존 통합 읽기·인풋 작성기 회귀도 유지한다. 사용자 설치 RisuAI의 실시간 인증을 뜻하지 않는다.

공유 IPC factory의 생성본을 사용하는 LIBRA·HAYAKU·Flashback도 동기화한다. owner의 데이터 생산·저장 API를 변경하지 않는다. GRADIA의 보존된 readonly SDK 변경은 해당 변형의 SHA pin만 갱신한다.
