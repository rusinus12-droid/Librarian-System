# HAYAKU 3.0.91 — 응답 전체 중단 대신 항목별 보존

## 변경

정규 응답의 기존 완료 검사를 유지하면서, 그 검사를 통과하지 못한 응답에도 항목 수용 경로를 적용한다. 바깥 래퍼·스키마 표기·추가 데이터가 다르더라도 인식 가능한 패킷 객체를 찾아 각 후보의 정상 항목을 보존한다. 한 후보의 오류로 다른 후보의 항목까지 버리지 않는다.

단일 JSON 파싱이 실패하면 완성된 객체 구간들을 별도로 파싱한다. 여러 객체 또는 뒤쪽 미완성 객체가 있어도 앞쪽의 유효 객체를 검사할 수 있다. 각 객체에는 기존 중복 키 등의 파서 검사가 적용된다. 모델 메타 컨테이너는 먼저 제외하고, 중첩 객체 탐색은 깊이 12·노드 512, 완성 객체 추출은 32개로 제한한다. 경계나 객체 자체를 해석할 수 없는 조각은 추정하여 고치지 않고 진단에 남긴다.

항목별 필수 필드·근거·의존성 검사를 적용한다. 저장된 결과는 현재 원문과 다시 결속하고 물리 재조회로 검증한다. 형식 복구를 위해 모델을 추가 호출하지 않는다. 원응답·최초 검증 오류·항목별 제외 사유는 보존한다.

이 경로에서는 후보 중 하나를 권위 있는 답으로 선택하지 않으며, scalar State와 혼합 종합 요약을 합쳐 현재 상태로 만들지 않는다. 유효한 개별 과거 기억을 저장한다. 완전한 패킷 완료 판정은 별도다.

## 결과 표현

- 정상 항목을 실제로 저장: partial_memory_saved / 정상 기억 저장
- 분석 응답에서 저장 가능한 항목이 없음: no_storable_memory / 저장 가능한 기억 없음
- 저장·전송·원문 결속 문제: 해당 실패 상태를 유지하며 기억이 없었다고 바꾸지 않음

정상 항목이 저장된 경우 화면을 일괄 오류색으로 표시하지 않고, 완전 패킷 수와 부분 기억 저장 턴 수를 구분한다.

## 검증

hayaku_response_record_salvage_runtime_test.cjs에서 중첩 구조·스키마 표기 차이, 정상/오류 후보 혼합, 여러 JSON 객체, 뒤쪽 미완성 객체, 유효 기억이 없는 응답을 시험했다. 정상 항목의 실제 검색 가능 상태, 오류 항목 제외, 원응답 보존, 모델 호출 1회와 완료 판정 미승격을 확인했다.

기존 선택 회귀 17개 중 14개 통과. 새 수용 시험 및 스키마 래퍼·원문 경계·파생 기억 시험 4개도 통과하여 선택 범위 총 21개 중 18개 통과다. 나머지 3개는 이전부터 폐기된 실패 복구 화면 및 awaitingUserReview=true를 요구하는 계약이다. 일반 문장 응답의 예상 결과는 이번 사양에 따라 generation_failed에서 no_storable_memory로 갱신했다.

문법·SDK 동기화 및 최종 배포 해시를 검증한다. 실제 RisuAI 제공자 호출이나 사용자 T5 저장소의 재실행은 하지 않았다. 콜드스타트 배치의 기존 단위별 결과 처리와 이번 단일 분석 응답의 후보 구제 경로를 구분하며, 임의의 손상 데이터를 모두 복구할 수 있다는 의미는 아니다.
