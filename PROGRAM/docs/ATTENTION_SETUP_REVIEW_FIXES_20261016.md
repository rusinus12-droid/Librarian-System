# 채팅 알림·빠른 연결 재현 결함 후속 패치 — 2026-10-16

기준 커밋은 `0161a9f` (`claude/usability-improvements-products-23ax1n`)이다. `b54467a` 리뷰에서 재현한 아래 다섯 P2 결함이 이 기준에도 남아 있어 수정했다. 버전은 LIBRA **2.3.152**, HAYAKU **3.0.142**다. 기존 파란 L / 주황 H 알림 구분은 유지한다.

## 변경과 검증

| 결함 | 수정 | 실제 플러그인 회귀 |
| --- | --- | --- |
| HAYAKU를 꺼도 예약된 모델 호출이 실행됨 | 비활성화 설정 저장 시 자동 확인 타이머를 취소한다. 콜백 실행, probe 시작, 물리 모델 큐에서 제출하기 직전에 활성 상태·런타임 소유권을 재확인한다. 제출 전 취소는 연결 실패로 기록하지 않는다. | 예약 뒤 비활성화, 이미 배달된 콜백 실행, 다른 호출 뒤 큐 대기 중 비활성화를 각각 검사한다. 자동 추가 호출은 0회다. 이미 제출된 앞선 명시 호출은 1회로 유지된다. |
| 빠른 연결 저장 실패 후 일부 설정만 남음 | 생성 프리셋·전역 기본값·Librarian 연결·임베딩과 키를 기존 설정 트랜잭션으로 저장한다. 영속 읽기 검증과 호스트 인자 키 복원을 포함한다. GUI는 커밋 후 갱신하며 임베딩 재구축 상태 갱신도 커밋 뒤 시작한다. | 임베딩 저장 거부, 성공처럼 응답하지만 실제 저장을 누락하는 호스트, 최종 저널 제거 실패에서 기존 설정·키·GUI를 복원한다. 정상 동시 저장과 시험 중 다른 임베딩 편집의 보존도 검사한다. |
| 연결 완료 표시와 실제 분석 모델이 다름 | 새 프리셋을 Librarian 전용 연결에도 지정한다. 상태 표시도 실제 실행과 같은 `resolvePreset`을 사용해 단계 연결과 기본값을 해석한다. | 기존 `old-ai` 연결 및 오래된 argument가 있는 상태에서 빠른 연결 후 실제 기억 분석 요청의 endpoint와 model이 새 선택을 사용하는지 확인한다. |
| 기존 5턴 채팅의 누락 알림이 없음 | 가장 최근 구간이라는 이유로 누락을 숨기지 않는다. 같은 채팅·현재 예약 번호에 실제 대기/실행 중인 자동 분석이 있을 때 그 대상만 잠시 제외한다. 예약 종료·실패도 갱신 감지에 포함한다. | 플러그인을 불러오기 전부터 존재한 5턴 채팅이 `지난 대화 1구간` 알림을 모델 호출 없이 표시한다. 실패·다른 채팅·교체된 예약·자동 분석 비활성 상태가 누락을 숨기지 않는지도 검사한다. |
| 장치 저장 API가 있어도 확인 기록이 소실됨 | LIBRA 첫 설정 확인은 장치 로컬 저장 경로를 사용한다. HAYAKU 보조 모델 성공 캐시도 `getLocalPluginStorage` / `safeLocalStorage`에서 읽고 저장한다. | 전역 `localStorage`가 없는 호스트에서 LIBRA 팝업 닫기 후 재시작, HAYAKU 각 장치 저장 API로 성공 후 재시작을 검사한다. 플러그인 공용 저장소에는 이 장치 기록을 넣지 않는다. |

설정 시험이 실패하면 저장을 시작하지 않는다. 저장이나 영속 읽기 검증이 실패하면 기존 트랜잭션의 복원 결과를 반환한다. 호스트가 복원까지 거부한 경우에는 `rollback_failed`를 표시하며 복원 완료로 보고하지 않는다. 커밋 이후 임베딩 재구축 상태 갱신이 실패한 경우에는 연결 설정이 이미 저장되었다는 안내와 상태 확인 요청을 표시한다.

## 검증 파일과 결과

- `tests/attention_setup_review_fixes_runtime_test.cjs`: 실제 LIBRA GUI·공개 API·저장소를 사용하는 8개 시나리오. Full **8/8**, Min **8/8** 통과.
- `tests/hayaku_attention_probe_lifecycle_runtime_test.cjs`: 실제 HAYAKU 타이머/모델 큐/저장소를 사용하는 4개 시나리오. **4/4** 통과. 큐 진입 검사를 위한 비공개 함수 노출만 테스트에서 추가하며 큐와 제출 구현은 교체하지 않는다.
- `tests/memory_attention_owner_identity_runtime_test.cjs`: 두 플러그인의 양쪽 로드 순서에서 아이콘·콜백·해제 독립성 확인. Full **2/2**, Min **2/2** 통과.
- 갱신한 `libra_quick_connect_test.cjs`, `libra_quick_connect_flow_test.cjs`, `libra_zero_touch_attention_test.cjs` 통과. 기존 HAYAKU 알림·설정 트랜잭션·afterRequest 복구·은퇴한 백그라운드 복구 승인 검사, GUI 등록 격리, LIBRA 설정 영속 트랜잭션 검사도 통과.
- LIBRA·HAYAKU Full/Min 산출물 생성 및 구문 검사 통과. Full은 원본과 바이트 단위로 일치한다. 빌드 도구의 과거 크기 기준 경고는 생성 실패가 아니다.

## 검증 한계와 별도 미제 항목

- 실제 플러그인 소스를 VM과 합성 호스트에서 실행했다. 모델·임베딩 HTTP 응답은 합성이며 실제 제공자 과금 호출과 실제 RisuAI 창에서의 수동 검증은 하지 않았다.
- 기존 `libra_gui_memory_settings_transaction_test.cjs`와 `libra_gui_memory_settings_storage_modes_test.cjs`는 현재 화면에 없는 `.setnav [data-subtab="mem"]`을 찾아 실패한다. **패치 전 `0161a9f` 소스도 같은 호스트에서 같은 이유로 실패**한다. 해당 구형 화면 탐색 회귀의 갱신은 별도 미제이며, 이번 변경으로 전체 테스트가 모두 통과했다고 주장하지 않는다. 관련 기존 검사 묶음 결과는 14개 검사 단위 중 12개 통과, 위 2개 실패다.
- 자동 확인 취소는 아직 모델에 제출되지 않은 요청에 적용한다. 이미 호스트에 제출한 호출의 비용·실행을 되돌리지는 않는다.
