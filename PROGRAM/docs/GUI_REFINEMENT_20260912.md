# GUI 사용성 재정리 — 2026-09-12

대상: HAYAKU 3.0.81 / Flashback Memory 1.0.61.

사용자가 제공한 실제 호스트 스크린샷에서 로그 카드와 스코프 목록의 높이 부족, 하야쿠 관제창의 과도한 탐색·진단 노출을 확인하고 수정했다.

## Flashback

기존 activity 패널은 고정된 공간에서 두 로그 카드가 flex:1로 줄어들고 overflow:hidden으로 잘렸다. storage 패널 역시 고정 grid 비율 안에 헤더·검색·표를 넣어 표의 본문 공간이 사라졌다. 컨셉 적용 때 카드 여백만 늘린 것이 문제를 확대했다.

두 패널을 내용 높이에 따라 흐르고 세로 스크롤되는 구조로 변경했다. 로그 카드는 줄어들지 않으며 각 본문은 최대 440px에서 스크롤된다. 스코프 표는 최소 230px, 최대 520px(모바일 420px)을 확보하고 열 제목을 고정했다. 좁은 화면에서는 표를 가로로 스크롤한다. 삭제·선택·검증 로직은 변경하지 않았다.

실제 renderStorageRows에 가상 스코프 64개를 제공한 브라우저 검증에서 목록 높이 520px, 전체 스크롤 높이 4741px를 확인했다. 390px 화면에서는 목록 높이 420px, 가시 폭 274px, 표 폭 700px였다. 세 작업 로그의 본문 높이는 약 396px였고, 비어 있는 내부 오류 기록도 제목·검색·본문이 보였다.

## HAYAKU

상시 사이드바를 숨기고 상단에 관제창·설정 진입을 두었다. 관제창은 현재 상태, 패킷 수, 패킷 기록·구간 점검·운행 기록 진입, 최근 4턴의 실제 패킷 요약으로 구성한다. 기존 노선 그림은 관제창에서 제거했다. 전체 패킷 열기와 개별 패킷 선택은 기존 기록 뷰로 연결하고, 누락·검토 대기는 기존 점검 뷰로 연결한다. 새 렌더링 이후에도 전체 기록 버튼이 동작하도록 해당 영역에서 클릭을 위임한다.

세계선·실패 복구·서버 연결과 중복 진단은 ‘상세 상태와 관리’ 안에 접어 두었다. 기존 이벤트 대상과 기능은 유지했다. SDK의 테마가 루트에 제공하는 변수보다 가까운 GUI 컨테이너에 컨셉 팔레트를 선언해 호스트의 다크 변수에 의한 본문 색상 변경을 막았다.
