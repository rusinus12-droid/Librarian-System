# HAYAKU 3.0.90 — 단일 스키마 래퍼 수용

`{"hayaku.native_repair_output.v1":{"packet":{},"grounding":[]}}`를 표준 `schema/packet/grounding` 구조로 정규화한다. 외부 키가 정확히 하나이고 내부 packet과 grounding의 타입이 맞아야 한다. 내부 schema가 있으면 외부 스키마와 같아야 하며, 추가 키·중첩 래퍼·충돌 스키마는 추정해서 풀지 않는다.

원응답을 수정하지 않고 복제한 후보에 response_admission 진단을 기록한다. 정규화 뒤 기존 패킷·근거·항목 수용·저장 검사를 계속한다. 이 처리는 모델 호출을 추가하지 않는다.

실제 첨부 e83c9e85의 파싱 후보를 적용하여 최상위 세 키, 내부 패킷 여섯 영역, grounding 33개를 보존하고 기존 외피 오류를 통과함을 확인했다. 실제 원문이 첨부에 없어 전체 근거 검증은 수행하지 않았다.

새 hayaku_schema_wrapper_runtime_test.cjs에서 런타임 부분 저장 readback, 원응답 보존, 스키마 충돌·모호한 래퍼·잘못된 인용 거부, 단일 호출을 확인했다. 응답 수용·원문 경계·파생 기억/디버그 시험까지 총 4개 파일이 통과했다. SDK 동기화와 문법 검사를 수행하고 배포 해시를 갱신했다. 실제 RisuAI 복구 완료를 의미하지는 않는다.
