# LIBRA 2.3.56 콜드스타트 대기 및 실패 안내 수정

2.3.55 첨부 진단의 실행 `run_mtskcx5x_mfco5ow`는 Ollama Cloud / deepseek-v4-flash:0731에 한 번 제출됐습니다. 전송 출력 상한은 24,000, 추론 설정은 medium, 비스트리밍 요청입니다. 120초 후 LIBRA의 nativeFetch 타이머가 `NATIVE_FETCH_TIMEOUT`을 발생시켰고 응답 본문은 없었습니다. JSON 검증이나 State 저장 단계에 도달하지 않았습니다. 모델이 내부에서 무엇을 처리했는지, 언제 끝났을지는 이 진단만으로 알 수 없습니다.

- 실패 안내의 닫기 이벤트는 실행됐지만 `memory-failure-dismissed`가 화면 영역 갱신 목록에 없어 본문이 갱신되지 않았습니다. 실제 본문 갱신을 요청하도록 수정했습니다. 접은 뒤에도 미완료 구간 수와 상세 진단은 남고 새 실패는 다시 표시합니다.
- 구간 상태를 `미완료 · 새 분석 가능`, 작업 선택을 `실패 구간 새 분석`으로 표시합니다. 수동 콜드스타트는 여전히 missing 모드로 미완료 구간을 선택하고, 이전 임시 작업을 폐기한 뒤 새 분석을 실행합니다. 저장된 기억은 유지합니다.
- 직접 제공자에 연결한 정본 기억 분석에는 프리셋의 짧은 단계 제한 대신 최소 600,000ms(10분)의 응답 대기 시간을 적용합니다. 호스트와 백엔드 전달 timeout도 같은 값입니다. 이 정책은 상한 없는 대기나 자동 재호출이 아닙니다. 일반 연결 검사 등 다른 작업의 제한은 유지합니다.
- 실제 nativeFetch Promise를 별도로 추적합니다. 취소 또는 로컬 시간 초과 이후에도 물리 요청이 끝나지 않았다면 새 정본 분석과 이전 작업 삭제를 막습니다. 늦게 온 응답은 저장하지 않습니다. 종료 후 새 실행에서는 이전 임시 작업을 폐기합니다. 추적은 현재 플러그인 실행 세션에 한정됩니다.
- 정본 호출자가 이미 AbortSignal을 넘긴 경우에도 시간 초과 시 호스트에 중단 신호가 전달되도록 내부 컨트롤러와 연결합니다. 호스트가 중단을 따르지 않으면 실제 종료 전까지 요청 추적을 유지합니다.
- 진단에 설정된 시간과 실효 대기 시간, 물리 요청 종료 여부를 남깁니다. 전송 실패에도 제공자/모델을 기록하고 실패 UI는 저장된 오류 코드도 분류에 사용합니다.

모의 제공자를 사용하는 실제 cold start 경로에서 저장 readback, 취소, 늦은 응답 폐기, 중복 호출 차단, 실제 호스트 오류 전달을 검사했습니다. Edge 브라우저에서는 실제 DOM 클릭·갱신 큐·화면 영역 선택 코드를 연결해 닫기와 새 분석 선택을 검사했습니다. 실제 사용자 RisuAI 및 외부 모델 호출은 수행하지 않았습니다. 외부 서비스 자체 제한이나 느린 생성이 10분 안에 해결된다고 보장하지 않습니다.
