# Flashback / LIA 화면 읽기 실패 처리

작업 브랜치: `codex/flashback-offline-opening`, 기준 main `31a8e1a`.

## 확인한 차이

Flashback은 초기 skeleton을 띄운 뒤 `loadSettings → buildUiHtml → mountGuiRoot`에서 서버 오류가 전파되면 일반 화면을 구성하지 못했다. 설정 캐시를 비우고 읽기에 `MEMORY_SUITE_SERVER_UNAVAILABLE`를 주입하면 `showUi`가 reject하고 skeleton이 남았다.

LIA는 현재 `local_only` 정책이며 서버 저장 모드에 의존하지 않는다. 기존에도 `refreshPreview`가 오류와 12초 읽기 제한을 처리하며 다시 읽기·닫기를 제공했다. 따라서 유사한 화면 증상만으로 같은 서버 의존 문제라고 판정하지 않았다.

## 변경

- Flashback의 열기 실패를 내부에서 처리하고, 기존 테마의 명시적인 실패 화면을 표시한다. 자료 읽기 실패를 빈 저장소나 정상 판정으로 바꾸지 않는다.
- 다시 시도는 서버 오류일 때 기존 SDK의 인증된 공개 연결 검사 `testConnection`을 실행한다. 성공 후 일반 화면을 다시 연다. 실패 시 재시도 버튼을 복원한다. 사용자 클릭 없이 루프를 돌거나 모드를 전환하지 않는다.
- 연결 설정 버튼은 기존 SDK 연결 패널을 사용한다. 오류 화면에 raw 예외나 저장 값을 넣지 않는다.
- Flashback의 창 열기 시퀀스를 무효화해, 로딩 중 닫은 뒤 늦게 도착한 읽기 실패가 새 오류 화면을 그리지 않게 한다. 연결 검사 중 닫은 경우에도 다시 열지 않는다.
- LIA의 기존 loading/error 렌더러를 라일락 테마 카드로 정리한다. 호스트/로컬 자료 읽기 문제로 설명하며 원시 예외 대신 제한된 진단 코드를 표시한다. 실패 상태에서 메뉴로 다시 열 때도 읽기를 재시도할 수 있다.
- Persona 저장·채택·바인딩이나 기억 복구 엔진은 변경하지 않는다.

## 실행 증거와 한계

- `plugin_opening_failure_gui_test.cjs`: 5개 통과. Flashback 실패 처리·연결 패널 진입·중복 재시도 방지·복귀, 재시도 중 닫기, 첫 로딩 중 닫기, LIA 재시도와 Persona/바인딩 보존, LIA 늦은 응답 차단과 재열기.
- `flashback_maintenance_live_job_gui_test.cjs`: 6개 통과.
- `lia_random_chat_popup_test.cjs`: 2개 통과.
- `lia_pocket_gui_runtime_test.cjs`: 통과, 기존 7개 라우트와 렌더 중 쓰기 없음 계약.
- `sdk_session_availability_currentness_runtime_test.cjs`: 일반/LIBRA SDK 총 40개 통과. 인증된 공개 연결 검사만 기존 실패 캐시를 해제하는 계약과 URL·권한·세대 변경 시 오래된 검사 거절을 확인했다.

신규 테스트는 실제 플러그인 렌더러와 DOM 이벤트를 사용한다. 실패 주입과 서버 연결 검사 응답은 합성이며 실제 RisuAI/외부 서버/모델/과금 검증이 아니다. SDK 테스트는 로컬 합성 서버를 사용한다. 샌드박스의 임시 파일 rename 제한은 권한 제한 밖에서 재실행해 해결했다.

Chromium에서 두 플러그인의 실패 화면과 재시도 후 일반 화면 전체를 캡처했다. 390px 모바일 실패 카드의 clientWidth/scrollWidth는 Flashback 326/326px, LIA 322/322px이다.

기존 `lia_reopen_evolution_gui_test.cjs`는 Chromium에서 7개 페이지를 기다리는 단계가 30초 타임아웃으로 실패했다. 변경 전 main 소스를 동일한 호스트/Chromium 조건에 넣어도 같은 단계에서 타임아웃이 발생했다. 이번 변경의 통과 근거에는 포함하지 않는다. 전체 회귀·배포·실제 Risu 호스트 검증은 이 작업의 완료 근거로 주장하지 않는다. 기존 DATA 변경은 작업 대상에서 제외한다.

## GRADIA / HAYAKU 추가 패치

- GRADIA: 최초 설정 읽기 예외가 빈 창과 호출자 reject로 남는 경로를 처리했다. 실패 안내·재시도·닫기를 제공하며 중복 열기를 하나의 읽기로 묶는다. 닫기 후 늦은 결과는 화면을 그리지 않는다. 서버 저장소 장애로 단정하지 않는다.
- HAYAKU: 읽기 실패한 원장이 헤더와 상태 로그에서 정상으로 표시되지 않게 한다. 완료된 복구 작업이 있어도 현재 원장 실패가 우선한다. 오류 전에 확인한 현재 채팅 범위는 보존하고, 읽기 실패만으로 대화방 미선택으로 바꾸지 않는다.
- `gradia_hayaku_opening_failure_test.cjs` 3개 통과. 실제 렌더러·등록된 클릭 동작에 합성 설정/원장 오류를 주입했다. 그라디아의 예외 처리 검증이며 낮은 저장소 계층이 오류를 숨기는 모든 경우까지 검증했다고 주장하지 않는다.
- 그라디아 기존 프리셋·NSFW·수동 스킬 GUI 및 앞선 플래시백/리아 열기 실패 검증 16개 통과. 하야쿠 점검·복구 GUI 검증 10개 통과(로컬/서버 누락·콜드스타트, 읽기 전용, 닫기, 범위 전환 포함). 이번 추가 집중 검증은 총 29개 통과했다.
- 기존 LIBRA 실패 처리 경로는 변경하지 않았다. 네 플러그인의 변경은 별도 작업 브랜치에서 구현하고 검증했다.
