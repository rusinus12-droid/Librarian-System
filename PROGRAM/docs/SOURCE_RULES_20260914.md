# 사용자 정의 원문 비교 규칙 — 2026-09-14

대상: LIBRA 2.3.117, HAYAKU 3.0.124, Flashback 1.0.85. 공통 Source Edit Consent 1.6.1.

입력 방법은 [여는·닫는 표식 안내](SOURCE_DELIMITERS_20260914.md)를 참고하세요.

## 설정과 적용 순서

LIBRA는 설정 → 기억과 검색 → 원문 수정 확인에서 엽니다. HAYAKU는 복구 화면, Flashback은 고급 설정의 원문 수정 확인에서 엽니다. 각 카드에 여는 표식과 닫는 표식의 전체 형태를 넣고 추가 또는 Enter를 누른 뒤 규칙 저장을 누릅니다. ×는 항목 삭제, 모든 규칙 비우기는 전체 제거이며 저장 전까지 적용되지 않습니다. 예: `<original>` / `</original>` 또는 `[LBDATA START]` / `[LBDATA END]`. 각 최대 128개입니다. 제품별로 저장합니다.

1. **원문 영역 선택**: 해당 태그가 없으면 전체 본문, 정확히 하나의 정상적인 비어 있지 않은 영역이 있으면 그 내부를 사용합니다. 여러 태그 이름을 지정할 수 있지만 한 메시지에서 둘 이상 발견되면 선택하지 않습니다.
2. **영역 제외**: 태그와 내부 내용을 제외합니다. `lb-xnai` 기본 예시는 기존과 같이 삽화 호출만 담긴 경우에만 제외합니다. 서사 내용이 들어 있으면 보존합니다.
3. **태그만 제거**: 정상적인 태그의 표식만 제거하고 내용을 유지합니다.

세 항목을 **모두 비워 저장하면** 외부 태그·주석·삽화·제어문을 포함한 전체 사용자/응답 본문을 비교합니다. Suite 자체 운용 표식은 별도 내부 처리 대상입니다. 줄바꿈 표현과 앞뒤 공백은 정규화합니다. 수정 추적 모드 자체는 별도 설정입니다.

동일 태그를 둘 이상의 작업에 지정하면 저장을 거부합니다. 원문 영역이 비어 있거나 불완전·중복이면 전체 본문으로 돌아가며, 이후 제거 규칙도 적용하지 않습니다. 원문 선택 실패 시 전체 본문 비교를 유지합니다. 불완전한 제외/제거 태그는 그 작업에서 보존합니다.

## 삭제 가능한 기본 항목

외부에서 본문에 추가되는 삽화·제어 태그를 기본 목록으로 보여 줍니다. 삭제하고 저장하면 새 비교 경로에서 해당 태그를 다시 몰래 제거하지 않습니다.

태그 이름으로 표현할 수 없는 제어문은 **영역 제외** 목록에 예약 항목으로 표시됩니다.

| 항목 | 대상 |
| --- | --- |
| `@html-comment` | 완전히 닫힌 HTML 주석 |
| `@lbdata` | `[LBDATA START]`부터 `[LBDATA END]`까지 |
| `@inlay` | `{{inlay::...}}` 삽화 호출 |

위 예약 항목은 기존 설정과 API의 호환 표현입니다. 새 GUI에서는 시작·종료 표식으로 직접 추가합니다. 예약 항목도 삭제할 수 있습니다. 기존 원문 비교 설정은 새 규칙을 처음 저장할 때까지 기존 경로를 유지합니다. 새 규칙을 저장하면 명시적 규칙 경로로 전환하며, 과거 정리 함수의 암묵적인 태그/문장 삭제는 이어서 적용하지 않습니다. 따라서 일부 과거 정리 결과와 달라질 수 있습니다. 불완전한 제어문 뒤를 통째로 삭제하던 동작은 새 경로에서 하지 않습니다.

## 모듈 호환 예시

GigaTrans의 경우 **원문 영역 선택**에 여는 표식 `<GigaTrans>`와 닫는 표식 `</GigaTrans>`를 입력합니다. 구현 코드에는 GigaTrans 이름이나 전용 분기를 넣지 않았습니다.

```text
번역 전: Original                          → Original
번역 후: 번역문<GigaTrans>Original</GigaTrans> → Original
재번역: 다른 번역<GigaTrans>Original</GigaTrans> → Original
원문 변경: 번역문<GigaTrans>Changed</GigaTrans> → Changed
```

선택 영역 밖의 내용은 선택이 성공했을 때 비교 대상에서 빠집니다. 사용자는 원문 전체를 보존하는 태그를 지정해야 합니다. 현재 응답 불러오기와 규칙 적용 미리보기는 제거했습니다. 카드별 설명과 입력 예시를 제공합니다.

## 저장과 기존 기록

- 원문 규칙은 비교·분석용 본문을 만드는 데 적용합니다. 실제 RisuAI 채팅을 수정하지 않습니다.
- 기존 원문 근거, 기억, 패킷, State를 설정 저장만으로 재작성하지 않습니다.
- 저장 후 같은 값을 다시 읽어 확인한 뒤에만 메모리 내 규칙을 바꿉니다. 요청/승인 처리가 진행 중이면 규칙 변경을 거부합니다.
- 세 제품의 본문 캐시 키에 규칙이 포함됩니다. 같은 메시지에서 설정만 바뀌어도 다시 계산합니다.
- LIBRA/HAYAKU의 새 원문 근거에는 명시적 규칙의 정규화 버전과 규칙 해시를 기록합니다.
- 이미 다른 구조로 저장된 과거 기록의 기준을 **자동 재설정하지 않습니다**. 새 투영과 기존 기준이 다르면 기존 수정 확인/승인 절차로 남깁니다. 이것은 기존 근거를 새 규칙으로 소급 해석해 정상으로 승인하는 것을 막습니다.
- 플러그인이 소유하는 내부 메시지, 비활성 메시지 등의 메시지 소유권 판별이나 패킷 검증 권한을 태그 설정이 바꾸지는 않습니다.

공개 API: 세 제품의 기존 API 객체에서 `getSourceEditRules()`와 `setSourceEditRules({ignoredTags, unwrapTags, sourceTags})`를 사용합니다. 예약 항목은 `ignoredTags`에 넣습니다. 반환 객체의 `controls`는 예약 항목을 정규화한 목록입니다. 기존 `setSourceEditIgnoredTags`는 유지되며 새 규칙이 이미 있으면 다른 항목을 보존합니다.

## 검증 범위

- 공통 파서: 태그 없음, 최초 격리, 재번역, 실제 수정, 순서, 빈/중복/불완전 태그, 예약 항목 삭제, 충돌, 저장 실패, 새 VM 재시작.
- 실제 제품 런타임 fixture: LIBRA 정본 저장, HAYAKU 원장, Flashback 본문 저장 이후 규칙 전환과 수정 감지. 원문 채팅 보존과 캐시 무효화.
- 기존 DB/State/승인 회귀와 명시적 규칙을 켠 LIBRA 로컬·서버·미러 저장/롤백 회귀.
- Chromium의 실제 제품 GUI 렌더러: 카드에서 태그 추가·삭제, 기본값 삭제, 빈 설정 저장, 수정 추적 모드 변경.

검증 산출물과 변경 전 전체 사본: 저장소 루트의 `review_artifacts/source_rules_20260914/`. 실제 RisuAI에 설치하여 GigaTrans와 동시 실행하거나 외부 모델을 호출한 검증은 수행하지 않았습니다.

## 확인창 표시 순서

원문 수정 확인창의 z-index는 LIBRA 41, HAYAKU 42, Flashback 43입니다. 호스트 알림 카드는 각각 44, 45, 46입니다. LIBRA의 별도 z-index 덮어쓰기를 제거했습니다. z-index는 겹침 순서이며 제품별 확인 요청을 순차 처리하는 잠금이 아닙니다. 별도 iframe의 부모 겹침 순서까지 보장하지는 않습니다.

## 외부 규칙과 내부 운용 표식

사용자 목록은 외부 모듈·모델이 본문에 추가하는 표식을 위한 것입니다. `hayaku_packet_contract`와 Suite 기억·패킷 운반 블록은 내부에서 처리하며 목록에 노출하지 않습니다. 출처가 확인되지 않은 `dag_runtime_contract`는 기본 목록과 기존 LIBRA 자동 제거에서 제외했습니다. 일반 HTML 주석 전체를 내부 표식으로 간주하지는 않습니다.

이전 설정의 해당 기본 항목은 불러올 때 분리하고, 나머지 사용자 정의 규칙은 유지합니다. 설정을 읽기만 할 때 저장소를 재작성하지 않으며, 다음 설정 저장 시 읽기 검증을 거쳐 반영합니다. 과거 원문 근거나 기억을 소급하여 덮어쓰지 않습니다.
