# Flashback 미완료 벡터 복구 설계

## 목표와 범위

기존 ‘미완료 벡터 재생성’을 공통 ‘점검 → 복구 방법 선택 → 실행 → 검증’ 흐름에 연결합니다. 첫 적용 대상은 현재 로컬 저장 범위에 이미 원문과 작업 정보가 저장된 미완료 벡터입니다. 분석·임베딩 엔진은 기존 것을 재사용합니다.

점검과 실행 전 미리보기는 저장, 모델 호출, 네트워크 요청을 하지 않습니다. 서버 모드의 읽기 전용 점검은 별도로 검토하며, 이 변경으로 서버의 실제 복구까지 허용하지 않습니다. 원문 자동 재분석, 원문 전체 재구축, 세계선 정리, 아카이브 임베딩, 새 이관, 실패·결과 불명 요청의 자동 재시도는 포함하지 않습니다. 원본 원문과 이력은 보존합니다.

## 기존 화면과 공통 실행 제어

기존 벡터 재생성 버튼을 공통 제어기의 ‘실제 저장소 복구’ 작업에 연결합니다. 캐시 복구나 명시적 원문 재분석과 구분하며, 새 패널은 만들지 않습니다. 자동 복구·동기화·전체 재구축은 이번 단계에서 기존 경로를 유지합니다.

미리보기는 실행 가능한 로컬 미완료 원문 묶음을 확정합니다. 다른 아카이브·이관 필요·실패·결과 불명 묶음은 제외 사유와 함께 남겨 두며, 실행 가능한 묶음까지 일괄 차단하지 않습니다. 선택한 묶음이 모두 부적격이면 실행을 막습니다. 제외 대상을 다른 작업으로 바꾸거나 범위를 몰래 넓히지 않습니다.

실행 권한은 당시 화면, 채팅 범위와 원문, 선택한 원문 묶음과 리비전, 저장소 매니페스트와 작업 등록부, 저장 방식, 전역 설정·임베딩 프로필·세대에 묶습니다. 외부에는 범위·개수·작업 종류·비용 안내만 표시합니다. 호출자가 원문이나 설정을 바꿔 끼워 실행할 수 없게 합니다.

실행 권한은 첫 비동기 작업 전에 한 번만 소비합니다. 중복 클릭은 같은 실행을 기다리고, 다른 복구와 동시에 실행되지 않습니다. 공통 제어기에서 시작한 작업만 내부 실행 권한으로 기존 실행기에 진입하며, 공개된 ‘진행 중 검사 건너뛰기’ 옵션은 만들지 않습니다. 화면이나 범위가 바뀌면 새 미리보기가 필요합니다.

## 기존 엔진 재사용과 저장 직전 검증

기존 재임베딩 실행기의 사전 검증, 자격 증명 확인용 쿼리 요청, 요청 수·시간 제한, 영속 작업 등록부를 유지합니다. 선택한 원문 묶음 목록을 실행기부터 각 큐 처리와 작업 예약까지 전달하고, 확인용 요청 직전과 예약 직전에 다시 검증합니다.

이 작업에서는 큐가 이관을 먼저 수행하지 못하도록 합니다. 이미 영속화된 작업의 원문·등록부 검증은 유지합니다. 미리보기에서만 대상을 거르는 방식은 사용하지 않습니다.

기존 자격 증명 조회와 설정 로딩에는 동기화·이관 저장이 포함될 수 있습니다. 이번 작업은 점검에 도입한 엄격한 읽기 경로를 실행까지 전달하여, 이미 있는 자격 증명과 설정을 메모리에서만 해석합니다. 자격 증명 저장소·플러그인 인수 변경이나 설정 이관은 하지 않습니다. 권한·설정이 불명확하거나 충돌하면 확인용 요청 전에 중단합니다. 실제 확인용 요청과 임베딩 호출은 이 읽기 검증 이후 기존 엔진으로 수행합니다.

화면 수명·취소 검사를 기존 원문·프로필·세대·등록부·저장소 권한 검사와 함께 적용합니다. 후보 데이터 쓰기 전, 제공자 요청 전, 내부 비동기 처리가 끝난 뒤 실제 매니페스트를 쓰기 직전에 검사합니다. 아직 존재하지 않는 작업을 검증하는 대신 예약 전과 예약 후에 맞는 검사를 각각 사용합니다.

이미 발행한 호스트 저장 요청은 화면을 닫았다고 원자적으로 취소할 수 없습니다. 이 경우 후속 작업을 멈추고 실제 저장 여부를 보고합니다. 취소를 ‘저장 없음’이나 ‘전체 롤백’으로 표시하지 않습니다. 저장 응답이 유실되면 기존처럼 양쪽 데이터 세대를 보존합니다.

## 결과를 구분하는 기준

작업 결과에는 다음 상태를 따로 기록합니다.

- 진행 기록 저장: 없음 / 요청함 / 읽기 검증 완료 / 결과 불명
- 기억 데이터 게시: 없음 / 요청함 / 읽기 검증 완료 / 결과 불명, 작업·커밋 식별자 포함
- 제공자 요청: 미제출 / 제출 / 완료 / 확정 거절 / 결과 불명
- 작업 개수: 완료·미완료·실패·결과 불명·아카이브 대기
- 최종 검증: 완료 / 미완료. ‘정상 상태’ 여부는 별도 점검 결과

진행 기록은 실제 저장 요청 시점을 추적하고, false 반환을 실패로 처리하며, 저장소에서 같은 값을 다시 읽은 경우에만 검증 완료로 기록합니다. 기존 보조 함수가 오류 없이 반환했다는 이유만으로 저장 성공으로 판단하지 않습니다.

제공자 요청은 물리 요청 기록의 식별자·횟수를 기준으로 셉니다. 예약 전 확인용 쿼리와 원문 임베딩을 구분하고, 체크포인트 재사용은 새 요청으로 세지 않습니다. 영속 작업 식별자는 존재하는 경우에만 덧붙입니다.

최종 상태는 실행 차단, 검증 완료, 부분 성공, 확정 실패, 결과 불명으로 구분합니다. 일부가 완료되고 나머지가 남으면 부분 성공입니다. 모두 확정적으로 실패한 경우를 결과 불명으로 바꾸지 않습니다. 진행 기록만 저장된 뒤 중단된 경우에도 ‘아무것도 쓰지 않았다’고 표시하지 않습니다.

예약 저장이 적용된 뒤 응답만 유실된 경우처럼, 실행 함수가 정상 결과를 반환하지 못해도 이미 발행된 쓰기와 커밋 정보를 보존합니다. 큐의 오류 처리에서 이를 단순 실패 문자열로 축약하지 않습니다. 결과 불명 요청은 자동 재시도하거나 재개하지 않습니다.

화면이 바뀐 뒤에도 해당 실행에서 발급한 정확한 불변 결과만 보존합니다. 내부에서 발급했다는 사실만으로 성공 상태로 올리지 않습니다. 자격 증명, 제공자 원문 응답, 가공하지 않은 예외 내용은 결과에 포함하지 않습니다.

## 검증 기준

가짜 호스트·저장소·제공자를 제어하는 테스트로 다음을 확인합니다.

- 점검·미리보기에서 쓰기와 제공자 요청 0회
- 한 번만 실행, 중복 클릭 합류, 복구 작업 간 양방향 동시 실행 차단
- 각 비동기 구간의 화면·범위·원문·설정 변경과 저장 직전 중단
- 쓰기 중 취소, 예약 응답 유실, 일부 성공 뒤 실패에서 정확한 결과 유지
- 실패·결과 불명 요청 자동 재시도 없음
- 아카이브·이관·복구 필요 묶음이 실행 범위에 섞이지 않음
- 자격 증명·설정의 숨은 저장 없음, 진행 기록만 저장된 경우의 정확한 표시

기존 관련 테스트와 실제 Full·Min 산출물의 공개 실행 경로를 검증하고, 소스·산출물 해시와 매니페스트를 갱신합니다. 실제 Risu나 외부 모델을 호출하지 않습니다. 이번 결과를 모든 제품·서버 기능 검증으로 확대해서 표시하지 않습니다.
