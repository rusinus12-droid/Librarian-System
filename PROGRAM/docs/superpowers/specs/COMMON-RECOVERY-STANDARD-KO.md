# 프로젝트 공통 점검·복구 기준

작성일: 2026-10-05
상태: 프로젝트 전체에 적용할 공통 설계 기준. 제품별 구현·검증 상태는 아래 표와 구분합니다.

## 1. 적용 범위와 소유권

LIB의 LIBRA·HAYAKU·Flashback·LIA·RETRACE, WM, 독립 GRADIA에 적용합니다. 공통화하는 것은 점검·실행 권한·저장 검증·결과 표시 계약입니다. 각 제품의 기존 분석기와 저장소 어댑터는 유지합니다.

자료를 소유한 제품만 해당 자료를 복구합니다. 연결·조회 제품은 인증된 소유자에게 요청하거나 상태를 표시하며, 다른 제품의 기억을 직접 고치지 않습니다. GRADIA에는 이 기준을 이유로 자체 기억·아카이브·임베딩 저장소를 추가하지 않습니다. 소비한 자료의 권한·범위·최신성 검증과 자기 실행 상태에만 적용합니다.

원본 원문과 보존 이력은 임의로 바꾸지 않습니다. 명시적 재분석은 확인한 원문에서 파생 결과를 다시 만드는 작업입니다. 자동 점검이 원문 변경을 발견해도 모델 재분석을 시작하지 않습니다.

## 2. 점검과 미리보기는 읽기 전용

점검과 실행 전 미리보기에서는 다음을 하지 않습니다.

- 사용자 기억·설정·자격 증명·진행 기록 저장
- 저장소 준비, 이관, 로컬 자료 업로드, 인증 갱신이나 자동 재연결
- 모델·임베딩 호출, 불명확한 작업의 자동 재개

현재 승인되어 연결된 권한만 사용합니다. 추가 인증이나 연결이 필요하면 그 상태를 표시하고 명시적인 연결 흐름으로 넘깁니다. 자격 증명 조회는 존재 여부와 충돌·사용 가능 상태를 확인하며, 숨은 동기화나 저장을 하지 않습니다. 오류와 결과에 비밀값을 노출하지 않습니다.

서버의 기존 제한된 접속·보안 진단 기록은 유지할 수 있습니다. 이는 기억 자료 변경과 구분되는 운영 기록이며, ‘모든 서버 로그가 0회’라고 주장하지 않습니다. 클라이언트 점검이 별도의 진행 기록을 쓰는 근거로 삼지 않습니다.

## 3. 실제 권위와 정확한 대상에 묶기

로컬 모드에서는 검증된 로컬 권위를, 서버 모드에서는 인증된 서버 원본을 읽습니다. 서버 오류를 이유로 남아 있는 로컬 복사본을 대신 읽어 정상으로 판정하지 않습니다.

증명에는 적용 가능한 다음 항목을 묶습니다.

- 제품 소유자·자료 영역·범위와 저장 방식
- 서버의 실제 DATA 식별자·초기화 세대·연결 권한
- 현재 캐릭터·채팅·페르소나·분기 계보·원문 리비전과 실행 세대
- 범위별 매니페스트·원문·작업 등록부의 버전과 해시
- 전역 설정의 별도 저장 권위, 모델·임베딩 프로필
- 실행 화면의 수명과 선택한 대상 목록

서버는 저장 자료를, 제품은 현재 호스트·화면 상태를 각각 검증합니다. 서버가 현재 화면까지 증명했다고 간주하지 않습니다. 전역 설정과 각 아카이브는 자신의 권위를 따로 검증합니다. 읽는 중 어느 항목이 바뀌면 결과와 실행 권한을 폐기합니다.

## 4. 점검 결과와 실행 상태

점검 결과에는 검사한 범위·완전성·제외 사유를 함께 제공합니다.

| 점검 상태 | 의미 |
|---|---|
| 정상 | 해당 대상과 필요한 항목을 모두 검증했고 문제가 없음 |
| 문제 발견 | 검증된 대상에서 결함·미완료 작업을 확인함 |
| 점검 불완전 | 일부 누락·과대 자료·읽기 실패 등으로 필요한 검증을 끝내지 못함 |
| 점검 불가 | 권한·연결·저장 방식·기능 지원을 확인할 수 없음 |

부분 점검이나 미지원은 정상과 다릅니다. 준비되지 않은 저장소를 점검 중 생성하지 않습니다. 확인된 빈 범위와 확인할 수 없는 범위를 구분합니다. ‘실행이 끝남’과 ‘자료가 정상임’도 별개입니다.

## 5. 작업 종류와 명시적 실행 권한

| 작업 종류 | 실행 기준 |
|---|---|
| 파생 캐시 복구 | 원문·영속 기억·자격 증명·모델 호출과 분리된 기존 안전 정책 적용 |
| 명시적 재분석 | 사용자가 확인한 원문·선택 범위에 한해 기존 분석기를 한 번 실행 |
| 실제 저장소 복구 | 작업 범위·쓰기·모델 비용 가능성을 확인하고 별도의 물리 복구 권한으로 실행 |
| 연결·이관·소유자 인계 | 해당 제품의 기존 명시적 절차와 권한 검증을 유지; 위 작업으로 위장하지 않음 |

기존 안전한 캐시 자동복구 정책은 별도로 유지할 수 있습니다. 이 기준이 모델 재분석·원문 수정·물리 복구의 자동 실행을 허용하지는 않습니다. 정상 동작으로 캐시가 다시 채워졌다면 이전 복구 기록을 근거로 결함이 반복된다고 표시하거나 같은 복구를 몰래 재실행하지 않습니다.

명시적 작업은 대상과 원문·권위 증명에 묶인 불투명한 일회성 실행 권한을 사용합니다. 첫 비동기 작업 전에 소비하고, 중복 클릭은 같은 실행 결과에 합류합니다. 호출자가 대상·설정·증명 내용을 바꿔 끼울 수 없습니다. 사용한 권한이나 오래된 화면으로 새 실행을 시작하지 않습니다.

같은 작업 ID로 결과를 다시 조회하는 것은 허용하지만, 그것이 새 모델 호출이나 새 쓰기 허가는 아닙니다. 실행 중 공통 제어기와 기존 제품 실행기는 서로를 차단해야 합니다. 화면을 닫아도 진행 중인 실행 잠금이 조기에 풀리지 않습니다.

## 6. 저장 직전 검증과 멱등성

기존 엔진과 저장 경로에 원문·범위·권위·취소 검사를 전달합니다. 대상 목록은 미리보기뿐 아니라 각 큐 처리와 예약까지 유지하며, 저장 직전 내부 비동기 처리 뒤에 다시 검사합니다.

서버 저장은 필요한 읽기 집합의 버전·해시·작업 ID를 같은 조건부 저장 트랜잭션에서 확인합니다. 매니페스트 몇 행만 비교했다고 원문과 작업 등록부 전체가 보호된 것으로 보지 않습니다. 로컬에서는 제품의 기존 잠금·새 세대 준비·게시·읽기 검증을 사용합니다.

이미 발행한 호스트 쓰기나 제공자 요청은 취소로 없었던 일이 되지 않습니다. 후속 작업을 멈추고 실제 결과를 보존합니다. 응답 유실 시 안전한 이전·새 세대를 유지하며, 확인 전 삭제나 전체 롤백을 주장하지 않습니다. 같은 작업 ID는 같은 의도·대상·내용에만 재사용하며, 결과가 불명확하면 먼저 조회·검증합니다.

## 7. 결과는 독립된 효과로 기록

| 효과 | 공통 상태와 증거 |
|---|---|
| 진행 기록 | 없음 / 요청함 / 읽기 검증 완료 / 결과 불명 |
| 기억 자료 게시 | 없음 / 요청함 / 읽기 검증 완료 / 결과 불명; 작업·커밋 ID 포함 |
| 제공자 요청 | 미제출 / 제출 / 완료 / 확정 거절 / 결과 불명; 실제 요청 ID·횟수 포함 |
| 대상 작업 | 완료·미완료·실패·결과 불명·제외 대상 수 |
| 최종 점검 | 검증 완료 여부와 별도의 정상 여부 |

확인용 쿼리, 실제 분석·임베딩 호출, 체크포인트 재사용을 구분합니다. 영속 작업 ID가 생기기 전의 확인용 요청도 비용과 요청 수에 포함합니다. 이미 계산된 결과의 재사용은 새 물리 요청으로 세지 않습니다.

저장 보조 함수가 반환했다는 이유만으로 성공으로 기록하지 않습니다. 실제 쓰기 발행과 읽기 검증을 추적합니다. 예약 함수가 결과를 반환하기 전에 저장된 경우에도 커밋·불명 상태를 보존합니다. 진행 기록만 저장된 뒤 차단되었다면 ‘아무것도 쓰지 않음’으로 표시하지 않습니다.

최종 실행 상태는 차단 / 검증 완료 / 부분 성공 / 확정 실패 / 결과 불명입니다. 일부 완료와 남은 작업을 함께 표시하고, 모든 작업의 확정 실패를 불명으로 바꾸지 않습니다. 내부에서 발급한 정확한 해당 실행의 불변 결과만 인정하며, 출처가 맞다는 이유로 성공으로 승격하지 않습니다. 화면 이동 뒤에도 실제로 발생한 효과는 유지합니다.

## 8. 연결 끊김·재접속·역방향 이관

결과 불명 작업은 자동 재시도하거나 모델 호출을 다시 시작하지 않습니다. 재접속은 명시적인 연결 흐름에서 수행합니다. 같은 DATA와 초기화 세대인지 확인하고, 같은 작업 ID와 실제 저장 자료를 먼저 조회합니다. ‘작업 ID 없음’ 응답만으로 중복 호출이 안전하다고 판단하지 않습니다.

서버에서 로컬로 되돌리는 등 권위를 옮기는 작업은 새 복구 진입을 먼저 막습니다. 실행 중이거나 결과가 불명인 영속 효과를 해결하기 전에는 기존 권위를 내리지 않습니다. 브라우저 재시작·잠금 만료·현재 실행기의 유휴 상태만으로 이 제한을 해제하지 않습니다. 이어서 처리할 작업은 확인된 상태로 새 미리보기를 제시합니다.

| 제품 | 적용 역할 | 현재 확인된 구현 | 아직 별도 구현·검증이 필요한 범위 |
