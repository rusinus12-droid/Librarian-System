## 변경

1. **같은 장소의 일반 명사 재언급**: 정본은 검증된 이전 장소명과 동일한 엔티티에 한해, 같은 인물의 확인된 현재 위치 사실과 현재 원문의 `방`·`이 방`·`이곳` 등을 대조한다. 문·바닥만 인용된 경우 해당 인물의 위치 인용부터 앞으로 160자 이내에 있는 실제 장소 표현을 추가 인용한다. 이동·다른 방·여러 후보·인물 위치 불일치는 자동 연결하지 않는다. 새 사실 수를 선별하는 제한이 아니라 동일 장소를 입증하는 근거 범위다.
   - 정본에는 원문 표현과 실제 인용을 저장하며 기존 장소 ID로 State를 구성한다. 이름 검증 계약과 서버 코덱을 완화하지 않았다.
   - `contextualReferences`는 memory ID·revision·artifactDigest·tempId·표현에 묶인 파생 Registry 기록이다. `방`을 전역 별칭으로 만들지 않으며, 기억 근거 인덱스도 이 정본에 한해 같은 장소를 읽는다.
   - Micro도 같은 인물의 직전 위치와 단일 후보를 대조해 같은 장소로 연결한다.
2. **서사 제목 공유**: 프롬프트에 내용을 구별하는 제목을 요구한다. 서로 다른 생명주기가 같은 제목을 공유하면 화면에서 요약을 덧붙여 구별한다. 저장 정본·생명주기 ID·연결 판단은 바꾸지 않는다. 내용도 같을 때의 표시 구분은 순번을 사용한다.
3. **외형의 인물·인용 귀속**: 색상과 머리·눈·피부 조합을 각 사실의 인용과 인물에 대조한다. 배치 전체의 다른 인물 문장으로 정당화하지 않는다. 이름이 생략된 짧은 인용은 같은 문장만 확인하며, 두 문장의 대명사는 해당 인용 안의 이름과 같은 신체 부위 근거가 필요하다. Micro에도 적용한다.
   - 지원되는 항목은 외형 State에 남기고 근거 없는 항목은 각각 `character_note`로 보존한다. 여러 항목을 합친 메모의 길이 초과나 생성 ID 충돌 때문에 항목이 사라지지 않도록 했다.
   - 기존의 로어 문구 검사는 항목별로 적용한다. 배경·성격 등 다른 프로필 필드는 이 외형 검사를 받지 않는다.
   - **과제 문서의 전제 정정**: 세희의 붉은 눈은 실제 T10에 명시돼 있다. 차단 대상은 색 자체가 아니라 잘못된 인물·인용 귀속이다.

## 남은 문제와 검증 범위

아래 서사 보류는 최초 세 과제 검증 시점의 기록이다. 후속 연결 복구와 실제 재검토 결과는 마지막 절에 기록했으며, 해당 1건은 해결됐다.

- 최종 실제 재분석과 최종 응답 재적용에는 서사 1건이 `thread_link_pending:candidate_status_disallows_link`로 남았다. 모델이 새로운 **스피커 통화 과제**를 **학교에 전화해 등교 여부를 확인하는 기존 과제**의 alias에 `reaffirm`으로 연결했다. 데이터 부재가 아니라 모델의 잘못된 연결 제안이며 런타임 보류는 정상이다. 후속 과제는 새 과제로 남기거나 맞는 후보를 다시 선택하는 복구 경로다. 첫 실행 응답만 재적용한 경로에는 참여자 불일치 보류 2건이 남는다.
- 첫 실측 T1~5의 ID 없는 사실 1건은 형식 검증에서 거절됐다. 이번 세 과제에 포함되지 않는 모델 출력 형식 문제이며, 전체 원문 사실이 빠짐없이 추출됐다고 주장하지 않는다.

- 실제 RisuAI 앱 설치·GUI 조작·기존 기억 재분석은 수행하지 않았다. 화면 검증은 production reader와 DOM 모델이다. 커밋·push·버전 변경은 하지 않았다.

## 후속: 잘못된 후보 연결의 복구

사용자가 남은 1건의 해결을 요청해 추가 보강했다. `repairUnifiedThreadLinks`는 검증된 현재 사실 중 활성 이야기의 `reaffirm`이 실패하고 참여자가 모두 독립적으로 확인된 경우에만, 후보 목록이 완전할 때 한 번 재검토한다. 모든 해당 사실과 모든 검증 후보를 보내며 개수로 선별하지 않는다. 정상 연결에는 추가 호출이 없다.

- 모델은 `new`(별개 과제), `link`(동일 과제의 올바른 후보), `hold`(불확실)만 제안한다. 사실 내용·참여자·상태·근거를 변경할 수 없다. 반환한 인용은 기존 사실의 인용과 정확히 일치해야 한다.
- `new`는 별도 생명주기로 기록한다. 같은 종류·참여자·요약의 기존 이야기가 있으면 신규 중복 등록을 거부한다. 기존 완료 과제에는 쓰지 않는다.
- `link`는 기존 생명주기 검증을 다시 통과해야 한다. 참여자·종류·문구·후보 상태가 맞지 않으면 계속 보류한다. 종료·재개·대체를 임의로 수행하지 않는다.
- 잘못된 응답·중복 제안·실패는 기존 보류를 유지한다. 원문이 바뀌면 커밋을 거부한다. 승인된 판단은 기존 정본 형식으로 저장하므로 재생·재시작에는 모델 호출이 없다.
