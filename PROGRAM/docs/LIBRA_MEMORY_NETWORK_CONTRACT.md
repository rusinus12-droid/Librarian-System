# LIBRA memory network — A1/A2/B1 staged contract

## Document role and successor design (2026-10-13)

This document records the A1/A2/B1 implementation and its qualified boundaries. The successor architecture is [LIBRA unified memory engine design](LIBRA_UNIFIED_MEMORY_ENGINE_DESIGN.md): canonical, Micro, State and lore participate in one graph and retrieval controller, and existing caches, Memory Lane and indexes are redesigned together.

The implementation baseline for that design is ca40d76450784f4ff6397666d47aba079415eec9. The new node/edge model, activation propagation, cache manager, lane scheduler and durable graph indexes are proposed work, not current APIs. Existing A1/A2/B1 safety and evidence claims below remain scoped to their recorded source/tests. The current scorer-preservation and pathBonus=0 rules describe the migration stages; they do not define the final propagation algorithm. The successor's UM0–UM6 stages map and qualify the later B2/C2/D1/D2 work.

A1 is a canonical registry transition on the approved A0 recall baseline. It preserves the existing shortlist, associative admission, BM25F/dense scorer, ranked-list fusion, gate, excerpt, and packing behavior. C2/D1 will replace that flow with the approved single frontier/scorer; A1 does not claim that engine is active. Normal runtime parity targets are `plugin_only` and `server_only`. Mirror tests remain migration evidence.

## Pure factory and interfaces

`PROGRAM/tools/libra_memory_network.cjs` exports `createMemoryNetwork({tokenize, adapters})`. `adapters.hash(serialized)` supplies a deterministic compatibility hint and optional `adapters.rowForUnit(unit,input)` supplies the original hydrated row. The factory performs no storage/provider calls, source rescans, clocks, timers, embedding, or automatic analysis. The runtime embeds its exact `toString()` through the unique `LIBRA MEMORY NETWORK` marker. `sync_libra_memory_network.cjs --check` and the LIBRA builder reject missing, duplicate, reversed, or stale factory markers before output assembly.

Source/analysis revisions (including the memory revision fallback) support null/absent, opaque strings, or nonnegative safe integers. Empty revision strings remain legacy unknown metadata. Structured objects, arrays, booleans and other numeric values are rejected with `LIBRA_NETWORK_REVISION_TYPE` before output freezing. Explicit `claim.entityIds` entries support nonempty strings, trimmed into primitive posting keys; object IDs and other types are rejected with `LIBRA_NETWORK_ENTITY_ID_TYPE`. Rejection leaves caller data and capability-bearing memory/row objects untouched.

Stable source atoms (`ownerNamespace`, `originScope`, `objectUUID`, `birthIncarnation`) and typed claim identifier atoms (`actorId`, `targetId`, `predicate`, `direction`, `polarity`, `certainty`, source anchors) support strings; absent/null and blank optional identifiers cannot establish complete identity. Tokenizer posting keys likewise support strings and cannot retain caller objects. Identifier objects and other scalar types reject with `LIBRA_NETWORK_IDENTIFIER_TYPE`, rather than becoming `[object Object]` identity atoms. Typed semantic values and time objects remain supported and copied into the projection.

Network identity/binding labels combine the adapter hint with a factory-local SHA256 fingerprint; rendered-text hashes use SHA256 directly. The factory-local UTF8/SHA256 implementation is adapted from `MemorySuiteComputeBridge` in `PROGRAM/plugins/LIBRA.js` (the existing `utf8Bytes` and `sha256Hex` helpers). The self-contained synchronous browser factory cannot use Node crypto or await SubtleCrypto. Its manual UTF8 fallback replaces unpaired surrogates consistently with TextEncoder; tests compare ASCII, non-ASCII, astral and unpaired-surrogate outputs with Node crypto. Existing core `digest/createTextHasher` and canonical physical-proof digest behavior remain unchanged.

Exact normalized logical identity and full binding/body tuples are held privately per issued unit. Registry duplicate counting uses exact typed semantic tuples; candidate merging and binding replacement compare exact tuples, never hash labels alone. Registry adapters consume units issued by their own factory. An unexpected equal source or node label for unequal exact identity tuples throws `LIBRA_NETWORK_IDENTITY_LABEL_COLLISION` with partial reason `identity_label_collision`, leaves the existing source/lease intact, and records that reason/counter in diagnostics. Same logical identity with unequal exact binding replaces the old candidate and invalidates old leases even when binding labels match. This guards the known runtime short-hash source collision and adversarial adapter hints without changing legacy digest users.

| Interface | Produces and consumes in A1 |
| --- | --- |
| `project({memory,source,frame,row})` | Frozen `EvidenceUnit[]`; one canonical candidate unit contains source/claim identities, representation/binding and token/entity/predicate/time postings. Claims remain separately identified inside the candidate. The row stays in a private WeakMap. |
| `upsert(units,{frame,row?,access?})` | Coverage with indexed units, canonical candidate count, identity coverage, and complete/partial status. Owns one active registry. Physical binding mismatch replaces the candidate and invalidates old leases. Frame changes require explicit invalidation. |
| `invalidate(refs,liveEpoch)` | Removes source IDs (`string` or `{sourceId}`) and their postings. Numeric live epoch advances the current frame; a complete live frame can also replace owner/scope/worldline/as-of/mapping. Epoch rewind rejects. |
| `discover(accessResults,registry?)` | One `SingleCandidate` per unit with original row and merged access evidence. Array results use `{unitId,kind,score}`; posting access uses `{tokens,entities,predicates,times,semanticIds}`. Semantic access does not require lexical overlap; lexical access does not require an embedding. |

`scoreCandidate` and `retrieve` are deliberately absent in A1; those interfaces belong to later implementation. Internal compatibility helpers `projectCanonical`, `createRegistry`, registry `upsert`, `invalidate`, `discoverCandidates`, `rows`, `capture`, `isCurrent`, and `diagnostics` support precise binding tests and subsequent adapters. Registry capture returns an opaque issued object: a JSON clone/forged lease cannot certify currentness. Candidates and projection/binding objects are frozen. Their original runtime rows remain mutable for the existing scorer, without changing registry identity. Access score is max per channel, and path bonus is always zero; repeated access never awards additional relevance.

## Identity is separate from authority

A complete `SourceObjectID` requires caller/runtime established `ownerNamespace`, `originScope`, source `objectUUID`, and `birthIncarnation`. Surface message ID, array position, same turn, same display name, changing body hash, or producer tempFactId does not prove those anchors. A copied source must have a new local UUID/incarnation with any origin link handled explicitly by its owner.

A complete stable `ClaimID` is runtime derived from the source object plus typed actor ID, target ID, predicate, direction, value, polarity, time, certainty, and explicit source anchors. Identical typed meaning and source attachment may preserve identity across text/revision changes. Changed meaning, negation, target/time/certainty, split/merge attachments, or different entities with the same name produce distinct IDs. Complete stable claim identity does not use or adopt caller-supplied claim IDs. Partial legacy identities hash the full revision-bound claim/body representation, so caller identity metadata can change a derived partial hash but cannot declare an ID or authority. Duplicate matching claims have ambiguous one-to-one assignment and fall back to partial, revision-bound identities. Ambiguous legacy sources/claims remain revision/body-bound with partial coverage; this stage never launches corpus reanalysis or converts source-only/State/lore into confirmed events.

`EvidenceBinding` independently contains current owner/scope/worldline/as-of, active mapping, live authority epoch, source/analysis revisions, physical record key/digest, source digest, semantic digest, rendered hash, projection version, and embedding space. Representation identity binds text/projection/space separately from logical claims. Equal source/claim IDs do not authorize reuse of a changed vector or representation.

The registry's live epoch is supplied by the trusted runtime, never restored from a canonical payload. For `A(epoch7) → B(epoch8) → A(epoch11)`, source identity and A text hash may match but an epoch7 job/readset is invalid. Candidate replacement/revocation also invalidates its private issued lease even if a binding is later reused. Runtime restore generation is the existing nonrewinding `state.microRestoreGeneration`; server owner identity additionally binds the exact normalized mode/client-data-instance/connection tuple through stable JSON, rather than its legacy short hash. Final readsets capture this frame privately and check owner, scope, worldline, restore generation, and active manifest revision before and after physical evidence reads. Existing response-boundary validation enforces the selected temporal view. A changed frame fails open through the existing consumer error path.

## Runtime capability and parity boundary

Every canonical hydrated row, including A0 associative rows, passes through `project → upsert → discover` before the existing batch scorer. A1 kept Micro separate; B1 adds the access and verified-row path described below. The adapter returns original row and memory references; it never serializes, spreads, clones, or adds public JSON proof flags to capability-bearing memories. Existing canonical proof WeakMaps and final physical owner-store validation continue to supply authority. Projection identifiers themselves certify no physical authority. The network's final frame is attached to the original recall result in a private WeakMap and retained only in the existing bounded private readset registry.

`Runtime.lastMemoryNetworkDiagnostics` exports counts and coverage only, with no proof objects, raw body, rows, or lease handles. Counters cover inserted projections, upserts, merges, posting additions, discovery calls and invalidation calls. They do not claim to measure or fix full catalog preparation, hashing, vector reads or warm corpus cost; A2 owns those costs. No GUI, server tokenizer/SDK, provider/model config, shared pins, or installation is changed.

## Evidence

Projection tests additionally cover unsupported revision/entity/identifier object rejection without caller mutation, known runtime-hash and constant-hint collisions, local UTF8/SHA256 correctness, unexpected strong-label collision diagnosis, and exact-binding lease replacement. They cover semantic equivalence/change, split/merge, duplicate ambiguity, same-name entities, owner/scope/incarnation separation, revision-bound legacy IDs, postings, channel-independent discovery, merged accesses, frozen identity, revocation and ABA old-job rejection. The actual-hook parity test compares selected identities, delivered source text and complete provider-packet bytes against A0 for plugin_only graph OFF/ON and server_only, with nonce/timestamp as separately checked sidecars. A synthetic epoch advance at the actual final physical read rejects identical A bytes. A0's actual-hook regression and existing canonical/recall/freshness suites remain required. Mock providers and synthetic interleavings attest wiring/safety, not real-model accuracy or performance envelopes.

## A2 derived paged access and measured costs

`createPagedIndex({pageSize=256})` retains owner-bound token/entity/predicate/time postings by page, reverse source dependencies, exact metadata tuples, and optional packed Float64 vector pages. It contains no canonical row or proof capability. It changes neither A1 candidate discovery nor any scorer, frontier, relevance weight, final gate or packing policy. Page size controls allocation and cooperative work, not corpus coverage, candidate count, token count or final injection size.

`reconcile({frame,revision,items})` fully verifies a metadata snapshot when the owner does not provide a trusted revision. Items contain `{id,fingerprint,postings,dependencies,vector?}`; IDs and posting/dependency keys are nonempty strings. All supplied items participate, including oldest items. Exact metadata tuples and unchanged supplied double-precision vector values decide reuse; a hash label or cached object alone does not. Changed rows replace their postings and vector slot; missing IDs delete them, and a changed order moves the affected posting pages. Owner/scope/worldline/as-of/epoch changes discard the previous index. `activeSourceMapping` is a revision binding rather than a stable owner identity. This derived cache is never proof that an owner row is physically current.

A capable trusted adapter may use `trustedRevision:true` for an unchanged opaque revision, with no metadata traversal. For a changed revision it must provide the exact previous `fromRevision`, `verifiedChangedIDs:true`, exhaustive unique `changedIDs` matching `items`, and `deletedIDs`. An append optimization additionally requires `append:true,prefixVerified:true`; `orderIDs` is a verified complete order when explicitly supplied. These flags describe trusted adapter evidence, not a public proof or an authentication mechanism. Neither plugin_only nor server_only currently wires a trusted owner-wide changed-ID signal to this fast path. Tests exercise it with synthetic acknowledged revision receipts.

`reconcilePaged(snapshot,{checkpoint,yieldPage})` performs the same validation and mutation in cooperative batches. The caller owns cancellation and scheduling. Only one reconciliation may write an index at a time; overlapping synchronous or paged calls reject with `LIBRA_NETWORK_RECONCILIATION_BUSY`. A dependency invalidation during suspended work aborts that work with `LIBRA_NETWORK_RECONCILIATION_INVALIDATED`; it cannot publish complete coverage afterward. Invalid metadata rejects before mutation. An already dirty index rejects any trusted delta with `LIBRA_NETWORK_DIRTY_SNAPSHOT_REQUIRED`; only a fully traversed owner snapshot can recover coverage, so an unrelated delta cannot erase outstanding dependency refresh or cancelled mutation work. Cancellation after mutation starts leaves explicit partial coverage (`dependency_refresh_required`) until an owner refresh completes. `invalidateDependencies(sourceIDs)` removes only reverse dependents and likewise requires refresh. Query cursors are privately issued, generation-bound objects; forged, cloned, changed-query and stale cursors reject. `query({tokens,entities,predicates,times,cursor?,frame?})` reads the required posting pages and emits one result page in canonical order; it does not materialize a common token's entire candidate set before returning the first page. Ordinary queries beyond 64 tokens are paged without a token truncation rule. `pageExhausted` describes exhaustion of currently available postings; `complete` additionally requires a prepared, clean index with no reconciliation in progress. Dirty or in-flight posting and dense reads explicitly return partial coverage.

`scanDense(queryVector)` measures exact packed dot access over every retained vector in a single caller-established embedding space. It returns scanned-vector/dimension/dot-term/byte counts and a checksum, without ranking or gating. Packed values use Float64 to preserve the supplied JavaScript number values; unchanged reuse compares those values without retaining another full decimal vector JSON copy. Already quantized Float32 input retains its supplied numeric values, but the index does not silently quantize doubles. Dense byte reads count 8 bytes per dot term. This synthetic access probe is distinct from the production dense scorer and from real embedding quality. The factory currently validates dimension and finite values only: its normalized owner frame does not retain provider/model/task/profile/viewer/reset or representation identifiers, and `scanDense` accepts a bare vector. Same-dimension vectors from different models are therefore not independently rejected by this access API. A2 runtime postings contain no vectors; this synthetic dense helper must not certify model/profile-safe product reuse. An explicit vector-space/representation binding and query contract belongs to B2 and the staged index redesign. Packed O(Nd) scanning is permitted measured work; ANN is not introduced.

`bytes.packedVectors` counts allocated typed-array bytes; `bytes.exactMetadata` counts UTF8 serialization of retained exact metadata tuples. These are known representation byte counts, not exact heap retention. Map/Set entries, string storage, duplicated keys, record objects, cursor sessions, prepared snapshots, and the runtime catalog/WeakMap caches are not included. The inspector labels `accounting:serialized_metadata_and_typed_arrays_only`, `heapOverhead:unmeasured`, and `byteBounded:false`. The four-scope cache eviction count does not enforce a byte budget. Full in-memory byte bounds and durable shards remain a later staged architecture gate.

Metadata loops checkpoint at row zero but yield only after nonzero completed batches; sub-page preparation does not introduce an unnecessary timer turn. Cooperative full-page work remains interruptible.

The actual registered beforeRequest path retains a paged metadata cache over **every existing canonical catalog entry**, bound to the existing exact owner frame. Only changed entries reconstruct postings. This optional preparation runs only in guarded normal requests; direct preview and request-local read-only recall keep the established A1 scheduling and proof/currentness path without acquiring it. A queued derived-vector manifest publication during the normal request preparation invalidates cache completeness and fails closed for selected evidence; the base model request continues. Only an exact `LIBRA_NETWORK_RECONCILIATION_BUSY` exception skips optional preparation without waiting, increments `indexBusySkips`, and records `indexLastSkipReason:reconciliation_busy`; all post-preparation binding, cancellation and A1 source/proof checks still run. Other index exceptions propagate. This is an explicit availability limitation for binding changes, not a general guarded-retry or race-recovery implementation. The busy seam test exercises two guarded recalls with a paused real factory writer; full simultaneous beforeRequest publication/cancellation behavior is not certified. The cache is an access preparation for later stages; A1 discovery/scoring remains enabled. Existing catalog compact-middle and section caps remain representation limits, reported separately from complete traversal of the supplied catalog. No recent-N corpus cutoff or full-accuracy claim is introduced. The A2 cache remains canonical metadata access; B1 below adds independent Micro registry access.

`inspectMemoryNetwork({scopeKey})` reports `{coverage,jobs,io,bytes,cpu,eventLoop,vectorsScanned,dotTerms,frontier}`. Index state is per scope; runtime I/O counters are cumulative across all scopes and concurrent work, explicitly labeled `runtime_lifetime_all_scopes`. They are measurements, not currentness certificates. Sequential external before/after snapshots provide request deltas; overlapping requests cannot be attributed individually from these counters alone. CPU and event-loop measurements come from the external cost probe. Browser `signatureHashWallMs`, `refFingerprintHashWallMs` and `parseWallMs` are measured synchronous wall time, **not process CPU**. Local cosine counters cover actual local dot loops (including catalog sketches and MMR); server worker arithmetic remains externally unmeasured. Numeric-array byte counts are estimates of two Float64 input streams, not serialized network bytes.

Counters distinguish full signature calls/refs/hash bytes, fingerprint hashes, parsed rows/bytes, catalog reconstruction, canonical/vector loads, final physical-proof reads/bytes/read wall time, raw-role/body identity observations, sourceDigest pairs, fallback exact-ref bytes/comparisons, and new index fallback wall time/yields. Stored byte counts cover `getStoredJson`; parsed bytes include selected verified owner reads. Counted proof bytes require a serialization of the already-read selected body, and UTF8 byte/hash timing instrumentation adds measurable overhead. External traces add one ref traversal per signature to cross-check counters. Reported timings therefore describe instrumented fixtures, not installed-host latency certification.

The plugin host offers getItem/keys but no trusted external mutation revision. `manifestWriteRevisions` only advances at the plugin's saveManifest boundary: it detects in-runtime competing writes, not another runtime, external writer, independent body edit or restore. Server storage does offer monotonic **per-key** revision/digest metadata and paged prefix enumeration (`server.cjs` getMetadata/selectKeysPaged), but a manifest-key revision alone does not prove exhaustive changed IDs for independently edited canonical/vector keys. No owner/SDK protocol is changed. Both product modes use fully verified manifest/fingerprint fallback; its O(N) rows, bytes and hashes are reported, never relabeled zero or partial coverage merely because verification is expensive.

Warm catalog reconstruction and document embedding can be zero while full-ref signatures and inherited raw readset identity observations remain nonzero. `buildPairs` still checks the exact raw role/body identity sequence across the current chat, and active selected source/readset and final physical owner guards remain required. This is distinct from retired automatic source detection/reanalysis: A2 adds no automatic analysis, source embedding or new raw-history corpus access. The warm full-metadata/signature/raw-history-zero performance requirement remains **BLOCKED** on these hosts. The 100k actual-runtime fixture exhausted the default heap before a hook observation; it does not certify a deadline overrun, warm p95 or recall envelope. Historical synthetic Float32 packed-vector 1k/10k/100k measurements remain historical and cannot be presented as the current Float64 allocation curve. The current diagnostic defaults to n=100; larger permitted diagnostic sizes up to 10k require explicit `--sizes`. No 100k rerun or heap increase is authorized. Three- and seven-sample p95 estimates are descriptive, not final targets or model accuracy certification.


## B1 Micro and source-only lexical access

`projectMicro(record,{frame,source,row?,normalizedClaims?})` emits one frozen record candidate with revision-bound source/claim identities, authority, original source spans and full token/time postings. `resolveEvidenceCluster(units)` accepts only units issued by this factory and chooses a representative only for the same exact source and uniquely assigned fully typed claims. Identical incomplete/generic payloads, equal rendered text, equal quotes, and source-only excerpts do not establish typed correspondence. Global stable identity coverage remains partial when actual source UUID/birth anchors are absent. A validated revision-source attachment can establish local typed correspondence without claiming stable identity. Projection identifiers and adapter metadata remain incapable of authorizing physical delivery.

The semantic input excludes durable network projections, embedding/job fields, queue timestamps and public proof flags. Reusing derived metadata cannot recursively change access IDs. `normalizedClaims` is an adapter representation of verified claim semantics; it never creates claims for a source-only record. Micro binding and row capabilities remain separate. Existing final source/head/receipt/archive and nonrewinding frame checks remain mandatory.

Micro representation bindings use `libra.micro-network.v1`. Source-only node identity includes its exact role/span attachment, even when a complete stable SourceObjectID is available; multiple spans of one source must coexist rather than replacing each other. Typed normalization must preserve record claim cardinality. These are projection/registry safeguards, not physical authority.

New owner publications persist a versioned `libra.micro_network_evidence.v1` object inside the digest-bound durable recall projection. It contains per-record source/analysis revisions, physical locators, authority status and bounded claims/excerpt. It contains no embedding or proof capability. Legacy heads rebuild this metadata through existing verified reads without an owner write or automatic analysis. Each query projects the enumerated metadata into the same request registry before the old shortlist; lexical posting hits map network candidate IDs to physical hydration locators independently of canonical availability and embeddings. Verified hydration replaces the locator with the original proof-bearing row, retaining the same candidate IDs. The old Micro catalog still contributes legacy migration accesses; it is not the sole discovery mechanism. The actual test removes that catalog access and still obtains final packets in plugin_only and server_only.

All durable current heads through the eligible completed-turn boundary and allowed predecessor archive heads participate. There is no new recent-N access cutoff or token-64 cutoff. Claims retain the existing producer bounds (at most16 claims, claim text360 characters and exact quote600 characters). Source-only retains the existing producer's first500-character excerpt; B1 does not certify lexical access to the rest of that turn. These producer representation limits differ from candidate discovery, physical hydration deadlines and final injection budgets. Known local turns with no Micro head and no committed canonical coverage are reported pending/partial; a canonical-covered absent head is not labeled a pending producer job. Failed enumeration remains explicitly degraded, with its reason retained. No missing head triggers backfill, reanalysis, embedding or State mutation.

Posting discovery does not override admission. The existing as-of worldline/reference-order predicate is shared by the legacy shortlist and the new access-to-hydration adapter. Discovered but ineligible IDs retain an explicit reason and are not physically hydrated or injected. This preserves the existing conservative logical-canonical/physical-Micro worldline behavior; B1 does not redesign temporal resolution or promise expanded past-query recall.

Canonical candidate discovery/scoring remains the A1 migration flow. B1's independent Micro postings use network candidate IDs, while A2's canonical paged cache still uses physical memoryKeys. The new registry is request-local and may retain all supplied Micro metadata; it is not the completed durable shard/byte-budget design. Whole-corpus byte bounds, warm-zero, vector-space/model safety and the final single frontier/scorer remain uncertified or deferred to their assigned phases.

## B1 conservative absorption and consumption

Current-session canonical/Micro correspondence requires physically verified canonical source-evidence rows and the actual verified Micro receipt. Owner, source scope, worldline, session, turn, complete original U+A identity/text/raw bytes and active receipt revision must agree. The exact quote must have a unique original occurrence with matching role and offsets. UUID/birth identity is not fabricated. Inherited/copy ambiguity and repeated quotes remain distinct.

The runtime typed adapter permits only character_state, character_goal, scene_time and world_state, the four direct scalar claim contracts. It supports uniquely resolved character/world State-intent field/value/set-or-clear correspondence within that allowlist, with matching current temporal role and confirmed/observed authority. Other claim kinds, collection/profile selectors and future kinds remain distinct; the generic factory typed API is unchanged. Set values must be strings, booleans or finite numbers on both sides; explicit null/structured set values remain distinct. Clear means clearing the whole qualified field, and the canonical raw value must actually be null before normalization. A profile selector/item clear is never treated as a field clear. The ordinary world_state raw-null clear positive is verified by the actual fixture. Reference claim kinds and Ref-suffixed value/field selectors remain excluded for both operations, even when their legacy contract omits refType; nested temporary references are not interpreted as ordinary scalar values. It does not apply State patches. Cardinality is checked over the whole participating records after entity alias resolution, not one singleton projection. Generic event-vs-possession overlap cannot establish equivalence from text/quote alone. Such legacy claims intentionally remain separately emitted, and a repeated rendered quote is not a universal duplicate-zero guarantee. The updated T3 regression asserts that distinction; the new typed positive test independently proves legitimate absorption.

All packet preparation retains original Micro material. Classic absorption is deferred until the renderer has admitted rows under its actual final character budget. Only an admitted canonical counterpart and a complete recognized Micro excerpt chunk permit removal. If the canonical row drops later, the Micro remains; clipped/rewritten chunks remain distinct. This conservative policy performs no refill or reranking after suppression. Routes without this final admission/proof adapter preserve Micro material.

The renderer uses private WeakMap correspondence on the original delivery row. For an actually removed claim it appends the physically captured canonical source-evidence and entity-registry dependencies to the issued private consumed-data readset, independently of continuity-closure facts. Final physical mutation rejects delivery and preserves the base request. Potential correspondence that does not suppress a claim adds no such dependencies. The original selected Micro proof is retained conservatively even when all its text is absorbed; this can reject an otherwise usable canonical packet if that selected Micro becomes stale. No public dedup/verified flag can supply or erase this authority.

B1 evidence is synthetic fixture wiring/safety evidence, not real-model semantic accuracy, performance certification or final architecture completion. Mirror regressions remain migration evidence; supported-mode independent access evidence is plugin_only and server_only.
