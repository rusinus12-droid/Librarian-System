# Flashback 1.0.29 / BOOK_UX 5.22

## 기준과 범위
MemorySuite 0.3.23의 Flashback 1.0.28을 수정한다. LIBRA 2.3.30, HAYAKU 3.0.46, LIA 0.26.63, RE:TRACE 1.9.67의 JS는 변경하지 않는다. RisuAI 본체·데이터 키·저장 형식·리콜 허용 조건·임베딩 제공자·원문 수정 승인 계약은 유지한다.

## 저장 원문이 0 / 7로 보인 원인
buildRecallShardSummary의 sourceTypes는 isRecallIndexableRecord를 통과한 기록만으로 만들어진다. 기존 manualEditorShardIndexes가 이를 저장 원문 존재 여부로 재사용하여 확정 대기, 격리, 비활성, 비공개 등 리콜 제외 기록만 있는 shard를 생략했다. manifest 통계는 전체 저장 기록을 세므로 7개 / 원문 목록 0개가 함께 표시됐다. 수정 전 실제 JS+7개 fixture로 재현했다. 사용자의 저장 DB를 제공받은 것은 아니므로 사용자의 7개 기록이 정확히 어느 상태였는지는 확정하지 않는다.

원문 뷰어는 저장된 현재 owner/scope의 shard를 검사한다. 리콜 eligibility 판정은 바꾸지 않는다. rawTextOnly 읽기는 checksum·commit·scope·shard·record count 정합성 검증을 유지하며 임베딩 벡터 payload를 읽지 않는다. 첫 화면 80개, 추가 페이지, 검색 및 정렬은 유지한다. 읽을 수 없는 shard와 통계 불일치는 별도 경고로 표시하며 실패한 빈 결과는 정상 캐시로 남기지 않는다. 표시 상한에 도달하면 무한 더 보기 대신 검색 안내를 표시한다.

각 카드에서 원문 확정 대기/활성/격리/이전 후보 등의 상태를 본다. 원문 펼치기는 선택한 기록의 실제 저장 문자열을 다시 읽는다. 420자 요약만 보이던 기존 목록과 달리 전체 문자열을 textContent로 표시한다. 태그는 실행하지 않는다. 접으면 전체 텍스트를 DOM에서 해제한다. 조회 중 commit·scope 변경은 결과를 차단한다. 수정이 아니라 읽기 기능이며 원문/벡터 재생성을 실행하지 않는다.

공유 아카이브 자체의 전체 원문 탐색은 이번 패치에서 새로 구현하지 않았다. 스토리지 응답 원문은 기존과 같이 현재 스코프의 로컬 shard 범위다. 상단 합산 통계와 별개로 카드 목록은 이 범위를 따른다. 아카이브의 백업/복원 및 리콜 정책은 유지된다.

## 세계선
사이드패널 → 기억 → 세계선. HAYAKU의 ‘채팅 분기 근거 + 턴 연속성’ 구성을 Flashback 데이터에 맞춰 적용한다.

- 현재 채팅/스코프/경로, 부모 채팅/분기 메시지/검증된 공통 U+A 구간/상위 경로 확인 상태.
- 저장된 nativeBranchCopy 확인 기록, 승계 당시 검증 범위와 승인된 완료 상태, 현재 로컬 원문 수. 이는 과거 readback 기록이지 화면을 열면서 새로 실행한 readback이 아니다.
- 기존 turn_worldline의 활성/격리/이전 후보/분리 분기/고아 노드, head/revision, 보존된 이전 원문 수. 최근 24개 노드를 먼저 표시하고 더 보기로 확장한다. 노드별 해시/상위 노드/후보 식별자는 펼쳐서 확인한다.

조회 전후 호스트 source identity와 저장 revision을 비교한다. 데이터가 없으면 없는 상태를, 손상이면 오류를 보여주며 기존 상태를 새로 생성하거나 자동 승계하지 않는다. 화면 모델에 retired 원문·vector payload는 포함하지 않는다. 수동 세계선 전환/노드 복구 기능을 새로 만들지 않는다.

## 원문 수정 동기화
기억 개요에서 제거하고 기억 유지보수 최상단으로 이동한다. 현재 scope의 저널만 표시한다. ‘보류된 원문 수정 확인’은 기존 getFlashbackSourceEdits().review(true)로 연결된다. 조회/진입은 재처리 승인이 아니다. owner/scope/source revision/범위별 명시적 승인, 취소/닫기/권한 오류의 비승인, 재시작 시 재확인을 유지한다. 중복 클릭, 늦게 도착한 다른 scope의 UI 업데이트를 차단한다.

## 확인 경로
- 스토리지 → 응답 원문 보기 → 원문 펼치기.
- 세계선 → 현재 세계선·채팅 분기 → 원문 승계·저장 확인 → 턴 연속성.
- 기억 유지보수 → 원문 수정 동기화 → 보류된 원문 수정 확인.

## 시험 범위
기존 전체 CJS 회귀 외에 flashback_storage_reader_v129_runtime_test.cjs와 flashback_worldline_workspace_v129_runtime_test.cjs를 추가했다. 별도 evidence에는 실제 배포 JS를 Chromium에서 실행한 화면/클릭 검사, 수정 전 재현, 최종 재추출본 검사 로그를 제공한다. RisuAI API/저장소는 fixture이며 사용자 계정/실제 사용자 DB/외부 모델/모바일 실기기 시험이 아니다.

## 적용
JS만 업데이트해도 적용된다. 기존 Flashback 항목에 교체 설치하고 플러그인 또는 RisuAI를 다시 로드한다. 기존 설정·DATA 초기화나 벡터 재생성은 필요 없다. 구버전과 중복 활성화하지 않는다.
전체 패키지 업데이트는 서버 종료 → 기존 DATA 백업 → PROGRAM만 교체. 배포본의 DATA는 신규 설치용이며 기존 DATA 위에 덮어쓰지 않는다.
