# HAYAKU 3.0.105 — 정상 생성과 후속 원문 영향 판정

## 첨부 로그에서 확인한 원인

최종 확인 파일은 `hayaku-debug-chat_h642iri7zyn3pgw6-2026-09-12T08-27-59-600Z.json`이며 실행 버전은 3.0.104다. 먼저 첨부된 3.0.100 로그에는 T11이 없었다.

- T11은 `current_snapshot`, `recordState: active`, `captureSource: risu_chat_output`이다. 저장된 패킷 해시는 `h641gb464ynus6oq`이며 저장·결속 시각이 모두 기록됐다.
- T11의 `originalDigest`와 `sourceDigest`는 모두 `h641ypjslnixw754`다. 본문 변경으로 판정된 것이 아니다.
- 검토 사유는 `dependency_affected`다. T10의 변경 때문에 뒤의 T11도 영향을 받았을 수 있다고 묶었으나 GUI는 이를 “원문 수정 승인 대기”라고 표시했다.

## 수정

정규 생성에는 요청 시점의 이전 턴 원문 버전을 증명하는 기록이 없었다. 반면 복구 경로는 `sourceRevisionBasis`로 재분석에 사용한 원문 범위를 구별했다. 따라서 변경된 이전 턴을 보고 이미 새로 생성한 정상 패킷도 후속 영향 검토에 포함될 수 있었다.

정규 생성 요청 등록 때 이전 완료 턴들의 원문 지문을 보존한다. 실제 요청 nonce와 패킷 검증을 거친 저장 경로에서 현재 응답 지문을 결합해 `sourceRevisionBasis` 및 `sourceRevisionOrigin: regular_request`를 원장에 기록한다. 읽기 때도 허용된 정규 저장 출처와 패킷 내부 nonce 일치를 확인한다. 이는 모델이 제출한 근거 선언으로 생성하지 않는다.

현재 원문 범위와 저장된 생성 기준이 같고 해당 턴의 패킷도 정확히 일치하면 후속 영향 재분석 대상으로 묶지 않는다. 생성 도중이나 그 뒤에 실제 이전 원문이 달라졌다면 기준이 달라지므로 계속 검토한다. 기존 패킷의 생성 근거를 현재 문맥으로 소급해서 만들거나, 패킷이 있다는 이유만으로 수정 검사를 무시하지 않는다.

GUI에서는 본문 직접 변경과 “앞선 변경의 영향 검토 · 이 턴의 본문은 동일”을 구분한다. HAYAKU 원문 확인창의 체크박스는 `color-scheme: light`와 명시적 흰색 바탕·체크 표시를 적용해 어두운 호스트 테마의 검은 네이티브 체크박스에 의존하지 않는다. 공통 SourceReview 원본과 세 내장본을 동기화했으며 CSS 적용 범위는 HAYAKU 테마다.

## 검증 범위와 한계

새 회귀 검사는 정상 요청 등록→패킷 저장→원장 재조회→결속을 실행한다. 이전 턴이 바뀐 뒤 생성한 새 패킷은 검토에서 제외되고, 생성 중·생성 후 다시 바뀐 경우에는 검토되는지 확인한다. HTML 주석과 기존에 정의된 삽화 전용 태그 추가는 같은 본문으로 유지된다. 미정의 태그나 실제 내용 추가를 무조건 무시하는 규칙은 넣지 않았다. 모의 실행에서 외부 모델 호출은 0회다.

기존 32개 회귀 검사, 새 생성 기준 검사, 원문 증거·승인·리뷰 관련 4개 검사를 합쳐 37개가 통과했다. 전체 저장소의 모든 테스트나 실제 RisuAI 제공사 실행을 뜻하지 않는다.

브라우저 보안 정책이 로컬 검증 HTML 열기를 차단해 변경 후 GUI 스크린샷은 확보하지 못했다. 이를 다른 브라우저나 직접 프로토콜로 우회하지 않았다. 실제 호스트 GUI의 시각적 확인은 남아 있다.

워크스페이스 `_diagnostics/hayaku-source-basis-20260912/`에 수정 전 파일과 로그의 판정·해시만 추린 근거를 보관한다. 사용자 채팅이나 실제 저장 데이터는 수정하지 않았다.
