# MemorySuite 0.3.22 / BOOK_UX V5.20 GUI 통합

## 구성

LIBRA 2.3.29, HAYAKU 3.0.46, Flashback 1.0.28, LIA 0.26.63, RE:TRACE 1.9.67.
서버의 배포 버전은 0.3.22이며, 이 릴리스에서 서버 동작이나 DATA 스키마는 바꾸지 않았다.

## HAYAKU 화면 배치

- 개요: 기존 상태판과 회상·최근 동작을 유지한다. 세계선 활성/전체 및 정리 가능 고아 상태판 바로 아래에 ‘이번 패킷 작성’ 카드를 둔다. 제목은 가로 한 줄이며, 관측 기록은 제목 아래에 표시한다. 기존 건강 상태판의 34px 아이콘 열을 재사용하지 않는다.
- Recovery Journal: ‘원문 수정 동기화’를 복구 엔진 카드 위에 배치한다. 보류·실패·동의 대기 등 실제 상태와 최근 20건을 표시하며, 전체 건수도 남긴다. 확인 버튼은 기존 source-edit review(true)에 연결된다. 렌더링·메뉴 진입 자체는 승인이나 LLM 실행이 아니다.
- 세계선: ‘현재 세계선 · 채팅 분기’를 기존 턴 연속성 보드와 한 화면에 배치한다. 현재/부모 채팅, 분기 메시지, 경로, 공통 원문 범위 및 실제 결속 노드를 표시한다. 상위 경로 검증과 개별 패킷 저장·활성 결속 여부는 구분한다.

새 카드에는 HAYAKU의 밝은 배경·회청색 테두리·본문 서체·버튼 계열을 적용했다. 긴 ID나 오류는 영역 안에서 줄바꿈하고, 좁은 화면에서는 상태 배지 전체와 항목 값을 다음 행으로 배치한다. 미조회·미확인을 성공색이나 완료 문구로 바꾸지 않는다.

## 기능 경계

렌더러는 기존 요청 영수증, 원문 수정 동의 엔진, 공유 Host Lineage 정규화 결과를 읽는다. 새로운 기억 저장소·월드라인 엔진·자동 재분석 경로를 추가하지 않는다.

원문 수정 확인 버튼은 현재 채팅의 범위를 다시 확인한 뒤 기존 동의 화면을 연다. 연속 클릭, 닫힌 화면, 메뉴 이동, 조회 중 채팅 변경과 다른 scope의 작업/오류 노출을 방어한다. 취소는 승인으로 바뀌지 않는다.

원장 새로고침은 scope와 ledger를 각각 다른 시점에 화면에 대입하지 않고, 읽기 완료 및 현재 채팅 재확인 뒤 한 쌍으로 게시한다. 조회 중 채팅이 바뀌면 이전 채팅 원장을 새 분기에 표시하지 않는다. 이 검사는 읽기 전용이다.

원래의 원문 수정 확인 문구, scope/source revision에 묶인 승인, 패킷별 원문·결속·저장 검사, 정상 캡처와 복구 파이프라인, 기존 DATA/다른 채팅 보존 조건은 변경하지 않았다.

## LIBRA 통합

직전 제공된 LIBRA 2.3.29 JS를 바이트 변경 없이 포함했다. 그 JS의 저장 패널 수정과 sdk/MemorySuiteStorageClient.libra.source.js를 동기화했다. 이후 SDK 재삽입이나 배포 과정에서 이전 저장 패널 색상 코드로 되돌아가지 않도록 하기 위함이다. 표준 SDK와 다른 세 플러그인은 직전 0.3.21과 동일하다.

이전 미완료 회귀 항목인 ‘보조 패널에서만 BOOK 테마’ 조건은 현재의 두 진입점(설정실과 보조 패널) 모두 BOOK 테마라는 계약으로 갱신했다. 버전 고정 검사는 배포 버전에 맞춰 갱신했으며 기능 검사를 생략하지 않았다.

## 검증 재실행

```sh
node tools/check_sdk_sync.cjs
node tests/hayaku_gui_workspace_v346_runtime_test.cjs
python run_regression_batch.py
node tools/build_distribution.cjs --output-dir ../RELEASES
```

선택적 브라우저 검사:

```sh
python tests/browser/hayaku_gui_workspace_browser_test.py <PROGRAM 절대경로> <증거 출력 폴더>
```

브라우저 검사에는 Python Playwright와 Chromium이 필요하다. Chromium 경로는 CHROMIUM_PATH로 지정할 수 있다. 이 검사는 배포 JS 전체를 실행하되 RisuAI API와 저장소를 일회용 경계로 대체하고 화면 상태를 주입한다. 검사 전용 hook은 브라우저 메모리에만 추가하며 배포 JS에는 없다. 실제 사용자 데이터·RisuAI 본체·외부 모델을 연결한 시험으로 해석하면 안 된다.

CJS 회귀, 브라우저 검사, 배포 smoke 검사, 최종 ZIP 재추출/해시 대조는 서로 다른 검증이다. 실행 결과는 함께 제공하는 검증 로그와 최종 보고서를 확인한다.

## 남은 실제 환경 확인

첨부 화면의 current_chat_indexes_invalid는 현재 채팅 범위를 얻지 못한 실제 오류 표시다. 이번 화면 재배치로 해당 오류의 원인을 해결했다고 주장하지 않는다. 정상 상태로 숨기거나 임의 채팅으로 대체하지 않으며, 실제 발생 환경의 API/권한/선택 상태는 별도 확인이 필요하다.

LIBRA Input Writer의 사용자 환경 장시간 진입 지연은 직전 수정본의 한계가 그대로 남는다. 불필요한 렌더링 작업을 줄인 코드를 포함했지만, 실제 사용자 환경 지연이 해소됐다는 추가 통합 시험은 하지 않았다. 이전 CONTINUATION_V518.md의 LIA 과거 binding 등 비-GUI 후속 범위도 그대로다.

## 업데이트

서버를 종료하고 기존 DATA 및 필요한 플러그인 기억을 먼저 백업한다. 기존 설치는 DATA를 보존하고 PROGRAM만 교체한다. RisuAI에서는 PROGRAM/plugins의 LIBRA.js와 HAYAKU_Locator_Continuity.js를 기존 항목에 업데이트한다. 다른 세 플러그인의 버전은 0.3.21과 같다. 신규 설치에서는 다섯 JS를 설치한다. 구버전과 새 버전을 중복 활성화하지 않는다.

배포 ZIP의 DATA는 신규 설치용 빈 구성이다. 기존 DATA에 덮어쓰지 않는다.
