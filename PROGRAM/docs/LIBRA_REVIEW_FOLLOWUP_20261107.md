# LIBRA 외부 리뷰 후속 검증

기준: `8a16c13`, `claude/libra-content-completeness-20261106`. 리뷰의 코드 위험은 정적 추정과 실제 재현을 구분해 검사했다. 원문과 모델 응답을 포함한 `.development/` 자료는 저장소에 포함하지 않는다.

검토 대상의 로컬 Git 값도 확인했다. main 대비 앞선 커밋 5개, 뒤처진 커밋 0개, 커밋된 변경 파일 43개다. 아래 후속 수정은 이 집계에 포함되지 않은 작업 트리 변경이다.

## 재현과 수정

| 리뷰 항목 | 기준 코드 재현 | 변경 |
|---|---|---|
| P1 장소 오귀속 | 직전 위치가 `좁은 방`일 때 `민아는 폐공장 앞에 서 있다. 이곳은 어둡다.`를 입력하면 기존 방을 반환했다. 미등록 장소 `창고 앞`도 동일했다. | 이동 동사뿐 아니라 다른 명시적 장소와 공간 표현을 확인한다. `이곳·그곳·실내`는 현재 근거 안에 선행 장소 표현이 있어야 한다. 불충분하면 연결을 보류한다. |
| P2 외형 표현 공백 | `금발 머리`가 속성 검사 대상에서 빠졌다. | 금발·은발·흑발·백발 등 모발 표현과 금색·은색·노란색·보라색 등 일반 색상·동의 표현을 추가했다. 인용에 없는 속성은 메모로 보존한다. |
| P2 이름 경계 | `김민아`의 붉은 눈을 별개 인물 `민아`에게 귀속하고, 정작 `김민아`의 기록을 보류할 수 있었다. | 검증된 사람 레코드의 이름·별칭을 단어 경계로 찾고, 겹치면 긴 이름을 우선한다. 같은 위치·같은 이름이 다른 ID를 가리키면 보류한다. |
| P2 서사 중복 | 재검토 모델이 `학교 등교 여부 확인 전화`를 `new`로 제안하면 기존 `학교에 전화해 등교 여부를 확인하는 일`과 같은 참여자여도 새 이야기로 승인됐다. | 같은 종류·참여자의 내용 단서를 비교한다. 의미가 겹쳐 별개 과제임이 불확실하면 `new`를 보류한다. 유사성을 근거로 병합·종결하지 않는다. |

장소를 확인하지 못했을 때 `이곳`을 새 전역 장소 이름으로 만들거나, 기존의 동명 `방` 레코드를 정확한 이름 일치만으로 재사용하지 않도록 Micro와 정본의 호출 경로도 보강했다. 원문 관측·사실은 정본에 남고 State 연결만 보류된다. 관리 화면의 `location_context_unresolved` 사유도 자연어로 표시한다.

기존 저장소에 `방`이라는 location이 있는 추가 반례에서는 Micro의 종류 생략 및 정본의 `other` 분류가 검사를 우회했다. 실제 writer로 구형 할당 정책의 테스트 스냅샷을 만든 뒤 현재 런타임에 읽혀 `admitted`를 재현했다. 호출 인자의 종류뿐 아니라 기존 Registry 레코드의 종류도 확인하도록 수정했고, 두 경로 모두 연결을 보류하는 것을 확인했다. 이는 실제 사용자 DB를 변환한 검증이 아니다.

서사 복구 프롬프트에는 `tN-u`와 `tN-a` 모두를 명시했다. 사용자 발화에서도 별개 과제 등록과 올바른 기존 후보 연결을 세 저장 모드로 검증한다. 서사 사실·참여자·상태·근거를 복구 응답으로 덮어쓰지 않는 기존 제한은 유지한다.

### 보강 중 발견한 회귀

새 이름 검색 함수에서 Core의 `string()`을 사용하면 앞뒤 공백이 제거돼 이름 오프셋이 달라졌다. 이 때문에 실제 응답 재적용에서 세희의 명시된 흰 머리 보완 기록이 빠졌다. 원문 문자열을 그대로 사용하도록 수정하고, 240자 근거 창의 첫 글자가 공백인 회귀 사례를 추가했다. 단순 반례 검사와 실제 응답 재적용을 모두 통과했다.

## 검증 증거

- `libra_review_state_safety_test.cjs`: 기준 코드에서 독립 반례 9건 실패, 같은 장소의 명시적 선행 표현 양성 사례 1건 통과. 수정 후 이름 오프셋 사례를 포함한 11개 검사 통과.
- `libra_review_state_safety_runtime_test.cjs`: plugin_only·mirror·server_only에서 잘못된 장소 연결 보류, 관측의 정본 보존, 금발·타인 속성·긴 이름 귀속, 유효한 흰 머리 보완, 재생·재시작을 확인했다.
- 같은 런타임 검사에 구형 일반 명사 장소 스냅샷의 종류 생략·오분류 우회 차단 사례를 추가했다.
- `libra_thread_link_repair_runtime_test.cjs`: 기존 13개에서 20개 시나리오로 확장. 요약을 바꾼 중복 신규 등록 보류와 사용자 발화 근거의 신규·재연결 6건을 추가했다.
- `run-review-followup-recorded-final`: 이전 실제 모델 응답 17개를 최종 수정 코드에 재적용했다. **새 모델 호출 0회**다. 실제 새 모델 생성 실측으로 세지 않는다. 같은 원문 revision·digest임을 비교했다. 세아의 검은 머리·붉은 눈동자, 세희의 흰 머리·붉은 눈, 장소 4개, 서사 연결 보류 0건, 재생 동일성을 확인했다.
- 별도 authority proof preflight 단위 검사 1건 통과. 이것만으로 전체 서버 호환성을 입증하는 것은 아니다. 서버 경로의 근거는 위 세 모드 런타임 검사와 아래 호환성 검사다.

### 최종 전체 회귀

최종 보강 후 실행한 LIBRA 검사 569개(CJS 567개·JS 2개)의 최초 결과는 **510 통과·59 실패**다. 실패 59개를 `8a16c13`의 플러그인 소스를 별도 사본과 읽기 전용 preload로 읽혀 재실행했다. 작업 파일을 기준선으로 교체하지 않았다.

| 검증 | 결과 |

| 최종 전체 검사 | 569개 완료, 510 통과·59 실패 |
| 실패 59개 기준선 대조 | 58개는 기준선에서도 실패, 1개는 기준선 통과 |
| 기준선만 통과한 복원 검사 | 최초 실패는 임시 파일 rename의 `EPERM`. 수정 코드로 개별 재실행해 9개 내보내기·복원 조합 모두 통과 |
| 신규·확장 검사 3개 파일 | 모두 통과: 반례 11개, 세 모드 및 구형 장소 스냅샷 런타임, 서사 복구 20개 시나리오 |

최종 소스 SHA-256은 `d8cb1b47590cf1b4776d4dfe3df71a9e36018ad210821bcbd20510f9b588da9b`이다. 실행·기준선 집계는 `.development/libra-completeness-20261106/review-final2-regression/`에 보관했다. 앞선 보강 중 실행과 중단된 실행은 최종 집계에 합산하지 않는다.

**전체 검사가 녹색인 상태는 아니다.** 재검사 후에도 기준선에서 재현되는 실패 58개가 남는다. `libra_mirror_readback_order_test`, `libra_phase_d_candidate_context_scale_synthetic_test`, `libra_phase_d_timeline_caps_test`는 양쪽 모두 실행당 180초 제한에서 종료됐다. 기존 `libra_main_memory_legacy_boundary_read_compat_test`의 `UNIFIED_IDENTITY_PROVENANCE_MISMATCH` 실패도 남으므로 구버전 호환성이 전부 검증됐다고 해석하면 안 된다. 이번 변경에서 확인한 새 기능 회귀는 보강 후 재현되지 않았다.

## 릴리즈·호환성 경계

- 리뷰 지적대로 플러그인 버전은 `2.6.36`이다. 이번 작업은 리뷰 반례 수정이며 릴리즈·배포·버전 변경은 수행하지 않았다.
- 기존 v4/v5 형식과 서버 검증 계약을 바꾸지 않았다. 새 중복 검사와 근거 검사는 생성·State 투영 경로에서 적용한다. 기존 기억을 일괄 변환하거나 사용자 DB에 쓰지 않았다.
- 기존 기억에 새 추출·연결 판단을 반영하려면 패치된 플러그인에서 해당 구간을 재분석해야 한다. 사전 기반 외형 검사를 모든 언어·모든 외형 속성의 완전한 의미 검증으로 간주하지 않는다.
- `libra_legacy_continuity_migration_gate_test`, `libra_librarian_v1_compatibility_test`, `libra_main_memory_schema_compatibility_test`, `libra_main_memory_v4_thread_binding_compat_test`, `libra_settings_migration_runtime_test`, `libra_unified_migration_v1_test`는 최종 전체 실행에서 통과했다. 위에 적은 기존 호환성 실패와 함께 판단해야 하며 모든 구버전 배포 조합이 호환된다는 뜻은 아니다.
- 로컬의 `risu-compatibility-gate.yml`과 `release-builder-gate.yml`은 main 대상 PR, main push, 수동 실행을 트리거로 설정한다. 작업 브랜치 push만으로 이 두 워크플로가 실행되지는 않는다. 원격 Actions 결과를 새로 조회하거나 실행하지 않았다.
- 버전·배포 메타데이터 갱신, 실제 배포 대상의 구버전 조합 검사, 실제 RisuAI 설치·GUI 검증은 릴리즈 전에 남아 있다. 성능·시간적 리콜 전달은 별도 과제로 유지한다. 건수 기반 절삭은 재도입하지 않았다.
