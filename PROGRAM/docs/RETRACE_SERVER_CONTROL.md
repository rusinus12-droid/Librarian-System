# RE:TRACE 서버 관제

서버 데이터 탭의 '서버 관제'에서 서버 상태·연결 진단·백업·복원·최근 작업을 관리합니다. RE:TRACE 1.9.73은 한눈에 보기, 서버 데이터, 백업 · 복원, 연결 진단, 작업 이력의 다섯 하위 화면을 제공합니다. 관제 API를 지원하는 서버가 필요합니다. 서버 실행·설치·Docker 네트워크 설정은 각 실행 환경에서 수행합니다.

하위 화면을 이동해도 백업 선택과 작업 결과를 유지합니다. 백업 또는 복원 대상 선택을 바꾸면 이전 복원 미리보기는 무효화됩니다. 연결 진단의 '서버 연결 설정'은 기존 연결 설정 화면을 엽니다. 중간 화면과 모바일에서는 관제 카드가 한 열로 배치됩니다. 서버 사본 정리 및 초기화는 '서버 데이터' 하위 화면에 있습니다.

1.9.74는 관제 전용 스타일을 실제 RE:TRACE 셸에 적용합니다. 상태 요약 아래 플러그인 저장 상태와 작업 바로가기·최근 이력을 배치하고, 백업을 선택형 카드로 표시합니다. 검색과 상태 필터는 조회된 서버 사본 목록에 적용되며, 전체 선택은 필터와 별개로 전체 삭제 가능 항목을 선택합니다. 초기화는 목록 아래 고급 관리에서 엽니다. 작업 이력은 결과별로 필터링하고 상세를 펼칠 수 있습니다. 진단 요약 내보내기는 기존 RE:TRACE 디버그 내보내기를 사용합니다.

서버 사본 수와 용량은 조회한 목록의 합계이며 서버 전체 디스크 사용량이 아닙니다. 일부 색인 실패나 미조회는 별도로 표시합니다. 복원·초기화 실행 이후 재연결 안내를 유지하며, 응답 단절 시 작업 이력에서 결과부터 확인해야 합니다. 클라이언트의 복원 미리보기 만료 확인 외에 서버의 기존 만료/자료 변경 검증도 유지합니다.

## 상태와 연결

탭을 열거나 '상태 새로고침'을 누르면 서버 버전, DATA 식별자와 저장 위치, 최근 백업, 플러그인별 마지막 접촉, 저장소 무결성 상태를 표시합니다. 마지막 접촉 기록은 플러그인이 지금도 연결되어 있다는 뜻은 아닙니다. DATA 정보와 마지막 접촉 목록은 상세 항목을 펼쳐 확인합니다.

'연결 진단'은 서버 응답·프로토콜·저장소 연결과 RE:TRACE 관리 API를 순서대로 확인합니다. 실패 응답만으로 DNS·방화벽·PocketRisu 프록시 중 어느 원인인지 구분할 수 없으면 원인 확정을 주장하지 않습니다. 다른 서버로 자동 우회하지 않습니다. 기존 정제된 디버그 로그 내보내기는 그대로 사용할 수 있습니다.

## 백업과 복원

- '지금 백업 만들기': 서버에서 수동 백업을 생성합니다.
- 백업 목록: 시간·구분·용량·최근 검사 결과를 표시합니다. 최근 검사 결과는 그 시점의 결과이며 이후 파일 변경까지 보장하지 않습니다.
- '선택 백업 검사': 서버가 체크섬과 DB 상태를 검사합니다.
- 복원: 백업과 플러그인을 선택하고 '복원 미리보기'를 누릅니다. 백업·대상·필요 공간을 확인한 뒤 '미리본 내용으로 복원'을 누르고 최종 확인합니다.
- 미리보기 이후 현재 데이터나 백업이 바뀌거나 시간이 지나면 실행을 중단합니다. 다시 미리보기를 만드세요.
- 실제 복원은 서버의 기존 사전 백업·복원 저널·rollback 경로를 사용합니다. RE:TRACE에 서버의 관리자 원본 토큰을 전달하지 않습니다.

복원 실행을 시작하면 기존 클라이언트의 쓰기 세대를 무효화합니다. 복원 후 각 플러그인의 서버 연결 설정에서 '서버 자료 사용 · 로컬 업로드 안 함'을 선택하고 RisuAI를 새로고침하세요. 이 선택은 복원된 서버 자료를 사용하며 서버를 비우는 동작이 아닙니다. 실패한 복원도 재연결 확인이 필요할 수 있습니다. 로컬 원본은 별도로 유지됩니다.

## 작업 이력

백업 생성·검사·복원 결과를 서버에 기록하며 삭제 영수증과 초기화 완료 이력을 함께 표시합니다. 서버 재시작 당시 끝나지 않은 관제 작업은 '중단 · 결과 확인 필요'로 표시하고 자동 재실행하지 않습니다. 응답이 끊겼다면 재실행 전에 상태와 이력을 확인하세요.

이 화면은 정상 실행 중인 서버의 관리 기능입니다. DB 손상으로 복구 전용 모드에 들어간 서버는 기존 복구 도구를 사용해야 합니다. 실제 RisuAI 모바일 화면과 다양한 Docker 환경에서의 사용 검증은 별도입니다.
