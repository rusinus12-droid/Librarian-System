# 사서의 여백 기능 점검

## 결론

설정 입력·저장·새 실행에서 재조회 및 사실 데이터와의 분리는 동작한다. 저장한 방향을 실제 LIBRA Classic 응답 요청에 전달하는 연결은 현재 빠져 있다. 따라서 현재 구현을 다음 응답을 유도하는 완성된 기능이라고 설명할 수 없다.

이번 요청은 점검이므로 사서의 여백 제품 코드는 수정하지 않았다.

## 입력의 의미와 저장 경로

`buildApprovedMockupStory`의 여백은 목표, 완료 조건, 강제하지 말아야 할 전개, 부드러운 선호, 잠금을 입력한다. 이는 미래의 사용자 선호이며 이미 일어난 사건이나 확정 사실이 아니다. 완료 조건 자체가 사건을 완료시키거나 달성 여부를 자동 판정하는 기능은 현재 확인되지 않았다.

`saveNarrativeDirectionDraft`는 현재 스코프와 편집 스코프를 대조하고 공개 `setNarrativeDirection`을 호출한다. 이어 `getNarrativeDirection`으로 다시 읽어 저장 영수증과 비교한다. 저장 레코드는 `libra.planner_narrative_direction.v1`이며 스코프별 키와 revision을 가진다.

생산 렌더러에서 네 텍스트 입력과 잠금을 저장하고 새 브라우저 페이지에서 플러그인을 다시 초기화했다. 모든 필드가 다시 표시됐고, 정본과 현재 상태의 기존 저장 바이트는 그대로였다. 이 검증은 합성 호스트의 로컬 저장 모드에서 수행했다.

## 응답 전달 확인

실제 공개 API와 등록된 `beforeRequest`를 사용해 다음을 대조했다.

| 경로 | 관측 결과 |
| --- | --- |
| 저장 → 재조회 → 새 런타임 재조회 | 방향 값 보존 |
| 공개 `getResponseContext` | `values.narrativeDirection`에 방향 제공 |
| `narrativeDirectionPromptBlock` | 네 선호 항목과 ‘사실이 아님’ 안내문 생성 |
| Classic 실제 요청의 기억 주입 | 은빛 열쇠에 관한 원문 사실이 정상 포함됨 |
| 동일 요청의 방향 주입 | 목표·완료 조건·금지 전개·선호 표식 모두 없음 |
| 점검 중 추가 제공자 호출 | 0회 |

포맷 함수와 공개 조회 데이터가 있는 것만으로 실제 모델에 전달되지는 않는다. 현재 Classic 경로는 방향 포맷 함수를 연결하지 않는다. 일반 기억이 정상 주입되는 요청으로 대조했으므로, 플러그인 비활성화나 검색 실패를 방향 누락의 근거로 삼지 않았다.

후속 패치는 실제 요청에 소비되는 동일 스냅샷에서 방향을 가져와 별도 미래 선호 블록으로 전달해야 한다. 현재 사용자 입력과 정본의 우선순위, 스코프·저장값 변경 검증, 사실 저장 경로와의 분리는 유지해야 한다.

증거: 로컬 `memory-management-unified/margin-runtime-audit.json`, `margin-gui-audit.json`과 실행 스크립트. 기존 여백 GUI·렌더 경로·렌더 루프 회귀도 통과했다. 실제 RisuAI 앱 또는 제공자 응답의 문체·전개 변화는 검증하지 않았다.
