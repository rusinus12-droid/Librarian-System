# 통합 설계 구현 1차 — MemorySuite 0.3.27

문서 작성: 2026-09-06 · 개발 증분 01  
기준: MemorySuite 0.3.26 / 통합 설계 v1.0  
상태: **안전성 기반의 실제 코드 수정. 통합 설계 P0–P8 전체 완료본이 아니다.**

## 포함된 실제 변경

LIBRA 2.3.34는 상태 적용의 비교 기준과 적용용 복사본을 분리한다. 같은 작업에서 위치·자세 등을 서로 다른 패치로 바꾸어도 첫 패치의 결과가 두 번째의 외부 변경으로 오인되지 않는다. 인물·세계·방향 관계·내러티브 경로 모두 동일한 원칙이다. 실제 외부 변경에 대한 record/field hash 검사는 유지한다. 같은 필드에 서로 다른 값, set/clear 충돌, 중복 patch ID는 명시적으로 반려한다.

LIBRA는 원문 수정 대기만으로 기존 정본을 비활성화하지 않는다. 현재 범위의 5 U+A 메시지 ID, 저장된 정본의 ID/revision/sourceDigest, 원본 artifact/render hash가 맞는 기록만 유지한다. 과거 버전이 source_edit_pending으로 제외한 동일 기록도 이 조건이 확인되면 복구한다. 원문을 호스트에 되돌려 쓰거나 모델을 재호출하는 복구가 아니다. 다른 응답 identity, 다른 계통, 사용자 삭제 등은 보존 대상이라고 오인하지 않는다.

세 플러그인의 Source Edit Consent 코어를 1.1.0으로 통일했다. 기존 owner별 파일 경로는 빌드 호환을 위한 동일 본문 사본으로 남기며 `tools/sync_source_edit_consent.cjs --check`가 사본과 embedded 코드의 일치를 검사한다. 각 플러그인의 저널·실행·권한은 독립적이다.

승인 응답은 명시적인 `keys` 배열을 반드시 포함해야 한다. 누락·null·존재하지 않는 키·숫자 키는 실행하지 않고, 빈 선택은 0건, 중복 키는 한 번만 실행한다. 승인 scope·identity·비교 digest·실제 sourceDigest·basis를 실행 시 재검증한다. 다른 플러그인의 승인을 가져오는 우회는 없다.

기존 Flashback 비교 선택 UI는 유지한다. LIBRA/HAYAKU의 현재 전체 구간 확인 UI는 자신이 표시한 전체 키를 명시적으로 반환하도록 연결했다. LIBRA 기본 확인창은 모든 대상 구간과 개수를 표시한다. **이것은 공통 diff UI의 완성이 아니다.** LIBRA/HAYAKU의 전·후 전체 본문 저장·비교·개별 선택 UI는 P2 후속 작업이다.

## 이번에 구현하지 않은 부분

Ariadne 1회 통합 분석, v4 finalArtifact, typed ito 보정, 본문/초기 artifact 불일치 해결, 기본 ito 정책 전환, Observer 제거, 임베딩 후처리 분리, 전체 Head writer 통합, 의존 그룹 단위 원자 처리, prepared/written/verified/activated 중단 복구, 공통 diff와 증거 blob, 과거 상태 재적용, GRADIA ResponseContext 경계는 아직 미구현이다.

현재 기억·상태 모델 호출 수나 기존 ito 설정은 바꾸지 않았다. 이번 CAS 수정으로 불필요한 반려를 줄일 수 있지만 실제 외부 모델 속도 개선 수치를 측정하지 않았다. 다른 도메인까지 넓어지는 기존 hard-reject 범위는 다음 작업에서 별도 정리한다.

## 검증과 한계

기준 원본에서 선택 keys 무시, CAS 자기 충돌, ito 본문/artifact 분리를 먼저 재현했다. 신규 검사는 실제 SDK 또는 실제 배포 JS를 사용하고 호스트·모델·저장 경계만 중립적인 시험 자료로 대체한다. 원본 함수 검사와 전체 플러그인 VM 검사를 구분한다. 사용자 DB/외부 모델/실제 RisuAI 설치·모바일 실기기는 사용하지 않았다.

신규 검사:
- `source_edit_selection_v11_test.cjs`: 세 owner의 선택·취소·scope/source 변동·읽기 보존 42개 시나리오.
- `libra_state_baseline_cas_v1_test.cjs`: 정상 분리 패치·실제 외부 충돌·같은 필드 충돌·방향 관계 등 14개 시나리오.
- `libra_source_preservation_v1_test.cjs`: 실제 LIBRA의 보류·분석 실패·후보 저장/readback 실패·정상 교체·응답 ID 변경·기존 대기 복구·사용자 제외 보존 7개 시나리오.
- `source_edit_shared_core_sync_test.cjs`: 공통 소스/프로필/embedded 일치와 비변경 검사.

기존 회귀 중 두 LIBRA 원문 수정 시험은 과거의 '보류 즉시 inactive' 기대를 새 'committed 유지' 계약으로 바꿨다. 기존 SDK 테스트의 승인 응답도 명시적인 keys를 반환한다. 기능 검증 조건을 삭제하거나 실패 검사를 무조건 PASS로 바꾸지 않았다. 현재 버전을 고정한 테스트·배포 안내는 실제 새 헤더와 맞췄다. HAYAKU 브라우저 테스트의 오래된 3.0.48 고정값은 현재 실행 파일의 헤더와 대조하도록 수정했다.

최종 실행 로그와 ZIP 재검사는 별도 검증 묶음 및 최종 구현 보고서에서 확인한다. 이전 배포의 PASS 수는 이 빌드의 결과로 재사용하지 않는다.

## 구성과 적용 범위

| 구성 | 버전 | 변경 |
|---|---|---|
| LIBRA | 2.3.34 | CAS 기준, 기존 정본 유지, 공통 동의 |
| HAYAKU | 3.0.50 | 공통 동의 및 기존 확인창의 선택 키 전달 |
| Flashback | 1.0.31 | 공통 동의. 원문 저장/벡터 엔진은 유지 |
| LIA | 0.26.63 | 원본 바이트 유지 |
| RE:TRACE | 1.9.67 | 원본 바이트 유지 |
| 서버/패키지 | 0.3.27 | 버전·배포 메타데이터만 변경 |

이 합본은 개발 증분이며 전체 설계 완료를 뜻하지 않는다. 기존 DATA·설정을 백업하고 분리 환경에서 확인한 뒤 같은 플러그인 항목에 업데이트한다. 신구 플러그인을 동시에 실행하지 않는다. ZIP의 DATA는 신규 설치용이며 기존 DATA에 덮어쓰지 않는다. 기존 기억·벡터의 전체 재생성이나 강제 콜드스타트는 하지 않는다.

제품 source의 기존 스키마·저널 키와 저장 namespace는 유지했다. 사용자 데이터를 자동 이전하거나 삭제하지 않는다. 설치 및 외부 호출은 사용자의 실제 환경에서 검수해야 한다.
