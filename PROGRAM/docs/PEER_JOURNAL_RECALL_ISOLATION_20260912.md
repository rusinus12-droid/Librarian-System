# 승인 기록 오류와 기존 기억의 읽기 분리

적용 버전: LIBRA 2.3.89, Flashback 1.0.66.

## LIBRA

승인 저널 오류는 SDK blocks()를 전체 스코프에서 true로 만든다. 기존 분기 검증은 이 값을 실제 미승인 변경으로 해석했으며, 해당 구간에 작업이 없으면 이전 정본 보존 검사도 실패했다. 정상 기억이 source_edit_identity_unverified로 비활성화되는 것을 격리 호스트에서 재현했다.

원문 수정 점검의 SOURCE_EDIT_JOURNAL_* 오류만 분리하여 기존 원문·분기 검증을 계속한다. 미완료 수정 작업이 실제로 존재하는 구간에만 기존 정본 보존 분기를 적용한다. 원문이 일치하는 정본은 정상 검증 경로로 유지 또는 재활성화되며, 실제 변경의 새 쓰기는 기존 canWrite() 제한을 유지한다. 다른 예외는 삼키지 않는다.

## Flashback

beforeRequest의 승인 저널 점검 예외가 외부 catch로 전달되어 기억 검색 준비를 중단했다. SOURCE_EDIT_JOURNAL_* 오류를 해당 점검 구간에서 기록하고 기존 리콜 준비를 계속하도록 수정했다. 기존 세계선·수명주기 검사 및 새 원문 교체 승인 제한은 유지한다. 오류 이벤트는 source_edit_journal_recall_preserved이며 승인 기록 상태에도 원래 오류가 남는다.

## 검증

- peer_journal_recall_isolation_test.cjs: LIBRA 실제 런타임에 저널 쓰기 실패를 주입하여 기존 정본 활성·본문 보존, 과거 오분류 정본의 동일 원문 재활성화, 실제 변경의 미승인 쓰기 차단, 추가 모델 호출 없음 확인.
- 같은 테스트에서 Flashback 실제 beforeRequest의 승인 점검 지점에 쓰기 거부·재조회 실패를 주입하여 리콜 준비가 계속되는지 확인. 무관한 오류는 여전히 중단됨을 확인.
- 기존 관련 회귀 테스트 13개 통과.

테스트는 가상 호스트이며 실제 RisuAI 화면, 사용자 기기의 저장 실패 원인 및 실서비스 검색 품질을 검증한 것은 아니다. 승인 기록의 쓰기 실패 자체를 성공으로 처리하지 않으며 사용자 DATA를 삭제하거나 재생성하지 않는다.
