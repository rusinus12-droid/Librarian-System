# HAYAKU 3.0.89 — 부분 저장과 분석 원문 경계 수정

## 반영 내용

- 부분 저장의 원문 비교에 동일한 분석용 정규화를 적용했다. 공백·CRLF 차이가 내용 변경으로 오인되는 경로를 수정했다. 실제 내용 변경, 스코프 변경과 현재 원문 결속 검사는 유지한다.
- think/thought/thoughts/reasoning/analysis로 명시된 메타 컨테이너를 분석용 원문 및 grounding 대상에서 제외한다. 원본 채팅과 기존 원장의 물리 데이터·해시는 수정하지 않는다. 이야기 속에 직접 등장하는 AI나 서술자를 단어 목록으로 제거하지 않는다.
- 단일·배치 콜드스타트, 누락 복구, 공통 분석 요청의 대상 원문·참고 문맥에 같은 메타 분리 함수를 사용한다.
- lock/detail/item/invitation/current_state/attire 등 검사에서 빠졌던 필드를 인식한다. lock/invitation/action/consequence/emotion 등의 요약은 정확한 근거 인용과 함께 비권위적인 파생 기억으로 보존할 수 있다. 현재 State·완전한 패킷으로 자동 승격하지 않는다.
- 임의로 번역한 이름을 동일 인물이라고 추정하지 않는다. 프롬프트는 기억 출력 언어와 관계없이 원문 이름 표기를 유지하도록 지시한다. 실제로 알려진 이름·참조를 잘못 쓴 결과는 계속 거부한다.
- 제외된 인물을 holderEntityIds 등 배열로 참조하는 항목도 종속 격리한다. 기존에는 단일 참조만 검사하여 일부 비밀 기억이 남을 수 있었다.
- 물리적으로 저장된 부분 기억의 결과 코드가 일반 생성 실패로 남던 연결 누락을 수정했다. durable readback이 성공하면 partial_memory_saved를 반환하며, 완전 패킷 완료 판정과 구별한다.

## 기존 데이터

분석용 원문 버전을 visible_story_v2로 결속한다. 이전 버전의 부분 기억 레코드는 삭제하지 않지만, 새 기준으로 검증하지 않은 레코드를 바로 검색에 투입하지 않는다. 실패 진단과 원본 응답도 유지한다. 자동 유료 재분석이나 사용자의 실제 저장소에 대한 이관은 실행하지 않았다.

## 검증

실제 로그에서 확인한 구조를 비민감 합성 자료로 재현한 hayaku_visible_source_admission_runtime_test.cjs를 추가했다.

- 메타 컨테이너가 분석 입력·인용 근거에서 제외됨
- 원본 채팅에는 메타 영역이 그대로 남음
- 공백·줄바꿈 차이가 있는 부분 기억은 저장 성공
- 실제 단어가 바뀐 원문은 저장 거부
- planner 객체·문자열 항목 수용 및 파생 기억 검색
- 제외된 인물의 배열 참조 격리
- 단일·배치 콜드스타트의 입력 정제
- 모델 호출 추가 없이 부분 저장·재조회 완료

새 시험과 파생 기억·디버그 시험이 통과했다. 기존 선택 회귀 17개 중 14개 통과, 두 추가 시험 포함 19개 중 16개 통과다. 나머지 3개는 이전 버전부터 폐기된 실패 복구 화면과 awaitingUserReview=true를 요구하는 계약이다:

- hayaku_otherax_evidence_grounding_runtime_test.cjs:162
- hayaku_native_otherax_recovery_contract_test.cjs:98
- hayaku_gui_ux_contract_test.cjs:14

문법과 SDK 동기화를 확인했으며 배포 manifest/checksum을 최종 파일로 갱신한다. 실제 사용자 원문과 sidecar의 정확한 차이는 첨부에 없으므로, 사용자 T5의 실제 재실행 성공을 인증하는 시험은 아니다. 실제 RisuAI·모델 제공자의 재실행 및 속도는 별도 확인이 필요하다.
