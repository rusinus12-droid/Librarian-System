# GUI 시안 독립 감사 — HAYAKU · Flashback · GRADIA · RE:TRACE (+ suite.js)

- 대상: `PROGRAM/docs/gui-redesign/{hayaku,flashback,gradia,retrace}.html`, `assets/suite.js`, `assets/suite.css`
- 방법: suite.js 계약(data-ctx/fill/variant/inherit-ctx/proxy, scope 기반 dirty, data-sync, preset, runJob, typed 확인)을 먼저 읽고, 각 화면의 마크업·인라인 스크립트를 따라 사용자 경로를 추적. 의심 항목은 `agent-browser`(1280×920)에서 클릭/`input` 이벤트를 그대로 재현해 확인. 검증 스크립트: `/projects/sandbox/.kiro/audit/js/*.js`
- 대상 폴더 파일은 수정하지 않았음.
- 심각도: **P0** 보이는 흐름이 깨짐 / **P1** 상태가 사용자를 오도함 / **P2** 다듬기
- 줄 번호는 근사값.

## 요약

| 파일 | P0 | P1 | P2 | 합계 |
|---|---|---|---|---|
| suite.js (공통) | 0 | 1 | 2 | 3 |
| HAYAKU | 1 | 9 | 3 | 13 |
| Flashback | 0 | 9 | 5 | 14 |
| GRADIA | 0 | 12 | 2 | 14 |
| RE:TRACE | 0 | 5 | 3 | 8 |

반복해서 나온 근본 원인 세 가지:
1. **`?open=`·proto-bar 경로에 화면 쪽 방어가 없음.** Flashback `dlg-del-scope`에만 있는 "열릴 때 현재 선택으로 다시 계산" 방어가 다른 확인창에는 없음. 토스트 `{key}` 치환은 `lastCtx`를 쓰는데, 이 값이 overlay `_ctx`와 따로 놀아서 `{name}` 같은 문자열이 그대로 화면에 나옴.
2. **"요약 표시 = 원본 값에서 계산" 원칙이 일부 화면에만 적용됨.** 배지·수치·"현재 값" 열·footer가 아직 하드코딩된 곳이 많음.
3. **결과를 주장하는 토스트**(기본값 불러오기, 지침 생성, 저장 후 닫기, 재검증 완료 등)가 실제 상태를 바꾸지 않음.

## A. 브라우저로 확인한 결함

### suite.js (공통)

**S-01 · P1 · suite.js ~70 (`toast`), ~421 (data-close 처리), ~454 (`?open=`)** — 확인창 토스트에 `{name}`·`{turn}`·`{names}`·`{stage}`가 그대로 표시됨
- 재현: 각 페이지에 `?open=<id>`를 붙여 열기 → 실행 버튼 클릭. 같은 방식으로 모든 확인창을 열어 본 결과(`js/sweep.js`):
  - HAYAKU: `dlg-delete`("{name} 실패 기록을 삭제하고…"), `dlg-compare`("{turn} 재생성 후보를 채택…")
  - Flashback: `dlg-del-scope`("{name} 스코프를 삭제…"), `dlg-del-items`("{names} 삭제를 적용…")
  - GRADIA: `dlg-ooc`, `dlg-skill`, `dlg-del-skill`, `dlg-del-prov`
- 원인:
  - `toast()`가 `lastCtx`만으로 치환함.
  - `openOv(id, null)`은 `lastCtx`를 바꾸지 않음.
  - Flashback처럼 `suite:open`에서 `ov._ctx`를 다시 계산해도 `lastCtx`는 그대로임.
- 수정 제안:
  - data-close 처리에서 `toast(msg, cov._ctx || lastCtx)` 형태로 **닫히는 overlay의 `_ctx`를 우선** 사용.
  - 치환되지 않은 `{key}`가 남으면 토스트를 띄우지 않거나 일반 문구로 대체.
  - 대상이 필요한 overlay에는 `data-require-ctx`를 두고, ctx 없이 열리면 실행 버튼을 비활성 + 안내.

  - 복원 select에 새 백업 없음. 초기화(백업 포함) 완료 후에도 같음.
- 수정: 백업 목록을 하나의 배열로 두고 `suite:jobdone`(job-backup / job-reset backup)에서 추가 → 배지·통계·경고·select를 다시 그리기.

**RT-05 · P1 · ~310 (`dlg-retry`)** — 재검증 토스트가 "승계가 완료되었습니다"라고 하지만 결과는 미완료 그대로
- 재현: 다음 세션 › 미완료 승계 재검증 → 재검증.
- 관찰: 토스트는 완료라고 하는데 LIBRA 배지 "영속 검증 실패", 시나리오 `partial` 그대로.
- 수정: 재검증을 작업으로 실행하고 결과에 따라 시나리오를 `ok`로 바꾸거나(성공), "아직 미완료"를 정직하게 알리기.

**RT-06 · P2 · ~423 (`syncRestore`)** — 동적 이름 뒤 조사 오류
- 재현: 복원할 플러그인을 LIA·RE:TRACE만 체크 → 미리보기.
  - 관찰: "LIBRA · HAYAKU · **Flashback는** 그대로입니다".
- 재현: 전부 체크.
  - 관찰: "**없음는** 그대로입니다".
- 수정: 마지막 이름의 받침을 판정하는 조사 함수 사용(영문은 발음 사전 또는 "‘…’ 플러그인은"처럼 조사를 고정할 명사 붙이기). 0개면 "다른 플러그인은 변경되지 않습니다"로.

**RT-07 · P2 · ~190** — 종류 필터(전체/활성/조상/…)가 눌린 표시만 바뀌고 카드는 그대로
- 재현: '확인 불가' 클릭.
- 관찰: 보이는 카드 7개 그대로.
- 수정: `.scope-card` k-* 클래스로 필터 적용.

## B. 코드로만 확인한 의심 (브라우저 재현 안 함 또는 표본 성격)

- **HY-S1 (P2)**: T132 '후보 채택' 후에도 버튼이 활성이라 다시 누르면 같은 성공 토스트가 나옴(힌트: "이미 해결된 항목은 채택할 수 없습니다"). 실패 기록 삭제·고아 정리(2) 후에도 목록·count가 그대로.
- **HY-S2 (P2)**: 원장 읽기 실패 시나리오에서도 "원장 JSON" 내보내기·패킷 보기 전환·필터가 활성. 패킷/로그 검색·필터는 동작 없음.
- **HY-S3 (P2)**: '패킷 복구 사용'이나 'HAYAKU 사용'을 끄고 저장해도 복구 버튼·상단 "정상 작동" 칩에 반영되지 않음.
- **FB-S1 (P2)**: footer 차원은 모델 이름 정규식(`dimOf`)으로만 정해져 '벡터 차원' 입력값(0=자동 외)을 무시함. small→large 변경 시 기존 1,536차원 벡터와의 불일치 경고가 없음.
- **FB-S2 (P2)**: 리콜 프리셋 설명 "4개 값(Top K·최소 점수·후보 수·주입 글자)"·세부 값 "외 7개"인데 실제 프리셋·필드는 2개.
- **FB-S3 (P2)**: 복원(현재 기억 37개 제거, 되돌릴 수 없음)이 입력 확인 없이 버튼 하나로 실행됨. 다른 파괴적 동작과 확인 강도가 다름.
- **GR-S1 (P2)**: AI 연결의 "키 삭제"가 확인 없이 바로 실행되고 배지 '완료' 유지. 상단 "추가"·"복제", 내보내기의 "클립보드로 복사", 디버그 버튼에 동작 없음.
- **GR-S2 (P2)**: Skill 우선도에 숫자가 아닌 값을 넣으면 안내 없이 0으로 저장(`parseInt||0`). 이름 중복 허용. Skill 검색 동작 없음.
- **GR-S3 (P2)**: 사용자 Skill 사용 스위치를 바꾼(미저장) 상태에서 그 Skill을 삭제하면 미저장 변경 수에서 조용히 빠짐. Skill 추가·삭제는 즉시 반영이라 저장 바 "변경 취소"로 되돌릴 수 없는데, 이 차이가 화면에 안내되지 않음.
- **RT-S1 (P2)**: job 창에 "창을 닫지 마세요"라고 하지만 배경 클릭·Esc로 닫히고 다시 열 경로가 없음(suite 공통, HY-01과 같은 원인). `data-sticky` 또는 상단 작업 표시가 필요.
- **RT-S2 (P2)**: `ok` 시나리오에서도 `?open=dlg-retry`로 재검증창이 열림. 승계 결과 count가 다음 세션 실행 결과와 연결되지 않음(transferId 고정).
