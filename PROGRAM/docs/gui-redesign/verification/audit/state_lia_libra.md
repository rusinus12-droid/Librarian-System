# LIA · LIBRA 시안 상태 일관성 감사 보고서

대상: `PROGRAM/docs/gui-redesign/lia.html`, `libra.html`, `assets/suite.js` (+`suite.css`)
방법: suite.js 공통 계약(data-ctx / data-fill / data-variant / data-inherit-ctx / scope 기반 dirty / data-sync / data-preset / suite:* 이벤트 / runJob)을 먼저 읽고, 각 페이지의 마크업과 인라인 스크립트를 따라 사용자 경로를 추적했습니다. "브라우저 확인" 항목은 모두 agent-browser(Chromium, 1280×920)에서 클릭·input 이벤트로 재현했습니다. 재현 스크립트는 `.kiro/audit/_s/`(l1–l9.js, b1–b8.js, `run.sh`)에 있습니다. 원본 파일은 수정하지 않았습니다.

심각도: **P0** 보여 주는 흐름이 깨짐 · **P1** 잘못된 상태를 보여 줌 · **P2** 다듬기

> 이번 감사에서 P0는 없었습니다. 주된 흐름(만들기 → 보관 → 편집 → 채택 → 연결, 구간 선택 → 작업 → 결과)은 정상 진입 경로에서 동작합니다. 남은 결함은 (a) 정상 경로가 아닌 진입로(`?open=`, proto-bar, 대상 없이 열리는 창), (b) 작업·확인 뒤 결과가 화면 데이터에 반영되지 않음, (c) 하드코딩된 수치·문구 쪽에 몰려 있습니다.

## 1. 공통 (suite.js) — 브라우저 확인

### COM-01 · P1 · `?open=`이 `suite:ready`보다 먼저 처리됨
- 위치: `assets/suite.js` 454행(`openOv(qs.get('open'))`) → 456행(`suite:ready` 발행)
- 원인: 페이지 스크립트는 `suite:ready`에서 표본 데이터를 만듭니다(LIA `seed()`, LIBRA `rows/sel/go` 초기화). 그런데 `?open=` 창은 그보다 먼저 열리고, 그 시점의 `suite:open` 처리기는 빈 상태를 읽습니다.
- 재현 / 관찰:
  1. `lia.html?open=sheet-bind#mine` → 연결 시트에 "연결할 수 있는 Persona가 없습니다"가 뜨고 [연결하기]가 비활성입니다. 실제로는 채택된 Persona 2개(세라·길손)가 있고, 내 페르소나 목록에도 보입니다.
  2. `lia.html?open=sheet-persona#mine` → 제목은 "‘세라 하운’ 관리"인데 본문은 "관리할 RisuAI Persona가 없습니다"입니다.
  3. `libra.html?open=dlg-range#desk` → `Uncaught TypeError: Cannot read properties of undefined (reading 'forEach')` (suite:open 처리기의 `rows`가 아직 undefined)
- 기대: 쿼리로 연 창도 데이터가 준비된 뒤의 상태를 보여 줘야 합니다.
- 수정: init에서 `suite:ready`를 먼저 발행하고, 그 뒤에 `?open=`/`?sub=`를 처리합니다. 또는 쿼리 처리를 `setTimeout(…,0)`으로 미룹니다.

### COM-02 · P1 · 대상이 필요한 확인창이 대상 없이 열림 → 표본 대상을 보여 주고, 아무것도 하지 않은 채 원시 placeholder 토스트를 띄움
- 위치: LIA `sheet-del-vault`(395행), `sheet-unbind`, `sheet-del-persona`, `sheet-persona` / LIBRA `dlg-del-version`(486), `dlg-promote`(485), `dlg-recover`(496)
- 재현(`?open=` 또는 `window.suiteOpen(id)`):
  - LIA `?open=sheet-del-vault` → "보관함의 ‘카엘 로웬’ 항목을 삭제할까요? · 최신 v1 · 채택 전"이 뜹니다. [보관함에서 삭제]를 누르면 토스트 **"‘{name}’ 보관함 항목을 삭제했습니다. {afterVault} (시안)"**이 뜨고 보관함 화면으로 넘어가지만, 보관함은 여전히 4개(카엘 포함)입니다.
  - LIA `sheet-unbind` → "‘{name}’ 연결을 해제했습니다"가 뜨지만 상단 카드는 여전히 세라입니다. `sheet-del-persona` → "‘{name}’ 항목을 정리했습니다. {vaultAfter}"가 뜨지만 목록은 그대로입니다.
  - LIBRA `?open=dlg-del-version#memory` → "M-25 · 비활성 버전 v2"가 뜨고, [삭제]를 누르면 토스트 **"{mem} {ver} 삭제 완료"**가 뜹니다.
  - LIBRA `suiteOpen('dlg-recover')` → 제목 "작업", 비용·영향이 "-"입니다. [실행]을 누르면 진행 후 '현재 상태 다시 적용' 결과(variant default=state)가 표시됩니다.
- 기대: 대상이 없으면 실행할 수 없어야 하고, 토스트는 일어난 일만 말해야 합니다.
- 수정: (1) overlay에 `data-require-ctx="pid"`(또는 `mem`)를 두고, `openOv`에서 ctx에 해당 키가 없으면 열지 않거나 "대상이 선택되지 않았습니다" variant를 보여 주며 확인 버튼을 비활성화합니다. (2) `toast()`에서 치환 뒤에도 `\{\w+\}`가 남으면 토스트를 내지 않고 `console.warn`을 남깁니다.

### COM-03 · P2 · `?open=job-*`로 연 작업창이 진행되지 않음

## 5. 확인 결과 문제없음 (요약)

**LIA**
- 저장 범위 분리: 편집 미저장(나이) + 설정 미저장 → 설정 저장 뒤에도 편집 1개가 유지되고, 이미지 범위도 유지됩니다. 편집 [변경 취소]는 실제 값(29세)을 복원합니다.
- 채택: 미저장 변경이 있으면 비활성화되고 안내가 뜹니다. 채택 토스트에 옵션(원문·Standard·현재 채팅 전용)이 들어갑니다.
- 클래식 생성: Source=길손 → 안내 "채택본 v2", 진행창 "‘이름 없는 길손 · 이 세계판’ · 클래식 생성". Esc로 창을 닫아도 완료되고, 보관함·메뉴 카운트가 5/5로 함께 갱신되며 완료 토스트가 뜹니다.
- 랜덤 후보: 후보 보기 → 토비 선택 → 버튼 "‘토비’ 상세 생성" → 진행창 "‘토비’" → 편집 "토비 · v1 · 랜덤 신규 생성 · 역할 순회 서기"
- 연결: 편집에서 [이 채팅에 연결…] → 시트에 그 Persona가 미리 선택되고 "현재 연결된 ‘세라 하운’ 연결은 해제됩니다" 안내 → 상단 카드가 토비로 바뀝니다. 채택 전에는 연결 버튼이 비활성입니다.
- 대상이 있는 정상 경로의 해제·정리·보관함 삭제는 ctx 대상과 일치합니다. 작업 취소는 상태를 cancelled로 바꾸고 결과를 만들지 않습니다.
- 보관함 카운트(본문·메뉴)는 P에서 계산합니다.

**LIBRA**
- 구간 선택: 열 때마다 초기화되고, 카드에서 들어오면 그 구간만 선택됩니다. 종류별로 선택 가능한 행이 걸러집니다. 선택 수·예상 호출 수·버튼 ctx가 일치합니다. regen variant는 '후보 보관' 단계와 '정본 변경 없음' 결과를 보여 줍니다.
- 복구 4종: ctx가 있으면 제목·비용·영향·결과 variant가 서로 맞습니다.
- data-sync(빠른 설정 ↔ 설정): 입력은 상대 칸에 복사되고 상대 범위도 dirty가 됩니다. 드로어 [되돌리기]는 설정 쪽 값과 dirty도 원래대로 돌립니다(8, 0). 설정 저장은 드로어 범위 dirty도 0으로 만듭니다.
- 성능 프리셋 ↔ 세부 값(data-preset)
- 읽기/관리 모드: 세계에서 '관리'를 고르면 서가 seg와 manage-only 도구도 함께 바뀝니다.
- 세계 도감: 분류 필터(규칙 2), 연결 칩을 누르면 '전체'로 돌아간 뒤 해당 카드에 포커스, '기타 0'이면 빈 상태
- 버전 드로어의 행 ctx 캡처(mem + 행 버전)가 승격·삭제 확인창 제목에 그대로 반영됩니다(내용은 LIB-06).
