## 9. 아직 남은 것 / 정직한 한계

1. **제품 통합 검증은 하지 않았습니다.** 감사 §12의 "제품 통합 후 별도로 필요한 시나리오"(실제 API·저장·복구·취소·동시성·scope 보호)는 정적 목업 범위 밖이라 그대로 남아 있습니다.
2. **일부 항목은 감사 본문을 근거로 반영했고 제품 코드와 직접 대조하지 못했습니다.** 해당 표의 "감사 기준" 표시를 참고하세요. 특히 (a) LIA 생성 모드별 논리 요청 수(2/3회) (b) HAYAKU 실패 기억의 수리 3방식 세부 (c) GRADIA 전문가 설정의 세부 항목명 (d) LIBRA 복구 5종의 세부 동작. 실제 구현 전에 코드와 한 번 더 대조해야 합니다.
3. **개별 선택 UI의 깊이는 대표 항목까지만 보여줍니다.** 예: LIA 캐릭터·모듈 로어북을 항목 단위로 고르는 화면, LIBRA 분석 입력 규칙의 모든 옵션, HAYAKU 설정 48개의 값 범위 검증은 "위치와 의미"만 보여주며 모든 값을 구현한 것은 아닙니다.
4. **상태 표현은 대표 시나리오 위주입니다.** 부분 성공·결과 불명·차단·미저장은 RE:TRACE·Flashback·HAYAKU·LIBRA·LIA 핵심 경로에 넣었지만, 모든 기능×모든 상태 조합을 만든 것은 아닙니다. 로딩 상태는 거의 표현하지 않았습니다.
5. **접근성은 레이블 연결 + 기존 포커스/ESC 처리까지만** 확인했습니다. 실제 스크린리더, 키보드 전용 전체 순회, 화면 확대, 실기기 모바일은 검증하지 않았습니다.
6. 이 환경의 Chromium에서 한국어 글리프는 표시되지만 서체에 따라 줄바꿈 위치가 달라질 수 있습니다.
