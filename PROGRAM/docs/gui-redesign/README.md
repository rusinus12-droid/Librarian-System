# 플러그인 6종 GUI 재설계 시안

대상: **LIBRA(리브라) · HAYAKU(하야쿠) · Flashback(플래시백) · GRADIA(그라디아) · LIA(리아) · RE:TRACE(리트레이스)**

각 플러그인의 GUI 코드(`PROGRAM/plugins/*.js`)를 분석한 뒤, 정보 구조를 먼저 정리하고 그 위에 시각 디자인을 입힌 **정적 HTML 시안**입니다.
플러그인 코드는 **한 줄도 수정하지 않았습니다.** 이 폴더만 추가됩니다.

> **2026-10-12 감사(LIB-6-GUI-20261012) 반영본입니다.** 감사 지적 사항별 처리 결과와 남은 한계는 [`AUDIT-RESPONSE.md`](AUDIT-RESPONSE.md)에 있습니다. 이 시안은 *화면 구조와 안전 규칙*을 보여주는 것이며, 기능을 줄이거나 의미를 바꾼 곳이 없는지 현행 코드와 대조한 결과를 함께 적었습니다. 선택·편집·저장·채택·연결이 **같은 데이터**를 읽고 쓰도록 만든 상태 모델(범위별 저장 상태, 저장소 객체, `data-sync`, `data-preset-*`)은 `AUDIT-RESPONSE.md` §11에 정리했습니다.

## 1. 현행 GUI 분석 요약

코드 분석에서 확인한 공통 문제와 플러그인별 문제입니다.

### 공통
- 같은 상태(저장 정상/연결됨)가 사이드바·배너·칩에 **여러 번** 표시됨
- 같은 설정/저장 버튼이 **여러 곳**에 존재
- 글자 크기 8~11px 다수, 모바일에서 읽기 어려움
- 파괴적 작업의 확인 방식이 제각각 (네이티브 `confirm()`, 자체 대화상자, 확인 없음)
- 플러그인마다 다크/라이트/레거시 CSS가 겹쳐 있음 (`!important` 다수)
- 진행 상황이 텍스트뿐인 작업이 있음

## 2. 설계 원칙

기준 문서: `PROGRAM/docs/Librarian-Mobile-GPU-UI-IMPLEMENTATION-GUIDE-20260920-v2-FLASHBACK-REFERENCE.md`

1. **GPU 안전**: `backdrop-filter`, `filter: blur` 사용 안 함. 불투명 면 + 1px 테두리. 그림자는 메뉴·모달·서랍 같은 *떠 있는 요소*에만. 모바일에서는 바깥 그림자 제거.
2. **오버레이**: 알파 딤 + 불투명 대화상자. 활성 상태는 번짐(glow)이 아니라 **대비(+글자)** 로 표현.
3. **구조를 복사하고 팔레트는 복사하지 않음**: Flashback의 베이지를 그대로 쓰지 않고, 플러그인마다 고유 모티프를 가짐.
4. **정보 구조 먼저**: 메뉴 4~6개, 한 화면 한 목적, 상태는 상단 칩 1개, 저장은 막대 1개.
5. **위험 작업 규칙**: 영향 범위 설명 → (큰 작업) 확인 문구 입력 → 진행 단계/바 → 결과 재확인.
6. **반응형**: 컨테이너 쿼리 기반. 좁은 폭에서 사이드바가 하단 탭으로 바뀌고, 5개 초과 시 ‘더보기’ 시트.
7. **접근성**: 본문 12px 이상(보조 라벨만 11~11.5px), 포커스 링, 색만으로 상태를 구분하지 않음, `prefers-reduced-motion` 존중.

### 공통 셸

```
┌ topbar: 브랜드 · 범위(스코프) · [상태 칩 1개] · ⋯ 메뉴 ┐
├ sidebar(그룹 라벨) │ page-head(eyebrow/제목/설명)      │
│  └ 좁으면 하단 탭   │ page-body                          │
│                    │ savebar (설정이 있는 화면만, 1개)  │
└────────────────────┴────────────────────────────────────┘
```

공통 컴포넌트: `list/row`, `stats`, `steps`(단계), `progress`(작업 진행), `choices`(큰 선택지), `setting`(토글/슬라이더 행), `note/banner`, `dialog`(+`dialog--danger`), `sheet`(바텀 시트), `drawer`, `tabs`(서브 탭), `kv`.

## 4. 실제 구현 시 바꾸면 안 되는 계약 (중요)

시안은 화면 구조만 보여줍니다. 구현 시 아래는 **유지**해야 합니다.

- 테스트가 참조하는 **버튼 ID / `data-*` 훅** (예: `gui_verify.js` 135개 검사, `retrace_*_test.cjs`). 이름을 바꿀 때는 테스트도 함께 이전.
- Flashback의 `class="panel"` 문자열 치환 기반 탭 활성화 방식 (구조 변경 시 함께 수정 필요)
- 공용 SDK가 렌더링하는 패널 (서버 연결, 이동식 백업) — 플러그인 쪽에서 위치/스타일만 조정
- 진단은 **읽기 전용** 의미를 유지 (진단 버튼이 상태를 바꾸면 안 됨)
- RE:TRACE: Owner IPC 계약, **fail-closed** 게이트, **삭제 증명**, `manager_only` 역할
- **감사에서 확인된 의미 규칙**(시안이 이를 어기지 않도록 반영했고, 구현에서도 유지해야 함)
  - LIBRA: 기억은 *완결된 5턴* 단위. 마지막 미완성 턴은 선택 불가. 재분석은 성공 시 교체·실패 시 기존 유지, 재생성은 정본을 유지한 후보 비교
  - LIA: 보관함 저장 ≠ RisuAI Persona 채택 ≠ 채팅 연결. 기본 Persona는 덮어쓰지 않음. 다른 채팅이 관리하는 Live Persona는 직접 연결 불가
  - GRADIA: RP는 player-controlled 계약 고정. 연결됨 ≠ 생성 호환(검증 조합만 호환)
  - HAYAKU: 분석·검증 완료 ≠ 패킷 교체 완료(사용자 선택 필요)
  - Flashback: 진단은 읽기 전용, 비용이 있는 복구는 계획 확인·동의 후. 영구 기록은 삭제 후보에서도 보호
  - RE:TRACE: *확인 불가* 사본은 삭제 차단. 활성 사본은 로컬 보존·모드 전환 증명 후에만 삭제. 초기화는 서버 기억만(로컬·기존 백업 보존)
- 저장 소유 구조(`PLUGIN-ROLE-AND-STORAGE-DESIGN-20261007.md`): writer = LIBRA/HAYAKU/Flashback, GRADIA = LIB 읽기 소비자, LIA = local_only, RE:TRACE = manager_only

## 5. 구현 로드맵 제안

1. **토큰 먼저**: 플러그인별로 `suite.css`의 토큰(색·간격·타이포·반경)을 가져와 기존 CSS 레이어를 단계적으로 대체 (`!important` 제거 목표).
2. **파일럿 1종**: 영향이 작고 구조가 단순한 **RE:TRACE** 또는 **LIA**부터 → 컴포넌트(스테퍼·시트·진행 바)를 검증.
3. **통합 순서 제안**: RE:TRACE → LIA → Flashback(시각 언어 유지라 위험 낮음) → HAYAKU → GRADIA → LIBRA(가장 큼).
4. 각 단계마다: GUI 검증 스크립트 통과 → 모바일 실기기에서 스크롤/전환 성능 확인 → 다음 플러그인.
5. 죽은 코드(LIBRA 작성실, HAYAKU `failed_recovery` UI, GRADIA alias 경로)는 화면 개편 PR과 **분리해서** 정리.

## 6. 신규 제안 (현행 기능이 아님)

시안에서 **제거**했지만 장래 검토할 만한 아이디어입니다. 도입하려면 동작과 영향을 먼저 결정해야 합니다.

| 대상 | 아이디어 | 현행과의 차이 |
|---|---|---|
| LIA | AI 없이 빈 양식에서 시작 | 현행 생성 모드 4종과 별도 경로 |
| LIA | 갱신 알림 · 3~15턴 간격 · 갱신 전 미리보기 | 현행은 다음 완결 5쌍을 한 번 처리하는 수동 갱신. 자동 스케줄러는 꺼져 있음 |
| LIA | 남은 감정만 생성 | 현행 묶음 생성은 neutral 외 전체를 생성·갱신 |
| LIA | 범용 백업 가져오기·내보내기 | 현행은 에셋 ZIP·디버그 JSON·이전 자료 복구 |
| LIBRA | 정본 기억 일반 병합 · 즉시 삭제 | 현행에 없음. 인물·세계의 같은 항목 병합·분리, 비활성 버전 삭제만 있음 |
| RE:TRACE | 초기화 전 백업 예외 없이 필수화 | 현행은 "백업 없이 진행" 선택이 있음 |

## 7. 한계 및 알림

- 정적 시안입니다. **실제 RisuAI 호스트에서 검증하지 않았습니다** (호스트 CSS 간섭, iframe 크기, 플러그인 API 제약은 구현 단계에서 확인 필요).
