# Flashback 서버 커밋 보호

버전: Server 0.3.39 / Flashback 1.0.36 / Storage SDK 1.8.16.

## 적용 범위

Flashback에서 서버 단독 또는 미러를 선택한 범위에 적용된다. 플러그인 단독 기본값, 자동 서버 요청 0회, 원문 승인, 원격 모델 설정은 유지한다. 다른 플러그인은 공통 SDK 포함본을 갱신하며 owner별 저장 정책은 유지한다.

## 저장 계약

- 기존 scope 쓰기 잠금이 서버의 배타적 쓰기 권한을 먼저 취득한다. DB에 저장되는 epoch는 새 권한마다 증가한다. 권한은 120초 후 만료되며, 작업 중 저장 시 남은 시간이 30초 미만이면 갱신한다. 만료 후의 갱신은 거절된다. 사용 종료 시 해제한다.
- 권한 검증과 실제 set/remove/batch는 같은 SQLite 트랜잭션에서 실행한다. 서버 프로세스가 여러 개여도 동일 DB에서 하나의 유효 writer만 허용한다. 권한 해제를 확인하지 못하면 만료 전까지 다른 writer를 거절한다.
- 보호 표식은 첫 새 writer가 접근할 때 기존 KV와 별도 표에 저장된다. 이후 구버전의 조건 없는 set/remove와 권한 없는 batch는 거절된다. 아직 보호가 시작되지 않은 범위나 구버전 서버에는 이 보장이 없다.
- 원문 shard와 벡터를 저장하고 재조회한 뒤 manifest와 복구 포인터를 조건부 batch로 함께 확정한다. operation receipt도 같은 트랜잭션에 저장된다. 실패한 후보는 기존 커밋을 덮어쓰지 않는다.
- 응답 유실은 같은 operation ID의 결과를 조회한다. 확인되지 않으면 결과 미확정으로 남기며, 새 무조건 저장이나 원격 모델 재호출을 하지 않는다. 이미 전송된 요청에는 옛 epoch가 고정되어 늦은 완료가 새 데이터를 덮어쓸 수 없다.
- 관리 도구의 조건부 삭제는 활성 writer가 없는 경우에만 허용한다. scope 삭제 후에도 보호 표식은 남는다.

## 미러와 데이터 이관

서버를 선택한 Flashback 원문·벡터는 서버를 정본으로 읽는다. 서버 키가 없는 경우에만 기존 로컬 값을 조건부로 이관하고 서버에서 재조회한다. 서버에 이미 있는 값과 로컬 값이 다르면 수동 동기화도 서버를 덮어쓰지 않고 충돌로 보존한다. 삭제 표식은 자동으로 되살리지 않는다. 미러 로컬 복사본 갱신 실패와 서버 커밋 실패는 구별한다.

이 패치는 사용자의 저장 모드를 자동 전환하지 않는다. 적용 시 서버와 Flashback을 함께 업데이트해야 한다. 서버의 새 capability가 없으면 새 서버 커밋 경로는 중단한다. DATA는 보존하고 PROGRAM을 업데이트한다. 구버전 서버로의 단독 다운그레이드는 보호 계약을 유지하지 못한다.

## 검증 경계

제품 회귀 `tests/flashback_fenced_commit_v136_test.cjs`는 실제 로컬 HTTP/SQLite, 분리된 플러그인 VM, 두 서버 프로세스, 지연 요청·응답 유실·DB 오류, 미러 캐시, 재시작과 원문을 검사한다. 환경 변수 `FLASHBACK_LEGACY_SOURCE`에 보존된 구버전 소스를 주면 실제 구버전 실행 시험도 추가한다. 의도적으로 거절된 캡처는 pending을 보존하고 다음 캡처 재시도에서 처리한다.

plugin_only는 `host_readback_only` 증거이며 호스트가 실제 영속 저장을 거짓으로 응답하는 경우까지 보장하지 않는다. 서버 커밋 증거는 `server_sqlite`로 구분한다. 실제 RisuAI GUI, 외부 모델·임베딩 업체, 전원 차단·장치 장애 시험은 NOT_RUN이다.
