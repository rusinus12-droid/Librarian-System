# GRADIA 스킬 라우터 검토 — 문제 의식과 권장 해결

날짜: 2026-10-22 · 대상: GRADIA `0.26.8` · 상태: **검토 문서. 코드는 아직 바꾸지 않았다.**

후속: GRADIA 0.26.9에서 자동 라우터를 퇴역시키고 [단계별 수동 선택과 독립된 기본 품질 규칙](GRADIA_MANUAL_SKILLS_20261022.md)으로 교체했다. 아래 수치는 변경 전 기록이다. 기존 평가 도구 진입점은 수동 선택 점검으로 연결되며, 당시 자동 라우터 재현 코드는 커밋 `40b3405`에 보존되어 있다.

## 1. 현재 구조

"스킬 라우터"는 초안 4단계(SHADOW, 인물·세계관·플롯 AIDE)의 프롬프트에 글쓰기 절차를 넣는 계층이다. 실제로는 성격이 다른 두 부분으로 되어 있다.

| 부분 | 내용 | 분량(호출당) |
|---|---|---|
| 기본 품질 규칙 `GRADIA_BASE_SKILL_IDS` | 지식 경계, 상태 연속성, 인물 구별, 단일 신호 절제, 장면 연기, 유저 행동 경계(RP만), 출력 형식 등 7개의 요약 | 약 2,000자 |
| 동적 선택 `routeSkillsForStage` | 스킬 39개 중 점수 상위 `topK`(기본 2)개의 전문(필요하면 참고 문서 1개 포함) | 약 11,000~12,700자 |

동적 선택의 동작은 다음과 같다. 모델 호출 없이 단어 비교로만 점수를 매긴다.
- **비교 대상:** 현재 입력·직전 장면·직전 초안·연속성 원장을, 각 스킬의 이름과 영어·한국어 설명에 비교한다(`skillRouterFastTextScore`, 토큰·문자 n-gram Jaccard).
- **점수 구성:** 단어 관련도에 단계별 친화도(`GRADIA_SKILL_STAGE_AFFINITY`)와 문맥 가산점을 더한다.
- **선택 조건:** 최고 점수의 34% 이상, 절대 하한 0.03 이상인 스킬만 고른다.

라우터 블록(`stageSkillBlockForPrompt`)에는 RP 모드의 "스킬 주체 게이트"와 "턴 넘김 계약"도 함께 붙는다.

## 2. 문제 의식

### 2.1 동적 선택이 장면에 맞는 스킬을 거의 고르지 못한다

`tools/rag_eval/gradia_skill_router_eval.cjs`로 측정했다. 정답 스킬이 분명한 장면 10개를 실제 라우터와 컴파일러에 넣었다.
- 장면: 전투, 고백, 코미디, 심문, 폭발 직후, 조용한 내면, 새 인물 등장, 재판, 중대한 결정, 협동 작전
- 기대 스킬 예: 전투 → `physical-conflict`, 코미디 → `comedic-scene-construction`

| 항목 | 한국어 장면 | 영어 장면 |
|---|---|---|
| SHADOW 상위 2개에 기대 스킬 포함 | **1 / 10** | 2 / 10 |
| AIDE 3단계 상위 2개에 기대 스킬 포함 | 5 / 30 | 4 / 30 |
| 선택된 스킬의 관련도 점수 | 0.002~0.039 | 0.05~0.11 |

엉뚱하게 고른 예는 다음과 같다.
- 심문 장면 → `comedic-scene-construction`
- 코미디 장면 → `scene-boundary-crossing`, `immediate-aftermath`
- 전투 장면 → 선택 없음
- 영어 장면 → 기본 규칙에 이미 들어 있는 `scene-performance`, `output-contract-discipline`을 다시 골라 같은 내용을 전문으로 중복 삽입

점수가 노이즈 수준이라 순위가 장면 내용을 반영하지 못한다. 짧은 장면 문장과 일반적인 절차 설명문 사이에는 공유 단어가 거의 없기 때문이다. 영어 결과도 크게 다르지 않으므로 번역 문제가 아니라 **방식의 한계**다.

### 2.2 비용이 크다

- 동적 선택 블록은 호출당 약 1.1만~1.3만 자다. 경량(4회)은 턴당 약 4.4만 자, 중량(8회)은 약 9만 자를 쓴다.
- 대부분이 장면과 무관한 절차이므로, 토큰 비용과 함께 모델의 주의를 흐트러뜨릴 위험이 있다.
- 라우팅 시간은 단계당 약 0.14~0.17초로 모델 호출에 비해 작다. 문제는 시간이 아니라 분량이다.

### 2.3 끄면 기본 품질 규칙까지 사라진다

`compileSkillGuidanceForStage`는 `route.enabled`가 거짓이면 빈 문자열을 돌려준다. 그래서 설정에서 스킬 라우터를 끄면(`skillRouterEnabled: false`) 동적 선택뿐 아니라 **기본 품질 규칙 7개도 함께 빠진다.** 사용자는 "부정확한 자동 선택"만 끄고 싶어도 핵심 규칙까지 잃게 된다.

RP 계약 두 개는 라우터 설정과 무관하게 유지된다(`stageSkillBlockForPrompt`가 따로 붙임).

## 3. 권장 해결

### 3.1 [필수] 기본 품질 규칙을 라우터 설정과 분리

- `compileSkillGuidanceForStage`가 `route.enabled`와 관계없이 기본 규칙 블록을 만들게 한다. 동적 선택이 꺼져 있으면 "COMPILED SELECTED SKILLS" 부분만 생략한다.
- 기본 규칙의 단계별 우선순위 설정(`skillPriorityResolution`)과 소설 모드에서 `user-agency-boundary`를 빼는 규칙은 그대로 둔다.
- 검증: 라우터를 끈 상태에서도 네 단계 프롬프트에 BASE QUALITY FLOOR가 들어가는지 확인한다. 끈 경우와 켠 경우의 기본 규칙 텍스트가 같은지도 확인한다.

### 3.2 [권장] 동적 선택을 기본값에서 끄기

- `DEFAULT_SKILL_ROUTER_ENABLED`(또는 동적 선택만 켜고 끄는 새 설정)를 기본 꺼짐으로 바꾼다.
- 스킬 편집 화면, 사용자 정의 스킬, 우선순위 설정은 유지하고, 사용자가 켜면 지금처럼 동작하게 한다.
- 효과: 호출당 약 1.1만 자 감소, 장면과 무관한 절차 혼입 제거, 프롬프트 내용이 입력에 따라 들쭉날쭉하지 않음.
- 기존 사용자 설정에 `skill_router_enabled`가 명시돼 있으면 그 값을 존중할지 정해야 한다(마이그레이션 판단 필요).

### 3.3 [선택] 동적 선택을 계속 쓰려면 방식 교체

단어 유사도를 버리고, 스킬마다 **명시적 신호 목록**(한국어·영어 키워드와 정규식)을 두는 결정적 방식으로 바꾼다.
- 예: `physical-conflict` ← 검, 칼, 주먹, 공격, 막아, 반격, 총, 싸움 / sword, strike, parry, attack
- 예: `comedic-scene-construction` ← 웃기, 농담, 장난, 우스꽝 / joke, prank, comedic
- 신호가 하나도 맞지 않으면 아무것도 넣지 않는다. 지금처럼 "최고 점수의 34%" 상대 기준으로 무관한 스킬을 억지로 채우지 않는다.
- 기본 규칙에 이미 있는 스킬은 동적 선택 후보에서 뺀다(중복 삽입 방지).
- 통과 기준: 위 평가 스크립트에서 SHADOW 기준 10장면 중 8개 이상 정답 포함, 무관한 선택 0개. 관련 장면이 아닌 입력에는 선택 없음.
- 모델 호출을 늘리는 방식(분석 단계가 스킬을 고르게 하는 것 등)은 비용과 지연이 늘어 권하지 않는다.

### 진행 순서

1. 3.1을 먼저 적용한다. 동작을 바꾸지 않는 안전한 분리다.
2. 3.2로 기본값을 바꾼다.
3. 동적 선택이 필요하다고 판단되면 3.3을 별도 작업으로 진행하고, 평가 스크립트를 통과 기준으로 쓴다.

## 4. 한계

- 이 평가는 "맞는 스킬을 고르는가"와 "분량"만 측정했다. 스킬이 실제 글 품질에 주는 효과는 가짜 모델로는 측정할 수 없다. 3.2 적용 전후의 품질 비교는 실제 모델로 따로 확인해야 한다.
- 장면 10개와 기대 스킬은 사람이 정한 대표 사례다. 한 장면에 맞는 스킬이 여럿일 수 있어 "기대 스킬 포함"은 엄격한 정답률이 아니라 최소한의 관련성 지표다.

