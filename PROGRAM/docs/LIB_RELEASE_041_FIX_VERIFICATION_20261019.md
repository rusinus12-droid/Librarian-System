# LIB 0.4.1 실사용 패치 검증 — 2026-10-19

이번 기록은 기존 감사·설계 문서를 판정 근거로 사용하지 않고, 현재 소스와 새로 실행한 서버·브라우저·모델 호출 결과로 작성했다. 기준 소스는 main `562e50501c76571c4fc3930c36bc4a7edf304469`이며, 패치 버전은 패키지 0.4.1 / LIBRA 2.3.172 / GRADIA 0.25.91이다.

## 수정한 문제

1. **Micro의 Ollama 추론 설정 누락.** 정본과 달리 Micro 요청은 추론 비활성화 선택이 공급자에 전달되지 않아, 4,096 출력 토큰을 추론에 소모하고 최종 JSON 없이 길이 제한으로 종료될 수 있었다. 공통 요청 빌더에서 선택을 전달한다. 강제 추론 모델은 지원하는 동작을 유지하며, 사용자의 명시적 추론 설정도 유지한다. Micro 출력 한도 증액이나 자동 추가 호출로 해결하지 않았다.
2. **정본 생성 프롬프트의 ID·공간 관계 혼동.** 임시 ID는 ASCII 순번으로 요청하고, 장소 간 포함과 물건의 배치를 구분하도록 명시했다. 이름·본문·근거는 원래 언어를 유지한다. 실제 근거·타입·참조 검증은 그대로 적용한다.
3. **동시 상태 조회에서 투영 결과 누락.** 후속 snapshot 갱신이 먼저 시작되면 앞선 narrative 호출이 검증된 Micro 투영 없이 반환될 수 있었다. 해당 호출에는 자체 현재 상태 뷰를 계산하되, 공유 snapshot 게시에는 기존 최신 순번·scope 검사를 유지한다.
4. **분석 저장과 상태 반영의 GUI 구분 부족.** Micro 상세에서 현재 상태 승인·보류 수와 확인 안내를 읽기 전용으로 조회한다. scope·분석 revision이 바뀐 결과는 사용하지 않는다. 조회 자체는 모델 호출이나 저장을 수행하지 않는다. 미등록 장소·근거 불일치 등의 보류를 임의 승인하지 않는다.
5. **복구의 과도한 완료 표시.** 저장 확인만 된 원문, 분석 미완, 상태 승인 보류를 완료로 표시하지 않는다. 완료·확인 필요·실패를 구분하고, 검증된 완료에만 모든 단계 표시를 완료한다. 실행 전 비용 확인은 유지한다.
6. **GRADIA 화면 버전 불일치.** GUI 브랜드 버전을 실제 플러그인 버전으로 표시한다.
7. **정식 Min 배포의 명세 생성 실패.** 최적화로 제거된 퇴역 Compute pilot 상수는 캡처한 소스 SHA-256과 실제 출력 SHA-256이 모두 결속된 release 변환에서만 원본 선언을 사용한다. 활성 pilot과 결속되지 않은 출력에는 기존 리터럴 검사를 유지한다. 변경·누락·위조 선언 거부 검사를 유지했다.
8. **검사 목록의 현행화.** GRADIA 현재 메타데이터 비교와 누락된 두 기존 검사 등록, LIBRA 현재 진단 빌더의 지연 생성 검사, 새 복구·Micro 상태 GUI 검사를 배포 검사에 반영했다. 벡터 선별이나 근거 검증을 완화하지 않았다.

## 실모델 기억 생성과 GUI

`deepseek-v4.1-flash:cloud`를 제품의 Ollama 요청 빌더와 실제 HTTP 경로로 호출했다. 새 저장소에 한국어 5턴 정본을 생성하고, T6 응답 캡처 후 Micro를 생성했다. T6에는 문 열기와 정본에 아직 등록되지 않은 제어실로의 이동이 포함된다.

| 최종 ZIP의 새 설치 실행 | 정본 | Micro |
| --- | --- | --- |
| 모델 호출 | 1회 | 1회 |
| HTTP / 종료 | 200 / stop | 200 / stop |
| 공급자 요청 경과 시간 | 6,350 ms | 2,844 ms |
| reasoning_effort | none | none |
| 출력 한도 | 24,000 | **4,096 유지** |
| completion tokens | 1,732 | 671 |
| 최종 응답 문자 / 추론 문자 | 4,397 / 0 | 2,028 / 0 |
| 저장 결과 | completed, 1개, 경고 없음 | 분석 verified, claim 4개 |

열려 있는 GUI에 새 Micro가 자동으로 나타났고, 실제 본문과 분석 완료 표기를 확인했다. 브라우저 예외는 없었다. 암묵적 재시도는 없었다.

**분석 완료가 모든 상태 변경의 승인을 의미하지 않는다.** 이 실행의 State는 T5를 유지했다. Micro의 상태 변경 2개는 각각 `state_value_not_source_bound`와 `registry_location_unresolved`로 보류됐다. GUI에는 승인 0개·보류 2개와 원문·정본 확인 안내, 미등록 장소 연결 안내 및 확인 동작이 표시됐다. 이 결과를 T6 상태 자동 반영 성공으로 집계하지 않았다. 유효한 알려진 대상·일치하는 근거가 있을 때의 상태 반영과 GUI 표시는 별도 3개 저장 모드 및 현재 상태 GUI 회귀 검사로 확인했다.

읽기 전용 상태 승인 조회는 모델 호출·저장 횟수를 늘리지 않으며, 잘못된 scope/revision을 거부하는 검사도 통과했다. 정본 이전·이후의 동시 narrative 3개 조회 모두 검증된 Micro 상태를 반환하는 회귀 검사도 3개 저장 모드에서 통과했다.

읽기 가능한 Full 소스도 독립적으로 실모델 실행했다. 정본 7,562 ms(모델 근거/형식 경고가 있는 부분 저장), Micro 2,804 ms(claim 4개, verified)와 GUI 보류 안내를 확인했다. Full과 Min은 같은 응답을 재생한 A/B가 아니므로 품질·지연 차이를 컴파일러 영향으로 해석하지 않는다.

## 같은 저장 스냅샷의 검색

위 최종 ZIP 실모델 실행의 저장 스냅샷을 재사용했다. 기억 추출을 반복하지 않았고, 임베딩 재생성도 하지 않았다. 외부 공급자 fetch를 거부한 상태에서 실제 `beforeRequest` 전달 패킷을 검사했다.

- 소유·양도·보관 위치·문 상태 질문 4개 × 2회: **근거 전달 8/8**.
- 콜드 조회: **817 ms**. 반복 조회 중앙값: **80.5 ms**, p95/max: **94 ms**.
- 검색 중 LLM 호출 0 / 임베딩 호출 0 / 자원 예산 중단 0 / 오류 0.
- 소비한 근거의 최종 검증은 verified, 모델 전달 허용 true.
- 전체 이력 커버리지는 **불완전**으로 보고됐다(`projection_coverage_incomplete`, `queryComplete=false`). 위 8개 정답 전달은 확인했으나, 전체 저장 이력을 빠짐없이 검색했다는 뜻은 아니다.

이번 스냅샷 검색은 작은 6턴 시나리오의 어휘 검색이다. Micro 벡터 검사는 별도의 합성 벡터 검사이며, 실제 Voyage 임베딩 성능을 증명하지 않는다. 정확 코사인 top-8 선별·원본 읽기 예산·선택 후 digest 재검증·최종 저장 본문/revision 검증은 유지했다.

## 판정 범위와 남은 한계

재현한 Micro 무응답, 동시 상태 조회 누락, 복구 완료 오표시, 화면 버전 불일치, 정식 Min 명세 생성 실패는 패치 후 재검증했다. 위 Linux/Node 24/Chromium 환경의 ZIP 설치·서버 재시작·관리·기억 생성·GUI·한정 검색 시나리오는 통과했다.

다음은 이번 실행으로 보장하지 않는다.

- 빌더의 463개 배포 검사는 통과했지만 **전체 회귀 모음은 실행하지 않았다**. 빌드 보고서도 `fullRegressionRunByBuilder=false`, `fullRegressionRequiredBeforePublication=true`로 기록한다.
- Windows/macOS 실기기 설치, 실제 RisuAI 앱의 전체 호스트 통합, 장시간·대규모 부하, 장애 중 운영 데이터 복구는 이 검사에 포함하지 않았다.
- Voyage 키가 현재 비공개 환경에 없어 `voyage-4-large` 실모델 임베딩과 Claude 기준의 통제된 실모델 A/B는 재실행하지 않았다.
- 실모델 1개 시나리오의 기억 저장 성공을 임의의 출력에 대한 무조건 승인·상태 완전성·최종 LLM 답변 정확성으로 일반화할 수 없다. 근거 불일치·미등록 대상은 계속 보류한다.

따라서 이번 결과는 **수정한 결함과 명시한 실사용 경로의 통과 근거**다. 전체 회귀·지원 OS/실호스트 검증까지 완료한 공식 공개 배포 승인으로 확대하지 않는다.
