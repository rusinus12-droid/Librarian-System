# HAYAKU 3.0.103 — 정규 패킷과 복구의 항목 수용 공통화

## 변경한 동작

- 정규 응답의 캡처·채팅 이력 검사·빠른 추출·지연 추출에서 공통 항목 수용 함수를 사용한다. 복구와 콜드스타트도 같은 함수를 사용한다.
- 읽을 수 있는 기억은 남기고 잘못된 항목과 그 항목에 명시적으로 의존하는 기록을 제외한다. 유효한 요약만 남아도 완성된 기억 패킷으로 처리하며, 빈 패킷은 완료로 만들지 않는다.
- 요약만 있거나 항목이 제외·변환된 패킷은 `stateAuthority:false`로 처리한다. 기억으로 저장하는 것과 현재 상태를 확정하는 것은 구분한다.
- 소유자가 확인되지 않은 기억은 소유자 연결을 미확정 상태로 보관한다. 다시 정규화할 때 빈 ownerEntityId를 만들어 필수 필드 오류를 내던 문제도 수정했다.
- 캡처와 이력 검사가 동일한 정규화 본문·해시를 사용한다. 원장 재조회와 반복 동기화에서도 같은 패킷을 중복 생성하지 않는지 검증했다.
- 정규 프롬프트에서 요약 외의 축 항목을 반드시 채우라는 조건을 제거했다. 근거 없는 항목을 만들어 개수를 채울 필요가 없다.

## 경로별 근거와 저장 경계

정규 패킷은 현재 응답의 요청 nonce와 턴·세계선 결속을 계속 사용한다. 기존 패킷에는 별도 grounding envelope가 없으므로 이를 새 필수 조건으로 삼지 않는다. 선택적으로 제공되는 `meta.record_grounding`은 복구와 동일한 항목별 원문 인용 검사에 연결한다. 기존 패킷의 모든 기억 문장을 새로 의미 검증했다는 뜻은 아니다. 진단에는 `response_bound_legacy`와 `explicit_target_quotes`를 구분한다.

과거 턴의 recovery/cold-start 패킷은 현재 응답 본문과 인용을 비교하지 않는다. 해당 경로의 기존 대상 원문·저장 검증을 유지한다. 정규 응답 자체는 수정하지 않고 원장에 들어갈 패킷만 정규화한다. afterRequest가 Other Ax로 복구한 경우에는 현재 응답에 current_snapshot을 붙여 반환하고, 호스트의 실제 저장 후 결속 절차를 따른다. 뒤늦은 누락 복구는 기존 미러 원장 채택 경로를 유지한다.

## afterRequest 승인 보류

- 원문 수정 승인 기록을 읽거나 저장할 수 없으면 `suspended`로 종료한다. 모델 호출 전이면 `attempted:false`, `physicalCalls:0`이다.
- 이 보류를 실패한 모델 응답으로 저장하거나 빈 생성 후보를 만들지 않는다. 같은 대기 요청에서 진행 중인 자동 호출을 겹쳐 실행하지 않으며, 정상 패킷 관찰 후에도 이미 사용한 호출 횟수를 유지한다.
- 모델 응답을 기다리는 동안 채팅·사용자 원문·요청 nonce·대상 응답이 바뀌면 해당 후보를 응답에 붙이지 않는다.
- 리롤 도중 호스트가 이전 응답을 계속 보여주는 경우는 시작 시점과 같은 이전 응답 또는 이번 새 응답을 허용한다. 관계없는 다른 수정은 보류한다.
- afterRequest 복구 패킷에 cold-start 출처 메타데이터가 함께 붙던 분기도 수정했다.

## 후보를 보관하는 이유와 범위

사용할 수 없는 후보를 무조건 보관하기 위해 새 저장 경로를 만들지 않았다. afterRequest의 승인 보류·근거 미확보에는 후보가 생성되지 않는다. 사용자의 기존 정상 기억은 교체 저장이 확인되기 전까지 유지한다.

기존 `readNativeRepairCandidate` → `executeNativeRepairDebt` 경로는 검증을 끝냈지만 채택을 마치지 못한 후보를 읽어, 원문·대상·프롬프트 계약이 일치할 때 모델을 다시 호출하지 않고 저장을 재시도한다. 이 실제 재사용 경로는 유지했다. 완료 또는 취소 시 후보를 제거하며, 계약이나 대상이 다른 후보는 자동 채택하지 않는다. 실패 원인 확인을 위해 사용자가 요청한 진단 로그와 기존 데이터는 일괄 삭제하지 않았다.

## 검증

관련 회귀 검사 26개 통과. 새 검사 `hayaku_common_admission_runtime_test.cjs`는 다음을 확인한다.

- 정규·afterRequest·누락 복구·콜드스타트의 요약 수용
- 잘못된 관계만 제외하고 나머지를 저장, 미확정 소유자 재조회
- 캡처/이력 해시 일치, 원장 재조회, 반복 동기화 중복 방지
- 잘못된 명시적 근거와 빈 패킷이 완료로 처리되지 않음
- 승인 기록 저장 실패 시 호출 0회, 실패 후보 미생성
- 모델 호출 중 원문 변경과 리롤의 이전/새 응답 처리

기존 검사 두 개는 수정 전 3.0.102에서도 실패함을 대조했다. 응답 수용 검사의 낡은 내부 함수명 단언을 제거하고, 근거 검사의 관계 분류값은 원문에 문자 그대로 없어도 수용하는 사례로 갱신했다. 인용 원문 확인·명시적 부정 모순·증거의 물리적 재조회·요청 크기 제한은 유지한다. 요청 크기 초과가 폐기된 실패 검토 UI를 다시 요구한다는 옛 단언도 갱신했다.

이는 실제 생산 함수를 실행하는 격리 호스트/저장소 시험이다. 실제 RisuAI GUI, 외부 모델 응답 품질, 실제 기기 지연·비용은 이번 검증에 포함되지 않는다. 전체 저장소 회귀 검사를 모두 실행했다는 의미는 아니다.
