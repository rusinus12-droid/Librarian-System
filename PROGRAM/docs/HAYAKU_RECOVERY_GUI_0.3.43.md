# HAYAKU 복구 GUI 개선 · 0.3.43 / HAYAKU 3.0.58

복구 엔진과 누락 턴 선택 카드를 한 열로 쌓아, 옆 카드의 길이 때문에 카드 내부 여백이 늘어나는 현상을 수정했습니다. 실패 기록 목록과 상세 내용도 세로로 배치합니다.

후처리(afterRequest) 복구와 백그라운드 자동 복구의 기본값은 모두 켜짐입니다. 기존 화면은 저장소·누락 턴 조회가 완료된 뒤 체크박스를 갱신하여 초기에는 꺼짐처럼 보일 수 있었습니다. 이제 이미 로드된 설정으로 처음부터 표시합니다. 사용자가 저장한 false와 구형 nativeAutoRepair의 명시적 false는 유지합니다. 백그라운드 설정이 켜져 있어도 실행 전 확인 절차는 유지합니다.

실패 복구에서 체크박스로 여러 문제를 선택하고 전체 선택·전체 해제·선택 삭제를 사용할 수 있습니다. 확인창은 선택한 문제 수와 그에 속한 처리 이력 수를 표시합니다. 기존 삭제 경로로 각 이력을 지우고 저장소 readback을 확인합니다. 확인된 삭제 수를 별도 결과 영역에 남기며, 중간 실패는 부분 완료로 표시하고 중단합니다. 전체 묶음이 하나의 원자적 트랜잭션은 아닙니다. 채팅 범위 변경이나 중복 실행은 차단합니다. 실패 기록 삭제는 Recovery Journal 원문, 복구 부채, 정본 패킷을 삭제하지 않습니다.

서버 연결은 HAYAKU 소유 컨테이너에 한정하여 흰색 카드, 옅은 배경, 어두운 글자, 보라색 기본 버튼으로 표시합니다. 공유 SDK의 다른 플러그인 테마와 저장·연산 동작은 변경하지 않았습니다.

검증: 실제 플러그인 소스를 격리된 Chromium 호스트에서 실행하여 1440/390px 배치, 초기 설정, 선택·취소·일괄 삭제, 여러 이력, 채팅 변경, 물리 삭제 실패 시 중단/복원/readback, 계산된 색상을 확인했습니다. `hayaku_failure_bulk_delete_runtime_test.cjs`는 GUI 삭제 조정 함수의 8개 경계 조건을 검증합니다. 기존 삭제·설정·복구·GUI 회귀 및 배포 smoke 검증 결과는 작업 검증 보고서에 기록합니다.

실제 RisuAI 실행 환경, 외부 모델/서버 호출은 이번 GUI 패치의 검증에 포함하지 않았습니다.
