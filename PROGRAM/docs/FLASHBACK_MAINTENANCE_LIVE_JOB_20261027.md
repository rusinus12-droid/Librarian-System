# Flashback 상태 점검·자동 복구 실시간 작업창

2026-10-27 · 현재 작업 폴더의 Flashback 1.3.8 로컬 수정본.

## 사용자 동작

- `상태 점검 및 자동 복구`를 누르는 즉시 작업창이 열린다. 기존 임베딩의 저장 확인 대기, 범위·저장소 확인, 원문 대조, 복구 계획, 최종 검증을 실제 실행 보고에 따라 표시한다.
- 점검이 끝나면 기존 진단 화면에서 필요한 복구를 선택한다. 로컬 자동 복구, 서버 누락 턴 동기화, 서버 대기 벡터 처리 모두 같은 실시간 작업창을 사용한다.
- 복구 중 현재 턴, 이번 큐의 처리량, 저장이 확인된 벡터 수, 제공자 요청·응답 대기·결과 미확정 수, 경과 시간과 최근 진행 내역을 볼 수 있다.
- 리브라 미크로·렌즈 작업창과 같은 `overlay / dialog--wide / steps / progress / badge / dialog__actions` 구조를 사용한다. 최소화하면 작업 버튼으로 다시 열 수 있고, 실행이 끝나면 같은 창에서 완료·확인 필요·실패·중지 결과를 확인한다.
- 복구 중지 버튼은 현재 작업 ID와 실제 실행 컨트롤러가 일치할 때만 동작한다. 이미 발행된 요청의 종료나 결과가 확정됐다고 가정하지 않는다. 창 최소화·확인은 실행 요청을 추가하지 않는다.

## 실행과 표시의 연결

`GUI 버튼 → runMaintenanceGuiTask → inspectMemoryMaintenance / runMemoryMaintenance → 실제 단계·큐·ledger 보고 → 현재 작업에 묶인 화면 갱신 → 최종 진단/저장 결과`.

작업창은 현재 GUI 세션의 일시 상태다. 저장소 권한·복구 승인·journal을 대신하지 않고, 과거 journal의 완료 기록을 새 작업처럼 자동으로 띄우지 않는다. 전체 분모를 모를 때 진행률을 만들지 않으며, 수치가 없는 요청 통계는 `미확인`으로 표시한다. 큐 진행률은 기록 처리량이고, 저장 확인된 벡터·실패·불명 결과를 성공으로 합산하지 않는다.

실제 ledger의 `reserve/settle`을 관찰하되 기존 ledger에 같은 인자를 전달한다. 예산·원문·범위·저장 readback·불명 결과 재전송 방지 규칙은 그대로 적용한다. 보고 콜백이나 화면 렌더링 실패가 저장 실행 경로를 중단하지 않게 격리했다. 로컬 journal의 구독은 해당 실행의 `finally`에서 해제한다.

창을 닫으면 DOM·키보드 리스너·화면 갱신 타이머를 정리한다. 숨겨진 GUI는 완료 알림으로 다시 열지 않는다. 다시 열었을 때 같은 범위의 이번 세션 작업을 확인할 수 있다. 다른 작업·다른 범위에 이전 중지 버튼이 동작하지 않도록 현재 작업 객체와 operation ID를 확인한다.
