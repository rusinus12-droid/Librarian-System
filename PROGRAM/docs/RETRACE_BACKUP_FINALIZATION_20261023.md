# RE:TRACE 백업 종료·취소와 헤더 수정

## 제공된 진단에서 확인한 내용

RE:TRACE 1.10.0의 첨부 로그는 서버 0.4.1에 연결되어 있었고 다섯 namespace의
SQLite 무결성 검사가 모두 정상이다. 현재 캐릭터 읽기는 실패했고, 화면 작업은
busy 상태였지만 파일 전송 단계는 기록되지 않았다. 이 로그만으로 파일 저장이
지연된 정확한 원인을 확정하지 않았다. 이후 사용자가 권한 문제를 해결하고
백업 생성 완료를 확인했다. 첨부 자료는 진단 데이터로만 읽었으며 기억 본문을
테스트나 문서에 복제하지 않았다.

## RE:TRACE 1.10.1의 변경

- 파일 준비·쓰기·저장 완료 응답과 내보내기 요청을 기다리는 동안에도 취소
  신호를 처리한다. 늦게 도착한 내보내기 영수증의 임시 세션도 정리한다.
  파일 작업 응답은 2분을 한도로 기다리고, 응답을 확인하지 못하면 저장 경로나
  다운로드 목록을 확인하도록 안내한다. 이미 생성된 서버 백업은 보존한다.
- 검증·저장 완료 뒤의 임시 전송 세션 정리와 서버 목록 조회는 작업 완료를
  지연시키지 않는다. 서버 복원 실행 이후에는 기존대로 취소를 허용하지 않는다.
- 파일 수신, 전체 SHA-256 검증, 파일 저장 마무리를 구분해 표시한다. 실제
  전체 해시가 서버 영수증과 일치하고 파일 저장 응답이 와야 검증 완료로 표시한다.
  취소·시간 초과에서는 완료를 표시하지 않는다. 이미 호스트에 전달한 파일 작업은
  나중에 끝날 수 있으므로 취소 시에도 다운로드 목록 또는 선택 경로를 확인한다.
- 디버그 내보내기에 작업 단계·전송 건수·취소 요청 여부만 추가한다. 파일 내용과
  전송 토큰은 포함하지 않는다.
- 헤더의 고정된 ‘시안 (제품 v1.9.87 기준)’을 제거하고 현재 플러그인 버전을 표시한다.

현재 캐릭터를 읽지 못해 채팅 목록 검사가 불완전한 경우나 다른 스코프가 실제로
참조하는 승계 조상의 삭제 제한은 유지한다. 이번 수정은 관리 검증을 우회하지 않는다.

## 검증

- `portable_transfer_finalization_test.cjs`: 정리 응답 지연, 준비·쓰기·저장 중 취소,
  요청 중 취소, 늦은 세션 정리, 파일 저장 시간 초과. 정리 지연 사례는 수정 전
  코드에서 작업이 끝나지 않는 것을 먼저 재현했다.
- `retrace_portable_finalization_gui_test.cjs`: 전체 RE:TRACE 원본의 실제 클릭과
  서버 ZIP 생성·다운로드를 실행해 저장 대기 중 취소, 완료 후 목록 조회 지연,
  동적 버전 헤더와 원문·인증값 없는 진행 진단을 검사한다.
- 기존 portable 전송의 청크·전체 해시 검사, 서버 취소·복원 생명주기,
  논리 이관 왕복과 RE:TRACE GUI의 실제 백업·복원 테스트를 함께 실행한다.

테스트에는 격리된 임시 서버와 합성 자료를 사용했다. 사용자 서버의 백업을
재실행하거나 실제 저장 데이터를 변경하지 않았다.
