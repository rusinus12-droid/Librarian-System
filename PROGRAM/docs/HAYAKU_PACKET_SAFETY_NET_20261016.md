# HAYAKU 패킷 안전망 강화 (2026-10-16)

응답 모델이 RP 응답과 숨은 HAYAKU 패킷을 함께 쓰는 현재 방식은 그대로 둔다. 패킷이 빠졌을 때 실제로 복구되는 비율을 높이고, 왜 빠지는지 사용자가 볼 수 있게 했다.

## 기존 경로 정리

1. 응답 모델이 패킷을 쓴다(일반 경로, 추가 호출 없음).
2. 패킷이 없거나 못 쓰는 상태면 afterRequest에서 Other Ax(RisuAI 보조 모델)를 1회 호출해 복구한다(`afterRequest 자동 복구`, 기본 켜짐).
3. 2가 실패하면 실패 기록이 남고, `실패 복구 자동 처리`가 백그라운드에서 검증하고 AI 재분석을 1회 한다(3.0.61, 기본 켜짐).
4. 누락 턴은 Recovery Journal에 원문이 보존되고 `백그라운드 자동 복구`가 처리한다. 이 단계는 **항목마다 확인창을 띄웠다.** 확인창은 기록당 한 번만 뜨고, 답하지 않거나 닫으면 그 턴은 계속 비어 있었다.

2가 건너뛰어진 턴은 실패 기록도 없이 4의 확인창에만 의존했다. 2가 건너뛰는 경우는 보조 모델 연결 테스트 중, 원문을 확정하지 못함, 요청 계보 없음 등이다. 사용자가 확인창을 놓치면 패킷이 비는 주요 경로로 보인다.

## 변경

### 1. 건너뛴 턴은 확인 없이 백그라운드 복구
`afterRequest 자동 복구`가 켜져 있으면 사용자는 이미 "누락 패킷당 Other Ax 1회" 비용에 동의한 상태다. 다음 조건을 모두 만족하는 누락 턴은 확인창 없이 바로 백그라운드 복구한다.

- afterRequest 복구를 시도하지 않았다(`attempted !== true`).
- 결과가 `failed_journal_required`, `candidate_returned_pending_commit`, `candidate_not_committed_journal_required`, `disabled_journal_only`가 아니다.
- 실패 기록(`failedAnalysisId`)이 없다.

이미 시도했거나 실패한 턴은 기존 흐름(실패 복구 자동 처리, 확인창)을 그대로 따른다. 최초 관측 객체 대신 저장 큐에서 읽은 최신 Journal로 확인창을 선점하고 자동 승인 여부를 결정한다. 자동 승인 기록을 저장할 때와 복구 lease를 획득할 때도 시도·실패·설정·진행 중 캡처를 재검사한다. 검사 중 afterRequest 복구가 진행됐으면 자동 호출을 중단한다. `afterRequest 자동 복구`를 끄면 이전처럼 확인창을 띄운다. `백그라운드 자동 복구`를 끄면 백그라운드 복구 자체를 하지 않는다. 작업 기록에 `native_recovery:background_auto_approved`가 남는다. 이 기록만으로 실제 호출·저장 완료를 뜻하지는 않는다.

설정 화면 설명을 "afterRequest 자동 복구가 켜져 있으면 확인 없이 실행하고, 꺼져 있으면 시작 전에 확인합니다."로 바꿨다.

### 2. 패킷 작성 현황
`패킷 · 세계선 → 이번 패킷 작성` 카드 아래에 현재 채팅의 최근 턴(이번 세션, 최대 60턴) 작성 결과를 집계해 보여 준다.

| 항목 | 의미 |
| --- | --- |
| 메인 모델이 정상 작성 | 응답 모델의 패킷이 바로 쓸 수 있었음 |
| 패킷 생략 | 패킷 표시가 전혀 없음 |
| 패킷 잘림 | 시작 표시만 있고 끝이 없음(출력 길이 부족 가능성) |
| 형식 오류 | JSON·schema·계보 검사 실패 |
| 보조 모델 후보 작성 | 검증된 후보 패킷을 반환한 횟수. 저장 완료 여부는 별도로 확인해야 함 |
| 보조 모델 복구 실패 / 건너뜀 | afterRequest 복구 결과와 건너뛴 사유 |

반복되는 원인에는 할 일을 함께 표시한다.

- 잘림이 실패 턴의 1/3 이상: 응답 최대 토큰(출력 길이)을 늘린다.
- 생략이 실패 턴의 1/3 이상(최소 2턴): 프롬프트 방식을 전체(full)로 바꾸거나 지시를 잘 따르는 모델을 쓴다.
- 보조 모델 복구 실패: 실패 복구 자동 처리가 한 번 더 시도한다. 계속 실패하면 RisuAI 보조 모델 설정을 확인한다.

기록은 메모리에만 두고 저장하지 않는다(새로고침하면 초기화).
후보 반환 후 실제 Assistant 출력에 패킷이 채택되지 않거나 저장이 취소·실패할 수 있다. 이 작성 이력은 durable commit을 추적하는 지표로 사용하지 않는다.

## 확인 범위

- 새 `tests/hayaku_packet_safety_net_test.cjs`: 자동 승인 조건(건너뜀은 승인, 시도·실패·끔은 기존 흐름), 채팅별 집계, 안내 문구, 기록 상한.
- HAYAKU 관련 테스트 210개를 변경 전 코드와 나란히 실행했다. 새 실패 없음(manifest 해시 테스트는 manifest 갱신으로 해결).
- 기존 `hayaku_after_request_recovery_journal_runtime_test`의 "실패한 턴은 확인 UI 없이 추가 호출하지 않는다" 단언은 그대로 통과한다.
- 실제 RisuAI와 실제 보조 모델로 누락률이 얼마나 줄어드는지는 측정하지 않았다. 작성 현황 카드가 그 측정에 쓰일 수 있다.

## 하지 않은 것

- 응답 모델 대신 보조 모델이 매 턴 패킷을 쓰는 분리 작성 모드(선택하지 않음).
- afterRequest 복구의 즉시 재시도. 응답 표시가 그만큼 늦어지고, 실패한 턴은 이미 실패 복구 자동 처리가 백그라운드에서 재시도한다.
- 잘린 JSON 자동 봉합. 잘린 패킷은 afterRequest 복구가 원문에서 새로 쓴다.
