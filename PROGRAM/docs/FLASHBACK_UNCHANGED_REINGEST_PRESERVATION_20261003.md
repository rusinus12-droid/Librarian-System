# Unchanged-source retained embedding preservation

An actual raw-only ingest or nonincremental current-chat coldstart can build a valid vectorless record for a source already present in the active owner. The exact-hash upsert previously merged that draft over the existing record, replacing its retained vector, model provenance and unresolved record attempt even though the canonical raw source had not changed. The separately saved uncertain attempt registry entry survived; this is a record tuple loss, not registry deletion.

The repair is limited to that existing exact-hash branch with `deferEmbedding: true`. Both incoming vectorless work and previous retained work must pass their existing validators. Canonical scope, source type/ID/hash, full text, turn, chunk index/count, message IDs, raw digest and logical origin must agree. Source revision, physical job ID and the complete target profile must agree with the current embedding fingerprint. The retained vector dimension must match the current declared dimension. Running and uncertain work must additionally match an actual saved registry entry and physical job. Only then does the writer retain the previous complete embedding projection, work and origin and validate the result again.

Publicly prepared pending work has not submitted a request and legitimately has no attempt. It stays pending. Definitive failed work retains its failed status and prior record attempt. Running and uncertain work retain their exact attempts and registry authority. This change never certifies these vectors as ready or supplies permission to resubmit. A malformed retained tuple, changed raw source, model, dimensions, preprocessing, endpoint, revision or scope cannot enter this reuse branch. Near-duplicate and explicit source-replacement branches are unchanged.

## Preservation and remaining limits

No schema migration or sweep of existing storage is introduced. Reuse occurs only during an already requested same-source raw publication. Old unknown registry entries remain authoritative. Changed source/profile operations continue to establish raw first and use existing durable queue authority for a replacement; this patch does not expand source-edit consent or guarantee all cleanup, rechunk, clone/archive or global migration routes.

This is local mock-provider storage evidence. Actual embedding/model calls, remote requests, installed native GUI acceptance and complete four-product approval are unrun. Existing saved temporal values and explicit user values remain authoritative; no numeric defaults are invented. Separate GRADIA input is preserved outside this change.
