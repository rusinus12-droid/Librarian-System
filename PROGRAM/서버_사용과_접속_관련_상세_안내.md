## 1. 한눈에 보기

| 상황 | 할 일 | 접근 키 |
| :--- | :--- | :--- |
| 이 PC에서 서버와 RisuAI를 함께 사용 (기본) | 서버 실행 → 플러그인에 `http://127.0.0.1:47630` | 필요 없음 |
| 47630 포트를 다른 프로그램이 사용 | `서버_포트_변경`으로 포트 변경 → 플러그인 주소 변경 | 필요 없음 |
| 서버를 Docker 컨테이너로 실행 | `docker compose ... up -d --build` → 플러그인에 `http://127.0.0.1:47630` | 필요 없음 |
| 내부 네트워크(공유기 안쪽)의 다른 기기에서 접속 | 외부 접속 켜기 | 필요 없음 |
| 인터넷 · VPN 너머에서 접속 | 외부 접속 켜기 + 접근 키 | **필요함** |

다른 기기에서 접속하는 경우에는 먼저 [6-6. 현재의 제한](#6-6-현재의-제한)을 확인하세요.

설정 파일은 `DATA/config/server-config.json` 하나입니다. 포트와 외부 접속 여부가 여기에 저장됩니다. 접근 키는 `DATA/config/remote-access-key.txt`에 따로 저장됩니다. 두 파일은 직접 고치지 말고 아래의 도구로 바꾸세요.

## 2. 서버 실행과 종료

| 운영체제 | 실행 | 백그라운드 실행 | 종료 | 상태 확인 |
| :--- | :--- | :--- | :--- | :--- |
| Windows | `PROGRAM\1_서버_실행.bat` | `PROGRAM\서버_백그라운드_실행.bat` | `PROGRAM\2_서버_종료.bat` | `PROGRAM\서버_상태_확인.bat` |
| macOS | `PROGRAM/macOS_서버_실행.command` | `sh PROGRAM/서버_백그라운드_실행.sh` | `sh PROGRAM/2_서버_종료.sh` | `sh PROGRAM/서버_상태_확인.sh` |
| Linux · Termux | `sh PROGRAM/1_서버_실행.sh` | `sh PROGRAM/서버_백그라운드_실행.sh` | `sh PROGRAM/2_서버_종료.sh` | `sh PROGRAM/서버_상태_확인.sh` |

- 일반 실행은 창이 서버를 띄우고 있으므로, 창을 닫으면 서버도 꺼집니다. 안전하게 끄려면 종료 스크립트를 쓰세요.
- 서버는 시작할 때 `DATA/config/server-config.json`을 읽습니다. 포트나 외부 접속 설정을 바꾸면 **서버를 다시 실행해야** 적용됩니다.
- 실행 창에 표시되는 주소로 현재 상태를 알 수 있습니다.
  - `Server ready at http://127.0.0.1:47630`: 이 PC 전용(기본)
  - `Server ready at http://0.0.0.0:47630`: 외부 접속이 켜진 상태

## 3. 서버 주소와 플러그인 연결

기본 서버 주소는 `http://127.0.0.1:47630`입니다. 플러그인은 서버 주소를 **각자 따로** 저장합니다. 한 플러그인에서 바꿔도 다른 플러그인의 주소는 그대로이므로, 주소를 바꿀 때는 모든 플러그인에서 바꿔야 합니다.

| 플러그인 | 서버 주소를 바꾸는 곳 |
| :--- | :--- |
| LIBRA · HAYAKU · Flashback | 서버 연결 설정 → 서버 주소 → 연결 테스트 → 설정 적용 |
| GRADIA | 소스 탭 → 서버 주소 |
| RE:TRACE | 서버 관리 → 연결 진단 → 서버 주소 → 주소 저장 |
| LIA | 서버를 쓰지 않습니다 |

- RE:TRACE의 주소 저장은 RE:TRACE 관리 연결과 LIA 보관 자료 연결에만 적용됩니다. LIBRA · HAYAKU · Flashback 연결은 각 플러그인에 저장된 주소를 따릅니다. 주소가 서로 다르면 RE:TRACE 화면에 표시됩니다.
- 플러그인 저장 방식(플러그인 단독 · 서버 단독)은 **전역 설정**입니다. 한 플러그인의 모든 대화에 함께 적용됩니다.

**플러그인이 받는 서버 주소**

`http://` 뒤에 포트를 붙인 다음 네 가지만 쓸 수 있습니다.

| 주소 | 쓰는 경우 |
| :--- | :--- |
| `http://127.0.0.1:포트` | 기본. 이 PC에서 실행 중인 서버 (Docker 포함) |
| `http://localhost:포트` | 위와 같음 |
| `http://[::1]:포트` | 위와 같음 (IPv6) |
| `http://host.docker.internal:포트` | RisuAI도 컨테이너에서 실행하고, 플러그인 요청이 그 컨테이너에서 나갈 때 |

## 4. 서버 포트 바꾸기

1. 서버를 끕니다 (`2_서버_종료`).
2. 포트 변경 도구를 실행하고 새 포트(1024~65535)를 입력합니다.
   - Windows: `PROGRAM\서버_포트_변경.bat`
   - macOS · Linux · Termux: `sh PROGRAM/서버_포트_변경.sh` (예: `sh PROGRAM/서버_포트_변경.sh 48000`)
3. 서버를 다시 실행합니다.
4. 모든 플러그인의 서버 주소를 `http://127.0.0.1:새포트`로 바꿉니다 ([3절](#3-서버-주소와-플러그인-연결)).

도구는 저장하기 전에 다음을 확인합니다.
- 서버가 꺼져 있는지
- 새 포트를 다른 프로그램이 쓰고 있지 않은지
- 마치지 않은 업데이트가 없는지

**서버 단독으로 쓰는 중이어도 주소를 옮길 수 있습니다.**
- 플러그인은 서버 단독 설정을 적용할 때 그 서버 DATA의 식별값을 기억합니다.
- 주소를 바꾸면 새 주소의 서버가 **같은 DATA인지** 확인한 뒤 주소만 옮깁니다. 자료는 옮기지 않습니다.
- 그래서 4단계 전에 서버가 새 포트로 실행 중이어야 합니다.
- 다음 경우에는 주소 변경이 거부되고 기존 주소가 유지됩니다.
  - 새 주소가 다른 DATA의 서버인 경우
  - 새 주소에 연결할 수 없는 경우
  - 이 버전에서 서버 단독 설정을 적용한 적이 없어 식별값이 없는 경우
- 마지막 경우에는 도구로 예전 포트로 되돌립니다. 서버 연결 설정에서 서버 단독을 한 번 적용한 뒤 다시 바꾸세요.

## 5. 이 PC와 내부 네트워크 접속 (기본)

- 서버는 기본적으로 **이 PC(`127.0.0.1`)에서 오는 연결만** 받습니다. 별도 설정이나 접근 키 없이 바로 사용합니다.
- 서버 실행 중 플러그인이 처음 연결하면 서버가 연결용 토큰을 자동으로 발급합니다. 사용자가 할 일은 없습니다.
- 외부 접속을 켜도 이 PC와 내부 네트워크의 사용 방식은 **바뀌지 않습니다.** 다음에서 오는 연결은 계속 키 없이 바로 연결됩니다.
  - 이 PC (`127.x.x.x`, `::1`)
  - 내부 네트워크의 사설 주소 (`10.x.x.x`, `172.16~31.x.x`, `192.168.x.x`, 링크 로컬 `169.254.x.x`, IPv6 `fc00::/7` · `fe80::/10`)
  - 이 PC의 Docker 컨테이너 (컨테이너는 위의 사설 주소에서 오는 연결로 봅니다)

## 6. 외부 접속과 접근 키

### 6-1. 외부 접속이란

외부 접속을 켜면 서버가 이 PC뿐 아니라 **모든 네트워크 주소**에서 연결을 받습니다.
- 내부 네트워크에서 오는 연결은 키 없이 연결됩니다 ([5절](#5-이-pc와-내부-네트워크-접속-기본)).
- 내부 네트워크 바깥(인터넷, VPN, `100.64.0.0/10` 대역)에서 오는 연결은 **접근 키**가 있어야 연결용 토큰을 받습니다.
- 키가 없거나 틀리면 서버는 `remote_access_key_required`로 거부합니다.

### 6-2. 켜기 · 끄기

설정 도구는 설정을 저장하고 바로 끝납니다. 서버 실행 창과 함께 띄워 둘 필요가 없습니다.

1. 서버를 끕니다. 서버가 켜져 있으면 도구가 바꾸지 않고 거부합니다.
2. 설정 도구를 실행합니다.
   - Windows: `PROGRAM\서버_외부접속_설정.bat`을 실행하고 메뉴에서 번호를 고릅니다.
   - macOS · Linux · Termux: `sh PROGRAM/서버_외부접속_설정.sh`를 실행합니다. 인자로 바로 줄 수도 있습니다: `enable` · `disable` · `rotate` · `show`
3. 서버를 평소처럼 다시 실행합니다.

| 메뉴 | 인자 | 하는 일 | 서버를 꺼야 하나 |
| :--- | :--- | :--- | :--- |
| 1. 외부 접속 켜기 | `enable` | 외부 접속을 켭니다. 키가 없으면 새로 만들어 화면에 보여 줍니다. | 예 |
| 2. 외부 접속 끄기 | `disable` | 다시 이 PC 전용으로 돌아갑니다. 키 파일은 남겨 두므로 다시 켜면 같은 키를 씁니다. | 예 |
| 3. 접근 키 새로 만들기 | `rotate` | 새 키를 만듭니다. 예전 키로는 더 이상 연결할 수 없습니다. | 예 |
| 4. 현재 상태와 키 보기 | `show` | 켜짐/꺼짐 상태와 키를 보여 줍니다. | 아니요 |

- 한 번 켜면 서버를 다시 시작하거나 PC를 재부팅해도 **계속 켜져 있습니다.**
- 업데이트로 DATA를 이관할 때도 설정과 키가 함께 옮겨집니다.

### 6-3. 플러그인에 접근 키 넣기

접근 키는 내부 네트워크 바깥에서 접속하는 플러그인에만 넣습니다.

| 플러그인 | 접근 키를 넣는 곳 |
| :--- | :--- |
| LIBRA · HAYAKU · Flashback | 서버 연결 설정 → 접근 키 → 연결 테스트 또는 설정 적용 |
| RE:TRACE | 서버 관리 → 연결 진단 → 접근 키 → 주소 저장 |
| GRADIA | LIBRA에 저장한 접근 키를 함께 씁니다 |

- 키는 플러그인마다 따로 저장됩니다. RE:TRACE에서 저장한 키는 RE:TRACE와 LIA 연결에만 적용됩니다.
- 입력한 키는 저장한 뒤 칸이 비워지고, 다시 화면에 표시되지 않습니다. 화면에는 "접근 키 저장됨"만 보입니다.
- 칸을 비워 두고 저장하면 이미 저장된 키를 그대로 씁니다. 지우려면 "키 지우기"를 누르세요.
- 키는 서버에 처음 연결할 때(`/bootstrap`)만 보냅니다.

### 6-4. 키를 바꿨을 때

`rotate`로 키를 새로 만들었으면 키를 저장해 둔 모든 플러그인에 새 키를 넣어야 합니다. 이미 연결된 플러그인도 다음 연결부터는 새 키가 필요합니다.

### 6-5. 보안 안내

- 접근 키는 이 DATA에 접속할 수 있는 열쇠입니다. 믿을 수 있는 곳에만 입력하고, 다른 사람에게 보내지 마세요.
- 외부 접속을 켜면 **내부 네트워크의 기기는 키 없이 접속할 수 있습니다.** 카페나 공용 와이파이처럼 믿을 수 없는 네트워크에서는 켜지 마세요. 필요할 때만 켜고, 쓰지 않을 때는 끄세요.
- 이 PC에서 실행되는 터널 프로그램(예: 포트를 인터넷에 공개하는 도구)을 거쳐 들어오는 연결은 서버에게 "이 PC에서 온 연결"로 보입니다. 이 경우 키 검사를 받지 않으므로 그런 도구로 서버 포트를 공개하지 마세요.

### 6-6. 현재의 제한

플러그인은 서버 주소로 [3절](#3-서버-주소와-플러그인-연결)의 네 가지(`127.0.0.1` · `localhost` · `[::1]` · `host.docker.internal`)만 받습니다.

- 외부 접속을 켜도 **다른 기기의 RisuAI 플러그인에 `http://192.168.0.10:47630` 같은 주소를 넣을 수는 없습니다.** 서버는 연결을 받을 준비가 되어 있지만, 플러그인이 그 주소를 거부합니다.
- 지금 외부 접속이 실제로 쓰이는 경우는 다음 두 가지입니다.
  - Docker 컨테이너로 실행하는 서버 ([7절](#7-docker로-실행하기))
  - 다른 기기의 연결을 그 기기의 `127.0.0.1`로 넘겨 주는 방식 (예: SSH 포트 포워딩)

## 7. Docker로 실행하기

### 7-1. 동작 방식

- 플러그인은 지금처럼 RisuAI 안에서 실행되고, 서버만 컨테이너에서 실행됩니다.
- 컨테이너에는 포트 포워딩으로 연결이 들어오므로 **외부 접속이 항상 켜져 있습니다.**
- 이 PC에서의 연결은 사설 주소로 들어오므로 키 없이 연결됩니다.
- DATA는 이미지에 들어가지 않습니다. `librarian-data` 볼륨에 저장됩니다.
- 처음 시작할 때 DATA를 준비하고 접근 키를 만들어 로그에 한 번 보여 줍니다.

### 7-2. 처음 실행

패키지를 압축 해제한 폴더(`PROGRAM`과 `DATA`가 있는 곳)에서 실행합니다.

```sh
docker compose -f PROGRAM/docker/compose.yaml up -d --build
```

- 상태 확인: `docker compose -f PROGRAM/docker/compose.yaml ps`
- 로그 보기: `docker compose -f PROGRAM/docker/compose.yaml logs librarian`
- 멈추기 · 다시 시작: `docker compose -f PROGRAM/docker/compose.yaml stop` / `start`

`compose.yaml`은 포트를 **이 PC(`127.0.0.1:47630`)에만** 엽니다.

### 7-3. 플러그인 연결

PC에서 직접 실행할 때와 같습니다.
- 서버 주소는 `http://127.0.0.1:47630`이고, 접근 키는 넣지 않아도 됩니다.
- RisuAI도 컨테이너에서 실행하고 플러그인 요청이 그 컨테이너에서 나간다면 `http://host.docker.internal:47630`을 씁니다.

### 7-4. 컨테이너에서 설정 도구 쓰기

설정 도구는 `run --rm librarian <명령>`으로 실행합니다. 키나 포트를 바꾸기 전에 컨테이너를 멈추세요.

```sh
docker compose -f PROGRAM/docker/compose.yaml run --rm librarian set-remote-access --show
```

```sh
docker compose -f PROGRAM/docker/compose.yaml stop
docker compose -f PROGRAM/docker/compose.yaml run --rm librarian set-remote-access --rotate
docker compose -f PROGRAM/docker/compose.yaml start
```

**포트를 바꾸려면**
1. 컨테이너를 멈추고 다음을 실행합니다.
   ```sh
   docker compose -f PROGRAM/docker/compose.yaml run --rm librarian set-port --port 48000
   ```
2. `PROGRAM/docker/compose.yaml`의 `ports`를 `"127.0.0.1:48000:48000"`으로 바꿉니다.
3. `up -d`로 다시 시작합니다.

컨테이너에서는 외부 접속을 끌 수 없습니다. 시작할 때마다 다시 켜집니다.

### 7-5. 같은 네트워크의 다른 기기에 열기

`compose.yaml`의 `ports`를 `"47630:47630"`으로 바꾸면 내부 네트워크의 다른 기기도 접속할 수 있습니다. 내부 네트워크의 기기는 키 없이 접속하므로 믿을 수 있는 네트워크에서만 바꾸세요. 플러그인 주소 제한은 [6-6절](#6-6-현재의-제한)을 보세요.

## 8. DATA 관련 주의사항

- **DATA 폴더 전체가 기억 자료입니다.** 백업은 서버를 끈 뒤 DATA 폴더를 통째로 복사하세요. 접근 키와 설정도 DATA 안에 있으므로 함께 백업됩니다.
- **DATA를 지우거나 빈 DATA로 덮어쓰지 마세요.**
- **DATA의 식별값에는 폴더의 실제 위치가 들어갑니다.**
  - 같은 DATA라도 위치가 바뀌면 다른 DATA로 인식됩니다. 예를 들어 다른 폴더로 옮기거나, PC에서 직접 실행하다가 Docker 볼륨으로 옮기는 경우입니다.
  - 옮긴 뒤에는 서버 단독으로 쓰던 각 플러그인에서 연결 테스트를 하고 설정을 다시 적용하세요.
  - 포트만 바꾸는 것은 위치가 바뀌는 것이 아니므로 그대로 이어집니다 ([4절](#4-서버-포트-바꾸기)).
- **같은 DATA 폴더를 두 서버에서 동시에 실행하지 마세요.** PC 서버와 컨테이너가 같은 DATA를 함께 쓰면 자료가 손상될 수 있습니다.
- **Docker 볼륨을 지키세요.**
  - `docker compose down -v`는 DATA 볼륨까지 지웁니다. 컨테이너만 지우려면 `-v` 없이 `down`을 쓰세요.
  - 백업은 컨테이너를 멈춘 뒤 볼륨 전체를 복사하세요.
- **업데이트**
  - PC에서 직접 실행하는 서버는 업데이터가 PROGRAM을 바꾸고 DATA를 이관합니다. 바꾼 포트, 외부 접속 설정, 접근 키도 함께 옮겨집니다.
  - Docker에서는 컨테이너 안에서 업데이터를 쓰지 않습니다. 새 릴리스를 받은 폴더에서 `up -d --build`로 이미지를 다시 만드세요. DATA 볼륨은 그대로 이어서 씁니다.
- 설정 도구는 마치지 않은 업데이트가 있으면 설정을 바꾸지 않습니다. 서버를 한 번 실행해 업데이트 복구를 끝낸 뒤 다시 시도하세요.

## 9. 문제 해결

| 증상 · 메시지 | 원인과 해결 |
| :--- | :--- |
| `서버가 현재 포트 …에서 실행 중입니다` | 설정 도구는 서버가 꺼져 있을 때만 바꿉니다. `2_서버_종료`로 끈 뒤 다시 실행하세요. |
| `현재 포트 …에서 응답하는 프로그램이 있어` | 그 포트를 다른 프로그램이 쓰고 있습니다. 그 프로그램을 끄거나, 다른 포트로 바꾸세요. |
| `포트 …는 다른 프로그램이 사용 중입니다` | 다른 포트를 고르세요. |
| `미완료 업데이트가 있어 … 바꾸지 않았습니다` | 서버를 한 번 실행해 업데이트 복구를 끝낸 뒤 다시 시도하세요. |
| 연결 테스트가 `remote_access_key_required`로 실패 | 내부 네트워크 바깥에서 접속하는 중입니다. 서버의 외부 접속 설정 도구에서 "4. 현재 상태와 접근 키 보기"로 키를 확인해 플러그인의 접근 키 칸에 넣으세요. 키를 새로 만들었다면 새 키를 넣어야 합니다. |
| `접근 키 형식이 올바르지 않습니다` | 도구가 보여 준 키를 앞뒤 공백 없이 그대로 붙여 넣으세요. |
| `허용되지 않는 주소입니다` | 플러그인은 [3절](#3-서버-주소와-플러그인-연결)의 네 가지 주소만 받습니다. |
| 서버 단독 플러그인이 다른 DATA라며 연결을 거부 | DATA 위치가 바뀌었거나 다른 DATA의 서버입니다. 맞는 서버라면 연결 테스트 후 설정을 다시 적용하세요 ([8절](#8-data-관련-주의사항)). |
| 외부 접속을 켰는데 실행 창이 `127.0.0.1`로 표시 | 설정 후 서버를 다시 실행하지 않았습니다. 서버를 다시 실행하세요. |
| 다른 기기에서 연결이 안 됨 | 방화벽에서 서버 포트를 허용했는지 확인하세요. 플러그인 주소 제한은 [6-6절](#6-6-현재의-제한)을 보세요. |
