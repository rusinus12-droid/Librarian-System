서버 사용과 접속 관련 상세 안내
========================================

Librarian System 서버를 실행하고 플러그인을 연결하는 방법을 한곳에 모았습니다. 서버 주소, 포트, 내부 접속 모드와 원격 접속 모드, 접근 키, 다른 기기에서 접속하기(Tailscale · Cloudflare Tunnel), Docker 실행, DATA 주의사항을 다룹니다.

- 1. 한눈에 보기
- 2. 서버 실행과 종료
- 3. 서버 주소와 플러그인 연결
- 4. 서버 포트 바꾸기
- 5. 내부 접속 모드 (기본)
- 6. 원격 접속 모드와 접근 키
- 7. Docker로 실행하기
- 8. DATA 관련 주의사항
- 9. 문제 해결

1. 한눈에 보기
----------------------------------------

서버는 어떤 경우에도 이 PC(127.0.0.1)에서만 연결을 받습니다. 다른 기기는 Tailscale이나 Cloudflare Tunnel을 거쳐 https:// 주소로만 들어옵니다.

- 이 PC에서 서버와 RisuAI를 함께 사용 (기본, 내부 접속 모드)
  할 일  서버 실행 → 플러그인에 http://127.0.0.1:47630
  접근 키  필요 없음

- 47630 포트를 다른 프로그램이 사용
  할 일  서버_포트_변경으로 포트 변경 → 플러그인 주소 변경
  접근 키  모드에 따름

- 다른 기기(폰, 다른 PC)에서 접속 (원격 접속 모드)
  할 일  서버_원격접속_열기 → 열기 (Tailscale, 원격 접속 모드도 함께 켬) → 다른 기기 플러그인에 https:// 주소
  접근 키  필요함. 이 PC의 플러그인도 같은 키를 넣어야 합니다

- 서버를 Docker 컨테이너로 실행
  할 일  docker compose ... up -d --build → 플러그인에 http://127.0.0.1:47630
  접근 키  필요함. 컨테이너는 별도 기기로 취급하므로 항상 원격 접속 모드입니다

같은 공유기의 다른 기기라도 192.168.x.x 같은 내부 주소로는 연결할 수 없습니다. 다른 기기는 모두 6-4절의 방법을 쓰세요.

설정 파일은 DATA/config/server-config.json 하나입니다. 포트와 접속 모드가 여기에 저장됩니다. 접근 키는 DATA/config/remote-access-key.txt에 따로 저장됩니다. 두 파일은 직접 고치지 말고 아래의 도구로 바꾸세요.

2. 서버 실행과 종료
----------------------------------------

- Windows
  실행  PROGRAM\1_서버_실행.bat
  백그라운드 실행  PROGRAM\서버_백그라운드_실행.bat
  종료  PROGRAM\2_서버_종료.bat
  상태 확인  PROGRAM\서버_상태_확인.bat

- macOS
  실행  PROGRAM/macOS_서버_실행.command
  백그라운드 실행  sh PROGRAM/서버_백그라운드_실행.sh
  종료  sh PROGRAM/2_서버_종료.sh
  상태 확인  sh PROGRAM/서버_상태_확인.sh

- Linux · Termux
  실행  sh PROGRAM/1_서버_실행.sh
  백그라운드 실행  sh PROGRAM/서버_백그라운드_실행.sh
  종료  sh PROGRAM/2_서버_종료.sh
  상태 확인  sh PROGRAM/서버_상태_확인.sh

- 일반 실행은 창이 서버를 띄우고 있으므로, 창을 닫으면 서버도 꺼집니다. 안전하게 끄려면 종료 스크립트를 쓰세요.
- 서버는 시작할 때 DATA/config/server-config.json을 읽습니다. 포트나 접속 모드를 바꾸면 서버를 다시 실행해야 적용됩니다.
- 실행 창의 Server ready at은 서버가 시작됐음을 알려 줍니다. 원격 접속 모드인지는
  서버 상태 확인에서 remoteAccess.enabled가 true인지 확인하세요.

3. 서버 주소와 플러그인 연결
----------------------------------------

기본 서버 주소는 http://127.0.0.1:47630입니다. 플러그인은 서버 주소를 각자 따로 저장합니다. 한 플러그인에서 바꿔도 다른 플러그인의 주소는 그대로이므로, 주소를 바꿀 때는 모든 플러그인에서 바꿔야 합니다.

- LIBRA · HAYAKU · Flashback
  서버 주소를 바꾸는 곳  서버 연결 설정 → 서버 주소 → 연결 테스트 → 설정 적용

- GRADIA
  서버 주소를 바꾸는 곳  소스 탭 → 서버 주소

- RE:TRACE
  서버 주소를 바꾸는 곳  서버 관리 → 연결 진단 → 서버 주소 → 주소 저장

- LIA
  서버 주소를 바꾸는 곳  서버를 쓰지 않습니다

- RE:TRACE의 주소 저장은 RE:TRACE 관리 연결과 LIA 보관 자료 연결에만 적용됩니다. LIBRA · HAYAKU · Flashback 연결은 각 플러그인에 저장된 주소를 따릅니다. 주소가 서로 다르면 RE:TRACE 화면에 표시됩니다.
- 플러그인 저장 방식(플러그인 단독 · 서버 단독)은 전역 설정입니다. 한 플러그인의 모든 대화에 함께 적용됩니다.

플러그인이 받는 서버 주소

이 PC의 서버는 http://, 다른 기기의 서버는 https://만 쓸 수 있습니다.

- http://127.0.0.1:포트
  쓰는 경우  기본. 이 PC에서 실행 중인 서버 (Docker 포함)

- http://localhost:포트
  쓰는 경우  위와 같음

- http://[::1]:포트
  쓰는 경우  위와 같음 (IPv6)

- http://host.docker.internal:포트
  쓰는 경우  RisuAI도 컨테이너에서 실행하고, 플러그인 요청이 그 컨테이너에서 나갈 때

- https://기기이름.tailnet이름.ts.net 또는 https://내도메인
  쓰는 경우  다른 기기에서 Tailscale이나 Cloudflare Tunnel을 거쳐 접속할 때 (6-4절)

- http://192.168.0.10:47630처럼 이 PC가 아닌 주소를 http://로 넣으면 플러그인이 거부합니다. 접근 키와 기억 자료가 암호화 없이 네트워크를 지나가기 때문입니다.

4. 서버 포트 바꾸기
----------------------------------------

1. 서버를 끕니다 (2_서버_종료).
2. 포트 변경 도구를 실행하고 새 포트(1024~65535)를 입력합니다.
   - Windows: PROGRAM\서버_포트_변경.bat
   - macOS · Linux · Termux: sh PROGRAM/서버_포트_변경.sh (예: sh PROGRAM/서버_포트_변경.sh 48000)
3. 서버를 다시 실행합니다.
4. 모든 플러그인의 서버 주소를 http://127.0.0.1:새포트로 바꿉니다 (3절).
5. Tailscale이나 Cloudflare Tunnel로 포트를 열어 두었다면 새 포트로 다시 엽니다 (6-4절). 다른 기기의 https:// 주소는 그대로입니다.

도구는 저장하기 전에 다음을 확인합니다.
- 서버가 꺼져 있는지
- 새 포트를 다른 프로그램이 쓰고 있지 않은지
- 마치지 않은 업데이트가 없는지

서버 단독으로 쓰는 중이어도 주소를 옮길 수 있습니다.
- 1.0.0에서 업데이트하면 기존 DATA와 서버 주소를 그대로 사용합니다. 서버 단독 모드를 다시 적용할 필요가 없습니다.
- 새 플러그인은 기존 서버 주소에서 서버 단독 DATA에 정상 연결되면 식별값을 자동으로 저장합니다. 포트를 바꿀 예정이라면 이 연결이 먼저 이루어져야 합니다.
- 주소를 바꾸면 새 주소의 서버가 같은 DATA인지 확인한 뒤 주소만 옮깁니다. 자료는 옮기지 않습니다.
- 그래서 4단계 전에 서버가 새 포트로 실행 중이어야 합니다.
- 다음 경우에는 주소 변경이 거부되고 기존 주소가 유지됩니다.
  - 새 주소가 다른 DATA의 서버인 경우
  - 새 주소에 연결할 수 없는 경우
  - 기존 DATA의 식별값을 저장하기 전에 예전 포트를 닫은 경우
- 마지막 경우에는 도구로 예전 포트로 되돌려 서버를 실행합니다. 플러그인이 그 주소에서 서버 기억을 정상적으로 읽은 뒤 다시 포트를 바꾸세요.

5. 내부 접속 모드 (기본)
----------------------------------------

- 서버는 이 PC(127.0.0.1)에서 오는 연결만 받습니다. 별도 설정이나 접근 키 없이 바로 사용합니다.
- 서버 실행 중 플러그인이 처음 연결하면 서버가 연결용 토큰을 자동으로 발급합니다. 사용자가 할 일은 없습니다.
- 다른 기기는 연결할 수 없습니다.
- 내부 접속 모드에서는 Tailscale이나 Cloudflare Tunnel로 서버 포트를 열지 마세요. 터널로 들어온 연결도 서버에게는 "이 PC에서 온 연결"로 보이므로 키 없이 들어옵니다.

6. 원격 접속 모드와 접근 키
----------------------------------------

6-1. 원격 접속 모드란

- 서버는 여전히 이 PC(127.0.0.1)에서만 연결을 받습니다. 듣는 주소는 바뀌지 않습니다.
- 대신 서버에 처음 연결할 때(/bootstrap) 모든 플러그인이 접근 키를 내야 합니다. 이 PC의 플러그인도 마찬가지입니다.
  터널로 들어온 다른 기기의 연결도 서버에게는 이 PC에서 온 것으로 보여 구분할 수 없기 때문입니다.
- 키가 없거나 틀리면 서버는 remote_access_key_required로 거부합니다.
- 다른 기기는 Tailscale이나 Cloudflare Tunnel을 거쳐 https:// 주소로만 들어옵니다 (6-4절).

6-2. 켜기 · 끄기

설정 도구는 설정을 저장하고 바로 끝납니다. 바꾼 설정은 서버를 다시 실행해야 반영됩니다.

1. 서버를 끕니다. 서버가 켜져 있으면 도구가 바꾸지 않고 거부합니다.
2. 설정 도구를 실행합니다.
   - Windows: PROGRAM\서버_외부접속_설정.bat을 실행하고 메뉴에서 번호를 고릅니다.
   - macOS · Linux · Termux: sh PROGRAM/서버_외부접속_설정.sh를 실행합니다. 인자로 바로 줄 수도 있습니다: remote · local · rotate · show
3. 서버를 평소처럼 다시 실행합니다.

- 1. 원격 접속 모드 켜기
  인자  remote
  하는 일  원격 접속 모드로 바꿉니다. 키가 없으면 새로 만들어 화면에 보여 줍니다.
  서버를 꺼야 하나  예

- 2. 내부 접속 모드로 돌아가기
  인자  local
  하는 일  키 없이 이 PC에서만 연결받는 기본 모드로 돌아갑니다. 키 파일은 보존하므로 다시 remote로 켜면 같은 키를 씁니다.
  서버를 꺼야 하나  예

- 3. 접근 키 새로 만들기
  인자  rotate
  하는 일  새 키를 만듭니다. 예전 키로는 더 이상 연결할 수 없습니다.
  서버를 꺼야 하나  예

- 4. 현재 모드와 키 보기
  인자  show
  하는 일  현재 모드와 키를 보여 줍니다.
  서버를 꺼야 하나  아니요

- 한 번 켜면 서버를 다시 시작하거나 PC를 재부팅해도 계속 켜져 있습니다.
- 업데이트로 DATA를 이관할 때도 설정과 키가 함께 옮겨집니다.
- 내부 접속 모드로 돌아가는 자세한 순서는 6-5절에 있습니다. 이 서버로 열린 Tailscale 항목이 있으면 local이 닫을지 묻습니다.

6-3. 플러그인에 접근 키 넣기

원격 접속 모드에서는 이 PC와 다른 기기의 모든 플러그인에 키를 넣습니다.

- LIBRA · HAYAKU · Flashback
  접근 키를 넣는 곳  서버 연결 설정 → 접근 키 → 연결 테스트 또는 설정 적용

- RE:TRACE
  접근 키를 넣는 곳  서버 관리 → 연결 진단 → 접근 키 → 주소 저장

- GRADIA
  접근 키를 넣는 곳  LIBRA에 저장한 접근 키를 함께 씁니다

- 키는 플러그인마다 따로 저장됩니다. RE:TRACE에서 저장한 키는 RE:TRACE와 LIA 연결에만 적용됩니다.
- 입력한 키는 저장한 뒤 칸이 비워지고, 다시 화면에 표시되지 않습니다. 화면에는 "접근 키 저장됨"만 보입니다.
- 칸을 비워 두고 저장하면 이미 저장된 키를 그대로 씁니다. 지우려면 "키 지우기"를 누르세요.
- 키는 서버에 처음 연결할 때(/bootstrap)만 보냅니다.
- 서버를 다시 실행하면 그 전에 발급된 연결 토큰은 모두 무효가 됩니다. 플러그인은 저장된 키로 한 번 다시 연결하므로 사용자가 할 일은 없습니다.

6-4. 다른 기기에서 접속하기

다른 기기는 아래 두 방법 중 하나로만 들어옵니다. 어느 쪽이든 먼저 6-2절대로 원격 접속 모드를 켜고 서버를 실행하세요. 아래 예시의 47630은 지금 쓰는 포트로 바꾸세요.

Tailscale (권장) · 서버_원격접속_열기 도구
- 내 Tailscale 계정에 로그인한 기기끼리만 연결됩니다. 인터넷 전체에 공개되지 않습니다.
- 서버는 계속 이 PC(127.0.0.1)에서만 듣고, Tailscale 서비스가 https://기기이름.tailnet이름.ts.net 으로 들어온 연결을 서버로 넘겨 줍니다.

1. 서버 PC와 다른 기기(폰 포함)에 Tailscale을 설치하고 같은 계정으로 로그인합니다.
   안드로이드 · iPhone은 앱 스토어의 Tailscale 앱을 씁니다.
2. 서버 PC에서 도구를 실행하고 "1. 열기"를 고릅니다.
   - Windows: PROGRAM\서버_원격접속_열기.bat
   - macOS · Linux: sh PROGRAM/서버_원격접속_열기.sh (인자로 바로: open · close · status)
   도구가 하는 일
   - Tailscale이 설치되어 있고 로그인되어 있는지 확인합니다.
   - 내부 접속 모드라면 원격 접속 모드로 바꿀지 묻습니다. 바꾸지 않으면 열지 않습니다. 서버가 켜져 있으면 모드를 바꿀 수 없으니 먼저 서버를 끄세요.
   - tailscale serve로 이 서버의 포트를 엽니다. 처음이면 HTTPS 인증서를 켜라는 안내와 링크가 나올 수 있습니다. 링크를 열어 켜면 이어서 진행됩니다.
   - 다른 기기의 플러그인에 넣을 https:// 주소와 접근 키를 함께 보여 줍니다.
3. 서버를 실행합니다(모드를 방금 바꿨다면 다시 실행).
4. 다른 기기의 플러그인에 그 https:// 주소와 접근 키를 넣습니다. 이 PC의 플러그인에도 접근 키를 넣습니다.

- 별도 창을 띄워 둘 필요가 없습니다. 연 포트는 도구 창을 닫거나 PC를 재부팅해도 닫기 전까지 열려 있습니다. Tailscale 서비스가 계속 연결을 넘겨 주기 때문입니다.
- 닫기: 도구의 "2. 닫기". 이 서버로 열린 항목만 닫고, 직접 열어 둔 다른 항목은 건드리지 않습니다.
- 상태 보기: 도구의 "3. 상태 보기". 모드, Tailscale 로그인 상태, 열림 여부와 주소를 보여 줍니다.
- 443 포트를 다른 항목이 이미 쓰고 있으면 도구는 바꾸지 않고 멈춥니다. tailscale serve status로 확인해 직접 정리하세요.
- Docker 서버는 "4. Docker 서버용으로 열기"를 고릅니다 (7-3절).
- Tailscale 1.52 이상이 필요합니다.
- 도구 없이 직접 하려면: tailscale serve --bg --https=443 http://127.0.0.1:47630 으로 열고, tailscale serve --https=443 off 로 닫습니다. tailscale serve reset은 다른 항목까지 모두 지우므로 쓰지 마세요.
- tailscale funnel은 인터넷 전체에 공개하므로 쓰지 마세요. 도구는 Funnel이 켜져 있으면 경고합니다.
- 안드로이드에서는 Tailscale 앱으로 연결만 할 수 있습니다. 폰(Termux)에서 서버를 돌리고 다른 기기를 받는 기능은 지원하지 않으며, 도구도 Termux에서는 열지 않습니다.

Cloudflare Tunnel
- 내 도메인 주소로 인터넷 어디서나 접속할 수 있습니다. 대신 인터넷 전체에 열리고, 보호 수단은 접근 키뿐입니다.
1. Cloudflare에 도메인을 연결하고 cloudflared를 설치합니다.
2. 서버 PC에서 실행합니다. librarian.example.com은 내 도메인의 주소로 바꾸세요.
       cloudflared tunnel login
       cloudflared tunnel create librarian
       cloudflared tunnel route dns librarian librarian.example.com
       cloudflared tunnel run --url http://127.0.0.1:47630 librarian
3. 다른 기기의 플러그인에 https://librarian.example.com과 접근 키를 넣습니다.
- 마지막 명령을 실행한 창이 열려 있는 동안만 연결됩니다. 창을 닫으면 터널도 닫힙니다.
- Cloudflare Access(로그인 보호)는 켜지 마세요. 플러그인은 Access 로그인을 통과하지 못해 연결이 막힙니다.
- cloudflared tunnel --url http://127.0.0.1:47630 으로 여는 빠른 터널은 실행할 때마다 주소가 바뀝니다. 시험용으로만 쓰세요.

6-5. 내부 접속 모드로 돌아가기

1. 서버를 끕니다. 서버가 켜져 있으면 설정 도구가 바꾸지 않고 거부합니다.
   - Windows: PROGRAM\2_서버_종료.bat
   - macOS · Linux · Termux: sh PROGRAM/2_서버_종료.sh
2. 설정 도구로 내부 접속 모드로 바꿉니다.
   - Windows: PROGRAM\서버_외부접속_설정.bat을 실행하고 "2. 내부 접속 모드로 돌아가기"를 고릅니다.
   - macOS · Linux · Termux: sh PROGRAM/서버_외부접속_설정.sh local
3. 터널을 열어 두었다면 닫습니다. 가장 중요한 단계입니다.
   내부 접속 모드는 키를 검사하지 않는데, 터널로 들어온 연결도 서버에게는 "이 PC에서 온 연결"로 보입니다. 터널이 열려 있으면 다른 기기가 키 없이 들어올 수 있습니다.
   - Tailscale: 2단계에서 도구가 이 서버로 열린 항목을 찾으면 닫을지 묻습니다. 그렇게 답하면 함께 닫힙니다.
     따로 닫으려면 서버_원격접속_열기의 "2. 닫기" 또는 tailscale serve --https=443 off
   - Cloudflare Tunnel: cloudflared tunnel run을 실행한 창을 닫습니다.
4. 서버를 다시 실행합니다. 바꾼 설정은 이때 반영됩니다.
5. 바뀌었는지 확인합니다 (선택).
   - 서버_외부접속_설정의 "4. 현재 모드와 키 보기" (sh PROGRAM/서버_외부접속_설정.sh show)
   - "현재: 내부 접속 모드"라고 나오면 됩니다.

전환한 뒤
- 이 PC의 플러그인은 할 일이 없습니다. 원격 모드에서 받은 연결 토큰은 무효가 되지만, 플러그인이 알아서 한 번 다시 연결합니다.
- 플러그인에 저장된 접근 키는 남아 있어도 괜찮습니다. 내부 접속 모드의 서버는 키를 보지 않습니다. 정리하려면 서버 연결 설정에서 "키 지우기"를 누르세요.
- 다른 기기의 플러그인은 연결이 끊깁니다.
- 접근 키 파일은 보존됩니다. 다시 remote로 켜면 같은 키를 쓰므로 플러그인에 키를 다시 넣을 필요가 없습니다.
- Docker 서버는 항상 원격 접속 모드라 내부 접속 모드로 돌아갈 수 없습니다. 키 없이 쓰려면 PC에서 서버를 직접 실행하세요.

6-6. 키를 바꿨을 때

rotate로 키를 새로 만들고 서버를 다시 실행하면 이전 키와 이전 토큰으로는 연결할 수 없습니다. 모든 플러그인에 새 키를 넣어 주세요.

6-7. 보안 안내

- 접근 키는 이 DATA에 접속할 수 있는 열쇠입니다. 믿을 수 있는 곳에만 입력하고, 다른 사람에게 보내지 마세요.
- 다른 기기를 쓰지 않을 때는 터널을 닫거나 내부 접속 모드로 돌아가세요.
- 키가 새어 나갔다고 생각되면 rotate로 바로 바꾸세요.

7. Docker로 실행하기
----------------------------------------

7-1. 동작 방식

- 플러그인은 지금처럼 RisuAI 안에서 실행되고, 서버만 컨테이너에서 실행됩니다.
- 컨테이너는 별도 기기로 취급합니다. 항상 원격 접속 모드이며 내부 접속 모드로 바꿀 수 없습니다. 같은 PC의 플러그인도 접근 키를 넣어야 합니다.
- 컨테이너인지는 자동으로 추측하지 않고, 이미지에 들어 있는 환경변수 LIBRARIAN_CONTAINER=1로만 판단합니다. 제공하는 Dockerfile에는 이미 들어 있습니다.
  직접 만든 이미지나 다른 compose 파일에서 이 패키지를 실행한다면 LIBRARIAN_CONTAINER=1을 꼭 설정하세요. 없으면 서버가 컨테이너 안의 127.0.0.1에서만 들어 포트 포워딩으로 연결할 수 없습니다.
  확인: 서버 상태(/health)의 remoteAccess가 {"enabled":true,"container":true}이면 컨테이너로 인식된 것입니다.
- 연결은 이 PC 안에서만 오갑니다. compose.yaml이 포트를 이 PC(127.0.0.1)에만 열기 때문에, 같은 PC에서는 터널 없이 http://127.0.0.1:47630으로 연결합니다.
- DATA는 이미지에 들어가지 않습니다. librarian-data 볼륨에 저장됩니다.
- 처음 시작할 때 DATA를 준비하고 접근 키를 만들어 로그에 한 번 보여 줍니다.

7-2. 처음 실행

패키지를 압축 해제한 폴더(PROGRAM과 DATA가 있는 곳)에서 실행합니다.

    docker compose -f PROGRAM/docker/compose.yaml up -d --build

- 접근 키 확인: docker compose -f PROGRAM/docker/compose.yaml logs librarian
- 상태 확인: docker compose -f PROGRAM/docker/compose.yaml ps
- 멈추기 · 다시 시작: docker compose -f PROGRAM/docker/compose.yaml stop / start

compose.yaml은 포트를 이 PC(127.0.0.1:47630)에만 엽니다. 이 설정을 넓히지 마세요. 다른 기기는 6-4절의 방법으로 여세요.

7-3. 플러그인 연결

- 서버 주소는 http://127.0.0.1:47630이고, 로그에 나온 접근 키를 모든 플러그인에 넣습니다 (6-3절).
- RisuAI도 컨테이너에서 실행하고 플러그인 요청이 그 컨테이너에서 나간다면 http://host.docker.internal:47630을 씁니다.
- 다른 기기에서 쓰려면 이 PC에서 서버_원격접속_열기를 실행하고 "4. Docker 서버용으로 열기"를 고릅니다 (6-4절). 컨테이너 포트가 이 PC의 127.0.0.1에 열려 있으므로 그 포트로 연결을 넘겨 줍니다. 포트를 바꿨다면 sh PROGRAM/서버_원격접속_열기.sh open --docker --port 48000 처럼 포트를 줍니다.
  이때 도구는 이 PC의 DATA를 읽거나 바꾸지 않습니다. 접근 키는 컨테이너 볼륨에 있으므로 7-4절의 show로 확인합니다.

7-4. 컨테이너에서 설정 도구 쓰기

설정 도구는 run --rm librarian <명령>으로 실행합니다. 키나 포트를 바꾸기 전에 컨테이너를 멈추세요. 서버 컨테이너가 실행 중이면 도구가 거부합니다.

    docker compose -f PROGRAM/docker/compose.yaml run --rm librarian set-remote-access --show

    docker compose -f PROGRAM/docker/compose.yaml stop
    docker compose -f PROGRAM/docker/compose.yaml run --rm librarian set-remote-access --rotate
    docker compose -f PROGRAM/docker/compose.yaml start

포트를 바꾸려면
1. 컨테이너를 멈추고 다음을 실행합니다.
    docker compose -f PROGRAM/docker/compose.yaml run --rm librarian set-port --port 48000
2. PROGRAM/docker/compose.yaml의 ports를 "127.0.0.1:48000:48000"으로 바꿉니다.
3. up -d로 다시 시작합니다.

8. DATA 관련 주의사항
----------------------------------------

- DATA 폴더 전체가 기억 자료입니다. 백업은 서버를 끈 뒤 DATA 폴더를 통째로 복사하세요. 접근 키와 설정도 DATA 안에 있으므로 함께 백업됩니다.
- DATA를 지우거나 빈 DATA로 덮어쓰지 마세요.
- DATA의 식별값에는 폴더의 실제 위치가 들어갑니다.
  - 같은 DATA라도 위치가 바뀌면 다른 DATA로 인식됩니다. 예를 들어 다른 폴더로 옮기거나, PC에서 직접 실행하다가 Docker 볼륨으로 옮기는 경우입니다.
  - 옮긴 뒤에는 서버 단독으로 쓰던 각 플러그인에서 연결 테스트를 하고 설정을 다시 적용하세요.
  - 포트만 바꾸는 것은 위치가 바뀌는 것이 아니므로 그대로 이어집니다 (4절).
- 같은 DATA 폴더를 두 서버에서 동시에 실행하지 마세요. PC 서버와 컨테이너가 같은 DATA를 함께 쓰면 자료가 손상될 수 있습니다.
- Docker 볼륨을 지키세요.
  - docker compose down -v는 DATA 볼륨까지 지웁니다. 컨테이너만 지우려면 -v 없이 down을 쓰세요.
  - 백업은 컨테이너를 멈춘 뒤 볼륨 전체를 복사하세요.
- 업데이트
  - 1.0.0에서 PROGRAM만 교체하는 업데이트는 기존 DATA 폴더를 그대로 사용합니다.
    포트, 접속 모드, 접근 키도 유지됩니다. 업데이트가 확정되면 업데이터와
    UPDATER 폴더의 장해 대처법도 자동으로 갱신됩니다.
  - Docker에서는 컨테이너 안에서 업데이터를 쓰지 않습니다. 새 릴리스를 받은 폴더에서 up -d --build로 이미지를 다시 만드세요. DATA 볼륨은 그대로 이어서 씁니다.
- 설정 도구는 마치지 않은 업데이트가 있으면 설정을 바꾸지 않습니다. 서버를 한 번 실행해 업데이트 복구를 끝낸 뒤 다시 시도하세요.

9. 문제 해결
----------------------------------------

- 서버가 현재 포트 …에서 실행 중입니다
  원인과 해결  설정 도구는 서버가 꺼져 있을 때만 바꿉니다. 2_서버_종료로 끈 뒤 다시 실행하세요.

- 현재 포트 …에서 응답하는 프로그램이 있어
  원인과 해결  그 포트를 다른 프로그램이 쓰고 있습니다. 그 프로그램을 끄거나, 다른 포트로 바꾸세요.

- 포트 …는 다른 프로그램이 사용 중입니다
  원인과 해결  다른 포트를 고르세요.

- 미완료 업데이트가 있어 … 바꾸지 않았습니다
  원인과 해결  서버를 한 번 실행해 업데이트 복구를 끝낸 뒤 다시 시도하세요.

- 연결 테스트가 remote_access_key_required로 실패
  원인과 해결  서버가 원격 접속 모드입니다(Docker 서버는 항상). 이 PC의 플러그인도 키가 필요합니다. 설정 도구의 "4. 현재 모드와 키 보기"로 키를 확인해 플러그인의 접근 키 칸에 넣으세요. 키를 새로 만들었다면 새 키를 넣어야 합니다.

- 접근 키 형식이 올바르지 않습니다
  원인과 해결  도구가 보여 준 키를 앞뒤 공백 없이 그대로 붙여 넣으세요.

- 허용되지 않는 주소입니다
  원인과 해결  이 PC의 서버는 3절의 네 가지 http:// 주소, 다른 기기의 서버는 https:// 주소만 받습니다. 192.168.x.x 같은 주소를 http://로 넣었다면 6-4절의 방법으로 https:// 주소를 만드세요.

- 서버 단독 플러그인이 다른 DATA라며 연결을 거부
  원인과 해결  DATA 위치가 바뀌었거나 다른 DATA의 서버입니다. 맞는 서버라면 연결 테스트 후 설정을 다시 적용하세요 (8절).

- 원격 접속 모드를 켰는데 서버 상태에서 remoteAccess.enabled가 false로 표시
  원인과 해결  설정은 서버를 다시 실행해야 반영됩니다. 서버를 다시 실행하세요.

- 다른 기기에서 연결이 안 됨
  원인과 해결  서버는 이 PC에서만 연결을 받습니다. 다른 기기는 6-4절대로 Tailscale이나 Cloudflare Tunnel의 https:// 주소로 연결하세요. 서버_원격접속_열기의 "3. 상태 보기"로 열려 있는지, 다른 기기가 같은 Tailscale 계정에 로그인했는지 확인하세요.

- 서버_원격접속_열기: Tailscale을 찾지 못했습니다 / 로그인되어 있지 않습니다
  원인과 해결  Tailscale을 설치하고 앱에서 로그인한 뒤 연결을 켜세요. 1.52보다 오래된 버전이면 업데이트하세요.

- 서버_원격접속_열기: 443 포트를 다른 항목이 쓰고 있습니다
  원인과 해결  이 PC에서 tailscale serve로 다른 것을 열어 두었습니다. tailscale serve status로 확인해 정리한 뒤 다시 여세요. 도구는 다른 항목을 지우지 않습니다.

- 서버 컨테이너가 실행 중입니다
